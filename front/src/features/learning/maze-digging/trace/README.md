# 穴掘り法 視覚的デバッグ（Issue #264）

- 目的: 現在の学習者コードを表示用D1（9×9、主教材の choices）で実行し、フェーズ2と同じ盤面で掘削過程（バックトラックを含む）をステップ再生する。
- 適用範囲: トレース取得、盤面キャンバス変換、モーダル、フェーズ7画面との接続。状態: 現行。最終確認日: 2026-11-07。
- 正本: [Issue #264](https://github.com/BeppuKanato/engineer-quest/issues/264)、[穴掘り法基準データ §3 フェーズ7](../../../../../../docs/concept/maze-digging-unit-baseline.md)、[教材指針 §7-3](../../../../../../docs/concept/learning-materials-guideline.md)、[棒倒し法 視覚的デバッグ](../../wall-extension/trace/README.md)。

## 操作

`front/`で`npm run dev` → `http://localhost:3000/learning-preview/maze-digging-implementation` を開く。ログイン・バックエンド・DBは不要。

MonacoとPyodideの読込完了後、「盤面で掘る様子を見る」を押す。取得中は編集・採点実行・試しに実行・ヒント・重複実行を無効にし、取得状態を表示する。モーダルは84vw × 84dvhで、既存LearningPlayerの再生・前後・シークを使う。図はフェーズ2のMazeDiggingExecutionCanvasそのもの。下に観測行とsize・choices・壁の数を表示する。エディタのコード、採点結果、実行回数、ヒント回数はトレースでは変更しない。全テスト通過後は完了表示からも同じコードを確認できる。

## モジュールと安全なデータ経路

棒倒し法トレース（Issue #213）と同じ構造に揃える。共有トレース基盤（`public/python-trace-harness.mjs`）の grid 検出・size / choices の受け渡し・種類別曖昧判定（ambiguousKinds）をそのまま使い、本Issueでは基盤へ手を入れていない。

- `acquireTrace.ts`: 前の判定用ケースを含むWorkerを破棄し、新しいWorkerへD1の関数名と引数だけを送る。tests・期待値・判定用引数は送らない。
- `convertTrace.ts`: イベント列の `grid` スナップショットから、フェーズ2と同じ検証器（`validateMazeDiggingExecutionCanvas`）を通る完全スナップショットを生成する。正しい迷路を再実行して差し替える処理はない。誤った盤面（余分な通路・掘り残し）もそのまま表示する。
- `MazeDiggingTraceDialog.tsx`: 既存LearningPlayerとMazeDiggingExecutionCanvasを組み合わせるだけのモーダル。
- `trace.content.ts`: ボタン・状態・キャプションの文言。

トレースはD1だけ。標準出力・標準エラー、生の例外本文・トレースバック、任意のlocalsは返さない。例外は種別と学習者ソースの停止行だけを返す。イベント上限はBFS・棒倒し法と同じ500件。

## 状態への対応付け（段階適用）

- 盤面を用意した（全部が壁）→ 部屋が掘れた（間の壁＋部屋の2マスを掘った直後の状態で1コマ、掘った部屋を処理中・青、掘れた2マスをhighlight）→ バックトラック → 完成（旗＋一本道）の変化を1コマずつにする。間の壁だけが掘れた中間状態はコマにせず、部屋が掘れるまで保留する。
- スタックはトレース基盤の取得対象に含まれないため、現在マスと経路は盤面から導出する。掘削の途中では開いたマスが木をなすので、開始マスから現在マスへの経路は一意に定まり、スタックの経路と一致する。バックトラックは盤面が変わらないため、次の掘削の開始マスが前回の掘削先と異なることから検出し、盤面を変えずに現在位置と経路だけを移すコマとして挟む（戻る過程の推定であり、盤面そのものは実値どおり）。
- 壁が増えるなど掘削以外の変化は、変化としてそのまま1コマにする。部屋まで掘り切らずに止まった場合は、掘れたところまでを最後のコマとして出す。
- 途中から盤面として描けない状態（不揃いな行など）になった場合は、描けたところまで再生し「変換できない状態があるため、途中まで表示します。」と明示する。末尾が描ける状態に戻れば通常再生を続ける。
- `grid` のスナップショットが取れない構造（盤面を補助関数の中でだけ作る等）、変換できた状態がない場合、または形の候補が曖昧な場合は、停止位置と最終状態だけを表示する（教材指針 §7-3 の段階適用）。最終状態は戻り値のグリッドから作り、戻り値が盤面でなければ空の盤面に留める。

## 検証・対象外

`npm run verify:maze-digging-trace` は同じハーネスをpython3で実行し、参照コードの再生がフェーズ2の正準フレーム列（盤面・処理中・経路・highlight）と一致すること、改名した盤面変数の形検出、誤った迷路の忠実な再生、途中エラーと停止行、補助関数内で作る盤面の最終状態表示、構文エラー、曖昧な候補、末尾だけ描けない盤面の部分再生、打ち切り、実描画、D1限定・新規Worker・キャンセルを確認する。

参照コード、テスト内容、4段階ヒントは変更しない。DB・進捗／ログ保存・フェーズ接続・単元コンテナは後続Issueの対象。
