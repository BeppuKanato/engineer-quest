# 棒倒し法「動きの確認問題」

- 目的・適用範囲: フェーズ3の8問（タップ5問・選択肢3問）を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-18。
- 正本: [棒倒し法基準データ§3](../../../../../../docs/concept/wall-extension-unit-baseline.md)、[教材指針](../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../docs/wall-extension-phase3-208.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/wall-extension-check を開く。認証・DBは不要。

当初は連結2問だったが、2026-11-17 の判断基準（問題数ではなく「アルゴリズムの流れを理解できていると判断するに足るか」）で監査し、8問へ拡充した。フェーズ4が前提とする流れの理解7件のうち、既存2問は柱の処理順と伸長先（5本目の場面だけ）をカバーし、柱の配置規則・許される方向の規則・完成の判断が未確認だった。場面はすべてフェーズ2のステップをステップIDで参照し、壁を複製しない。

| 設問 | 内容 | 場面 | 回答対象・形式 | 正解 |
| --- | --- | --- | --- | --- |
| next-pillar-place | 次に立てる柱はどれですか | `pillar-6-2`（一番上の段の3本を立て終えた状態） | 柱9マスをタップ | (2,4) |
| next-pillar | 次に処理する柱はどれですか | `extend-2-4`（4本目まで伸長） | 柱9マスをタップ | (4,4) |
| wall-target | 壁になるマスはどれですか（方向の指示: 右） | `extend-2-4` | 柱 (4,4) に隣接する未壁マス3つをタップ | (5,4) |
| allowed-directions-lower | 一番上の段以外の柱が壁を伸ばせる方向はどれですか | `extend-2-4` | 文章4択 | 上を除く、下・左・右の3方向 |
| allowed-directions-top | 一番上の段の柱が壁を伸ばせる方向はどれですか | `directions-rule` | 文章4択 | 上下左右の4方向 |
| next-pillar-late | 次に処理する柱はどれですか | `extend-2-6`（7本目まで伸長） | 柱9マスをタップ | (4,6) |
| wall-target-late | 壁になるマスはどれですか（方向の指示: 右） | `extend-2-6` | 柱 (4,6) に隣接する未壁マス3つをタップ | (5,6) |
| maze-completion | すべての柱から壁を伸ばし終わりました。この後はどうなりますか | `extend-6-6`（9本目まで伸長） | 文章4択 | 迷路の完成です |

- 許される方向の規則は、タップ設問が方向を提示してしまうため従来は未確認だった。フェーズ4の `if-first-row` の分岐全体がこの理解の上に立つので、選択肢2問（下の段側・一番上の段側）で両面から確認する。理由（輪ができるため）はフェーズ6の担当で、ここでは問わない。
- タップ設問では場面ステップの canvas をそのまま使う（処理済みの柱が青いまま）。方向の指示がある設問では同じ盤面のまま、処理中の柱を前提設問の正解の柱へ移し、伸ばした直後を表す highlight を外した場面を返す（`getWallExtensionCheckScene`）。壁の集合は前提の前後で同一。
- 伸長先の回答対象を隣接する未壁マスに限るのは、壁が柱の隣にしか伸びないため。変化が起きる範囲はこの3マスに限られ、既に壁のマス（(4,3)、(3,6)）は含めない。
- 正解は `../wallExtensionMaze.ts` の組み立て済みトレースから導き、基準データ§3の確定事項と一致することをモジュール読み込み時に検証する。

回答形式は共通エンジン（`../../assessment/assessment.ts`）の `concept-check` を使い、タップ設問はノードIDの代わりにセルキー（`"x,y"`）を渡すグリッド版とする。選択肢設問は ChoiceQuestion の契約で requires を持てないため、連動は場面と状況キャプションで表す。新規の判定・進行は作らない。

- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップを参照のまま再生し、回答記録は変えない。
- 回答ボタンはマスの中心に重ねる HTML ボタン（`WallExtensionCheckCanvas`）。共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「○列目、○行目のマスを選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の大きさを保つ。選択肢設問では盤面は表示のみで、文章の選択肢ボタンを盤面の下に置く。

ファイル:

- `check.content.ts`: 設問・正解・依存条件・表示ステップID・復習ID・論点タグ・完了文と、場面の解決（`getWallExtensionCheckScene`）。
- `check.types.ts`: 共通 concept-check 形式へ方向の指示と状況キャプションを足した設問型・コンテンツ型と、単元接続用の要約型。
- `WallExtensionCheckCanvas.tsx`: 共通グリッド描画＋セル単位の回答ボタン。
- `WallExtensionCheckPreview.tsx`: アセスメント画面。BFSフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:wall-extension-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
