# バブルソート「動きの確認問題」

- 目的・適用範囲: フェーズ4が前提とする理解を一通り判断するための7問（タップ5問・選択肢2問）を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-18。
- 正本: [バブルソート基準データ§3](../../../../../../docs/concept/bubble-sort-unit-baseline.md)、[教材指針](../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../docs/bubble-sort-phase3-229.md)（当初2問の実装記録。7問への拡充は本READMEと基準データ§3が現行仕様）。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/bubble-sort-check を開く。認証・DBは不要。

設問数と内訳は固定数ではなく、フェーズ4（動きとコードの対応）が説明なしに使う理解（前提）を一通り判断できるかで決める（2026-11-17 の基準。当初の連結2問は Issue #229）。前提との対応は次のとおりで、場面はすべてフェーズ2のステップをステップIDで参照し、配列を複製しない。

| 前提 | 設問 | 場面 | 正解 |
| --- | --- | --- | --- |
| ペアの進行（左から右へ隣同士） | next-pair（タップ） | `compare-1-1`（[2, 4, 5, 1, 3]） | 位置2（値5） |
| 交換規則・交換する場合の行き先 | larger-destination（タップ、next-pair と連動） | `compare-1-1` | 位置3 |
| 交換規則・交換しない場合の行き先 | larger-stays（タップ） | `compare-2-0`（ペア (2, 4)、交換なし） | 位置1（そのまま） |
| 周の終わりの確定 | fixed-at-pass-end（タップ） | `compare-1-3` | 位置4（値5） |
| 次の周の再開 | pass-two-first-pair（タップ、fixed-at-pass-end と連動） | `pass-end-1` | 位置0 |
| 範囲の縮小量 | pass-two-pair-count（数値の選択肢） | `pass-end-1` | 3組 |
| 終了の理由 | why-finished（選択肢） | `compare-4-0` | 範囲が狭くなってペアがなくなるから |

- next-pair では場面ステップの canvas をそのまま使う（直前に比べたペア (4, 5) が青いまま）。larger-destination では同じ配列のまま、これから比べるペアを前提設問の正解（位置2）から [2, 3] と示し、直前の比較を表す highlight を外した場面を返す（`getBubbleSortCheckScene`）。pass-two-first-pair の前提（右端の確定）は場面ステップ `pass-end-1` の盤面自体が示すため加工しない。値の配列は全問とも場面ステップと同一。
- タップ設問の回答対象は、場面の未確定範囲や比べるペアなど、答えが行き着きうるマスだけに限る（確定済みの右端はもう比べない、比べた後の大きい値の行き先はペアの2マスだけ、など）。選択肢設問は二分探索フェーズ3と同じく共通エンジンの concept-check 形式で混在させ、盤面には回答ボタンを出さない。
- 正解はすべて `../bubbleSort.ts` の実行記録から導き、基準データ§3の確定事項と一致することをモジュール読み込み時に検証する。

回答形式は共通エンジン（`../../assessment/assessment.ts`）の `concept-check` を使い、ノードIDの代わりに配列の位置（インデックス）の文字列を渡す。新規の判定・進行は作らない。

- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップを参照のまま再生し、回答記録は変えない。
- 回答ボタンは棒の列に重ねる HTML ボタン（`BubbleSortCheckCanvas`）。共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「左から○番目のマス（値 ○）を選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の幅を保つ。選択肢設問のボタンは二分探索フェーズ3と同じ見た目（`data-choice-id` 付き）。

ファイル:

- `check.content.ts`: 設問・正解・依存条件・表示ステップID・復習ID・論点タグ・完了文と、場面の解決（`getBubbleSortCheckScene`）。
- `check.types.ts`: 共通 concept-check 形式の設問型・コンテンツ型と、単元接続用の要約型。
- `BubbleSortCheckCanvas.tsx`: 共通配列描画＋マス（棒の列）単位の回答ボタン。
- `BubbleSortCheckPreview.tsx`: アセスメント画面。BFSフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:bubble-sort-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
