# 穴掘り法「動きの確認問題」

- 目的・適用範囲: Issue #259の連結2問を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-07。
- 正本: [穴掘り法基準データ§3](../../../../../../../docs/concept/maze-digging-unit-baseline.md)、[教材指針](../../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../../docs/maze-digging-phase3-259.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/maze-digging-check を開く。認証・DBは不要。

場面はフェーズ2の `dig-3`（主教材9×9で3回目まで掘った状態）の盤面で、2問ともステップIDで参照し、壁を複製しない。

| 設問 | 内容 | 回答対象 | 正解 |
| --- | --- | --- | --- |
| next-room | (3, 5) から右へ掘ります。掘られる部屋はどれですか | 候補の部屋3マス（上 (1, 5)・右 (3, 7)・下 (5, 5)） | (3, 7) |
| between-wall | そのとき通路になる、間の壁マスはどれですか | 候補方向の間の壁マス3つ（(2, 5)・(3, 6)・(4, 5)） | (3, 6) |

- 場面は2問とも場面ステップの canvas そのもの（処理中の現在マス (3, 5) は両問で変わらない）。棒倒し法フェーズ3と違い、前提設問の正解で処理中マスが移ることはないため、場面の差し替えはしない。
- 方向は Q1 の問題文の中で提示する（基準データ §6-6）。穴掘り法は次の行き先が乱数（choices）で決まるため、方向を与えないと正解が一意に定まらない。与えた上でも「2マス先の部屋」と「間の壁」を特定する学習は成立する。棒倒し法のような独立した方向フィールド／表示行は持たない。
- Q1の回答対象は、アルゴリズムが実際に集める候補そのもの（現在マスから2マス先が盤内で、まだ壁のままの部屋）。左 (3, 3) は掘削済みなので候補に入らない。Q2の回答対象は候補方向それぞれの間の壁マスで、掘削で通路になるのはこの範囲だけ。
- 正解は `../mazeDiggingMaze.ts` の組み立て済みトレースの4回目の掘削から導き、基準データ§3の確定事項（セルキー "5,3" から右へ、部屋 "7,3"・間の壁 "6,3"）と一致することをモジュール読み込み時に検証する。なお座標の表示は Issue #326 で (y, x) の順に統一したため、画面上は現在マス (3, 5) のように表示される（セルキー自体は "x,y" のまま）。
- 場面の検証は単元側の `validateMazeDiggingCanvas`（processing は通路側の現在マス）で行う。共有の `validateMazeGridCanvas` は棒倒し法の前提のため使わない。

回答形式は共通エンジン（`../../assessment/assessment.ts`）の `node-tap-check` をそのまま使い、ノードIDの代わりにセルキー（`"x,y"`）を渡すグリッド版とする。新規の判定・進行は作らない。

- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップ（`dig-3` → `dig-4`）を参照のまま再生し、回答記録は変えない。
- 回答ボタンはマスの中心に重ねる HTML ボタン（`MazeDiggingCheckCanvas`）。共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「○列目、○行目のマスを選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の大きさを保つ。

ファイル:

- `check.content.ts`: 設問・正解・依存条件・表示ステップID・復習ID・論点タグ・完了文と、場面の解決（`getMazeDiggingCheckScene`）。
- `check.types.ts`: 共通 node-tap 形式の設問型・コンテンツ型と、単元接続用の要約型。
- `MazeDiggingCheckCanvas.tsx`: 共通グリッド描画＋セル単位の回答ボタン。
- `MazeDiggingCheckPreview.tsx`: アセスメント画面。BFSフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:maze-digging-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
