# バブルソート「動きの確認問題」

- 目的・適用範囲: Issue #229の連結2問を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-06。
- 正本: [バブルソート基準データ§3](../../../../../../docs/concept/bubble-sort-unit-baseline.md)（取り込みは Issue #226。未取り込みの間は承認済み原本に従う）、[教材指針](../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../docs/bubble-sort-phase3-229.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/bubble-sort-check を開く。認証・DBは不要。

場面はフェーズ2の `compare-1-1`（主教材 [4, 2, 5, 1, 3] で1周目の2回目の比較まで終えた状態、配列 [2, 4, 5, 1, 3]）で、2問ともステップIDで参照し、配列を複製しない。

| 設問 | 内容 | 回答対象 | 正解 |
| --- | --- | --- | --- |
| next-pair | 次に比べるペアの左側のマスはどれか | 未確定範囲のマス5つ（位置0〜4） | 位置2（値5） |
| larger-destination | 比べた後、大きい方の 5 はどのマスへ行くか | ペアの2マス（位置2・3） | 位置3 |

- Q1では場面ステップの canvas をそのまま使う（直前に比べたペア (4, 5) が青いまま）。Q2では同じ配列のまま、これから比べるペアをQ1の正解（位置2）から [2, 3] と示し、直前の比較を表す highlight を外した場面を返す（`getBubbleSortCheckScene`）。値の配列は両問とも場面ステップと同一。
- Q1の回答対象を未確定範囲に限るのは、確定済みの右端はもう比べないため（この場面では fixedFrom=5 で全マスが未確定）。Q2の回答対象をペアの2マスに限るのは、比べた後の大きい値が行き着く先は「そのまま」か「右隣」しかないため。
- 正解は `../bubbleSort.ts` の実行記録の次の比較（1周目 j=2、ペア (5, 1)、交換あり）から導き、基準データ§3の確定事項（位置2 → 位置3）と一致することをモジュール読み込み時に検証する。

回答形式は共通エンジン（`../../assessment/assessment.ts`）の `node-tap-check` をそのまま使い、ノードIDの代わりに配列の位置（インデックス）の文字列を渡す。新規の判定・進行は作らない。

- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップ（`compare-1-1` → `compare-1-2`）を参照のまま再生し、回答記録は変えない。
- 回答ボタンは棒の列に重ねる HTML ボタン（`BubbleSortCheckCanvas`）。共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「左から○番目のマス（値 ○）を選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の幅を保つ。

ファイル:

- `check.content.ts`: 設問・正解・依存条件・表示ステップID・復習ID・論点タグ・完了文と、場面の解決（`getBubbleSortCheckScene`）。
- `check.types.ts`: 共通 node-tap 形式の設問型・コンテンツ型と、単元接続用の要約型。
- `BubbleSortCheckCanvas.tsx`: 共通配列描画＋マス（棒の列）単位の回答ボタン。
- `BubbleSortCheckPreview.tsx`: アセスメント画面。BFSフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:bubble-sort-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
