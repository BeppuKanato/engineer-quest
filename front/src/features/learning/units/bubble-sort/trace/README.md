# バブルソート 視覚的デバッグ（Issue #234）

- 目的: 現在の学習者コードを表示用D1で実行し、フェーズ2と同じ配列キャンバス・プレイヤーで比較・交換の過程を再生する。
- 適用範囲: トレース取得、配列キャンバス変換、モーダル、単品ページとの接続。状態: 現行。最終確認日: 2026-11-07。
- 正本: [Issue #234](https://github.com/BeppuKanato/engineer-quest/issues/234)、[バブルソート基準データ §3 フェーズ7](../../../../../../docs/concept/bubble-sort-unit-baseline.md)、[教材指針 §7-3](../../../../../../docs/concept/learning-materials-guideline.md)、[UI定義](../../../../../../docs/concept/learning-player-ui.md)。BFS の視覚デバッグ（Issue #76）と同じ段階適用・構造に揃える。

## 操作

`front/`で`npm run dev`を実行し、起動したマシンで`http://localhost:3000/learning-preview/bubble-sort-implementation`を開く。ログイン・バックエンド・DBは不要。

MonacoとPyodideの読込完了後、「配列で動きを見る」を押す。取得中は編集・採点実行・試し実行・ヒント・重複実行を無効にし、取得状態を表示する。
モーダルは84vw × 84dvhで、既存LearningPlayerの再生・前後・シーク・矢印／Home／Endを使う。図はフェーズ2のBubbleSortExecutionCanvasそのもの。下に観測行とresult・i・jを表示する。
エディタのコード、採点結果、実行回数、ヒント回数はトレースでは変更しない。採点は別の「テストを実行する」で5件を実行し、全テスト通過後はリザルトの「配列で動きを見る」から同じコードを確認できる。

## モジュールと安全なデータ経路

- `lib/pythonTrace.types.ts`／`public/python-trace-harness.mjs`: BFSと共通のトレース基盤。Issue #234で、数値リスト（優先名 result、なければ型・内容で一意に検出）と整数の添字 i・j・n の記録、数値リストの戻り値の記録を追加した。BFSの queue・distances 検出は変更していない。
- `acquireTrace.ts`: 前の判定用ケースを含むWorkerを破棄し、新しいWorkerへD1の関数名と引数だけを送る。tests・期待値・判定用引数は送らない。
- `convertTrace.ts`: Pythonの実値から描画可能性を確認して完全スナップショットを生成する。正しいバブルソートを再実行して差し替える処理はない。
- `BubbleSortTraceDialog.tsx`: 既存LearningPlayerとBubbleSortExecutionCanvasを組み合わせるだけのモーダル。
- `trace.content.ts`: ボタン・状態・キャプションの文言。

トレースはD1だけ。標準出力・標準エラー、生の例外本文・トレースバック、任意のlocalsは返さない。例外は種別と学習者ソースの停止行だけを返す。
作業リストは result という名前を優先し、なければ有限な数値だけのリスト／タプルを型・内容で検出する。候補が複数なら推測せず最終状態のみへ落とす（入力 values と作業リストの両方が候補になる実装は、result という名前がない限り最終状態表示になる）。値の変更が過去イベントへ波及しないよう、イベントごとにコピーする。1イベントあたりコレクション64件・文字列100文字まで、既定500イベント（API上限2000）に制限する。上限時は打ち切りと停止行を返し、BaseExceptionで捕捉されても成功扱いにしない。
実行時間は既存の15秒制限に委ねる。ネイティブ処理中など行イベントで止められないタイムアウトではWorker自体が破棄されるため、途中の記録は取得できない。その場合は再生せず、タイムアウトを表示して再試行できる。

## 状態への対応付け

行イベントは「その行が実行される直前」に発火するため、比較の結果（交換後の並び）は次のイベントで初めて見える。変換では比較を開始時点の並びとともに保留し、次の比較・周の切り替わり・return のイベントで、比較後の並びと比較したペアを1コマとして確定する。外側ループ（i）の行イベントでは j が前の周の値のまま残るため、そのイベントからは比較を始めず、周の終わりの確定コマを挟む。
正解コードの再生は、フェーズ2の正準16コマ（初期・比較10・各周の確定4・完成）と、並び・比べたペア・確定範囲が一致する。
各コマはフェーズ2と同じ ArrayBarsCanvasState に行・変数のメタデータを付けたもの。比べているペアはフォーカス青、確定した右端は完了グレー、入れ替えた2マスはフェーズ2と同じく枠で強調する。キャプションは比較・交換・周の確定の差分から機械生成する。
誤った並び替え（途中で止まる交換、逆向きの比較など）もそのまま表示する。正しい並びに固定されたフェーズ2のデータは使わない。
負数を含む並びなど棒で描けない状態は飛ばす。末尾が描けない状態でも、変換できた状態があればそこまで再生し「変換できない状態があるため、途中まで表示します。」と明示する。i・j を使わない実装（while など）では並びの変化だけを追い、比べたペアは示さない。再帰など作業リストのスナップショットが取れない構造、変換できた状態がない場合、または候補が曖昧な場合は最終状態表示へ落とす。最終状態は戻り値の数値リストを描き、戻り値が描けない場合は最後に描けた状態、それもなければD1の入力の並びを描く。
最終状態モードは1フレームで再生操作は無効。エラーなら停止行と種別、上限なら途中までであることも明示する。

## 検証・対象外

`npm run verify:bubble-sort-trace`は同じハーネスをpython3で実行し、正解コードとフェーズ2正準16コマの一致、スナップショットのコピー、交換しない比較と誤った交換の再現、途中エラーと停止行、打ち切り、構文エラー、候補が曖昧な場合の最終状態、再帰の最終状態、D1限定・新規Worker・キャンセルを確認する。
bfsCodeに相当する参照コード（bubbleSortCode）、テスト内容、4段階ヒント、試しに実行は変更しない。単元フローへの接続・DB・進捗／ログ保存は対象外。
