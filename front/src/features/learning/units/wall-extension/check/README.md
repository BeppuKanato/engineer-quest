# 棒倒し法「動きの確認問題」

- 目的・適用範囲: Issue #208の連結2問を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-06。
- 正本: [棒倒し法基準データ§3](../../../../../../docs/concept/wall-extension-unit-baseline.md)、[教材指針](../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../docs/wall-extension-phase3-208.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/wall-extension-check を開く。認証・DBは不要。

場面はフェーズ2の `extend-2-4`（主教材9×9で4本目まで壁を伸ばした状態）の盤面で、2問ともステップIDで参照し、壁を複製しない。

| 設問 | 内容 | 回答対象 | 正解 |
| --- | --- | --- | --- |
| next-pillar | 次に処理する柱はどれですか | 柱9マス | (4,4) |
| wall-target | 壁になるマスはどれですか（方向の指示: 右） | 柱 (4,4) に隣接する未壁マス3つ | (5,4) |

- Q1では場面ステップの canvas をそのまま使う（処理済みの柱が青いまま）。Q2では同じ盤面のまま、処理中の柱をQ1の正解 (4,4) へ移し、伸ばした直後を表す highlight を外した場面を返す（`getWallExtensionCheckScene`）。壁の集合は両問とも場面ステップと同一。
- Q2の回答対象を隣接する未壁マスに限るのは、壁が柱の隣にしか伸びないため。変化が起きる範囲はこの3マスに限られ、(4,3) は既に壁なので含めない。
- 正解は `../wallExtensionMaze.ts` の組み立て済みトレースの5本目から導き、基準データ§3の確定事項（柱 (4,4)・右・(5,4)）と一致することをモジュール読み込み時に検証する。

回答形式は共通エンジン（`../../assessment/assessment.ts`）の `node-tap-check` をそのまま使い、ノードIDの代わりにセルキー（`"x,y"`）を渡すグリッド版とする。新規の判定・進行は作らない。

- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップ（`extend-2-4` → `extend-4-4`）を参照のまま再生し、回答記録は変えない。
- 回答ボタンはマスの中心に重ねる HTML ボタン（`WallExtensionCheckCanvas`）。共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「○列目、○行目のマスを選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の大きさを保つ。

ファイル:

- `check.content.ts`: 設問・正解・依存条件・表示ステップID・復習ID・論点タグ・完了文と、場面の解決（`getWallExtensionCheckScene`）。
- `check.types.ts`: 共通 node-tap 形式へ方向の指示を足した設問型・コンテンツ型と、単元接続用の要約型。
- `WallExtensionCheckCanvas.tsx`: 共通グリッド描画＋セル単位の回答ボタン。
- `WallExtensionCheckPreview.tsx`: アセスメント画面。BFSフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:wall-extension-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
