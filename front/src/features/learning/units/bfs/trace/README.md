# BFS 視覚的デバッグ（Issue #76）

- 目的: 現在の学習者コードを表示用D1で実行し、共通キャンバス・プレイヤーで状態を再生する。
- 適用範囲: トレース取得、BFSキャンバス変換、モーダル、単品ページとの接続。状態: 現行。最終確認日: 2026-11-05。
- 起点: `develop` `6d013f4`（PR #99マージ済み）。
- 正本: [Issue #76](https://github.com/BeppuKanato/engineer-quest/issues/76)、[教材指針 §1・7-3](../../../../../../../docs/concept/learning-materials-guideline.md)、[UI定義](../../../../../../../docs/concept/learning-player-ui.md)。

## 操作

`front/`で`npm ci` → `npm run dev`。起動したマシンで`http://localhost:3000/learning-preview/bfs-implementation`を開く。ログイン・バックエンド・DBは不要。
クラウドのlocalhostは手元PCへ公開したURLではない。

MonacoとPyodideの読込完了後、「実行する」を押す。取得中は編集・採点実行・ヒント・重複実行を無効にし、取得状態を表示する。
モーダルは84vw × 84dvhで、既存LearningPlayerの再生・前後・シーク・矢印／Home／Endを使う。図はBfsExecutionCanvasそのもの。下に観測行とqueue・distances・nodeを表示する。
エディタのコード、採点結果、実行回数、ヒント回数はトレースでは変更しない。採点は別の「テストを実行する」で5件を実行し、全テスト通過後はリザルトの「動きを確認する」から同じコードを確認できる。リザルトの「テスト実行回数」にトレースは含めない。

## モジュールと安全なデータ経路

- `lib/pythonTrace.types.ts`: 行イベント・限定したlocals・終了状態・停止行・上限の型。
- `public/python-trace-harness.mjs`: WorkerとCPython検証が同じPythonハーネスを使うビルダー。ソースのexec後にルート・イベント・件数をリセットしてから`sys.settrace`を有効化し、ハーネス自身のD1呼び出しだけを記録する。その呼び出し中の学習者ソースの補助関数も上限カウントに含める。トップレベルの試し呼び出しは記録・件数に含めず、既存Workerの時間制限だけに委ねる。トップレベルで例外があっても対象関数が定義済みならD1を実行し、未定義なら元の停止行・種別を返す。
- `lib/pyodideRunner.ts`／`public/pyodide-course-worker.mjs`: 既存のping・run・runCreateQuestを保ち、kind=traceを追加する。
- `acquireTrace.ts`: 前の判定用ケースを含むWorkerを破棄し、新しいWorkerへD1の関数名と引数だけを送る。tests・期待値・判定用引数は送らない。アンマウントされた呼び出し元は次の実行を開始しない。
- `convertTrace.ts`: Pythonの実値から描画可能性を確認して完全スナップショットを生成する。正しいBFSを再実行して差し替える処理はない。
- `BfsTraceDialog.tsx`: 既存LearningPlayerとBfsExecutionCanvasを組み合わせるだけのモーダル。
- `trace.content.ts`: ボタン・状態・キャプションの文言。

トレースはD1だけ。標準出力・標準エラー、生の例外本文・トレースバック、任意のlocalsは返さない。例外は種別と学習者ソースの停止行だけを返す。
queue・distancesという名前のローカル変数を優先する。なければ型・内容で検出し、queueは文字列だけのlist／tuple／deque、distancesは文字列キー・有限数値の辞書をコピーする。候補が複数なら推測せず最終状態のみへ落とす。検出した実際のキュー変数名をwhile条件のAST中の名前と照合する。node・neighborのみ名前ベースのままであり、改名すると処理中の強調は弱くなるがキュー・距離の再生は可能。画面の変数欄は従来のqueue・distances表記を保つ。値の変更が過去イベントへ波及しない。1イベントあたりコレクション64件・文字列100文字まで、既定500イベント（API上限2000）に制限する。上限時は打ち切りと停止行を返し、BaseExceptionで捕捉されても成功扱いにしない。
実行時間は既存の15秒制限に委ねる。ネイティブ処理中など行イベントで止められないタイムアウトではWorker自体が破棄されるため、途中の記録は取得できない。その場合は再生せず、タイムアウトを表示して再試行できる。

## 状態への対応付け

ユーザー確認により、距離代入と直後のキュー追加を1コマにまとめ、検出したキュー変数を条件に含むwhileの境界に「調べ終えた」状態を補う。変数表示のnodeはPythonに残っている実値であり、図の処理中表示はループ本体の処理区間を表す。
正解コードの正準19コマのうち、状態が変わらないskip-eを間引いた18状態と、処理中・キュー順・距離の列が一致する。

各コマはフェーズ2と同じBfsExecutionCanvasStateに行・変数のメタデータを付けたもの。距離とキューからノード色を決め、現在の場所は青、キュー内はベージュ、距離ありの残りはグレー、距離なしは白とする。キャプションは取り出し・追加・距離変更・完了の差分から機械生成する。queue[0]を見るだけのコードを「取り出した」とは表現しない。

連続する同一状態を間引き、最後の同一状態は終了・停止・打ち切りのキャプションへ更新する。エラー前の距離代入だけが残った場合は、その値も保持して停止フレームを作る。
誤った数値やLIFOの取り出し順もそのまま表示する。正しい距離に固定されたフェーズ2の検証器は適用しない。誤った距離と正準の距離帯が食い違う場合だけ帯を外し、ノード位置・数値は変えない。

既存キャンバスが描ける範囲はD1の6点、既知の距離を持つ重複のない最大6件のキューである。未代入や個別の無効な状態は飛ばす。末尾が重複／未知ノードのキューなどで変換不能でも、変換できた状態があればそこまで再生し「変換できない状態があるため、途中まで表示します。」と明示する。末尾が有効に戻れば通常の再生を続ける。再帰などキュー・距離のスナップショットが取れない構造、変換できた状態がない場合、または候補が曖昧な場合だけ最終状態表示へ落とす。返り値が数値辞書ならD1上の距離を描く。返り値だけからローカル変数を捏造せず、変数欄には型・内容で検出できた実値を表示する。検出できなければ未代入を示す。
最終状態モードは1フレームで再生操作は無効。エラーなら停止行と種別、上限なら途中までであることも明示する。

## 検証・対象外

`npm run verify:bfs-trace`は同じハーネスをpython3で実行し、正解・listキュー・初期化順交換と正準状態列の一致、LIFOの誤り、誤距離、コピー、途中エラーと停止行、再帰の最終状態、構文エラー、改名que／q・distと正準18状態、優先名・曖昧な候補、トップレベルの試し呼び出し・多数の呼び出し・定義前後の例外、無効な末尾の部分再生と回復、上限・捕捉された上限、D1限定・新規Worker・キャンセルを確認する。
既存verify一式、lint・typecheck・buildと、ブラウザの実Pyodide確認・画像は[実装報告](../../../../../../../docs/bfs-visual-debug-76.md)を参照する。

bfsCode、テスト内容、4段階ヒント、従来のMission/Activityは変更しない。エディタ改善・printコンソール・他フェーズへの組み込み・DB・進捗／ログ保存・フェーズ接続は対象外。
