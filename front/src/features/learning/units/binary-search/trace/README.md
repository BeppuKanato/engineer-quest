# 二分探索 視覚的デバッグ（Issue #293）

- 目的: 現在の学習者コードを表示用D1で実行し、フェーズ2と同じ盤面キャンバス・プレイヤーで探索範囲が狭まる過程を再生する。
- 適用範囲: トレース取得、盤面スナップショット変換、モーダル、フェーズ7画面との接続。状態: 現行。最終確認日: 2026-11-07。
- 正本: [Issue #293](https://github.com/BeppuKanato/engineer-quest/issues/293)、[二分探索基準データ §3 フェーズ7・§4](../../../../../../../docs/concept/binary-search-unit-baseline.md)、[教材指針 §7-3](../../../../../../../docs/concept/learning-materials-guideline.md)、[UI定義](../../../../../../../docs/concept/learning-player-ui.md)。バブルソートの視覚デバッグ（Issue #234）と同じ段階適用・構造に揃える。

## 操作

`front/`で`npm run dev`を実行し、起動したマシンで`http://localhost:3000/learning-preview/binary-search-implementation`を開く。ログイン・バックエンド・DBは不要。

MonacoとPyodideの読込完了後、「範囲が狭まる様子を見る」を押す。取得中は編集・採点実行・試し実行・ヒント・重複実行を無効にし、取得状態を表示する。
モーダルは84vw × 84dvhで、既存LearningPlayerの再生・前後・シーク・矢印／Home／Endを使う。図はフェーズ2のBinarySearchExecutionCanvasそのもの。下に観測行とvalues・lo・hi・mid・targetを表示する。
エディタのコード、採点結果、実行回数、ヒント回数はトレースでは変更しない。採点は別の「テストを実行する」で4件を実行し、全テスト通過後はリザルトの「範囲が狭まる様子を見る」から同じコードを確認できる。

## モジュールと安全なデータ経路

- `lib/pythonTrace.types.ts`／`public/python-trace-harness.mjs`: 全単元共通のトレース基盤。本Issueで、整数の lo・hi・mid・target の記録を加算した（対象名の変数が無い単元では何も記録されず、既存単元の結果は変わらない）。
- `acquireTrace.ts`: 前の判定用ケースを含むWorkerを破棄し、新しいWorkerへD1の関数名と引数だけを送る。tests・期待値・判定用引数は送らない。
- `convertTrace.ts`: Pythonの実値から描画可能性を確認して完全スナップショットを生成する。正しい二分探索を再実行して差し替える処理はない。
- `BinarySearchTraceDialog.tsx`: 既存LearningPlayerとBinarySearchExecutionCanvasを組み合わせるだけのモーダル。
- `trace.content.ts`: ボタン・状態・キャプションの文言。

トレースはD1だけ。標準出力・標準エラー、生の例外本文・トレースバック、任意のlocalsは返さない。例外は種別と学習者ソースの停止行だけを返す。
盤面として使える並びは、盤面型の前提（小さい順・非負・有限、64件まで）を満たすものだけ。イベントごとにコピーされ、1イベントあたりコレクション64件・文字列100文字まで、既定500イベント（API上限2000）に制限する。上限時は打ち切りと停止行を返し、BaseExceptionで捕捉されても成功扱いにしない。
実行時間は既存の15秒制限に委ねる。ネイティブ処理中など行イベントで止められないタイムアウトではWorker自体が破棄されるため、途中の記録は取得できない。その場合は再生せず、タイムアウトを表示して再試行できる。

## 状態への対応付け

行イベントは「その行が実行される直前」に発火するため、比較の結果（どちらの側を捨てたか）は次の範囲が現れるイベントで初めて見える。変換では比較を保留し、範囲が保留中の中央の片側を超えたイベントで、「捨てた側の盤面」と「確定した範囲の盤面」をこの順で確定する。新しい中央の観測が比較の開始になる。範囲が中央を含んだまま狭まるなど捨てる形にならずに別の比較へ移った場合は、保留を確定させずに解消し、新しい比較として扱う（`lo = mid` のような誤りの再生が「見つからなかった」で終わらないための措置）。
正解コードの再生は、フェーズ2の正準11コマ（範囲提示前の導入・全体範囲・比較3回分の中央／捨てる／確定範囲・発見・まとめ）と、盤面・強調・キャプションまで一致する。
各コマはフェーズ2と同じ BinarySearchExecutionCanvasState に行・変数のメタデータを付けたもの。範囲外は完了グレー相当、中央は処理中の青、発見は青＋強調リングで示す。キャプションはフェーズ2と同じ規則で、保留した比較の確定結果から機械生成する。
発見の判定は、関数が正常に返った時点で保留中の比較の中央が探す値と一致していることによる（ハーネスは整数の戻り値を返さないため、戻り値そのものは使わない。中央が探す値と一致しているのに -1 を返す誤実装では、発見として表示される。この制約は既存の盤面・行情報からは判別できないため、割り切った近似として採用し、PR にも要確認として明記する）。
範囲が空になって終わった探索は、最後の盤面に「範囲が空になり、見つかりませんでした」のキャプションを付けて示す。誤った範囲更新（例: 比較の向きを逆にする）もそのまま表示する。正しい探索に固定されたフェーズ2のデータは使わない。
盤面として描けない並び（小さい順でない・負数を含む等）が現れた時点で変換を打ち切り、変換できた状態までを再生して「変換できない状態があるため、途中まで表示します。」と明示する。lo・hi・mid を使わない実装（別の変数名、線形探索、再帰など）や、変数の候補が曖昧な場合は最終状態表示へ落とす。最終状態は最後に描けた盤面、それもなければD1の入力の並びを、範囲をまだ示していない状態で描く。
最終状態モードは1フレームで再生操作は無効。エラーなら停止行と種別、上限なら途中までであることも明示する。

## 検証・対象外

`npm run verify:binary-search-trace`は同じハーネスをpython3で実行し、正解コードとフェーズ2正準11コマの完全一致（盤面・強調・キャプション）、ハーネス加算が既存単元の記録を変えないこと、比較の向きを逆にした誤探索の再生、`lo = mid` の誤りの再生、途中エラーと停止行、打ち切り、構文エラー、候補が曖昧な場合の最終状態、lo・hi・mid を使わない実装の最終状態、D1限定・新規Worker・キャンセルを確認する。
参照コード（binarySearchCode）、テスト内容、4段階ヒント、試しに実行は変更しない。単元フローへの接続・DB・進捗／ログ保存は対象外。
