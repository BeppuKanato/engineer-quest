# 貪欲法（硬貨問題） 視覚的デバッグ（Issue #388）

- 目的: 現在の学習者コードを表示用D1で実行し、フェーズ2と同じ硬貨の図・プレイヤーで硬貨が1枚ずつ選ばれる過程を再生する。
- 適用範囲: トレース取得、盤面スナップショット変換、モーダル、フェーズ7画面との接続。状態: 現行。最終確認日: 2026-11-11。
- 正本: [Issue #388](https://github.com/BeppuKanato/engineer-quest/issues/388)、[貪欲法（硬貨問題）基準データ §3 フェーズ7・§4](../../../../../../docs/concept/greedy-coins-unit-baseline.md)、[教材指針 §7-3](../../../../../../docs/concept/learning-materials-guideline.md)、[UI定義](../../../../../../docs/concept/learning-player-ui.md)。二分探索の視覚デバッグ（Issue #293）と同じ段階適用・構造に揃える。

## 操作

`front/`で`npm run dev`を実行し、起動したマシンで`http://localhost:3000/learning-preview/greedy-coins-implementation`を開く。ログイン・バックエンド・DBは不要。

MonacoとPyodideの読込完了後、「硬貨が選ばれる様子を見る」を押す。取得中は編集・採点実行・試し実行・ヒント・重複実行を無効にし、取得状態を表示する。
モーダルは84vw × 84dvhで、既存LearningPlayerの再生・前後・シーク・矢印／Home／Endを使う。図はフェーズ2のGreedyCoinsExecutionCanvasそのもの。下に観測行とresult・remaining・coin・amountを表示する。
エディタのコード、採点結果、実行回数、ヒント回数はトレースでは変更しない。採点は別の「テストを実行する」で5件を実行し、全テスト通過後はリザルトの「硬貨が選ばれる様子を見る」から同じコードを確認できる。

## モジュールと安全なデータ経路

- `lib/pythonTrace.types.ts`／`public/python-trace-harness.mjs`: 全単元共通のトレース基盤。本Issueで、整数の remaining・coin・amount の記録を加算した（対象名の変数が無い単元では何も記録されず、既存単元の結果は変わらない）。
- `acquireTrace.ts`: 前の判定用ケースを含むWorkerを破棄し、新しいWorkerへD1の関数名と引数だけを送る。tests・期待値・判定用引数は送らない。
- `convertTrace.ts`: Pythonの実値から描画可能性を確認して完全スナップショットを生成する。正しい貪欲法を再実行して差し替える処理はない。
- `GreedyCoinsTraceDialog.tsx`: 既存LearningPlayerとGreedyCoinsExecutionCanvasを組み合わせるだけのモーダル。
- `trace.content.ts`: ボタン・状態・キャプションの文言。

トレースはD1だけ。標準出力・標準エラー、生の例外本文・トレースバック、任意のlocalsは返さない。例外は種別と学習者ソースの停止行だけを返す。
イベントごとにコピーされ、1イベントあたりコレクション64件・文字列100文字まで、既定500イベント（API上限2000）に制限する。上限時は打ち切りと停止行を返し、BaseExceptionで捕捉されても成功扱いにしない。
実行時間は既存の15秒制限に委ねる。ネイティブ処理中など行イベントで止められないタイムアウトではWorker自体が破棄されるため、途中の記録は取得できない。その場合は再生せず、タイムアウトを表示して再試行できる。

## 状態への対応付け

行イベントは「その行が実行される直前」に発火するため、硬貨1枚の選択は `result.append(coin)` と `remaining -= coin` の2行に分かれて現れる。記録だけが増えたイベントではトレイ合計と残額が一致しないので盤面にせず、両方がそろったイベント（while の再チェック等）で初めて選択を確定する。確定の条件は「トレイ合計＋残額＝金額」かつ「トレイの最後の硬貨＝今見ている額面（coin）」であり、額面が次へ進んだだけのイベントは選択として数えない。
正解コードの再生は、フェーズ2の正準11コマ（導入・選択9回・まとめ）と、盤面・キャプションまで一致する。
各コマはフェーズ2と同じ GreedyCoinsExecutionCanvasState に行・変数のメタデータを付けたもの。額面の状態は処理中＝青、未到達＝ベージュ、通過済み＝グレーで示す（完了の緑は使わない）。
残額が0にならずに終わった実行は、最後の盤面にその旨のキャプションを付けて示す。誤った選択（小さい硬貨から使う等）もそのまま表示する。正しい選択に固定されたフェーズ2のデータは使わない。
トレイとして描けない並び（額面に無い値を含む・選択順でない・合計が金額を超える）が現れた時点で変換を打ち切り、変換できた状態までを再生して「変換できない状態があるため、途中まで表示します。」と明示する。remaining・coin を使わない実装（別の変数名など）や、変数の候補が曖昧な場合は最終状態表示へ落とす。最終状態は最後に描けたトレイ、それもなければ空のトレイを、導入の盤面で描く。
最終状態モードは1フレームで再生操作は無効。エラーなら停止行と種別、上限なら途中までであることも明示する。

## 検証・対象外

`npm run verify:greedy-coins-trace`は同じハーネスをpython3で実行し、正解コードとフェーズ2正準11コマの完全一致（盤面・キャプション）、ハーネス加算が既存単元の記録を変えないこと、途中エラーと停止行、打ち切り、構文エラー、候補が曖昧な場合の最終状態、remaining・coin を使わない実装の最終状態、D1限定・新規Worker・キャンセルを確認する。
参照コード（greedyCoinsCode）、テスト内容、4段階ヒント、試しに実行は変更しない。単元フローへの接続・DB・進捗／ログ保存は対象外。
