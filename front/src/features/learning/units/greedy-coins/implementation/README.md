# 貪欲法（硬貨問題）「自分で実装」

- 目的・適用範囲: Issue #387の自由記述課題 `greedy_coins(amount, coins)`（表示用1件＋判定用4件、全通過が完了条件のハードゲート）と段階式ヒント4段、D1専用の試しに実行を単品で操作する。状態: 現行。最終確認日: 2026-11-11。
- 正本: [貪欲法（硬貨問題）基準データ§2・§3](../../../../../../../docs/concept/greedy-coins-unit-baseline.md)、[教材指針](../../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../../docs/greedy-coins-phase7-387.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/greedy-coins-implementation を開く。認証・DBは不要。

| 内部ID（画面には出さない） | 表示 | 入力・期待値 |
| --- | --- | --- |
| D1 | 金額・額面・期待する並び・実際の並び | 786円を [500, 100, 50, 10, 5, 1] で → [500, 100, 100, 50, 10, 10, 10, 5, 1]（主教材） |
| J1 | 種別・合否のみ | 主教材と同じ入力 → 同じ並びの完全一致 |
| J2 | 種別・合否のみ | 転移342円を [500, 100, 50, 10, 5, 1] で → [100, 100, 100, 10, 10, 10, 10, 1, 1] |
| J3 | 種別・合否のみ | 41円を [25, 10, 5, 1] で → [25, 10, 5, 1] |
| J4 | 種別・合否のみ | 6円を [4, 3, 1] で → [4, 1, 1]（反例。基準データ §6 決定3により判定用に追加し、表示用には出さない。最適化ソルバを書くと不合格になり、実装対象が貪欲であることを区別できる） |

- 期待する並びは教材データの正本 `greedyCoins` の実行記録（参照コードと同じ手順）から導き、フェーズ1〜6の教材とずらさない。判定は既存の教材テスト基盤（Worker 内の完全一致）で行う。契約どおり関数は引数を変更しない。
- テスト結果は表示用だけ金額・額面・期待する並び・実際の並びを示す。実際の並びは、トレイとして描ける場合（額面に含まれ・選択順で・合計が金額以下）は硬貨図のトレイで示し、それ以外は文字列の並びで示す。判定用の値・標準出力・生の例外は画面状態へ渡さない。
- 試しに実行は D1 だけを Worker を作り直して実行し、戻り値の硬貨の並びをトレイで示す。通過数・実行回数・完了判定は変えない。
- 入力量レベル3段階（Issue #328）: 全部書く（関数定義＋docstring のみ、プレースホルダ0）／骨格から書く（3）／穴埋めで書く（2）。骨格と穴埋めのテンプレートは基準データ §3 フェーズ7のコードブロックどおり。テストと完了条件はレベルによらず同一で、未着手のテンプレートは判定で失敗する。
- ヒントは1→2→3→4の順に解放する。レベル3の骨格は参照コード（契約 greedy-coins-v1）の意味ID `for-coin`／`while-remaining` の2行を原文のまま示す。レベル4はフェーズ6の Parsons 設問を土台に、固定行を外した全8行の並べ替えを練習モード（採点なし）で表示する（フェードさせない。互換グループは土台から引き継ぐ）。
- 視覚デバッグ（ボタン文言「硬貨が選ばれる様子を見る」）は Issue #388 で `../trace/` の再生へ接続した。
