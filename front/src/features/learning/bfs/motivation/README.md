## 確認方法

`front` で `npm ci` → `npm run dev` を実行し、`http://localhost:3000/learning-preview/bfs-motivation` を開く。
ログイン・DB・バックエンド起動は不要。既存画面にリンクは追加していない。
production build で確認する場合は `npm run build` の後、`node node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3000` で起動する。

前へ・次へ・再生・一時停止・スライダー、または ← / → / Home / End で全17コマを確認する。
1コマ目は途中のルートを隠し、2〜3コマ目で5手と3手を比較する。
4〜6コマ目は1手ずつ移動し、7コマ目では現在地を動かさずゴールだけが変わる。
8〜10コマ目で出発点に戻って2手の別例をたどる。
11〜13コマ目で格子の場所・つながりをA〜Fのノード・辺へ対応付け、駅・SNSの実用例を見る。
14〜16コマ目は格子で0歩・1歩の入口を見せてから、同じ状態をグラフへ写す。
17コマ目で初めて「幅優先探索」と名付け、出口ボタンを表示する。

出口の「フェーズ2へ進む」は未接続で disabled。実際の遷移先、押下後の画面や保存処理は作っていない。
最後のグラフと最初の1歩の強調は維持し、フェーズ2で突然表現を切り替えずに接続できる。

## データと数学的な条件

`motivation.content.ts` の `bfsMotivationContent` は #68 の `LearningContent<MotivationCanvasState>` を使い、用語表を追加したデータである。
キャプション・対象データ・現在地・ゴール・道筋・強調・用語タグ・出口を1コマの完全な状態として持つ。
前コマのイベントを累積せず、任意シーク・逆送りでもそのコマだけから復元できる。
描画・ボタンは `BfsMotivationCanvas.tsx`、再生・キャプション・操作バーは既存 `LearningPlayer` が担当する。
教材固有の遷移は600ms、`intervalMs` は3500ms。OSの「動きを減らす」設定では動きを省く。

格子の通行可能な場所は次の6か所（右下2マスは壁）。ノードIDは格子とグラフで共通である。

```text
A — B — E — F
|   |
C — D   壁  壁
```

`../bfsGraph.ts` がA〜Fの接続とグラフ配置を定義する。後続 #70 はこのデータを再利用できる。
辺は AB / AC / BD / CD / BE / EF。各辺は上下左右の1マス移動と1対1で対応する。

- 5手: A→C→D→B→E→F。
- 最短3手: A→B→E→F。
- ゴール変更後の最短2手: A→C→D（A→B→Dも同じ2手）。
- 駅の例は区間数の最小化であり、所要時間や乗換回数の最小化ではない。
- SNSは人の数ではなく関係の線を数える。AからFへは3本。
- 手数は選んでたどった道の移動回数。「○歩」は出発点からの最短距離を示す層の表現で、出発点を0とする。

`validateMotivationCanvas` は格子の位置、ノード参照、隣接、道筋、強調・用語タグの参照を検証する。
用語表の初出コマIDも読込時に検証する。入力は型付きTSモジュールのみで、API / JSON読込は追加していない。

## 判断点と土台側の既知差分

1. 約15コマの構成を保ちながら、移動を1手ずつ、ゴール移動と出発点への復帰を別の変化として分け、17コマとした。全文の「4〜5コマ」は目安として採用しない。
2. 作業依頼は実用例の後に格子へ戻るが、全文§1は締めをフェーズ2と同じ表現へ置くよう要求する。格子での入口提示の後に対応付けの16コマ目を挟み、17コマ目をグラフにして両方を満たす。
3. 全文1-4のシームレス接続と、要約・Issue #69の意思確認ボタンは食い違う。本Issueの明示指示を優先して出口ボタンを配置し、接続自体は実装しない。
4. 参照できる文書・IssueにはサンプルA〜Fの具体的な接続形状がない。この実装は格子と同じ接続・最短3本を満たす6ノードをデータとして分離した。サンプルと接続形状・座標まで一致したとの主張はせず、#70での再利用を要レビュー点とする。
5. 共通プレイヤーは100%表示、300msトークン、最低350msの再生制御、横幅いっぱいのスライダーが残り、最新UI定義とは異なる。#83の範囲として未変更。この教材の図の遷移600ms・指定間隔3500msは定義内だが、プレイヤー全体の一致は保証しない。
6. 390px幅の開発モードでは Next.js Dev Tools の左下バッジが再生ボタンと重なる場合がある。土台の配置は変更せず、最終操作はバッジのない production build でも確認する。

## 検証

`front` で `npm run lint` / `npm run typecheck` / `npm run build` / `npm run verify:learning-player` / `npm run verify:bfs-motivation`。
教材の検証は最短距離、5手/3手、各コマ1手、格子とグラフの全隣接一致、語彙の参照、入口・名称・出口の条件、不正な道筋の拒否を確認する。
ブラウザでは前後移動・シーク・再生、比較・ゴール移動・橋渡し・実用例・最終ボタン、狭い画面を確認する。
DB適用、バックエンド・他フェーズの検証は不要。フェーズ2へ遷移できないのは意図した対象外である。

2026-11-04 の実施結果: 上記5コマンドは成功。Chrome で全17コマ、前後移動、シーク、自動送り・一時停止・末尾停止・先頭からの再生、出口の表示条件を確認した。
1366×768 / 390×844で表示を確認し、390px幅で横スクロールなし。最終 production build の新規タブで全コマを通し、console error / warn なし。
build は既存 next/font のフォント取得のためネットワークアクセス可能な環境で実行した。既存の複数lockfileによる workspace root 警告と ESLint設定の module type 警告は残る。
