- 適用範囲: ノードの1タップ回答、再挑戦、メモリ上の回答記録、復習。状態: 現行。最終確認日: 2026-11-04。
- 起点: develop `ff52aa9`（#88 の共有グラフ統一を含む）。
- 正本: [教材指針](../../../../../../docs/concept/learning-materials-guideline.md) §1・フェーズ3、[UI定義](../../../../../../docs/concept/learning-player-ui.md)、Issue #71 と実装指示。

## 確認方法

`front` で `npm ci` → `npm run dev`、`http://localhost:3000/learning-preview/bfs-check` を開く。
ログイン・バックエンドは不要。production 確認は `npm run build` → `node node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3000`。

1. 問1でD等をタップすると「もう一度、」が付き、同じ図のまま再挑戦できる。問2へは進まない。
2. 誤答後の「該当ステップの動きを確認する」で復習モーダルを任意に開く。再生または次へで `complete-b` → `dequeue-c` を確認し、閉じる（Escも可）。回答・試行数は復習では変わらない。
3. Cをタップすると問2に進む。C処理中・キューD,Eの図が表示される。
4. 問2でE等をタップすると再挑戦できる。任意復習は `dequeue-c` → `skip-e` で、C–Eの破線と追加なしを確認できる。
5. 「どれも入らない」で正解する。同じキャンバス上で取り出す順序・重複追加しない判断を追えたことと、次のコード対応の予告を1文で示す。次フェーズへのボタンやリザルト画面は出さない。

ノードにはHTMLボタンを重ね、回答できるノードだと静止状態でも分かるよう `playerTokens.focus` の破線リングを常時表示する（ホバー／フォーカスで太くなる）。設問の下には「図の場所をタップして答えよう」の操作指示を常時出し、問2の「どれも入らない」もノードと同じ破線の選択肢ボタンとして並べる。キーボードでもTabで選択し、Enter / Spaceで回答できる。誤答時・次問・完了時はキャプションへフォーカスする。
ページを再読込すると未回答に戻る。保存処理・やり直し専用画面はない。

## データと共通処理

`check.content.ts` は設問文・正解・依存条件・表示ステップID・復習ID・論点タグ・完了文のみを持つ。
フェーズ2のステップやcanvas、グラフを複製・再定義しない。

| 設問 | 表示ID | 正解 | 前提 | 復習ID |
| --- | --- | --- | --- | --- |
| take-next | complete-b | C | なし | complete-b → dequeue-c |
| after-c | dequeue-c | どれも入らない | take-nextでCに正解済み | dequeue-c → skip-e |

`getLearningStep` が元のステップをIDで取得する。共有グラフの正本は `../bfsGraph.ts`。
描画は `BfsExecutionCanvas` を再利用し、任意の `renderNodeOverlay` で既存ノードの座標内にタップ領域だけを置く。
ノード・辺・層・キューの描画は増設していない。操作領域がある場合だけSVGのroleをgroupにし、内部ボタンを読み上げ・キーボード操作できるようにする。
フェーズ2のデータ・キャプションと、操作領域なしの場合の描画は変更しない。

`../../assessment/assessment.ts` はBFS・Reactに依存しない共通の進行管理である。
今回の形式は `version: 1 / kind: node-tap-check`。ノード選択と任意の「該当なし」のみを定義し、コード穴埋め等は実装しない。
正解するまで同じ設問に留まり、先行設問の正解と指定回答が揃ってから次問を出す。全問正解だけを完了とする。
回答イベントは設問IDを持つため、古い設問への連打が次問の回答へ混入しない。

回答記録は `AssessmentState` にassessmentIdと設問ごとの `QuestionRecord` を保持する。
各記録はquestionId、attemptCount、firstCorrect（未回答はnull）、solved、全attempts（試行番号・選択内容・正誤）を持つ。
初回誤答は後の正解で上書きしない。論点タグは設問データから結合でき、#78でログへ渡せるが、現在はメモリ内のみである。
フェーズ5・6での別回答形式や完了ポリシーはそれぞれのIssueで追加する。

`../../review/LearningReviewDialog.tsx` はBFSに依存せず、コンテンツ・ステップID列・rendererを受け取る汎用復習モーダル。
`selectReviewContent` は元ステップのオブジェクト参照を選び、共通 `LearningPlayer` で再生する。
モーダルを閉じるとプレイヤーをアンマウントしてタイマーを止め、再度開くと最初の参照状態から始まる。復習による回答記録の変更はない。

## 指針との差・判断点

- 問2の指定復習 `skip-e` を静止画だけにしないため、直前の `dequeue-c` から始めて同ステップへの変化を再生する。どちらも既存ステップへの参照であり、データ・キャプションの変更はない。モーダルはまず先頭を表示し、共通プレイヤーの再生・次へで動かす。
- 指針は完了後のリザルトを要求するが、今回の明示指示に従い同じキャンバス上の1文だけで完了・次フェーズ予告を示す。リザルト・接続は#77の対象。
- 誤答時も設問文を残しつつ1文に保つため、「もう一度、」を先頭に付ける。別の長文解説・評価パネルは追加しない。問1正解時は直ちに連動する問2へ移る。
- 出題中は回答による進行が必要なので自動再生・自由シークを出さない。共通プレイヤーを使うのは復習モーダルである。プレイヤー本体は未変更。
- 新規の確認枠・モーダルは幅と高さ84%を基準とする。復習内の共通プレイヤーには#83の既知差分（300ms共通トークン、短い再生下限、長いスライダー等）が残る。本教材の図は既存の600ms、コンテンツは3500msを使う。短い高さでは縦スクロールが発生し得る。
- アプリ組み込み、DB、API、回答・進捗・ログの保存、フェーズ接続、リザルトは対象外。DB適用なし。

## 検証

`npm run lint` / `npm run typecheck` / `npm run build` / `npm run verify:bfs-check`。
回帰確認は `npm run verify:learning-player` / `npm run verify:bfs-motivation` / `npm run verify:bfs-execution`。

新verifyは全参照IDの実在・元ステップの参照同一性・共有グラフ同一性、問1の正解と実キュー先頭の一致、問2の対象と問1の回答の一致、隣接点がすべて発見済みで新規追加がないことを確認する。
進行管理は誤答保持、依存先を未正解のまま回答できないこと、全ノード誤答後の再試行、初回正誤と全履歴、連打、全問正解だけの完了を検証する。不正なステップID・正解・依存条件・復習参照の拒否も確認する。

2026-11-04 の実施結果: 上記7コマンドは成功。production buildのChromeで、両問の誤答→任意復習→再挑戦、C正解後だけ問2へ進むこと、「どれも入らない」での完了・予告を確認した。
復習の再生・次へ・末尾停止、閉じる・Esc・再度開いたときの先頭復帰、ノードのTab / Enter / Space操作も確認した。
1366×768と390×844で表示し、狭い画面でもノードのタップ領域44px以上、最大3要素のキュー表示、横スクロールなし。console error / warnなし。
既存の複数lockfileによるworkspace root警告とESLint設定のmodule type警告は残るがexit 0。buildは既存next/fontの取得のためネットワーク可能な環境で実施した。DB・外部API・保存・フェーズ間接続の検証は対象外。
