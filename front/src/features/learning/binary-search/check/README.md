# 二分探索「動きの確認問題」

- 目的・適用範囲: Issue #288の確認問題を、フェーズ4が前提とする理解を一通り判断できる5問に拡充したもの（2026-11-17 の基準）を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-18。
- 正本: [二分探索基準データ§3フェーズ3](../../../../../../docs/concept/binary-search-unit-baseline.md)、[教材指針](../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../docs/binary-search-phase3-288.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/binary-search-check を開く。認証・DBは不要。

場面はフェーズ2のステップをIDで参照し、盤面を複製しない。設問は主教材（[3, 7, 12, 19, 25, 31, 42] で 25 を探す）のトレースを最初から最後まで1本にたどる並びになっている。

| 設問 | 内容 | 回答形式・対象 | 正解 |
| --- | --- | --- | --- |
| first-center | 最初に調べる真ん中のマスはどれか（場面は `range-full`） | 配列セルのタップ（全体の位置0〜6） | 位置3（値19） |
| range-after-first-compare | 19 と 25 を比べた後、次に残る範囲はどうなるか（場面は `probe-1-mid`） | 文章の4択ボタン | 左側を捨てて、範囲は 4 から 6 になる |
| next-center | 左側を捨てました。次に調べる真ん中のマスはどれか（場面は `range-after-drop-left`、lo=4 / hi=6、インデックス3の 19 は確認済みで範囲外） | 配列セルのタップ（残った範囲の位置4〜6） | 位置5（値31） |
| range-after-compare | 31 と 25 を比べた後、次に残る範囲はどうなるか（場面は `probe-2-mid`） | 文章の4択ボタン | 右側を捨てて、範囲は 4 だけになる |
| final-hit | 残った 1 個の 25 を見ました。どうなりますか（場面は `probe-3-mid`） | 文章の4択ボタン | 探す値と一致したので、探索は終わり、答えは位置 4 になる |

- 設問数と内訳は固定数ではなく、フェーズ4（動きとコードの対応）が前提とする理解を一通り判断できるかで決める（2026-11-17 の基準）。フェーズ4が前提とするのは、範囲が全体から始まること、次に調べるのは残った範囲の真ん中であること、小さい側・大きい側のどちらを捨てるかと捨てた後に残る範囲（真ん中自身も外れる）、一致したらその位置を答えとして終わること。当初の2問（next-center / range-after-compare）は「2回目の真ん中」と「右を捨てた後の範囲」だけを聞いており、最初の真ん中、左を捨てた後の範囲、一致での終了が未確認だったため、トレースの前後に3問を足した。
- タップ設問の回答対象を残った範囲に限るのは、捨てた部分はもう調べないため（19 を含む位置0〜3はタップできない）。正解はすべて `../binarySearch.ts` の実行記録（probes）から導き、基準データ§3の確定事項と一致することをモジュール読み込み時に検証する。
- 範囲の変化と一致での終了は「どちら側を捨てるか／どう終わるか」という変化そのものを問うため、セルのタップではなく文章の4択にした。選択肢の数値（位置・範囲）も実行記録から導く。選択肢設問の場面は、比べる値を見たステップ（`probe-1-mid` / `probe-2-mid` / `probe-3-mid`）で、選択肢は盤面の下にボタンとして並べる（フェーズ6の選択肢ボタンと同じ見た目）。
- 出題形式は共通エンジン（`../../assessment/assessment.ts`）の `concept-check` を使う。タップ設問と選択肢設問を1つのセッションに混在させるための種別である（choice 設問をフェーズ6の diagnostic-check へ寄せると、完了時に診断閲覧イベントが誤発火するため）。新規の判定・進行は作らない。
- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 正誤の文は設問ごとの解説（`correctFeedback` / `incorrectFeedback`）で出す。誤答時は、タップ設問では真ん中の決め方（残った範囲の両端から真ん中を求める）、範囲の設問ではどちら側を捨てるか（比べた値より大きい側／小さい側を捨て、比べたマス自身も範囲から外れる）、最後の設問では一致したらその位置を答えとして終わることに言及する。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップ（first-center: `range-full` → `probe-1-mid`、range-after-first-compare: `probe-1-mid` → `probe-1-drop-left` → `range-after-drop-left`、next-center: `range-after-drop-left` → `probe-2-mid`、range-after-compare: `probe-2-mid` → `probe-2-drop-right` → `range-single`、final-hit: `probe-3-mid` → `found`）を参照のまま再生し、回答記録は変えない。
- タップ設問の回答ボタンは棒の列に重ねる HTML ボタン（`BinarySearchCheckCanvas`）。描画はフェーズ2と同じ変換（`../execution/BinarySearchExecutionCanvas` の `toArrayBars`）＋共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「左から○番目のマス（値 ○）を選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の幅を保つ。

ファイル:

- `check.content.ts`: 設問・正解・表示ステップID・復習ID・論点タグ・正誤の解説文・完了文と、場面の解決（`getBinarySearchCheckScene`）。
- `check.types.ts`: 共通 concept-check 形式の設問型・コンテンツ型と、単元接続用の要約型。
- `BinarySearchCheckCanvas.tsx`: フェーズ2と同じ盤面変換＋共通配列描画と、マス（棒の列）単位の回答ボタン。
- `BinarySearchCheckPreview.tsx`: アセスメント画面。他単元のフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:binary-search-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
