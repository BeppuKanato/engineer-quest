# 貪欲法（硬貨問題）「動きの確認問題」

- 目的・適用範囲: Issue #383の連結2問を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-11。
- 正本: [貪欲法（硬貨問題）基準データ§3フェーズ3](../../../../../../docs/concept/greedy-coins-unit-baseline.md)、[教材指針](../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../docs/greedy-coins-phase3-383.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/greedy-coins-check を開く。認証・DBは不要。

場面はフェーズ2のステップをIDで参照し、盤面を複製しない。場面は `select-3`（主教材786円で500・100・100の3枚を使い終わり、残額86、トレイは [500, 100, 100]）で、2問とも同じ場面を使う。

| 設問 | 内容 | 回答形式・対象 | 正解 |
| --- | --- | --- | --- |
| next-coin | 残りは86円です。次に選ぶ硬貨はどれか | 額面列のタップ（全6額面） | 50円 |
| why-not-100 | なぜ100円ではなく50円を選ぶのか | 文章の4択ボタン | 100円は残額の86円より大きくて使えないから |

- Q1の回答対象を全額面にするのは、同じ額面は何枚でも使えるため、100（もう2枚使った）も500（通過した）も候補に残し、「残額より大きい硬貨は使えない」ことを含めて判断させるため。正解は `../greedyCoins.ts` の実行記録の4枚目の選択（選ぶ直前の残額86、硬貨50）から導き、基準データ§3の確定事項と一致することをモジュール読み込み時に検証する。
- Q2は「なぜその硬貨を選ぶのか」という理由そのものを問うため、基準データ§3の定めどおり額面のタップではなく文章の4択にした。誤答の選択肢は、額面の大きさ（50の方が小さい）や使用回数（100はもう2枚使った）に引っ張られるものを置く。
- 出題形式は共通エンジン（`../../assessment/assessment.ts`）の `concept-check` を使う。新規の判定・進行は作らない。
- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 正誤の文は設問ごとの解説（`correctFeedback` / `incorrectFeedback`）で出す。誤答時は、どちらの設問でも「残額以下で一番大きい硬貨を選ぶ」という決め方に言及する（基準データ§3）。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップ（`select-3` → `select-4`）を参照のまま再生し、回答記録は変えない。
- Q1の回答ボタンは額面チップに重ねる HTML ボタン（`GreedyCoinsCheckCanvas`）。描画はフェーズ2と同じ盤面（`../execution/GreedyCoinsExecutionCanvas`）＋共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「○円の硬貨を選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の大きさを保つ。

ファイル:

- `check.content.ts`: 設問・正解・表示ステップID・復習ID・論点タグ・正誤の解説文・完了文と、場面の解決（`getGreedyCoinsCheckScene`）。
- `check.types.ts`: 共通 concept-check 形式の設問型・コンテンツ型と、単元接続用の要約型。
- `GreedyCoinsCheckCanvas.tsx`: フェーズ2と同じ盤面描画と、額面チップ単位の回答ボタン。
- `GreedyCoinsCheckPreview.tsx`: アセスメント画面。他単元のフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:greedy-coins-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
