# 貪欲法（硬貨問題）「動きの確認問題」

- 目的・適用範囲: Issue #383の連結2問に、フェーズ4が前提とする理解を判断する4問を足した6問を単品で最後まで操作する。状態: 現行。最終確認日: 2026-11-18。
- 正本: [貪欲法（硬貨問題）基準データ§3フェーズ3](../../../../../../docs/concept/greedy-coins-unit-baseline.md)、[教材指針](../../../../../../docs/concept/learning-materials-guideline.md)、[プレイヤーUI定義](../../../../../../docs/concept/learning-player-ui.md)。
- 実装・検証・指針との留保: [実施記録](../../../../../../docs/greedy-coins-phase3-383.md)。

`front`で`npm run dev`を実行して http://localhost:3000/learning-preview/greedy-coins-check を開く。認証・DBは不要。

設問数は固定数ではなく、フェーズ4（動きとコードの対応）が前提とする理解を一通り判断できるかで決める（2026-11-17 の基準）。フェーズ4が説明なしに使う理解は、選択の規則（残額以下で一番大きい硬貨を選ぶ）、同じ額面の繰り返し使用、使えなくなった額面を過ぎて小さい額面へ進むこと、選んだ分だけ残額が減ること、残額0で終わることの5点。当初の2問は規則の1場面（select-3）しか見ておらず、繰り返し使用は Q2 の誤答選択肢と誤答解説での言及のみ、額面の前進は理由を聞くだけで進んだ先を選ぶ問題がなく、残額の更新と終了は無確認だったため、場面を分けて4問を足した。

場面はフェーズ2のステップをIDで参照し、盤面を複製しない。

| 設問 | 場面 | 内容 | 回答形式・対象 | 正解 |
| --- | --- | --- | --- | --- |
| next-coin | `select-3`（残額86、トレイ [500, 100, 100]） | 残りは86円です。次に選ぶ硬貨はどれか | 額面列のタップ（全6額面） | 50円 |
| why-not-100 | `select-3` | なぜ100円ではなく50円を選ぶのか | 文章の4択ボタン | 100円は残額の86円より大きくて使えないから |
| next-coin-repeat | `select-2`（残額186、トレイ [500, 100]） | 残りは186円です。次に選ぶ硬貨はどれか | 額面列のタップ（全6額面） | 100円（同じ額面をもう1枚） |
| next-coin-move-down | `select-4`（残額36、トレイ [500, 100, 100, 50]） | 残りは36円です。次に選ぶ硬貨はどれか | 額面列のタップ（全6額面） | 10円（50は使えなくなった） |
| remaining-after-next | `select-6`（残額16） | 次に10円を選ぶと、残りは何円になりますか | 数字の4択ボタン | 6円 |
| payment-finished | `summary`（残額0、トレイ9枚） | 残りが0円になりました。この後どうなりますか | 文章の4択ボタン | 払い終わりで、もう硬貨は選ばない |

- タップ設問の回答対象を全額面にするのは、同じ額面は何枚でも使えるため、100（もう使った）も500（通過した）も候補に残し、「残額より大きい硬貨は使えない」ことを含めて判断させるため。正解は `../greedyCoins.ts` の実行記録から導き、基準データ§3の確定事項と一致することをモジュール読み込み時に検証する。
- why-not-100 は「なぜその硬貨を選ぶのか」という理由そのものを問うため、額面のタップではなく文章の4択にした。誤答の選択肢は、額面の大きさ（50の方が小さい）や使用回数（100はもう2枚使った）に引っ張られるものを置く。
- remaining-after-next は数字を判断する問題（2026-11-17 に許可）で、選んだ分だけ残額が減ることを場面 select-6（16円→10円を選ぶ）で問う。
- 出題形式は共通エンジン（`../../assessment/assessment.ts`）の `concept-check` を使う。新規の判定・進行は作らない。
- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」を押して進む。正解していなくても進める（ソフトゲート）。完了条件は「最後まで進み、全問に1回以上回答したこと」で、結果と要約は初回回答のみから導く。
- 正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 正誤の文は設問ごとの解説（`correctFeedback` / `incorrectFeedback`）で出す。誤答時は、硬貨を選ぶ設問で「残額以下で一番大きい硬貨を選ぶ」という決め方に言及する（基準データ§3）。
- 誤答後は「該当ステップの動きを確認する」で復習モーダルを任意に開ける。復習はフェーズ2の元ステップを参照のまま再生し、回答記録は変えない。各設問の復習は、その設問の場面から次に正解の硬貨が選ばれる場面までを見せる。
- タップ設問の回答ボタンは額面チップに重ねる HTML ボタン（`GreedyCoinsCheckCanvas`）。描画はフェーズ2と同じ盤面（`../execution/GreedyCoinsExecutionCanvas`）＋共通の `answerCueSx`（破線リング＋タップアイコン）で回答可能だと示し、`aria-label` は「○円の硬貨を選ぶ」。画面上で44px未満になる場合は中心から広げて最低限の大きさを保つ。

ファイル:

- `check.content.ts`: 設問・正解・表示ステップID・復習ID・論点タグ・正誤の解説文・完了文と、場面の解決（`getGreedyCoinsCheckScene`）。
- `check.types.ts`: 共通 concept-check 形式の設問型・コンテンツ型と、単元接続用の要約型。
- `GreedyCoinsCheckCanvas.tsx`: フェーズ2と同じ盤面描画と、額面チップ単位の回答ボタン。
- `GreedyCoinsCheckPreview.tsx`: アセスメント画面。他単元のフェーズ3と同じく embedded / onComplete（要約通知）を持つ。

検証: `npm run verify:greedy-coins-check`。単元フローへの接続・進捗保存は後続Issueの対象で、このモジュールは保存処理を持たない。
