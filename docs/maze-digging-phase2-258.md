# 穴掘り法 フェーズ2（動きの説明）（Issue #258）

目的: 穴掘り法単元のフェーズ2を、#257 のグリッド描画基盤の上に21ステップの完全スナップショットとして実装する。設計は基準データ（docs/concept/maze-digging-unit-baseline.md §1・§3、正本は基準データ取り込み PR #267 で別途進行中のため、本実装はその承認済み原本に従う）に従い、§6 の要判断ポイントは推奨デフォルトで進行する決定済み。最終確認日: 2026-11-07。本 PR は feat/maze-digging-phase1-257（PR #268）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/maze-digging/mazeDiggingMaze.ts` への追加（加算のみ、フェーズ1の利用箇所は無変更）: 掘削列からバックトラックを決定的に導出する `mazeDiggingBacktracks`。次の掘削の開始マスが直前の掘削先と異なれば巻き戻しが起きており、再開マスと戻り終えたスタックは次の掘削のスタック経路から読み取る。最後の掘削の後にスタックが空になるまで戻る過程は完成側の状態として含めない。
- `front/src/features/learning/maze-digging/execution/` に content / types / Canvas / Preview / README.md を新設（構成は棒倒し法フェーズ2と本単元フェーズ1に合わせた）。
  - `execution.types.ts`: Canvas 型は共通グリッド基盤の `MazeGridCanvasState` をそのまま使う。検証は単元側の `validateMazeDiggingCanvas` に「highlight は掘ったばかりのマス（壁でないマス）であること」「target は使わないこと」を足す。
  - `execution.content.ts`: 盤面とステップは `mazeDiggingMaze.ts` の組み立て（参照コードの実行＋バックトラック導出）から作り、手書きの盤面・ステップ列はない。キャプションも基準データの形式（掘削＝現在マス＋方向、バックトラック＝行き止まりの理由＋再開マス）でデータから組み立てる。
  - `MazeDiggingExecutionCanvas.tsx`: 描画は共通グリッド基盤へ委譲する。
  - `MazeDiggingExecutionPreview.tsx`: 単品入口。単元フロー（接続 Issue）向けに任意の接続ポート（embedded / onLearningEvent / active / onComplete / nextLabel）を持ち、未指定なら単品ページとして動く。
- ステップ列（21ステップ = 準備2 + 掘削15 + バックトラック3 + 完成1、全スナップショット、キャプションは各1文）:
  - `all-walls` 全部が壁の 9×9（壁81）。
  - `dig-start` スタートの部屋 (1, 1) を掘る（壁80、processing = (1, 1)）。
  - `dig-1` 〜 `dig-15` 掘削。ステップIDは基準データ指定の `dig-<n>`。各ステップは掘った後の状態で、processing に掘った部屋、highlights に今回掘れた2マス（間の壁＋部屋、通路マスのため破線の枠）、path にスタック経路を置き、壁は前ステップからちょうど2マスだけ減る。キャプションは「(5, 3) から右へ掘ります。」の形式。
  - `backtrack-1`（掘削6回の後、戻る部屋数2、再開 (7, 3)）・`backtrack-2`（掘削13回の後、1、再開 (1, 5)）・`backtrack-3`（掘削14回の後、4、再開 (5, 7)）。バックトラックは発生した3回を各1ステップに圧縮し（基準データ §6-5 の推奨デフォルト）、盤面は変えず、processing が再開マスへ移り、スタック経路が短くなることで「戻る」を表す。キャプションは「行き止まりになったので、掘れる部屋がある (7, 3) まで戻ります。」の形式。
  - `complete` 完成（壁50）。基準データの指定（どの部屋からどの部屋へもたどり着けること・輪がないことを示す）に従い、スタート (1, 1) とゴール (7, 7) の旗と、導出した一本道（17マス）を重ねる。
- 単品プレビュー: `/learning-preview/maze-digging-execution`（フェーズ1と同じ登録方法）。

## 留保（判断が必要な点）

- バックトラックのステップIDの `<n>` は、基準データが意味を明示していないため発生順の序数（1・2・3）とした。フェーズ3・フェーズ6がフェーズ2のステップを参照するときはこの ID で引く。
- 掘削ステップでもスタック経路（path）を常時表示した。基準データ §3 フェーズ2は経路表示の範囲を明示していないが、教材指針 2-3（本質的データ構造と状態の一体可視化）に従い、本単元の本質的データ構造であるスタックを盤面上の経路として連動表示する判断をした。フェーズ1場面6の表現（スタック経路の重ね表示）とも一致する。
- 完成ステップでは旗と一本道を表示した（棒倒し法フェーズ2の完成ステップは盤面のみ）。基準データが完成ステップで「たどり着けることを示す」としているための差分で、フェーズ1の冒頭場面とも表現をそろえた。
- バックトラックのキャプションは、基準データの例示文を全ステップ1文の教材形式に合わせて1文に圧縮し、再開マスの座標を入れた。戻る部屋の数そのものは文面に出さず、経路が短くなる見た目で表す。
- 基準データ正本（docs/concept/maze-digging-unit-baseline.md）は PR #267 のブランチにあり、本 PR のツリーにはまだ無い。マージ順によっては README からのリンクが一時的に解決しない（フェーズ1と同じ留保）。
