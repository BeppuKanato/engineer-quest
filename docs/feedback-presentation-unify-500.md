## 実装内容（仕様）

### 祝福（フェーズ3・5の第1段）

- 3拍で見せる：①終わった（描き込みチェック 96px＋見出し 24/900。バブルソートでは「動きの確認、クリア！」「コードの確認、クリア！」の形）②成績の点灯（数え上げ：500ms 開始、1点あたり115ms）③マスコットの反応。
- 3ティア：PERFECT（全問初回正解）／CORRECTED（見直して全部正解）／REMAINING（残りあり）。事実文は点灯完了時にだけ出す：PERFECT・CORRECTED は「全{総数}問に正解しました（初回で{初回}問正解）。」、REMAINING は「{総数}問中、{到達}問を正解にしました（初回で{初回}問正解）。」。
- ドット：塗り青＝初回で正解、青の輪郭＝見直して正解、灰色の輪郭 #c3cad4＝残り。PERFECT 以外では凡例（「● 初回で正解」「○ 見直して正解」「○ まだ解けていない」14px、黒）を出す。
- マスコットの反応：PERFECT＝celebrate＋大きく跳ぶ、CORRECTED＝cheer＋小さく跳ぶ、REMAINING＝cheer（跳ばない）。紙吹雪は全ティアで出す。責める表現は置かない。

### 統合の流れ（フェーズ3・5）

- 最後の問題の直後に結果画面（第1段）を同期的に出し、完了保存の解決を待って、同じ画面のまま第2段（フィードバック）へ切り替える。ページ遷移はしない。
- 完了保存が 409 を返した場合は、自動で次へ進めない（学習者を置き去りにしない）。redesign-overview §6-2。
- 第1段の滞在は約3.4秒。前進ボタン「今回の学びを振り返る」は約2.6秒で出す。第2段へ入ったら紙吹雪は必ず止める。

### フィードバック（第2段）

- 構成：導入の標題＋副題 → 要約行（13px のドット＋事実文 14/700）→ マスコットの届け（point、吹き出し「フィードバック、持ってきたよ。」）→ 称賛カード → セクションカード群 → 次の一歩。
- 発見のスポットライト：称賛の見出し（praiseHeadline）があるとき、第2段の冒頭は見出しだけを見せる（枠付けの文「今回いちばんの収穫」、金の放射光、きらめき5つ、見出しの拡大、マスコット celebrate）。1.5秒後に称賛カード内の見出し位置へ吸着させる（同一要素のレイアウト連動）。タップで早送りできる。
- 称賛カードが唯一の強調面（白＋2px の主色枠）。ラベル「あなたの学び」、見出し 22/900、本文 18。一度だけ光のパルスを出す。場面シーンはこのカードの中に置く。
- セクションカード（強み／改善／次の一歩）：アイコンで区別する（強み＝緑のチェック、改善＝探索のアイコン（警告色は使わない）、次の一歩＝主色の旗）。要点の見出し 16/700 が要約層になる。
- 要約層：見出しがあるセクションは本文を「くわしく見る」／「閉じる」の後ろに畳むのが既定。見出しがなければ本文を直接出す。詳細を開いた事実はログに残す。
- 幅の階層：全体 1060 まで、セクションカードと次の一歩は 760 までに絞る。下部固定の行動バーは内側 1060、ボタンは 760 まで。
- 出現の刻み：行ごとに 0.35秒開始、+0.27秒ずつずらす。左のレールも同じ刻みで満ち、最後の節点は旗アイコンにする。
- マスコットの拍：届け＝point、称賛／スポットライト＝celebrate、改善＝thinking、次の一歩＝point。1場面に1体（スポットライトとカードで同じマスコットを二重に出さない）。
- 次のフェーズが最有力候補のときは下部固定バーを常時表示し、本文側の候補ボタンは隠して、行動ボタンを画面内に1つだけにする。

### ログ連動シーン

- 対象の選択規則（コード側）：評価記録のうち「初回は不正解で最終的に正解」の問題がちょうど1問のときだけ出す。複数あるときは出さない。
- 内容は記録だけからコードで組み立てる（LLM 本文との照合はしない）：ラベル「あの場面（{n}問目）」、図（その問題の場面）、プロンプト、最初（チップ＋答えのラベル＋✗）、見直して（緑チップ＋ラベル＋✓）。
- 両答えがノード回答なら、図の上でバッジが不正解のセルから正解のセルへ移動し緑の ✓ に変わる再生を1回だけ行う（約2秒）。動きを減らす設定では両バッジを静止表示する。
- フェーズ5では場面の代わりにコードのブロック（対象行ハイライト＋空欄）を使う。フェーズ6は問題自身が持つ場面図を使う（Parsons 問題には付けない）。

### フェーズ6と単元フィードバック

- フェーズ6：結果はプレビュー内の診断画面（「応用問題の結果」、初回正解 n/6、タグ別の行、完了文、「自分で実装へ進む」）が担う。フィードバックは見出し（祝福段）なしで続き、プレイヤー側で紙吹雪を出す。
- 単元フィードバック：見出し「単元のフィードバック」、要約行は単元リザルトの要約（ドット＋事実文）。進む操作は「結果に戻る」。次の行動の選択肢はフィードバックの後に置く（結果画面側には置かない。Issue #499）。

## 凍結範囲との関係

- 生成側の契約変更（見出しフィールドの必須化、シーン参照＝questionId＋試行番号の結果への付与）は AGENTS.md §10.2 の凍結への例外であり、本 Issue に含めない。シーン参照がない環境では、シーンはフロントが保持する評価記録から組み立てられる範囲に限る。

## 確認方法

1. バブルソートのフェーズ3を通し、最後の問題→第1段（3ティアのいずれか）→保存後に第2段へ切り替わることを確認する。
2. 直した問題が1問のケースでシーンが出ること、2問以上のケースで出ないことを確認する。
3. 保存が 409 のケース（再送等）で自動で進まないことを確認する。
4. フェーズ6の診断→フィードバック、単元フィードバック→「結果に戻る」を確認する。
5. スクリーンショットは約1093×614と約2560×1440の2サイズを PR に付ける。
