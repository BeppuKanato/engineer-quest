# 棒倒し法 アプリ統合（コース・カード・実績のシードと単元登録）（Issue #215）

目的: 棒倒し法単元（フェーズ1〜7は #206〜#212、視覚デバッグは #213、単元接続は #214）をアプリ全体へ統合し、コース一覧・ホーム・コレクション・実績で BFS と同等に扱えるようにする。マスタデータの正本は基準データ（`docs/concept/wall-extension-unit-baseline.md`）§5。最終確認日: 2026-11-07。

## 実装内容

- コースシード（`back/prisma/seedData/courseSeed.ts`）: `course-algorithm-wall-extension-v1`「棒倒し法」を追加。難易度 EASY、当初から解放・公開、version 1。説明文は BFS の書式（学ぶ内容＋前提知識）に合わせた。
- 知識カード（`back/prisma/seedData/knowledgeCardSeed.ts`）: 基準 §5 の3枚を追加。
  - 手続き型生成（RARE、フェーズ2 `wall-extension-execution` で配布）
  - 乱数とシード（COMMON、フェーズ5 `wall-extension-code-check` で配布）
  - 完全迷路（EPIC、フェーズ7 `wall-extension-implementation` で配布）
  - 配布スケジュールは BFS と同じテーブル表（15テーブル、平均約6割出現）を単元ごとに生成する形へ一般化した。BFS 分のスケジュール ID・内容は変更していない（後述の検証でバイト一致を確認）。
- 実績（`back/prisma/seedData/achievementSeed.ts`）: BFS と同じ構成の6件を追加。単元クリア（`ach-unit-wall-extension-complete`）、フェーズ7クリア、確認問題の初回全問正解、応用問題の初回満点、ノーヒントクリア、カードコンプリート（`ach-wall-extension-card-complete`）。
- 検証の汎用化（`back/src/scripts/verifyCollectionMasterData.ts`）: 「BFS の3枚だけが現行プール」「コース数7」などの BFS 前提を、カードを持つ単元ごとの検証へ一般化した（コース数8、カードは単元ごとにスロットと対応、スケジュール表は単元ごとに15テーブル、フェーズキーは実績のコース範囲で照合）。
- サムネイル（`front/src/app/courses/component/courseThumbnail.tsx`）: `course-algorithm-wall-extension-v1` の代表図を追加。教材と同じ主教材 9×9 の完成迷路（壁50マス）を縮小描画し、フェーズ1で示すスタート (1,7) → ゴール (7,7) の経路を重ねた。これにより単元一覧・ホームのカードと単元概要画面の背景図に、BFS と同経路で図が出る。
- 学習画面側の登録（unitRegistry）は #214 で完了済みであり、本 PR での追加作業はない。

## 判断と留保

- コースのカテゴリは基準データに指定がないため、`GAME` と `ALGORITHM` とした（迷路生成はゲーム寄りの題材であり、既存コースの2カテゴリ併記（BFS の GRAPH＋SEARCH）に倣った暫定判断）。
- 実績のうち全体カウント系（`ach-unit-count` の [1, 3, 7] 等）は既存実績の条件であり、本 PR では変更していない。新コース追加に合わせた最大値の見直しは別途判断とする。なお `ach-knowledge` の最終段階はカード総数から自動で決まるため、6枚に追随する。
- カードの label・本文（description / connection / useCase）と実績の説明文は、基準 §5 の「内容」欄を正本とし、BFS カードの文体に合わせて書き起こした。文言の最終確認はレビューに委ねる。
- サムネイルの迷路図はこの環境でブラウザ実機の目視確認をしていない（壁配置は教材データの生成規則から算出し、壁50マス・通路31マスが検証済みの数値と一致することを確認済み）。デプロイ後の実機確認をお願いしたい。

## DB 適用の要否

- **マージ後に開発 DB へのシード再実行が必要**。CD はコードのみをデプロイし、シードは自動適用されない。本 PR のコードだけでは、コース一覧に棒倒し法は現れず、カード・実績も付与されない。シードは既存マスタの upsert と新規分の追加であり、BFS 分の既存データは変更しない（`verify:seed-preservation` の保持ポリシーの対象範囲内）。

## 検証

- `verify:seed-preservation`: PASS（変更前後とも）。
- `verify:feedback-v1`: PASS（変更前後とも）。
- `verify:collections`（コレクションマスタ検証）: 本 VM では Prisma Client が生成できない（エンジン取得不可）ため、そのままでは変更前のベースブランチでも同一の TS2305 で失敗する。代替として、schema.prisma から列挙値を読み込むスタブで同じ検証スクリプトを実行し、PASS を確認した（8コース、36実績、6カード、スケジュール54行）。あわせて BFS 分のカード・スケジュール・実績エントリが変更前とバイト一致であることをダンプ比較で確認した。正式な実行は CI（`verify:static`）が正本。
- `verify:create-quests`: 変更前のベースブランチでも同一の失敗（参照解の実行環境起因）であり、本変更の影響ではないことを確認した。
- back typecheck: エラーカテゴリ別の件数がベースブランチと完全一致（新規エラーなし。既存分は Prisma Client 未生成に起因）。
- front: 全 verify（37件）通過、lint エラー0件（警告2件は既存分）、typecheck / build 通過。

## 確認方法

1. 開発 DB へシードを再実行する（ユーザーの手元作業）。
2. 単元一覧とホームを開き、「棒倒し法」のカードに迷路のサムネイルが表示されることを確認する。
3. 棒倒し法の単元概要画面を開き、背景図に迷路が出ること、実績プレビューに棒倒し法の実績が並ぶことを確認する。
4. 実験割当のあるアカウントで単元を通し、フェーズ2・5・7の完了でカード（手続き型生成／乱数とシード／完全迷路のいずれか、テーブルにより変動）が付与され、コレクション画面に未所持分がシルエット＋「？？？」で並ぶことを確認する。
5. 単元完了時に「棒倒し法を修得した」などの実績が解放されることを確認する。
