# 単元の概念到達マップ（Issue #478）

- 目的・適用範囲: 新フロー7単元の単元画面に、学習者向けの概念到達状況を表示する。
- 最終確認日: 2026-11-19
- 正本: [Issue #478](https://github.com/BeppuKanato/engineer-quest/issues/478)、各単元の `concepts.json`、[開発ルール](development-rules.md)
- 対象実装コミット: `d7f57a54`（本報告の追加前）

## 実装

認証付きの `GET /api/learning/units/:courseId/concept-progress` を router → controller → service で追加した。公開単元について、本人のフェーズ3・5・6の LearningEvent と PhaseLearningProgress だけを参照する。DBへの書き込み、DailyReview の参照、フィードバック生成は行わない。

概念定義と証拠の検証関数は既存のものを参照するが、凍結対象の `aggregateConcepts` は呼ばず、学習者向けの集計を独立させた。問題・正誤判定・概念定義・実験条件・フィードバックのコードは変更していない。フェーズ7の実装概念を除いた7単元39概念が対象になる。

各問題は、保持されている学習セッションのいずれかで一度でも正解すると到達とする。再挑戦の正解も含み、後の再学習で不正解になっても到達を取り消さない。概念の全問題が到達なら「到達」、回答記録があるが全問到達していなければ「取り組み中」、回答がなければ「未確認」とする。未開始でも全概念を表示する。

確定した assessment_snapshot と完了summaryの assessmentEvidence、および answer_attempt を利用する。同一問題・セッションでは確定証拠を優先し、重複試行は1回として数える。同じ優先度の同一試行が矛盾する場合は不正解を採る。不正な証拠、未知の問題、別フェーズは数えない。

初回正解率は到達とは独立した補助情報である。問題ごとにサーバーで最も早く観測された初回試行を採用する。分母は実際に初回の記録がある問題数とし、正解数／分母も表示する。未回答問題や初回記録が欠けた問題を不正解と推定せず、初回記録が全くなければ「—（初回の記録なし）」とする。到達判定には使用しない。

UnitOverview の道順と単元実績の間に、状態の日本語と色、到達問題数、初回正解率を表示した。取得に失敗しても学習を継続でき、再読み込みできる。単元・利用者の切替時には古い取得結果を表示しない。

## 概念名のレビュー候補

概念名は `concepts.json` の原文を使用し、独自に改名していない。単元を終えた学習者が学んだ考え方と対応付けられるか、特に次の表現をレビューしてほしい。

| 現在の概念名 | 教材との対応・確認したい点 |
| --- | --- |
| 上方への伸長制約（棒倒し法） | 教材では「一番上の段以外の柱が、上へ壁を伸ばせない」理由を問う。概念名の硬い表現と対応付けられるか |
| 未掘削の判定（穴掘り法） | 教材では「まだ掘っていない部屋かどうかを調べる」と説明する。「未掘削」と同じ考え方だと分かるか |

開始前に分かるかではなく、学習後に教材の語彙と対応付けられるかを確認する。表現の変更はレビュー後の判断とする。

## 適用と検証の限界

Prisma schema、migration、seed の変更はなく、DBへの適用は不要。dev・本番DBへの操作は行っていない。ブラウザー証跡はAPI固定データを用いた表示検証であり、Firebase認証・実DB・Cloud Runを通した結合検証ではない。初回の時系列は保持されたサーバー受信記録に基づき、過去に欠落した試行は復元しない。現時点では学習者本人による概念名の理解確認は未実施。
