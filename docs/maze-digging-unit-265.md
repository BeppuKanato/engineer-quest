# 穴掘り法 フェーズ接続・単元コンテナ接続（Issue #265）

目的: 単品ページで確認済みの穴掘り法フェーズ1〜7を、1つの単元として通して学べるよう接続し、アプリの学習画面（進捗保存・学習ログ・フィードバック #202）へ登録する。遷移・結果画面・フィードバックの仕組みは BFS 単元（Issue #77 / #202）の接続モデルを正本として踏襲する。最終確認日: 2026-11-07。

## 実装内容

- 単元コンテナを新設（`front/src/features/learning/maze-digging/unit/`）：
  - `unit.content.ts`: 単元定義。タイトル「穴掘り法」、導入文、フェーズ並び（ID は単品プレビューの contentId と一致）、遷移類型（BFS と同じ bridge / result / result-in-phase / final の統一モデル）、ブリッジ文、フェーズ3・5のリザルト見出し、カードのレアリティ（基準データ §5：フェーズ2=RARE、フェーズ5=COMMON、フェーズ7=EPIC）。
  - `MazeDiggingUnitPreview.tsx`: 単元の状態機械と単元ナビゲーション。状態機械・遷移・保存失敗時の再試行・滞在記録は `BfsUnitPreview` と同一の実装で、フェーズの実体と単元定義だけが異なる。一度開いたフェーズはマウントしたまま隠し、戻っても再生位置・回答・コードが残る。
  - `UnitResultScreens.tsx`: フェーズ3・5のリザルト画面と単元最終結果。お祝い（`UnitResultCelebration`）は BFS 側の共通部品をそのまま使い、到達図は穴掘り法側の `MazeDiggingResultFigure`（完成した主教材 9×9 の迷路。正本の choices から参照手続きで導出した壁＋フェーズ1の一本道と旗）に差し替えた。盤面の検証は単元側の検証器（`validateMazeDiggingCanvas`、基準データ §4）で行う。
  - ブリッジ画面は `bfs/unit/PhaseBridgeScreen` をそのまま使う。単元固有の文言は props のフェーズ定義から読む部品であり、唯一の BFS 依存は総フェーズ数（両単元とも7で一致）の参照だけである。
- フェーズ1・2・4の単品プレビューは、穴掘り法では各フェーズの実装時点で接続ポート（任意 props: embedded / onLearningEvent / active / onComplete、2・4 は nextLabel）が用意済みだったため、本 Issue では追加変更なしでそのまま接続した（棒倒し法では接続 Issue #214 で追加した点が異なる）。フェーズ3・5・6・7のポートも同様に既存のものを使う。
- アプリ登録：`app/unitRegistry.ts` に courseId `course-algorithm-maze-digging-v1` を kind `"maze-digging"` で登録（本ブランチの系統では BFS・棒倒し法に次ぐ3単元目）。`app/LearningScreen.tsx` は kind でコンテナを出し分け、進捗保存（PhaseLearningProgress / UnitLearningProgress）・コード下書き・学習ログ・フィードバック接続の props は単元共通の形で組み立てて各コンテナへ渡す（コンテナ側の受け口の形は単元間で同一）。
- フィードバック接続（#202）：BFS と同じ配線。確認フェーズ（3・5・6）の完了保存後に先行生成を依頼し、フェーズ3・5のリザルト画面と単元最終結果に差し込み口を持つ。バック側は単元非依存の実装済みで変更はない。実験割当のない利用者・未完了イベントでは部品側の契約（404 / 409）により何も表示されない。
- 単品プレビューに `maze-digging-unit` を追加し、ログイン・DB なしで通し再生を確認できるようにした。

## 判断と留保

- リザルト画面（UnitResultScreens）は BFS 版が BFS の到達図とフェーズ7文言に結び付いているため、無理に一般化せず穴掘り法側に同形の複製を置いた。差分は到達図・フェーズ7文言・単元定義の参照だけに閉じている。単元がさらに増える場合は、この複製を共通化する再設計が要る。
- ブリッジ画面の再利用は構造的なもの（フェーズ定義の形が同一）であり、総フェーズ数の参照が BFS 側定義に残る。両単元とも7フェーズの間は問題ないが、フェーズ数が異なる単元を接続するときはブリッジ画面の共通化が必要になる。
- `unitRegistry.ts` と `LearningScreen.tsx` は、並行する回収 PR #254（バブルソートの接続・統合）でも変更されている。本 PR は自ブランチの現行形（BFS＋棒倒し法）を正として穴掘り法を追加した。マージ時に両者が競合した場合は、レジストリへ4単元（BFS・棒倒し法・バブルソート・穴掘り法）が並び、LearningScreen が kind で4コンテナを出し分ける形に統合すること。
- 到達図の盤面はブラウザ実機での目視確認をこの環境では行っていない（verify の静的描画で壁50マス・旗2つの出力を確認済み）。デプロイ後の実機確認をお願いしたい。
- コースシード・知識カード・実績のシードは Issue #266 の範囲で、本 PR には含まない。そのため本 PR のマージだけでは、コース一覧に穴掘り法は現れない（学習画面の経路と単品プレビューでは動作する）。

## 確認方法

1. `front/` で `npm run dev` を起動し、`http://localhost:3000/learning-preview/maze-digging-unit` を開く（ログイン・DB不要）。
2. フェーズ1の最終場面のボタンからフェーズ2へ進み、以降も各フェーズの完了でブリッジ画面（次のステージ名と目標）を挟んで進むことを確認する。フェーズ3・5の後はリザルト画面（スコアのドットと完成した迷路の図）が出ること、フェーズ6は内の結果から進むこと、フェーズ7の全テスト通過で最終リザルト（到達状況の一覧と要約タイル）が出ることを確認する。
3. 上部のナビゲーションで到達済みのフェーズへ自由に戻れること、戻っても回答や再生位置が残っていることを確認する。
4. アプリ側は Issue #266 のコースシード適用後、実験割当のあるアカウントでコース `course-algorithm-maze-digging-v1` の学習画面を開き、進捗が保存されることと、フェーズ3・5の結果画面・単元最終結果にフィードバックが出ること（割当のないアカウントでは出ないこと）を確認する。
