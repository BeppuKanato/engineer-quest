# Issue #126 DFS「応用問題」実装記録

- 目的は、基本例と異なる場面で深さ優先探索の動きを追い、探索処理の順序をコードで組み立てること。
- 対象は DFS の単品プレビュー、応用5問、基本例での復習、初回回答の診断。
- 最終確認日 2026-11-10
- 正本は [Issue #126](https://github.com/BeppuKanato/engineer-quest/issues/126)、[DFS 基準データ §6・§7](concept/dfs-unit-baseline.md)、[教材指針](concept/learning-materials-guideline.md)、[プレイヤー UI](concept/learning-player-ui.md)。

## 実装

出発点 F から最後に訪れる場所、木の J・K を処理し終えた直後のスタック、孤立した Z の訪問順での扱い、出発点 A が隣として現れたときの扱い、コードの並び替えの5問。誤答した問題はその場で再回答でき、次にも進める。誤答時と診断画面の復習には「動きとコードの対応」の基本例を使う。診断は初回の正解数と論点ごとの結果を表示する。単品の終了時は「もう一度解く」で最初の問題に戻れる。

基準データ §6 の全行並び替え案に対し、2026-11-09 の現行教材指針とユーザー指示に合わせて固定行つきの盤面を採用した。`dfs-order-stack` の12行を表示し、関数定義・`while stack:`・`return order` を正解位置に固定する。初期化3行はどの順でも正解とし、ループ本体では取り出し、訪問順の記録、隣の走査と判定、発見済みへの記録とスタックへの追加の6行を並べ替える。可動行は固定行で区切られた範囲ごとに動かせる。誤答時の「移動不要」の印は、提出した時点の可動行の並びから決める。

## 確認方法

front の開発サーバーを起動し、[単品プレビュー](http://localhost:3000/learning-preview/dfs-consolidation) を開く。

1. 問1で E、問2で「I のみ」、問3で「結果に入らない」、問4で「すでに発見済みとして記録されているので、もう一度は訪れない」が正解になる。
2. 問5は初期の並びで回答し、固定行の鍵と、可動行につく「移動不要」の印を確認する。復習で基本例の図とコードを開ける。
3. 問5のループ本体を `stack.pop` → `order.append` → `for` → `if` → `visited.add` → `stack.append` の順にして再回答する。問1〜4が初回正解なら、診断の初回正解は4/5問となり、コード全体の流れに復習ボタンが出る。

`npm run verify:dfs-consolidation` は、4つの場面の答えと初期化3行の全6順を実際の Python 実行で照合する。固定位置、2つの可動範囲、復習フレーム、初回スコアの集計も検証する。DB の適用は不要。
