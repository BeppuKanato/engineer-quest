# 棒倒し法 フェーズ7 視覚デバッグ（Issue #213）

目的: 棒倒し法フェーズ7に、BFS フェーズ7（Issue #76）と同じ段階適用の視覚デバッグを実装する。学習者のコードを表示用D1（9×9、主教材の choices）で実行し、生成過程をフェーズ2と同じ盤面再生でステップ表示する。想定解法に沿ったコードはトレース再現し、対応できない実行は停止位置＋最終状態のみに留める（教材指針 §7-3、基準データ §3 フェーズ7）。最終確認日: 2026-11-07。

## 実装内容

- `front/src/features/learning/wall-extension/trace/` を BFS の `bfs/trace/` と同じ構成で新設（`acquireTrace` / `convertTrace` / `WallExtensionTraceDialog` / `trace.content` / `trace.types` / README）。
  - 取得: 前の採点用入力を持ち込まず、毎回新しい Worker へ D1 の関数名と引数だけを送る。イベント上限は BFS と同じ500件。判定用ケース・期待値は送らない。
  - 変換: イベント列の `grid` スナップショットから、壁集合が変わるたびにフェーズ2と同じ検証器（`validateWallExtensionExecutionCanvas`）を通る完全スナップショットを組み立てる。外周と柱は1マスずつ書かれるため、同じ種類の追加が続く間はフェーズ2のコマ単位（「外周」「柱」）へまとめ、伸長は柱ごとに1コマ（処理中の柱を青、壁になったマスを highlight、キャプションは方向つき）にする。正しい迷路を再実行して差し替える処理はなく、誤った盤面もそのまま表示する。
  - 段階適用: 盤面として描けない状態が末尾に残る場合は描けたところまでを部分再生として明示する。`grid` のスナップショットが取れない構造（盤面を補助関数の中だけで作る等）・変換できた状態がない場合・形の候補が曖昧な場合は、戻り値の盤面による最終状態だけを表示する。エラーは停止行と種別だけを示し、生の例外本文は返さない。
  - 表示: モーダルは BFS と同じ 84vw × 84dvh、既存 LearningPlayer の再生制御、フェーズ2の `WallExtensionExecutionCanvas` をそのまま使う。下部に観測行と `size`・`choices`・壁の数を表示する。
- 画面接続: `WallExtensionImplementationPreview` に「盤面で動きを見る」を追加（エディタのパネルと全通過後の完了表示の両方。BFS フェーズ7と同じ配置）。取得中は編集・採点・試しに実行・ヒントを無効化し、トレースは採点回数・ヒント回数・完了判定を変更しない。Issue #212 の実施記録で留保した `active` の未消費は、この接続で解消した。
- 共通基盤への最小拡張: `front/public/python-trace-harness.mjs` の locals 検出に `grid` を追加した。`grid` という名前を優先し、なければ「奇数の一辺を持つ正方形の整数グリッド（3〜25）」の形で一意に検出する（候補が複数なら曖昧として推測しない）。あわせて `size`（整数）と `choices`（整数列）を名前ベースで通過させ、戻り値がグリッドの場合も結果として受け付ける。型は `front/src/lib/pythonTrace.types.ts` に追加。BFS の queue / distances 検出と結果の扱いは変えていない（盤面の戻り値を距離として扱わない分岐を `convertBfsTrace` に明示したのみ）。
- フェーズ7検証のピン更新: `verifyWallExtensionImplementation.cjs` の「視覚デバッグは #213 の対象で含めない」という #212 時点のピンを、接続済みであることの確認へ差し替えた。

## 検証

- `npm run verify:wall-extension-trace`（新規）: 同じハーネスを CPython で実行し、参照コードの再生の壁列がフェーズ2の正準列と一致すること（伸長9コマすべての処理中の柱と highlight の隣接を含む）、スナップショットのコピー性、盤面変数の改名（`board`）での形検出、方向の対応を誤ったコードの忠実な再生、途中エラー（停止行＝参照コードの `write-wall` 行）と例外本文の秘匿、補助関数内で作る盤面の最終状態表示、構文エラー、形の候補が複数の場合の曖昧判定、末尾だけ描けない盤面の部分再生、打ち切り、実描画（81マス・壁セルの数）、D1限定・新規Worker・キャンセルの取得経路、画面接続のピンを確認。
- 回帰: front の全 verify（32件、`verify:bfs-trace`・`verify:wall-extension-implementation` を含む）通過。`lint`（警告1件は既存 BfsUnitPreview の無関係なもの）/ `typecheck` / `build` 通過。
- DB・シードの変更はない。

## 留保（判断が必要な点）

- 伸長コマの「処理中の柱」は、壁になったマスに隣接する柱から推定している。隣接する柱が複数ある場合はまだ伸ばしていない柱を優先するが、学習者のコードが正準と違う順序で伸ばした場合に、実際に書いた柱と異なる柱が青くなる可能性がある。盤面（壁の集合）そのものは常に実値どおりであり、推定が外れるのは柱の強調だけに限る。厳密にやるには柱の書き込み行と対応づける仕組みが要るが、BFS の段階適用（まず想定解法に沿ったコードの再現）を超えるため本 Issue では行わない。
- 外周・柱の追加を1コマにまとめる際、途中の1マス単位の状態は再生に現れない。フェーズ2の教材コマと粒度を揃えるための意図的な間引きであり、壁の最終形や伸長の順序は変わらない。
- ブラウザ上の実 Pyodide での目視確認はこの環境では行っていない（CPython ハーネスでの検証と build まで）。マージ後に単品プレビューで「盤面で動きを見る」を押す確認をお願いしたい。

## 確認方法

1. `front/` で `npm run dev` を起動し、`http://localhost:3000/learning-preview/wall-extension-implementation` を開く（ログイン・DB不要）。
2. 初期コード（テンプレート）のままでは生成が進まないため、参照コード相当の完成コードを貼り付けて「盤面で動きを見る」を押す。モーダルで外周→柱→9回の伸長がフェーズ2と同じ盤面で再生され、変数欄に観測行・size・choices・壁の数が並ぶことを確認する。
3. 方向の対応表を1か所誤らせたコードで再度開き、誤った盤面のまま再生される（正しい迷路に差し替わらない）ことを確認する。
4. 全テスト通過後の完了表示からも「盤面で動きを見る」が開けることを確認する。
