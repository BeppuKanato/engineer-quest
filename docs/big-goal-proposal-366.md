## 実装内容

### 候補生成（`back/src/service/bigGoal.candidates.ts`、純粋関数）

- タイミングA（単元開始）：開始した単元の到達型（標準形＋条件を満たせば挑戦変種）と実績型（その単元の未獲得実績のうち定義順で最初のもの）のみ。確定中の大目標の対象に含まれる単元では新規設定をしない。
- タイミングB（大目標達成時）：到達型は未完了の全単元（進行中→未開始の順、各群は単元一覧の並び順）、実績型は単元ごとに未獲得の最初の1件、応用型は未完了の作る課題がある単元に1件。
- 統合：到達型以外を先に置いて型の多様性を優先し、重複を除いて最大8件。未完了単元がある限り標準形の到達型は常に出せるため、候補集合は空にしない。
- 初回に発行するのは到達型・実績型・応用型のみ。統合型・共有型・定着型は候補に出さない。
- 学習者状態の読み込みは `bigGoal.state.ts`。単元の並びは公開コースの作成順（単元マップの表示順）、実績は定義順（sortOrder、createdAt）。直近に完了した単元の初回正答率とフェーズ7のヒント有無から、挑戦変種を出す「余裕」を判定する。

### 適合度採点（`back/src/service/bigGoal.scoring.ts`）

- モデルは `gpt-6-1-luna` 固定、PROMPT_VERSION は `big-goal-scoring-v1-2026-11-10`。入力は候補集合・学習状態の要約・申告情報（現時点は null、下記の判断参照）。PERSONALIZED のときだけ HEXAD 6スコアとコードブック（HEXAD の型の説明＋目標型カタログの定義）を追加し、解釈を根拠に含めさせる。
- 出力は候補ごとのスコア（0〜100）と根拠、本命の指定。根拠は表示する候補すべてに付く。
- 機械検証：全候補がちょうど1回ずつ採点されていること、スコアの範囲、本命が候補集合内にあること。不正な応答はエラーにする。本命はコード側の argmax（同点は候補順で先）を正とし、LLM の指定と食い違う場合は不一致を検証ログに残す。
- 呼び出しログは `BigGoalProposalCall` に FeedbackV1Call と同じ粒度（stage、promptVersion、settings、prompt、result、validation、durationMs、error）で残す。

### 提案API（`bigGoalProposal.service.ts`、`/api/big-goals`）

- `POST /api/big-goals/proposals`：機会（タイミングAは単元、タイミングBは達成した大目標）ごとの eventKey で冪等。生成はフィードバック v1 と同じ GENERATING → GENERATED／FAILED の非同期パターン。
- `GET /api/big-goals/proposals/:id`：生成状態と、候補（スコア・根拠つき）と本命を返す。表示側で本命＋前後2件程度に絞る前提で、API は全候補（最大8件）を返す。
- `POST /api/big-goals/proposals/:id/confirm`：学習者の合意操作。確定時点の状態で候補を再検証し、合わなくなった候補は 409 で弾く。おすすめ以外の候補も選べる。有効な目標が既にある場合は合意のうえで差し替え、旧目標は見直し済み（REVISED）として閉じ、新目標に supersedesId を記録する。確定直後に達成判定を1回回す。
- `GET /api/big-goals/current`／`GET /api/big-goals/history`：G3 のホーム表示・履歴表示のための読み取り。

## 仕様との対応で判断した点

- 「余裕あり」の線：ルール仕様 §3.1／§7 の初回正答率 0.8 と、実装仕様の二値表現（初回成績が高くヒント未使用）は未統一のため、`ROOMY_FIRST_ATTEMPT_RATE = 0.8` として一箇所に寄せ、二値条件（ヒント未使用を併せて要求）と組み合わせて実装した。後で揃える場合はこの定数と条件を見直す。
- 実績型のタイミングBは規範ルール（単元ごとに未獲得の最初の1件）で実装した。ルール仕様の具体例2にある「実績1件」は、他単元に実績定義がないデータ条件ではそのとおり再現されるが、複数単元に未獲得実績がある場合は単元ごとに1件ずつ候補に出る。
- 申告情報の入力：初回利用時の申告（「どういうことにアルゴリズムを使ってみたいか」）の保存先が現行スキーマに存在しないため、`declaredInfo` は null で接続した。申告の保存が実装されたら、読み込みを足して接続する。
- 実験割り当てがない学習者：大目標は製品機能であり実験参加を前提にしないため、フィードバック v1 のような 409 にはせず、STANDARD 相当（HEXAD を入力に含めない）で採点する。PERSONALIZED でも HEXAD 回答がない場合は同様に HEXAD なしで採点する。
