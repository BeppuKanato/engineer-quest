# フェーズ6「たどり着けない場所の扱い」の復習先の修正（Issue #182）

目的: 復習先が、答えの根拠を確認できないステップを指していた不整合を直す。調査と提案は Issue #182 のコメントに記録し、推奨案（案C）の承認を得て実装した。最終確認日: 2026-11-06。

## 不整合の内容

- 対象はフェーズ6の選択問題 `unreachable-z`（つながっていない場所Zは結果にどうなるか）。
- 復習先はフェーズ4の最後の2ステップ（キューが空になったので繰り返しを終える／各場所までの最短距離を返す）だった。基本例は全場所が到達可能で、この2ステップからは「Zが結果に入らない理由」が確認できない。むしろ全場所分の距離が揃った結果が、逆の印象を与えかねなかった。

## 実装（案C）

- 復習先を「発見の関門」のステップ列に差し替えた：`for-a-b`（隣を取り出して確認）→ `if-a-b`（まだ記録されていないので新しく距離を求める）→ `assign-a-b`（距離の書き込み）→ `execution-discover-b`（キューへの追加）。「処理中の場所の隣として見つかった場所だけが、記録されてキューに入る」という仕組みを、そのまま見直せる。
- 不正解フィードバックを、推論の道筋を明示する文言に変えた（「距離が記録されてキューに入るのは、処理中の場所の隣として見つかった場所だけです。Zはどの場所の隣にもないので、最後まで見つかりません。」）。
- 問題自体と正解フィードバックは変更していない（フェーズ6の「推論可能な範囲のエッジケース」として成立する）。

## 検証

- `verify:bfs-consolidation` に、復習先が関門のステップ列であることを固定した（ステップIDの実在はコンテンツ側の検証でも担保される）。
- 全 verify・front の lint・typecheck・build が通過する。

## 確認方法

スクリーンショットは環境の都合で未取得のため、見え方はデプロイ後の実機確認に委ねる。
