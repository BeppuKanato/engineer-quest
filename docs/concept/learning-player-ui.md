# 学習プレイヤーUI定義

- 目的: 新学習フローの教材プレイヤーについて、画面構成、色、操作系、アニメーションの実装上の定義を定める。
- 適用範囲: 学習プレイヤー本体と、その単品プレビューページ。アプリ本体の画面（ヘッダー、コース画面等）のデザインは対象外。
- 最終確認日: 2026-11-05
- 関連文書: 教材の中身の規則は [learning-materials-guideline.md](learning-materials-guideline.md)（教材指針全文）、確定事項の要約は [learning-materials-v2.md](learning-materials-v2.md)。この文書はプレイヤー UI の実装定義の正本であり、教材指針とは分担が異なる。
- 経緯: Issue #68 の実装（PR #80）では、教材指針に具体的な配色と操作配置の指定がなかったため、暫定の色トークンと操作レイアウトが置かれた。この文書でその暫定値を置き換える。

## 1. 画面構成と占有率

- プレイヤーは、表示領域の大半を教材のために使う。単品ページでは、教材領域（キャンバス＋キャプション＋操作バー）がビューポートの幅・高さとも **70〜85% 程度** を占めることを目安とする。下限だけでなく上限も守ること。画面全体（100%）へ広げるフルブリードはしない。
- 固定の小さい最大幅（例: 880px）でカード状に中央寄せし、周囲に大きな余白を残す見せ方をしない。幅は表示領域に追従させ、キャンバスの高さも残りの領域を活かす。
- プレイヤー外側の余白と内側のパディングは最小限に留める（目安: 16px 以下）。背景色や影で教材を「浮かせる」装飾をしない。
- アプリへ組み込んだ状態でも、ヘッダー等のアプリ側要素を除いた残り領域の大半を教材が使う。組み込み側の都合で教材を縮小しない。
- フェーズ7のエディタ画面はこの占有率の対象外（Issue #110、#78設計決定10）。編集面積を優先し、単品は全画面、単元内はナビゲーション下の残り領域を使う。Monacoはライトテーマ、16pxを基準にする（2026-11-06 改訂・#149：#78設計決定10のダークテーマは、アプリとの一貫性を失うため廃止した。エディタ領域の分離は暗色ではなく、フォーカス色の枠と「Pythonコード」の見出しで表す。テスト／コンソール／ヒントの周辺パネルも同じ明色のエディタ専用トークンで合わせる）。図とトレース再生には引き続き§2の色・共通描画を適用する。

## 2. 色の定義

状態と色の対応は、確定済みの教材サンプル（指針のフェーズ1・2の見本）で使われている意味付けで固定する。実装側が別の対応を発明しない。

### 2.1 状態と色の対応

| 状態 | 意味 | 塗り | 枠 |
| --- | --- | --- | --- |
| 処理中 | 今まさに処理している要素 | 青 `#2563eb` | 青 `#1d4ed8` |
| キュー待ち | データ構造の中に保持されている要素 | ベージュ `#f5e7c1` | `#c9a227` |
| 完了 | 処理が終わった要素 | グレー `#e5e7eb` | `#9ca3af` |
| 未処理 | まだ処理されていない要素 | 白 `#ffffff` | `#9ca3af` |
| 層・段階 | 距離の層などの帯 | グレー系 `#f3f4f6` / `#e5e7eb` の交互 | なし |

- 強調（今見るべき要素のハイライト）は、処理中の青を使った太枠または破線枠で表す。強調専用の新しい色を増やさない。
- 層・段階の表現に、紫・ピンク等の装飾的なパステル色帯を使わない。層はグレースケールで表す。
- この対応はプレイヤー内に閉じる。アプリ本体の色の意味（青＝必須・次、緑＝完了、橙＝挑戦 等）を持ち込まない。特に「完了＝緑」は教材内では使わない。

### 2.2 テキストの色

- 情報を伝えるテキストは、**黒 `#111827` を基本**とする。対象はキャプション、ノード名、距離・層のラベル（例: 「0歩」）、データ構造の要素名、変数の表示のすべて。
- 状態をテキストの色で表さない。テキストを淡い色にして背景に溶かす表現をしない。
- 例外は、青い「処理中」要素の上に乗る文字だけで、白 `#ffffff` を使ってよい。
- 状態の区別は色を主とし、記号やラベルは補助に留める。全要素に状態テキストを常時表示するようなノイズを増やさない（教材指針の「無駄なメタ指示・UIノイズの排除」に従う）。

### 2.3 グラフの描画と拡縮（Issue #91）

ノード・辺・ノード内ラベル・強調リングは `player/GraphDrawing.tsx` の共通描画を使い、数値は `player/graphGeometry.ts` に集約する。土台の GraphCanvas と BFS フェーズ1・2（フェーズ3は実行キャンバス経由）で個別実装を持たない。
600幅の論理座標におけるフェーズ1の見た目（ノード直径60）を基準とする。

| 要素 | 論理座標での値 |
| --- | --- |
| ノード | 半径30、枠線2 |
| 辺 | 通常2、強調5 |
| ノード強調リング | 半径37、線幅3、破線 `5 4`。強調でノード本体を拡大しない |
| ノード内ラベル | 文字サイズ24、太字700、中央揃え、ベースライン y=7 |

- 共通SVGは `viewBox="0 0 600 450"`、`preserveAspectRatio="xMidYMid meet"` を基準とし、中央で縦横同じ倍率に拡縮する。ノード座標をコンテナ幅へ引き伸ばしたり、ノードや線だけを固定pxにしたりしない。どの画面幅でも、ノード直径・点の間隔・線幅・文字の比率を維持する。
- グラフの座標は正本データをそのまま使う。BFS のノード・辺・座標の正本は `bfs/bfsGraph.ts`。フェーズ固有の余白補正・座標投影は加えない。
- BFS は上部の600×360領域に図、下部にキューまたは出口を配置する。フェーズ1も出口用の別行でSVGの高さを減らさず、同じSVG内に配置する。横長の画面では余白を許容し、図を横へ引き伸ばさない。
- 土台の長いデータ構造は論理座標で折り返し、必要な場合だけSVGの高さを450より増やす。その場合もノード・辺を含む全体に同じ倍率を適用する。
- 色は §2.1・2.2 の既存 `playerTokens` のみを使う。距離帯、距離表示、キュー、ルート、出発点・ゴール、注釈は各教材の差分レイヤーとして重ねる。フェーズ3の回答用リングとタップ領域も、同じノード座標と半径を受け取る既存の `renderNodeOverlay` で重ねる。
- 同じ表示枠では図の大きさも一致する。プレビュー外枠（フェーズ3は既存の84vw/84dvh）による倍率の差と、図内部の比率の不一致は区別する。外枠・プレイヤー操作系の統一は #83 の範囲で、この描画統一では変更しない。

## 3. 操作系の配置

プレイヤーバーは、図の下に「横方向中央の操作グループ」を置く形を基準形とする。操作要素をバーの幅いっぱいに引き伸ばしたり、分散させたりしない点は従来どおり。（2026-11-06 改訂・#140：当初は一般的なメディアプレイヤーと同じ左寄せを基準形としていたが、動機づけ画面で操作系が目立たず見落とされるという実機レビューを受け、中央寄せ＋拡大に改めた。）

```
[再生 / 一時停止] [前へ] [次へ]  [ステップ進捗]  [ n / N ]
```

- **再生 / 一時停止ボタン**: 操作グループの **左端** に置き、グループの中で最も大きく目立つ主操作とする（大きさの目安: 56px 程度）。アイコンは一般的なメディア操作のものを使い、再生中は一時停止アイコンに切り替える。最終ステップで押した場合は先頭から再生し、その旨が分かる見た目（最初から再生アイコン）にする。
- **前へ / 次へボタン**: 再生ボタンの右に隣り合わせて置き、1つの操作グループとしてまとめる。他の要素で分断しない（大きさの目安: 48px 程度）。
- **ステップ進捗（シーク）**: 全教材で **スライダー型のシークバー** に統一する（2026-11-06 改訂: 当初はステップ数の少ない教材向けにセグメント型を基本としていたが、ステップ数の多い教材でセグメントが潰れて別の UI に見えたため、表示形式を1つに統一した）。横幅いっぱいには伸ばさず、幅は操作グループ内に収まる長さ（目安: 320px 以下）に制限する。ドラッグと矢印キー / Home / End で移動でき、現在位置は `n/N` を併記する。
- **n / N 表示**: 操作グループの右に置く。
- 操作グループはバーの中央に置く。最終ステップで出す次へボタンは、シークバーの近く（操作グループの右隣）に置く（出現時はフェードインさせる）。シークバーを持たない画面の次へボタンは中央に寄せる。将来の補助導線も操作グループの近くに置き、バーの両端へは置かない。
- キーボード操作: `←` / `→` で前後移動、`Home` / `End` で先頭・末尾へ移動できること（PR #80 の実装を定義として採用）。

## 4. アニメーション

- ステップ間の変化は、瞬時の表示切り替えにしない。変化した要素（例: キューからの取り出し、キューへの追加、強調の移動）をアニメーションで繋ぎ、学習者の視線を変化点へ誘導する。
- 1回の遷移のアニメーションは **500〜700ms** 程度を目安とする。目で追える速度を優先し、これより速くしない。
- 自動再生のステップ間隔は **最低 2.5 秒** とし、プレイヤー側で下限を保証する。コンテンツ側は間隔を長くできるが、2.5 秒より短くはできない（キャプションを読み、図の変化を確認できる時間を確保するため）。
- 状態の色変化だけに頼らず、要素の移動・出現を伴わせる。

## 5. 適用

- プレイヤーの色トークン、レイアウト、操作配置はこの文書に従う。PR #80 で置かれた暫定トークン（処理中＝琥珀、キュー待ち＝青、完了＝緑、層＝パステル）と操作レイアウト（[前へ] [再生] スライダー [次へ]）は、この文書の定義で置き換える。
- この文書と教材指針全文が矛盾する場合は、AGENTS.md の優先順位に従い、勝手に片方を選ばず PR で明示する。
