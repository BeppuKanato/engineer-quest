## 1. アルゴリズムの確定事項

バブルソート（昇順）:

1. 隣り合う2つを比べ、左が大きければ入れ替える。これを左端から右端まで行う（1周）。
2. 1周すると一番大きい値が右端に決まる。
3. 決まった右端を除いた範囲で同じことを繰り返す。範囲が1つになるまで続ける。
4. 途中で交換が起きなくても、範囲が尽きるまで比べ続ける（早期終了は入れない。基準コードの形を正とする）。

主教材は5要素の配列 [4, 2, 5, 1, 3]（比較10回・交換6回・4周）。転移用は [3, 1, 4, 2]（比較6回・交換3回）。

### 主教材の検証済みトレース

| 周 | 比較 (j) | ペア | 交換 | 比較後の配列 |
|---|---|---|---|---|
| 1 | 0 | (4, 2) | する | [2, 4, 5, 1, 3] |
| 1 | 1 | (4, 5) | しない | [2, 4, 5, 1, 3] |
| 1 | 2 | (5, 1) | する | [2, 4, 1, 5, 3] |
| 1 | 3 | (5, 3) | する | [2, 4, 1, 3, 5] ← 5 が右端に確定 |
| 2 | 0 | (2, 4) | しない | [2, 4, 1, 3, 5] |
| 2 | 1 | (4, 1) | する | [2, 1, 4, 3, 5] |
| 2 | 2 | (4, 3) | する | [2, 1, 3, 4, 5] ← 4 が確定 |
| 3 | 0 | (2, 1) | する | [1, 2, 3, 4, 5] |
| 3 | 1 | (2, 3) | しない | [1, 2, 3, 4, 5] ← 3 が確定 |
| 4 | 0 | (1, 2) | しない | [1, 2, 3, 4, 5] ← 2 が確定し完成 |

## 2. 参照コード（契約）

契約ID: `bubble-sort-v1`。入力リストは変更せず、並び替えた新しいリストを返す。

```python
def bubble_sort(values):
    result = list(values)
    n = len(result)
    for i in range(n - 1):
        for j in range(n - 1 - i):
            if result[j] > result[j + 1]:
                result[j], result[j + 1] = result[j + 1], result[j]
    return result
```

## 3. フェーズ別設計

### フェーズ1 導入

- 動機づけ: ゲームのスコアランキングなど、「並び順」が要る場面から入る。バラバラの数を見せ、コンピュータがどうやって小さい順に並べるのかを問う。
- 「隣同士を比べて入れ替えるだけ」という発想と、一番大きい値が右端へ押し出されていく様子を短く体験させる。用語（バブルソート）はまだ出さない。

### フェーズ2 動きの説明（16ステップ）

主教材 [4, 2, 5, 1, 3] の全過程。初期状態1ステップ＋比較10ステップ＋各周の終わり（右端の確定）4ステップ＋完成1ステップ。
- 比較ステップのキャプション: 「4 と 2 を比べて、入れ替えます」「4 と 5 を比べて、そのままにします」の形で、値と比較結果を一文で。
- 確定ステップ: 「一番大きい 5 が、右端に決まりました」の形。

### フェーズ3 動きの確認問題（連結2問）

場面: 1周目の2回目の比較まで終えた状態（配列 [2, 4, 5, 1, 3]、次は j=2）。
- Q1（処理対象の特定）: 次に比べるペアの左側のマスはどれか（配列をタップ）。正解は位置2（値5）。
- Q2（直後の変化）: 比べた後、5 はどのマスへ行くか（タップ）。正解は位置3。

### フェーズ4 動きとコードの対応

フェーズ2と同じトレースを、参照コードの行ハイライトと同期して再生する。対応づけの要点: 外側ループ（周回と範囲の縮小）、内側ループ（比べる位置 j の移動）、交換の条件 `result[j] > result[j + 1]`、タプル代入による交換。変数表示は i / j / n と現在のペア。

### フェーズ5 コードの確認問題（独立2問）

- Q1: 内側ループの範囲。`range(n - 1 - □)` の □ は `i`（選択肢はいずれも文法的に正しい式）。
- Q2: 交換の条件。`if result[j] > result[□]:` の □ は `j + 1`。

### フェーズ6 応用問題（4問）

- Q1（転移・タップ）: 転移用配列 [3, 1, 4, 2] の2周目が始まった場面（配列 [1, 3, 2, 4]）。「この後、入れ替えが起きるペアの左側はどれか」。正解は位置1（ペア (3, 2)）。
- Q2（推論可能なエッジケース・選択）: 最初から並んでいる配列 [1, 2, 3, 4] ではどうなるか。正解は「交換は一度も起きないが、比べることは範囲が尽きるまで行われる」。
- Q3（転移・選択）: 右端から順に決まっていくのはなぜか。正解は「比べるたびに大きい方が右へ移るので、1周すると一番大きい値が右端に届くため」という趣旨。
- Q4（Parsons）: 参照コード8行の並び替え（インデント提示あり、余分な行なし）。

### フェーズ7 自分で実装

- テンプレート: 関数の骨組みだけ与え、自由記述。
- テスト:
  - 表示用 D1: 主教材 [4, 2, 5, 1, 3] → [1, 2, 3, 4, 5]。
  - 表示用 D2: [3, 1, 4, 2] → [1, 2, 3, 4]。
  - 判定用 J1: 重複あり [3, 1, 3, 2] → [1, 2, 3, 3]。
  - 判定用 J2: 逆順 [5, 4, 3, 2, 1] → [1, 2, 3, 4, 5]。
  - 判定用 J3: 並び済み [1, 2, 3, 4] → [1, 2, 3, 4]。
  - いずれも実行検証済み。入力が変更されていないことも判定に含める（契約: 新しいリストを返す）。
- ヒント（4段ラダー）:
  - L1 使う部品: リストのコピー／二重ループ／値の交換。
  - L2 処理の流れ: ①左端から右端まで、隣同士を比べていく ②左が大きければ入れ替える ③右端が決まったら、範囲を1つ狭めてくり返す。
  - L3 条件とループの骨格: 外側・内側ループの範囲と交換条件の形。
  - L4 並び替え前のコード（Parsons盤面、練習モード）。
- 視覚デバッグ: 学習者のコードの比較・交換過程を配列でステップ表示する（範囲は BFS フェーズ7と同じ段階適用）。
