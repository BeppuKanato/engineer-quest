## 1. 目標と共通題材

地図上の場所AからFへ、道路の移動コスト合計が最小になる経路を探す。BFSの「辺の数が最小」と区別する。道路は無向、全コストは非負。A*はゴールへの推定値が過大評価しないことを明示する。単元順はダイクストラ法→A*を推奨（履修の強制は未決定）。

座標は道路距離の下界として使う格子上の座標。SVG座標は同一相対配置を拡大する。

| 場所 | x | y | Fまでのマンハッタン距離 h |
| --- | ---: | ---: | ---: |
| A | 0 | 0 | 6 |
| B | 2 | 0 | 4 |
| C | 0 | 1 | 7 |
| D | 4 | 0 | 2 |
| E | 3 | 1 | 4 |
| F | 6 | 0 | 0 |

| 道路 | コスト |
| --- | ---: |
| A–B | 2 |
| A–C | 1 |
| B–D | 2 |
| B–E | 2 |
| C–E | 5 |
| D–F | 2 |
| E–F | 5 |

各道路のコストはマンハッタン距離以上なので、hは整合的（各辺で h(u) ≤ w(u,v)+h(v)）かつ許容的。h(F)=0。探索の同順位はノード名昇順。隣接順は辺配列順。候補リストは重複させず距離を更新する。まず候補集合で最小値を選ぶ実装を扱い、ヒープ最適化は発展事項とする。

| 手法 | 候補の優先値 | 選択順 | 最短経路 | 合計 |
| --- | --- | --- | --- | ---: |
| ダイクストラ法 | g | A→C→B→D→E→F | A→B→D→F | 6 |
| A*探索 | g+h | A→B→D→F | A→B→D→F | 6 |

最短経路は両者同一。A*の選択数削減はこの例での結果であり、全入力で必ず減るとは教えない。Cの推定値7、Aの推定値6など、地図から実際に計算可能な数を使う。候補に入れた時点で確定しない。ゴールの選択時に終了する。

## 2. フェーズ1（導入）

ダイクストラ法：①AからFまで移動コストの小さい道を見つけたい ②辺数だけでは判断できない（A-C-E-Fは11、A-B-D-Fは6、同じ3辺） ③まずAの隣の移動コストを記録 ④その時点で最も小さい候補から調べる方法を「ダイクストラ法」と名付ける。

A*探索：①ダイクストラ法はゴールから外れたC/Eも確認した ②地図でFまでの残りの下界が分かれば候補順を変えられる ③Bはg=2,h=4、Cはg=1,h=7 ④合計6と8を比較しBを選ぶ ⑤これを「A*探索」と名付ける。図・式は段階的に追加し、1場面1文。

## 3. フェーズ2（動きの説明）と4（コードとの対応）

共通表示: 道路の重み、各ノードの暫定コストg（未到達は∞）、候補リスト（優先値の昇順）、処理中、選択済み、直前の更新辺、前の場所。A*ではhとf=g+hを同じ位置に追加。各辺の検討を一コマにし、更新しなかった場合も候補距離を見せる。色だけで状態を区別しない。

ステップ種別: init（開始点の距離0）、select（最小候補選択）、relax（より小さい距離と前の場所を更新）、keep（変化なし）、finish（ゴール選択後に経路を復元）。フェーズ4は同じスナップショットを参照し、対応するコード行と変数の変化を明示する。行単位のフレーム作成は次段階。

## 5. フェーズ4〜5（コード接続・確認）

参照コードはPython、候補集合を重複なく保持。行意味IDを select-min / relax-condition / update-distance / update-parent / add-frontier / goal-check / reconstruct に固定する。DijkstraとA*の差は優先キーのみ（g対g+h）。候補集合が空なら到達不能を返す。負の辺は入力契約外。A*のhは整合的、h(goal)=0を入力契約とする。優先順位同値はノード名順。

フェーズ5の独立穴埋め案（構文上成立する誤答にする）:
- Dijkstra: `min(frontier, key=lambda n: (g[n], n))` の g[n] / -g[n] / 0。
- A*: 同じ選択で g[n]+h[n] / h[n] / g[n]。
- 共通: `candidate < g.get(v, float("inf"))` の < / > / ==。
- 共通: `g[v] = candidate` の candidate / g[u] / w。
- 共通: `parent[v] = u` の u / v / goal。
- 共通: 終了判定 u == goal / u == start / not frontier（候補から選んだ直後の判定）。
各問いに意味タグを割当て、採点問題数とconcepts.jsonを一致させる。

## 6. フェーズ6（応用）

- 転移グラフ: S-X=8, S-Y=2, Y-X=2, X-T=3, Y-T=10。最短経路 S-Y-X-T、7。Xは8→4に更新される。A*では h(S)=4,h(X)=2,h(Y)=3,h(T)=0（整合性あり）。
- 境界: SからTへ辺がないとき候補が空になり到達不能。開始=ゴールなら0。負コストは保証対象外（負辺を含むグラフの最短路を本方式で教えない）。
- A*固有: h=0の場合はダイクストラ法と同じ選択、hだけで選ぶ方式は最短を保証しない。過大評価が起こる反例（S-A=2,A-T=2,S-B=1,B-T=8、h(A)=10,h(B)=0,h(T)=0でB経由9が先に選ばれる）。
- Parsons問題: 初期化・whileは固定、最小候補の選択、ゴール判定、緩和条件、更新、候補追加を並べる。インデント固定・妨害行なし。初回回答診断、再挑戦・復習を提供。

## 7. フェーズ7（自力実装）

関数契約案: `dijkstra(graph, start, goal)` および `astar(graph, start, goal, h)`。隣接リストは {ノード: [(隣接ノード,非負重み), ...]}、全ノードをキーに持つ。戻り値は (最小コスト, 経路リスト)、到達不能は (None, [])。同コストが複数ある入力は最適コスト・経路有効性で判定する（経路の固定比較はしない）。

表示テスト: 主グラフ（6,A-B-D-F）、転移グラフ（7,S-Y-X-T）。非公開判定は別データで、開始=ゴール、到達不能、ゼロ重み、緩和の再更新、同コスト経路を含める。A*のhはすべて整合的にする。正解コード・ヒント・可視化デバッグの実装と実行検証が必要。

ヒント4段階: ①使う部品（距離表・候補・前の場所）②手順（最小候補→終了判定→隣の更新）③条件とループの骨格 ④Parsons練習盤面（完成解の貼り付けは不可）。入力レベルによらず全テスト通過で完了。
