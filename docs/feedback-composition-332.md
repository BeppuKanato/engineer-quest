# フィードバック構成の見直し（Issue #332）

> 2026-11-11追記: 新フローの現行仕様（7単元の概念・回答証拠、1〜3候補、表示・計測）は [learning-feedback-402.md](learning-feedback-402.md) を参照。本書の1件推薦・従来文章構成の記述は変更当時の記録。

目的: フィードバック v1 の表示文章の構成を、Sadler (1989) と Hattie & Timperley (2007) のフィードバックモデル（目標／現在位置／ギャップを埋める一歩）に照らして規定し直し、生成済みだが未表示だった理由（reason）を学習者に表示する。
最終確認日: 2026-11-10

## 背景と判断

- 従来のプロンプトは「日本語で簡潔に説明する」だけで、表示3項目（currentState / nextGoal / nextStep）の分量や内容の要件がなかった。設計原案（2026-08-24）にあった「合計200〜300字程度」の目安は実装時に落ちていた。
- モデルとの対応は存在していたが、各要素の質が規定されていなかった。currentState は「目標に対する現在位置」として書く保証がなく、nextGoal には到達の目安がなく、ギャップ（差そのもの）を言語化する役割は未表示の reason にしかなかった。
- purpose は学習者向けの文章ではない。行動カタログ側（`feedbackV1.context.ts` の行動定義）に付いた「この行動の目的」が選択段への入力であり、選択結果の purpose はその記録である。表示には出さない。
- 文字数の数値そのものに先行研究の規範はない（Shute, 2008 は具体性や管理可能な単位といった質の条件のみ）。200〜300字は「最適値」ではなく、刺激統制と根拠提示に必要な分量を担保するための設計パラメータとして復活させる。
- 文体の温度（温かさ、励まし方、曖昧さ）は両条件共通プロンプトでは指定しない。文体の好みは動機特性と結びつき得るため、温度の調整は PERSONALIZED 条件で HEXAD が担う範囲として残す。

## 変更内容

### プロンプト（`back/src/service/feedbackV1.engine.ts`）

- `PROMPT_VERSION` を `feedback-v1-2026-11-10` に更新した（従来 `feedback-v1-2026-11-06`）。モデル、effort、スキーマ、検証は変更していない。
- 分析プロンプト（`analysisPrompt`）に currentState の要件を追加した。
  - 学習目標に対する現在の位置として、どこまで進んだかと何がまだ安定していないかを、観測された具体的な事実に触れて書く。
  - 70〜100字程度。表示文章全体（currentState・次の目標・次の一歩・理由の合計）は200〜300字を目安とする旨を明記した。
- 選択プロンプト（`selectionPrompt`）に表示文章の要件を追加した（両条件共通。HEXAD 条件分岐の前段に置き、STANDARD / PERSONALIZED の双方へ同一に適用される）。
  - nextGoal: 到達の目安（どうなれば達成と言えるか）を含めて40〜60字程度。
  - nextStep: 対象を具体的に名指しして50〜70字程度。
  - reason: 分析で得たこの学習者の具体的な根拠（観測された事実や安定していない点）に必ず触れ、なぜ今この一歩なのかが分かるように40〜70字程度。候補の目的の言い換えにしない。
  - 合計は分析の currentState と合わせて200〜300字を目安とする。
- 文体の温度に関する指定は追加していない。

### 表示（reason の追加）

- `back/src/service/feedbackV1.service.ts`: 応答の `feedback` に `reason`（選択結果の reason）を追加した。従来から `recommendation` には含まれていたが、フロントは参照していなかった。
- `front/src/app/component/feedbackV1.tsx`: 型に `reason` を追加し、「この一歩の理由」として次の一歩の下に表示する。表示は 現在の状態／次の目標／次の一歩／この一歩の理由／アクションボタンの順になる。
- purpose は表示しない（上記のとおり内部の選択・記録用）。

## 変更していないもの

- 生成の2段構成、モデル（gpt-6.1-terra）、reasoning effort（medium）、出力スキーマ、検証（`validateSelection`）。
- DB スキーマ、migration、seed（すべて不要）。
- 過去に保存済みの生成結果はそのまま再表示される（reason は v1 の当初から保存されているため、旧結果でも表示できる）。

## 検証

- `npm run verify:feedback-v1`（back）: PASS。
- back の型チェック: 変更前後で feedbackV1 関連ファイルのエラー集合が同一であることを確認した（当環境では Prisma 生成物の都合で既存の暗黙 any 等のノイズがあるため、ベースライン差分で確認）。
- front の型チェック（`tsc --noEmit`）: feedbackV1.tsx に関するエラーなし。
- `verify:feedback-v1-storage` は、当環境では Prisma クライアントが生成できず実行できない（develop でも同一の TS2305 で失敗することを確認済み。CI での確認に委ねる）。本変更は保存層に触れていない。
- `verify:feedback-v1-context` は、スクリプトファイル（`src/scripts/verifyFeedbackV1Context.ts`）自体が develop に存在せず実行できない（既存の問題で、本変更とは無関係）。

## 実機での確認事項

- 結果画面で4項目が表示され、合計200〜300字の目安に収まるか（モデル出力のため厳密な保証はない）。
- reason が「目的の言い換え」ではなく、その学習者の根拠に触れた文になっているか。
- 生成時間への影響（出力が長くなる分、従来より延びる可能性がある）。
