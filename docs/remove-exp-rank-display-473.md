# EXP・レベル・ランク表示の削除（判断2）

- 目的: 更新されないEXP・レベル・ランクの表示と、その画面専用の計算を取り除く。
- 適用範囲: ホーム／プロフィールの表示、APIレスポンスと型、関連検証。ホームの構成変更（B2）は含めない。
- 最終確認日: 2026-11-19。
- 正本: [Issue #473](https://github.com/BeppuKanato/engineer-quest/issues/473)、[開発ガイド](../AGENTS.md)、[フロント構成方針](frontend-architecture.md)。
- 対象実装コミット: `03faf06a`。
- 状態: 実装・自動検証・固定データによる2画面2サイズの撮影済み。DB適用不要。

## 変更内容

ホームのレベルチップ・EXP数値／バー・ランクカードを除去し、後続の学習ストリークと目標実績が詰まるようにした。ローディング用スケルトンも削除後の構成へ合わせた。「レベルアップしよう」は「学習を続けよう」へ変更した。プロフィールのレベル／ランクチップ・EXPバーと専用計算も除去した。名前未設定時の英語表示とプロフィール紹介の外来語は、変更した紹介欄の範囲で日本語表記にした。

ホームAPIはuserの `rank`／`level`／`exp`／`requireNextLevelExp` とルートの `nextRank`／`nextRankCondition` を返さない。プロフィールAPIはuserの `rank`／`level`／`exp` を返さない。両側の型とサービスを同時に更新し、ホームの専用レベル計算・ランク計算とプロフィールのランク計算を削除した。

完了数・実績数・カード数・学習カレンダー・目標実績と進捗バー・相棒／代表実績／通知設定・学習履歴・動機づけプロフィールは維持する。既存の完了コース等の集計方法も今回変更しない。

## フィードバックの凍結範囲との関係

`profile.service.ts` の `deriveLevel` は画面専用ではなく、凍結対象の `feedbackV1.context.ts` でも入力生成に使用していた。計算そのものを削除すると研究の入力が変わるため、同じ実装を `back/src/lib/legacyUserLevel.ts` に移し、従来のimportを維持できるようprofileサービスから再exportした。ホーム／プロフィールAPIはこの関数を呼ばない。フィードバック生成ファイル・入力項目・実験割当・問題・正誤判定に差分はない。従来の計算結果と既存フィードバック検証の成功を確認した。

## 検証

- front／backの `typecheck` 成功。
- backの `lint`／`build`／`verify:static` 成功（`verify:collections` を含む）。
- 新設 `verify:home-profile` をstaticに追加し、不要API項目がなく、統計・カレンダー・目標・選択実績・フィードバック互換計算を維持することをDB不要のアダプターで確認。
- frontの `verify:home-layout` 成功。表示削除と残す統計／設定／目標の進捗バーを既存検証に追加。
- frontの `build` 成功。sandbox内では生成先へのEPERMで失敗したが、同じコマンドの通常権限実行で成功。
- frontの通常 `npm run lint` は既存の `.next-migration` 生成物まで走査して失敗。生成物だけを除外した `node node_modules/eslint/bin/eslint.js . --ignore-pattern '.next-migration/**'` はエラー0件（既存の学習プレイヤーのHook警告5件のみ）。lint設定や既存生成物は変更しない。
- 実サーバー認証・実ユーザー操作を含むE2Eは未実施。画面検証は実ページコンポーネントを固定データで描画したもの。DB・外部サービスへは接続していない。

## 画面証跡

CSS表示領域1093×614と2560×1440、deviceScaleFactor=1、ブラウザー倍率100%、Asia/TokyoのヘッドレスChromiumでページ全体を撮影した。ローカルの固定データで、ホームの継続3日・目標3/7、プロフィールの完了コース2／知識カード9／実績6を描画した（dev DBの集計値を示すものではない）。EXP／Lv.／ランクのテキストがないこと、残す項目・画像の表示、ページ横スクロールがないことを検証し、4枚を目視確認した。

1093pxでは従来のブレークポイントどおり縦に並び、目標や統計は縦スクロール先にある。2560pxでは既存の複数列レイアウトを維持する。狭い幅の共通ヘッダーで一部ナビゲーションが見切れる既存挙動は今回の変更範囲外。
