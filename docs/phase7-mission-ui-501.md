## 開始の形（自由実装）

訂正（2026-11-25）：同日先に書いた「入口の関数を実行時に発見する」形は、名前だけ自由な関数を書かせるもので自由実装とは言えないとして Kanato が却下した。正しい形は本節のプログラム形式（標準入出力）である。旧・関数形の画面（開始ゲート＋書き方レベル）は、設計サンドボックスでは別ページ（`bubble-sort-implementation-legacy`）に保存してある。

- 学習者は関数ではなくプログラムを書く（競技プログラミングと同じ形式）。入力は標準入力から1行で与える：並べ替える番号が半角スペース区切りで並ぶ。出力は、並び替えた番号を半角スペース区切りで1行に出力する。関数を使うかどうかを含め、書き方は一切固定しない。
- 入口には、旧画面の量選択ゲートをプログラム形に合わせて残す（2026-11-25 Kanato 決定：レベル制は残す）。ゲートには問題の要約（題・入力形式・出力形式・入出力の例）を置き、その下で書き方の量を3択から選ぶ（全部書く／骨格から書く／穴埋めで書く。テンプレートはプログラム形）。問題文の全文（条件を含む）は作業画面のサイドパネルの「問題」タブにも常駐させ、作業中いつでも見返せるようにする。エディタの初期コード（全部書く）は、入力形式をコメントで示すだけの最小限にする。
- 判定は、ケースごとに入力を差し替えてプログラムを実行し、標準出力を数値の並びとして読んで比べる。出力が無い・数値でないものが混ざる・個数が違う場合は、実行エラーとは別の「出力の形」の問題として知らせる。
- 判定の内訳は、名前つきテスト（従来の5件）に自動チェックを1枠足す：小さい並びの網羅（順列・重複）と、種を固定した乱数による性質ベースの検査をまとめて判定し、「いろいろな並び（自動チェック）」として1行で出す。完了条件は全チェック通過（書き方によらず同一）。ミッションバンドの数と区切りもこの総数に合わせる。
- 支援のエスカレーション：ヒント（従来の段階式）は常駐。テストに2回つまずいたら「型を使う（橋渡し）」を一度だけ提案する（バナー、閉じられる）。橋渡しの型はプログラムの形にする（入力の受け取りと出力は用意し、骨格または要点の行を書く）。型のコードは書き方別の下書きとして残す（自由なコードは消えない。「自由に書くに戻る」で戻れる）。お手本（フェーズ6までの正解コードをプログラムの形に組み直したもの）は橋渡しの中でのみ、つまずきが続いたとき（失敗3回以上、または橋渡し使用中）に見せる。
- 「配列で動きを見る」（自分のコードのトレース）はプログラム形式では提供しない（トレース基盤が関数呼び出し前提のため）。旧ページには残してある。

## 実装内容（仕様）

### ミッションバンド

- 単元ミッションと同一のサムネイル部品・同一の色を使う（同じ課題だと絵と色で認識できることが条件。文字だけの参照は不可）。白＋2px の主色枠。開始前はサムネイル 150px 級、開始後は 96px 級。
- バンド内にチップ（単元ミッション）＋題＋達成の条件。区切りの下に進捗帯：「ミッション達成まで」＋大きな数「{通過} / 5」（22/900、通過数が1以上なら通過数だけ緑）＋5セグメントのバー（セグメントにテストごとのラベルと印）。
- 陳腐化した結果（コード変更後の未実行状態）は「前回 n / 5」と明示し、セグメントは白地＋緑2px枠で示し、注記行を添える。レベル変更時のみ前回結果を消す。同じレベルの編集では「前回」表示を保つ。
- 完了後（フロー内）はバンドの右下に主ボタン「単元の結果を見る」を常置する。

### 開始ゲート（未開始時）

- 見出し＋書き方レベル3択のカード（全部書く／骨格から書く／穴埋めで書く）。カードの図は「用意されているコード＝実線（濃色）、自分で書く部分＝青い破線」で、埋まり具合がレベルの実物と一致する向きにする（全部書く＝ほぼ空、骨格＝半分、穴埋め＝ほぼ埋まっている。コードがスカスカ→多く埋まってる、の向きと図を一致させる）。
- 難易度のラベルはカードに付けない。自己選択のガイド文と、実テンプレート冒頭（7行程度、176px、フェードマスク）のプレビュー、「この書き方で始める →」ボタン。図の凡例をグリッドの下に置く。

### 作業画面

- 配置はエディタ：サイドパネル＝60:40。エディタのパネル枠は通常 #dbe3ef、フォーカス時に主色。ヘッダーは「Pythonコード」＋実行ボタン3種＋実行環境の状態＋右端に「環境を再読込」。
- 実行ボタンには13px の役割ラベルを添える：試しに実行＝「結果を確認・採点なし」、配列で動きを見る＝「処理の過程を確認」、テストを実行する＝「達成できたか確認」。実行ボタンは、実行環境の状態文が「実行できます。」になってから有効にする。
- 「ここを書く」行はエディタ上でハイライト＋余白マーカーを付ける。
- 1093×614 ではエディタ高さ約248px を確保する（周辺を詰めて捻出する）。

### テストタブ

- 印は色でなく形と文で示す：通過＝緑で塗り「✓ 通過」、不一致＝濃色2px枠「× 不一致」、構文エラー＝「! 実行不可」、実行時エラー＝「! 実行エラー」、タイムアウト＝「! タイムアウト」、未実行＝灰色2px枠「○ 未実行」。赤は使わない。
- 全テストの結果が同じ種類のエラーを共有するときは、個別表示でなく集約パネルにする：タイトル＝エラーの種類（例外ごとに具体化できる場合はそのタイトル＋行番号）、案内文、問題のコード行、ボタン「エラー箇所を確認」「ヒントを見る」。締めの文は種類で変える（構文＝「テストはまだ実行されていません」、実行時・タイムアウト＝「テスト結果を判定できませんでした」）。
- 例外ごとの文面（NameError／IndexError／TypeError／ZeroDivisionError／ValueError）を用意し、名前や行など実行結果から取れる具体情報を差し込む。LLM は使わない。
- それ以外のときは診断ブロック＋「{通過} / 5 本通過」（陳腐化時は「前回 …」）。
- 大きな図を開くのは「不一致の表示テスト」だけ（168px の図カード：期待値ゴースト＋凡例＋差分の数＋トレースボタン）。通過した表示テストは「結果を大きく見る」で求められたときだけ拡大する。判定テストは拡大しない（実際の出力を持たない設計のため）。

### コンソールタブ

- 順序は固定：判定（戻り値の一致）→ 戻り値の本棚図（期待値ゴースト重ね＋凡例＋差分の数）→ print 出力。
- 図は単元ミッションと同じ本棚図の部品を使う（数値の配列を本で描く。色・高さは値に連動）。

### ヒントタブ

- 縦の番号ステップで順次解放する。各ステップに1行の説明を常時表示する。トークンの挿入操作でヒントパネルは閉じない。
- レベル別のヒント文の設計は教材内容の設計であり、本 Issue には含めない（未決事項）。

### 達成時の祝福オーバーレイ（閉じられる）

- 背景は薄い青のベール。カード（最大760）：マスコット（celebrate、120px）＋「ミッション達成！」＋本が並び替わる図（[4,2,5,1,3] が約700ms後にバネで整列）＋「どんな並びでも番号順に並べ替えるコードが完成しました」＋「{通過} / 5 すべてのテストを通過」＋ボタン「単元の結果を見る」「コードを見る」。
- 紙吹雪（final）と歓声は、本棚アニメーションの後（約1850ms）に遅らせて出す。
- トレースダイアログは画面の84%×84%で、共通の再生操作＋ステップごとのキャプション＋変数ブロックを持つ。

### 保存中の扱い

- 完了保存が終わるまで「単元の結果を見る」ボタンを無効化し、保存中であることを表示する（redesign-overview §6-3）。

## 確認方法

1. ゲートで3レベルそれぞれの図と実テンプレートの埋まり具合が一致することを確認する。
2. 構文エラー／実行時エラー／不一致／通過の各状態で、テストタブの表示（集約パネル、印、図の開閉範囲）を確認する。
3. 全テスト通過で祝福オーバーレイ→単元リザルトへ進めること、保存中はボタンが無効なことを確認する。
4. 1093×614 でエディタ高さを確認する。スクリーンショットは2サイズを PR に付ける。
