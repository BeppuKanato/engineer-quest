# ホーム画面レイアウト変更（Issue #137）実装報告

- 目的: ホーム画面の空白と「続きから始める／ほかの単元を探す」の役割重複を、要素を増やさず再配置と既存部品・既存データの再利用で解消する。あわせて、単元ごとのサムネイル（代表図）をコースカードに導入する。
- 適用範囲: ホーム画面（`front/src/app/home/`）、`ContinueLearning`、`HomeUnitGrid`（新設）、コースカードとそのサムネイル、コース一覧の進捗オーバーレイ共通化。
- 根拠: Issue #137、UI/UX 方針論点1（ホームは学習中心、「続きから始める」を最上部に）、ホーム画面レイアウト原案（2026-11-06、ユーザー承認済み：役割分担、グリッド上限6件、サムネイルは代表図の自動描画）。
- 最終確認日: 2026-11-06

## 実装内容

### 1. 「続きから始める」の主役化と、無いときの非表示（`ContinueLearning.tsx`）
- 進行中の単元があるとき: 単元名に加え、完了数（n / 7 完了）、進捗バー、次の段階名（次は「{formalName}」）を表示する。算出は既に取得している `LearningProgress` と `resumePhaseIndex` を使い、追加の取得はない。遷移先は従来どおり単元画面。
- 進行中の単元がないとき: カード自体を描画しない。従来は「コース一覧から学びたい単元を選びましょう」に化けて隣の探すカードと重複していた。
- 取得失敗時の警告カードと再試行は従来どおり。

### 2. 単元グリッド（`HomeUnitGrid.tsx` 新設、`home/page.tsx`）
- 「ほかの単元を探す」リンクカードを廃止し、右カラムに単元グリッドを置く。カードはコース一覧の `CourseCard` をそのまま再利用。
- 並び順は自分の進み具合（進行中 → 未着手 → 完了、同順位内は API の順序を保持）。上限は `HOME_UNIT_LIMIT = 6` 件。残りの単元と絞り込みは末尾リンクからコース一覧へ委ね、ホーム＝玄関／コース一覧＝カタログの分離を保つ。
- 取得はコース一覧と同じ経路（`getCourses` ＋進捗オーバーレイ）で、キャッシュ（`peekClientQueryData("courses")`）から初期表示する。取得失敗時は既存表示を保持し、データが無い場合のみ警告を出す。読み込み中はカード形スケルトン。
- ホームの読み込みスケルトン右カラムもグリッド形に合わせた。左カラムの3カード（プロフィール／ランク／学習ストリーク）は変更していない。

### 3. 進捗オーバーレイの共通化（`app/courses/courseProgress.ts` 新設）
- コース一覧ページ内にあった進捗の重ね合わせ計算を `withLearningProgress` として切り出し、コース一覧とホームのグリッドで共有する。計算内容と失敗時の扱い（対象コースは元の表示のまま）は従来どおりで、コース一覧の挙動は変えていない。

### 4. 単元サムネイル（`app/courses/component/courseThumbnail.tsx` 新設、`courseCard.tsx`）
- イラスト資産ではなく、単元を象徴する図を SVG で描く。対象は現行7コース。ホームとコース一覧の両方で同じ顔が出るよう `CourseCard` の視覚領域に組み込んだ。未定義のコースは従来のカテゴリ別ビジュアル（色＋アイコン）にフォールバックする。
  - BFS: 教材と同じグラフに距離の濃淡。DFS: 同じグラフに訪問順（A→B→D→F→E→C）の経路ハイライトと、それ以外の辺の破線。
  - バブルソート: 最大が末尾に確定した状態の棒グラフ。選択ソート: 確定済みプレフィックスと残りの最小への印。マージソート: 分割した2グループと統合後の昇順。
  - 二分探索: 配列と中央の印、探索範囲のブラケット。KMP法: 文と型の位置合わせ（一致部分を強調）。
- 図は装飾として `aria-hidden`（単元名はカードのタイトルが担う）。
