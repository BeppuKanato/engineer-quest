- 適用範囲: 単元画面（`UnitOverview`）、単元コンテンツ（段階の `cardRarity`、導入文）、実績 API（応答への `courseId` 追加）と BFS 実績 seed の小修正。
- 根拠: Issue #139、単元画面レイアウト原案（2026-11-06、ユーザー承認済み：Sin カーブ、開始ボタン廃止、あそび要素、白パネルではなく枠線のみ、実績プレビュー）。

- 前提: PR #163（ホーム画面・単元サムネイル）の上に積んだブランチである。`CourseThumbnail` を背景に流用するため、#163 のマージが先に必要（マージ後は差分が本 PR 分だけになる）。

## 実装内容

### 1. Sin カーブのマップ（`UnitOverview.tsx` の `UnitPathMap`）
- ノード配置をグリッド蛇行から、Sin カーブ上の絶対配置に変更した。ノード座標は段階番号から決まる関数（`wavePoint`：等間隔の t に対して y = center − amplitude・sin(3πt)）で、裏に SVG の曲線パスを1枚描く。完了区間（現在地まで）は濃く、未達区間は薄く色分けする。
- パス領域は白パネルにせず、枠線（1px＋角丸24px）だけのフレームにした。背景には単元自身の図（`CourseThumbnail`）を不透明度0.1で薄く敷く。未定義の単元では何も敷かない。
- 入場モーション（UI/UX 方針の日常モーションの範囲）：完了区間のパスが現在地まで描かれていく（framer-motion の pathLength、0.9秒）、ノードが順に小さく弾んで現れる、現在ノードのチップが小さく上下する。reduced-motion ではすべて止める。内容の表示は遅らせない。
- 狭幅（sm 未満）では波を縦に倒し、上から下へ進む縦の波形にする（座標の入れ替えで同じ関数を使う）。

### 2. 開始ボタンの廃止とノードの入口化
- 画面下部の開始ボタン（学習を始める／続きから始める／復習する）を廃止した。開始処理そのものはノードクリックが既に使っていたため、挙動は変わらない。
- 現在のノードは一回り大きく（118px、他は102px）＋二重リング＋影＋「ここから始める」チップで、静止状態でも入口と分かるようにした。到達可能なノードには影を付け、押せる見た目にした。全段階完了時は進捗の横に「単元完了」チップを出す（ボタンは置かない）。

### 3. あそびの要素
- スタート／ゴールの旗をパス上に立てる。最初の段階が現在地のときはチップと重なるため、スタート旗は出さない。
- 知識カードが提示されうる段階（BFS では 2・5・7）のノードに、レアリティ色（共通トーン `knowledgeCardTones`）の小さなカードバッジを付けた。段階側の根拠はコンテンツの `cardRarity` で、付与そのものの正本は seed のカードスケジュールである旨をコメントに明記した。aria-label にも「知識カードが手に入ることがあります」を加えた。
- タイトル下に単元の導入文（コンテンツの `intro`、コース説明の要約）を出す。

### 4. 実績プレビュー
- パスの下に「この単元の実績」として、その単元に関連する実績だけを並べる。絞り込みのために実績 API の応答へ `courseId` を追加した（バックエンドはモデルが既に持つ値を素通しするだけ。条件評価は変えていない）。達成済みは色付き＋「達成済み」チップ、未達成は条件文を表示する。取得に失敗した場合はプレビュー自体を出さず、画面は壊さない。
- BFS カードコンプリート実績（`ach-bfs-card-complete`）は BFS 専用なのに seed で `courseId` が付いていなかったため付与した。`KNOWLEDGE_CARD_COUNT` の進捗計算は courseId を使わないため評価結果は変わらない。**seed のみの変更のため、反映には対象 DB への seed 再実行が必要**（用語変更の実績文言と合わせて未実施）。
