# 応用問題レイアウトとカーソルの視認性の修正（Issue #327, #325）

目的: Issue #327（穴掘り法フェーズ6レビュー）の修正可能項目3点と、Issue #325（棒倒し法フェーズ7レビュー）のエディタのカーソル不可視を直す。対象は全単元共通部品と全5単元の応用問題・実装プレビュー。最終確認日: 2026-11-09。

## 問題と根本原因

### (a) 選択肢が2行に折り返すと、問題文と解説の間の余白がなくなる（#327）

応用問題プレビュー（全5単元で同一構造）は、固定高のセクション（埋め込み時 100%、単品時 84dvh）を縦フレックスにし、`justifyContent: "center"` で中央寄せしていた。選択肢が2行に折り返す（+約56px）、誤答後に再回答の注記とボタン行が増えるなどして内容がセクション高を超えると、フレックスのはみ出しが上下対称に発生する。上方向のはみ出しで問題文がセクションの上端を越え、単元画面で真上に描かれる「直前の回答」通知（解説）に重なる／隙間が消える。Issue のスクリーンショット1枚目はこの重なりそのものである。図のボックスは `flexShrink: 1`（下限 320px）まで縮むが、それを超えると受け止め先がなかった。

### (b) Parsons のドラッグカーソルと、フェーズ7エディタのカーソルが見えない（#327, #325）

- ParsonsBoard のドラッグハンドルは OS 標準の `cursor: "grab"`（手袋）であり、Windows の配色では白系で描かれるため、明るい行（白地＋青枠）の上でほぼ見えなくなる。手袋自体の評判は良い（Issue 本文）ため、形の意味は保ったまま色を保証する必要があった。
- フェーズ7の Monaco エディタ（全5単元の実装プレビューが個別に `theme="vs"` を指定）は、キャレット色もマウスの I ビームも既定任せで、共有設定が存在しなかった。環境によっては白系になり、白いエディタ背景で入力位置とマウスカーソルの両方が埋もれる。

### (c) 誤答後に Parsons の並び替え領域が狭すぎて操作できない（#327）

ParsonsBoard の `scrollable` 表示窓は残り高さの `flex: 1` でしかなく、下限がなかった。誤答状態では「直前の回答」通知（約110px）＋問題文＋操作指示＋再回答の注記＋ボタン行が固定高を占有し、ノートPC相当の高さ（CSS 約610px）では表示窓が約4行分（約185px、Issue スクリーンショット2枚目）まで潰れる。内部スクロール（PR #320）自体はあるが、22行の並び替えを4行窓でドラッグするのは実質操作不能だった。

## 実装内容

### 応用問題レイアウト（全5単元: BFS／バブルソート／棒倒し法／穴掘り法／二分探索）

- セクションの `justifyContent: "center"` を廃止し、「安全な中央寄せ」に変更した。問題文（先頭要素）と末尾スペーサに `marginTop: "auto"` を付け、余白があるときは従来どおり中央寄せ、内容が高いときは自動マージンが 0 になって上方向へはみ出さず、超過分は下方向のスクロール（単元画面の外側ボックス、PR #323 で内側スクロール化済み）へ逃げる。余白の指定値そのものは変えていないので、収まっているときの見た目は従来と同一。
- 再回答の注記とボタン行に `flexShrink: 0` を明示した。
- フェーズ3確認画面は別構造（#321 で再構成済み、中央寄せのはみ出しパターンはない）ため対象外。DFS は応用問題プレビュー未実装のため対象外。

### ParsonsBoard（共通部品。フェーズ7ヒントの練習盤面も同じ部品を使う）

- `scrollable` の表示窓に下限 `minHeight: 276`（行ピッチ 46px × 6行）を設けた。誤答後でも最低6行が見える。収まらない分は画面側のスクロールに逃がす前提で、盤面自体を潰さない。
- ドラッグカーソルを、濃色（#111827、白の縁取り付き）で描いた上下両向き矢印の SVG データ URI に変更した（`parsonsDragCursor` を export）。行全体とドラッグハンドルに指定し、フォールバックに標準の `grab` を後置する。↑↓ボタンのカーソルは従来どおり（明示的に default）。ドラッグの操作方式自体は変更していない。

### フェーズ7エディタ（全5単元）

- 共有モジュール `front/src/features/learning/code/learningEditor.ts` を新設し、各プレビューは `theme={LEARNING_EDITOR_THEME}` と `beforeMount={setupLearningEditor}` を渡すだけにした。テーマ `eq-light` は従来のライトテーマ "vs" をベースに継承し、`editorCursor.foreground` を #111827 で明示する（キャレットの色を環境既定に依存させない）。
- エディタ枠の sx で、Monaco のテキスト領域に濃色 SVG の I ビームカーソル（データ URI、`learningEditorTextCursor`）を指定した。OS 標準の I ビームが白系でも、マウスカーソルが背景に埋もれない。
- ヒントの練習盤面は Monaco ではなく ParsonsBoard のため、上記のドラッグカーソル修正がそのまま効く。

## 対象外（本PRでやらないこと）

- #327 の「合っている行／間違っている行の表示」は設計判断待ちのため未実装。順序の柔軟化も同様。
- #325 の print 確認・行番号なし問題、LLM ヒント案、テスト結果の表示形式（✓/×＋テスト名の一覧）は別件の判断・実装に委ねる。本PRで扱うのは #325 のうちエディタのカーソル不可視のみ。
