# 大目標の称賛演出の統合

- 目的: 大目標の達成を、学習フローの結果画面でアプリ最大級の称賛として提示する（Issue #370、親 #364）。フィードバック専用画面（#369）の上にスタックする。
- 最終確認日: 2026-11-10
- 正本: 方針資料「2026-11-10_大目標・フィードバック方針」（Drive）の称賛に関する決定、Issue #370、#369 の保存レスポンス拡張（`achievedBigGoals`）

## 達成の発生経路

- 達成は学習保存時のサーバ側評価（#365）で遷移し、保存レスポンスの `achievedBigGoals`（#369 で追加）でフロントが知る。フロント側で達成条件を再判定はしない。
- 提示先の振り分けは `LearningScreen` が保存ごとに目標ID単位で行う（下記）。実績の提示先の振り分け（#333）と同じ考え方で、結果画面が無いフェーズの保存分は次の提示面へ持ち越す。

## 称賛の一元化

同じ達成に対して紙吹雪・歓声が2回走らないよう、発火箇所を結果画面の既存の演出に一元化した。

- フェーズの結果画面（フェーズ3・5）: 通常は `UnitResultCelebration` がプリセット "phase"（紙吹雪90×2 origin＋中くらいの歓声）を1回発火する。大目標の達成が重なる結果画面では、同じ発火をプリセット "final"（110×3 origin＋大きな歓声＝現行のアプリ最大）に引き上げる。発火はこの1回だけで、達成バンド側は紙吹雪・歓声を持たない。
- 単元最終結果: もともとプリセット "final" で発火するため、達成した大目標を結果の一部（達成ゾーン）として表示するだけで、追加の発火や別の称賛画面は作らない。
- フィードバック専用画面（#369）: 称賛演出は繰り返さない。到達の事実と進捗、次の目標の提案で達成感を引き継ぐ。

## 提示先の振り分け

保存で達成した大目標は、2つの提示（称賛／次の目標の提案）にそれぞれ1回ずつ振り分ける。

- 称賛: その保存以降で最初に来る結果画面（フェーズ3・5の結果画面）。結果画面の無いフェーズ（1・2・4）の保存分は次の結果画面へ持ち越し、フェーズ6・7の保存分と単元完了保存分は最終リザルトへ。
  - 実績型の大目標がフェーズ2の保存で達成される場合（カード獲得などの実績が区切りで解除されるケース）が持ち越しの実例。
- 提案（#369 の BigGoalNextProposal）: その保存以降で最初に来るフィードバック専用画面（フェーズ3・5・6の後）。無ければ単元のフィードバック画面へ。フェーズ6の保存分はフェーズ6の専用画面で提案し、称賛は最終リザルトで担う（分担がずれるのはこのケースのみで、いずれも二重にはならない）。

## 提示コンポーネント

- `front/src/features/learning/app/bigGoal/BigGoalAchievementBand.tsx`
  - `BigGoalAchievementBand`（フェーズ結果用）／`BigGoalAchievementZone`（最終リザルト用）。実績の提示（#333）と同じ語彙で、旗のバッジがポップインし、放射が出る。色は到達の青に統一し、完了グレー・赤・× は使わない。動きを減らす設定では静止表示。
  - 表示は学習ログに `big_goal_present_view`（placement と phaseKey 付き）として記録する。
- 結果画面への差し込みは単元コンテナの render props（`renderPhaseGoalAchievement`／`renderFinalGoalAchievement`）経由で、全5単元コンテナと結果画面コンポーネントに同じ形で接続した。
- `UnitResultCelebration` に `preset` を追加し、結果画面コンポーネントが達成の有無で渡し分ける。

## 検証

- front: `npm run typecheck` 通過、`npm run lint` 通過（警告は既存の単元コンテナ4件の goToPhase 依存のみ）、`npm run build` 通過。
- front verify: `verifyBfsUnitFlow`、`verifyDfsUnitFlow`、全単元の unit verify（壁倒し・穴掘り・バブルソート・二分探索）が通過。
- back の変更はない。DB の変更もない（schema・migration・seed の変更なし）。

## 未実施の検証・実機確認項目

- 実機（デスクトップ）での確認は未実施：フェーズ3・5の結果画面で大目標を達成したときにバンドと最大級の紙吹雪・歓声が1回だけ出ること、単元完了と重なる達成が最終リザルトの一部として出て追加の紙吹雪が出ないこと、持ち越し（フェーズ2保存での達成がフェーズ3の結果画面で祝われること）、動きを減らす設定で静止表示になること。
- 達成の発生は保存レスポンス依存のため、実績型・到達型それぞれの目標を実際に達成する手順での確認が必要（デプロイ後、割り当て済みアカウントで大目標を設定して学習を進める）。
