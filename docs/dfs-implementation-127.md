# Issue #127 DFS「自分で実装」実装記録

- 目的は、出発点から届く場所を訪問順に返す DFS を実装し、基本例と境界ケースで確かめること。
- 対象は単品プレビューの Python エディタ、ヒント、テストと試し実行、全件通過時の完了表示。
- 最終確認日 2026-11-10
- 正本は [Issue #127](https://github.com/BeppuKanato/engineer-quest/issues/127)、[DFS 基準データ §7・§9-6](concept/dfs-unit-baseline.md)、[教材指針](concept/learning-materials-guideline.md)、[プレイヤー UI](concept/learning-player-ui.md)。

## 実装

BFS で使用しているエディタ画面を共有し、DFS の課題、結果、ヒントを渡す。`dfs_order(graph, start)` は場所名のリストを返す。採点は基本グラフと応用問題の木、孤立した場所、出発点のみ、隣接情報が未登録の場所を含むケースの5件を順に実行する。表示用2件にはグラフと期待する訪問順、実際の出力を表示し、場所の不足・余分な出現・並び順の違いを言葉で区別する。判定用3件はテスト名と成否を表示する。「試しに実行」は基本グラフだけを新しい実行環境で走らせ、コンソールに出力する。

基準データの最小テンプレートを「全部書く」に使用し、現行教材指針の「骨格から書く」「穴埋めで書く」を追加した。骨格は初期化と処理本体の7か所、穴埋めは取り出し・発見済みへの記録・スタックへの追加の3か所を埋める。下書きは単品ページで入力量ごとに保存する。

ヒントは部品と挿入トークン、処理の流れ、制御行、並び替えの順に開く。ヒント4には応用問題と同じ12行を使い、2026-11-09 の決定に沿って全行を動かす練習盤面にする。全5件が通るとエディタ上に完了を表示する。視覚的デバッグと単元への組み込みは後続 Issue の範囲。DB の適用は不要。

## 確認方法

front の開発サーバーを起動し、[単品プレビュー](http://localhost:3000/learning-preview/dfs-implementation) を開く。

1. 入力量を切り替え、テンプレートの違いと各レベルの下書きを確認する。未完成のまま「テストを実行する」を押すと、テスト結果に失敗の種別が表示される。
2. ヒントを順に開き、トークンを挿入する。ヒント4では全12行を動かして確認できる。
3. `dfs_order` を完成させて「試しに実行」を押すと、基本ケースの訪問順がコンソールに出る。「テストを実行する」で5件すべてが通ると完了表示が出る。

`npm run verify:dfs-implementation` は、Worker の採点ハーネスを CPython で実行し、正解コードと逆順を外したコード、隣接情報を直接参照するコードを照合する。テンプレート、全行を動かす練習盤面、結果の区別、判定用データの非表示、試し実行、全件通過の条件も検証する。
