# 二分探索フェーズ1 場面1の未ソート化（Issue #329）

目的: 二分探索フェーズ1の場面1を、主教材と同じ7つの数字を並び替えた「並んでいない」提示に変え、端から順に探す最悪のケースが場面の中で実際に起きるようにする。最終確認日: 2026-11-09。

## 問題（レビュー #329 の指摘）

旧場面1は小さい順に並んだ主教材 [3, 7, 12, 19, 25, 31, 42] を示し、「端から順に見ると最大で7回も見ることになります」と説明していたが、探す値 25 は左から5番目にあり、端から順に見ればちょうど5回で見つかる。「最大で7回」は最後尾の値についての一般論としては正しいが、25 を強調表示した図と並ぶと「25 が最大7回かかる」と誤読される。ユーザー判断（2026-11-09）により、文言だけの修正ではなく場面1そのものを未ソート化する案を採用した。並んでいないから端から順に見るしかない、という動機づけになり、フェーズ2冒頭の「並んでいるからこそ半分にできる」の説明（Issue #330 側で追加）の受け皿にもなる。

## 実装内容

### 場面1（`binary-search/motivation/`）

- 並びは固定の [19, 3, 31, 7, 42, 12, 25]。主教材と同じ7値の並び替えで、探す値 25 を最後尾（位置6）に置く。端から順に見ると 19→3→31→7→42→12→25 と7つ全部を見ることになり、最悪のケースが一般論でなく目の前の場面で起きる。棒の高さは 19, 3, 31, 7, 42, 12, 25 と単調でなく、並んでいないことが見た目でも分かる。
- キャプションは「バラバラに並んだ7つの数字から25を探すとき、端から順に見ていくしかなく、最後にある25は7つ全部を見てやっと見つかります。」に変更。「小さい順に並んだ」という主張はこの場面から外した。用語の統制（フェーズ1で二分探索・インデックス等を出さない）は従来どおり。
- 強調は探す値 25 のマス（位置6）のまま。場面の図の寸法は従来と同一（共通配列基盤のまま）。

### 型とバリデータ（`motivation.types.ts`）

配列の場面に並び方 `order: "sorted" | "unsorted"` を持たせた。

- "sorted"（場面5・6＝単元予告・主例予告）: 従来どおり小さい順（厳密な昇順）を検証する。フェーズ2の主例に直結する場面はソート済みのまま変えていない。
- "unsorted"（場面1専用）: 値の重複を禁止し（「探す値」のマスが一意に決まるため）、小さい順に並んでしまっている配列を「並んでいない場面として成立しない」として弾く。

### 場面2〜6

変更なし。数当てゲーム（場面2〜4）と、ソート済みの主教材を示す場面5・6は従来どおり。

## 基準データ文書との差異

`docs/concept/binary-search-unit-baseline.md` §3 フェーズ1の場面案1は「並んだ7つの数字から 25 を探す場面。端からだと最大7回見ることになる」と書いており、本 PR で場面1の提示が未ソート化により supersede される。基準データ文書自体は書き換えず、差異は本報告に記録する。
