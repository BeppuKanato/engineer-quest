# Issue #142 遷移ボタンの共通化 — 実施記録

実機レビュー（#142）の「次に進むためのボタンがフェーズごとに文章・種類・サイズ・位置が違う。全フェーズで統一する必要がある」への対応。保存レスポンスの指摘はテーマ4（#151）で対応済み。

## 現状調査

遷移ボタンは4か所に別々の実装があった。

| 場所 | 種類 | 文言 |
| --- | --- | --- |
| フェーズ1の出口（キャンバス内） | outlined | フェーズ2へ進む |
| フェーズ2・4（プレイヤー操作バーの endAction） | contained（高さ44） | 理解度を確認する／コードの確認問題へ進む |
| フェーズ3・5の後のリザルト画面 | contained（高さ44） | 次のフェーズへ進む |
| フェーズ6の診断画面 | contained（高さ44） | フェーズ7：自力実装へ進む |

## 対応

1. **共通部品 `PhaseNextButton`**（`front/src/features/learning/app/PhaseNextButton.tsx`）を新設し、上記4か所すべてをこれに置き換えた。contained・高さ48・太字・背景 `playerTokens.focus` で統一する。置かれる場所（操作バー／リザルト／フェーズ内）は各画面の既存レイアウトに従うが、ボタンの見た目は同一になる。
2. **文言は「次の段階の正式名称＋へ進む」で統一**し、手書きの `nextLabel` を廃止して `unit.content` の `nextPhaseLabel` で導出するようにした。「フェーズ」という語は遷移ボタンから消えた。
   - 1→2: アルゴリズム説明へ進む / 2→3: 理解度確認へ進む / 3→4: コードとの対応付けへ進む / 4→5: 理解度確認（コード）へ進む / 5→6: 応用・総括へ進む / 6→7: 自力実装へ進む
   - 単品プレビュー用のフォールバック文言も「次のフェーズへ進む」から「次へ進む」に変更した。
   - 段階の名称自体の見直し（テーマ2の用語提案）は別途提案中であり、名称が変われば導出のためボタン文言も自動で追随する。

## 追記（PR #157 レビューでの修正）

フェーズ1の出口ボタンは SVG 内の foreignObject に置かれていたため、SVG の拡大率に引きずられて指定より大きく表示されていた（実機スクリーンショットで確認）。ボタンを SVG の外の DOM オーバーレイ（キャンバス右下）に移し、他の遷移ボタンと実寸が一致するようにした。位置（キャンバス右下）は変えていない。

## 検証

- `verify:bfs-unit`（verifyBfsUnitFlow）に、導出ルール（全遷移ラベルが次の段階の正式名称＋「へ進む」であり「フェーズ」を含まない）と、4か所すべてが共通部品を使うことを固定した。
- front の lint / typecheck / build と verify 全17件が成功。DB・シードの変更なし。

## 確認方法（マージ後・ローカル実行時）

1. 単元を通して進める: フェーズ1の終わりのボタン、フェーズ2と4の最終ステップで操作バーに出るボタン、フェーズ3と5のリザルトのボタン、フェーズ6の診断画面のボタンが、すべて同じ見た目（青い contained・同じ大きさ）で、文言が「〜へ進む」形式に揃っていること。
2. どのボタンにも「フェーズ」という語が出ていないこと。
