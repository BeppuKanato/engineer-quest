# ユーザ向け用語の付け替え（テーマ2）— 実施記録

実機レビュー #140・#142・#149 の用語論点への対応。提案ドキュメント（Drive「2026-11-06_ユーザ向け用語-提案」）のセットが 2026-11-06 に採用され、そのまま実装した。対象は画面に出る文字列と実績シードの文言のみで、内部の識別子（bfs-check など）・教材指針や Issue の「フェーズN」表記は開発用語として変更していない。

## 1. 段階の表示名（共通名）

| 段階 | 変更前 | 変更後 |
| --- | --- | --- |
| 1 | 動機づけ | 導入 |
| 2 | アルゴリズム説明 | 動きの説明 |
| 3 | 理解度確認 | 動きの確認問題 |
| 4 | コードとの対応付け | 動きとコードの対応 |
| 5 | 理解度確認（コード） | コードの確認問題 |
| 6 | 応用・総括 | 応用問題 |
| 7 | 自力実装 | 自分で実装 |

- 定義は `unit.content.ts` の `formalName` / `shortName` に集約されている（チップ等の短縮名は正式名から素直に縮めた形）。遷移ボタンの文言は #157 以来 `formalName` から導出されるため、自動で追随する（例: フェーズ1の出口は「動きの説明へ進む」）。
- この名称セットは BFS だけのものにせず、DFS 以降すべての単元の共通名とする（2026-11-06 決定）。`docs/concept/dfs-unit-baseline.md` §0.1 にもその旨を明記した。
- 段階名セットそのものを `verify:bfs-unit` で固定した。

## 2. 「フェーズ」を画面に出さない

- 単元画面の進捗: 「フェーズ 3/7 完了」→「3 / 7 完了」。段階ボタンの読み上げは「3. 動きの確認問題：完了」の形式に。
- リザルト見出し・到達状況の行は名称のみ（「1. 導入」の形式）。
- 次予告: 「次はフェーズ4『コードとの対応付け』です」→「次は『動きとコードの対応』です」。
- 単元内ナビの見出し: 「単元のフェーズ」→「この単元の流れ」。
- 各段階内の文言: 復習リンク「この処理の動作（フェーズ4）をもう一度見る」→「この処理の動きをもう一度見る」、フェーズ6の復習リンクも「（フェーズ4）」を外した。完了文の「」「」は新名称に置換。
- テストケースのラベル: 「基本（フェーズ2のグラフ）」→「基本（動きの説明のグラフ）」、「転移（フェーズ6のグラフ）」→「転移（応用問題のグラフ）」。
- 知識カード画面のチップ: 「フェーズ完了時に獲得」→「学習の区切りで獲得」。

## 3. 実装画面（段階7）の用語

- 「フリー実行（print）」→「試しに実行」。状態文は「試し実行」に揃えた（「試し実行はテストの通過数・実行回数には含みません」など）。
- 「表示用グラフ」→「基本グラフ」（同じ画面で既に使っていた語に統一）。トレース表示の「表示用のグラフ」も同様。

## 4. 実績シードの文言

- `back/prisma/seedData/achievementSeed.ts` の実績名・説明も新名称に合わせた（「自分で実装クリア」「応用問題 初回満点」「確認問題 初回全問正解」など）。
- 注意: これはシード変更であり、マージ・デプロイだけでは画面に反映されない。対象 DB へのシード再実行が別途必要。

## 検証

- front の lint / typecheck / build と verify 全16件が成功。`verify:bfs-unit` に段階名セットの固定を追加し、`verify:bfs-code-check` の文言契約を更新した。
- バックエンドはシードの文字列のみの変更で、CI の結果で確認する。

## 確認方法（マージ後・ローカル実行時）

1. 単元画面: 進捗が「0 / 7 完了」形式になり、段階名が新しい名称（導入・動きの説明…）で並ぶこと。
2. 学習画面: 上部チップ、リザルト見出し、次予告、遷移ボタンに「フェーズ」が出ないこと。
3. 段階7: 実行ボタンが「試しに実行」になり、グラフの呼び方が「基本グラフ」に統一されていること。
4. 実績（シード再実行後）: 実績名が「自分で実装クリア」「応用問題 初回満点」などになっていること。
