# 穴掘り法 フェーズ6（応用問題）（Issue #262）

目的: 穴掘り法単元のフェーズ6を、基準データ §3 の4問（転移タップ1問・選択2問・Parsons 1問）として実装する。設計は基準データ（docs/concept/maze-digging-unit-baseline.md §3、正本は基準データ取り込み PR #267 で別途進行中のため、本実装はその承認済み原本に従う）と教材指針フェーズ6節に従う。最終確認日: 2026-11-07。本 PR は feat/maze-digging-phase5-261（PR #272）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/maze-digging/consolidation/` に types / content / Preview / README.md を新設（構成は棒倒し法フェーズ6と同型）。
  - Q1 `transfer-dig-target`（転移・タップ）: 転移用 7×7 の途中状態（掘削5回目まで、現在マス (3, 5)）で「左へ掘ります。掘られる部屋はどれですか」。正解は (1, 5)。場面は組み立て済みトレースの5回目の掘削直後の壁集合（38マス）とスタック経路から作り、回答対象はフェーズ3と同じくアルゴリズムが実際に集める候補（2マス先が盤内かつまだ壁のままの部屋、提示順で右 (5, 5)・左 (1, 5)）に限る。方向は基準データ §6-6 のとおり問題文の中で提示し、棒倒し法のような独立した方向フィールドは持たない（単元のフェーズ3で決めた形を踏襲）。
  - Q2 `completed-maze-properties`（転移・選択）: 完成した迷路の性質を選ぶ。正解は「すべての部屋が通路でつながっていて、輪がない」。場面はフェーズ2の完成ステップの盤面を参照のまま使う。棒倒し法と同じ観点で、作り方が違っても性質は同じことを問う。4つ目の選択肢は数の観点の誤答（掘った回数15は部屋の数16と等しくない）にした。
  - Q3 `backtrack-reason`（推論可能なエッジケース・選択）: 行き止まりでバックトラックが必要な理由を選ぶ。正解は「掘れる部屋がもうなく、戻らなければ残りの部屋にたどり着けないため」。場面はフェーズ2で行き止まり (5, 1) を掘った直後の盤面（`dig-6`）を参照のまま使う。復習先はフェーズ4で候補が空と判定して `stack.pop()` で戻るフレーム列（`if-candidates-7` → `else-branch-7` → `pop-stack-7` → `execution-backtrack-1`）で、戻り切った時点のチェックポイントが `pop-stack` 行に対応する。
  - Q4 `whole-code-order`（Parsons）: 参照コード（契約 maze-digging-v1、22行）すべての並び替え。インデント提示あり、妨害行なし。基準データ §3 のとおり行の順序はすべて意味を持つため、順序自由な行は設けない（棒倒し法の外周書き込みのような例外なし）。
  - 復習先は全問フェーズ4（コードとの対応）のフレームのみで、新しい盤面の答え合わせは作らない（教材指針フェーズ6の割り切り仕様）。Q1の復習は主教材で左へ掘る6回目の掘削のフレーム列。
  - 進行・診断は共通エンジンの統一仕様（回答では進まない／正解でロック／ソフトゲート／結果・診断は初回回答のみ）。Preview は単元フロー向けに embedded / onComplete / onNext の接続ポートを持ち、未指定なら単品ページとして動く。
- 単品プレビュー: `/learning-preview/maze-digging-consolidation`。

## 留保（判断が必要な点）

- Q2の4つ目の選択肢は、棒倒し法フェーズ6の数の観点の誤答（「伸ばした壁の数は柱の数より多い」）に対応させ、「掘った回数は、部屋の数と同じである」とした。基準データは性質問題の観点（つながっている／輪がない）のみを指定しており、選択肢の文面自体は指定されていない。
