# ミッション提示（ストーリーゲート）の実装（Issue #505）

目的: Issue #505 として、単元ミッションの提示の仕組みと、バブルソートのストーリーを実アプリに実装する。適用範囲はフロントエンドの提示層と教材コンテンツ（バブルソート分）。最終確認日: 2026-11-23。
正本・前提: [redesign-ui-policy-2026-11.md](redesign-ui-policy-2026-11.md) §7、[redesign-overview-2026-11.md](redesign-overview-2026-11.md) §2.1。完成形の画像は `ui-targets/mission-story.png`。

## 実装内容（仕様）

### 仕組み

- 入口は3つ：コースカードの「どんな問題を解く？」ボタン、単元バンドの同ボタン、未着手単元の学習開始時のゲート。どの入口からも同じ提示を開く。自動で割り込み表示はしない（学習開始時のゲートは開始操作に付随する状態として出す）。
- 提示はコマ送りのストーリー。各コマは場面図＋短い文。最後のコマに達成の条件と「学習を始める」を置く。スキップできる。
- 「見た」記録は、最後のコマに到達したときだけ付ける（途中で閉じたら付けない）。ゲートは未着手かつストーリー未見かつ復習でないときにだけ出す。
- ゲートのヘッダーと単元バンドに目標フラグ（その単元ミッションを自分の目標として採用するトグル）を置く。目標は重ね付けであり、ゲートにはしない。
- フェーズ1の最初のキャプションに、ミッション場面へつなぐ半文を入れる（redesign-overview §6-1。ストーリーの世界からフェーズ1の世界へ切り替わる接続を作る。全単元が対象だが、本 Issue ではバブルソートに適用し、他単元は各単元のストーリー実装時に同じ規則で入れる）。

### バブルソートのストーリー（6コマ、内容確定済み）

1. 場面：図書室の本棚。本の番号がバラバラに並んでいる
2. 困りごと：本を頼まれるたびに端から探すことになる。それが毎日来る
3. 解決の方向：番号順に並んでいれば、探すのは一瞬で済む
4. 人間なら：棚を見渡して、だいたいの場所に置くことができる（根拠：Norman et al. 2003。人間は線形の修正バケットソートに近い方法を使う）
5. 問い：機械には「見渡す」「この辺」ができない。どうすれば並べ替えられるか
6. 締め：方法を見てみましょう。最後は自分のコードで並べ替えに挑戦する

### 物語の規則（他単元を書くときの基準）

- コマ数は固定しない（拍の数で決める）。
- 困りごとと解決の対象は同じ物にする。
- 「人間ならできる」類の主張は、根拠を確認してから書く（想像で書かない）。
- 物語は問い（課題）で終える。手順（解法）は述べない。

## 確認方法

1. コースカード、単元バンド、学習開始ゲートの3入口からストーリーが開くことを確認する。
2. 最後まで進めると「見た」記録が付き、途中離脱では付かないことを確認する。
3. スキップして学習を開始できることを確認する。
