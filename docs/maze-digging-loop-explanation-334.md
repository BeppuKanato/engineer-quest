# 穴掘り法フェーズ2への輪の説明ステップ追加（Issue #334）

目的: 棒倒し法（PR #324）で入れた「輪」の説明に対応する説明を穴掘り法にも入れ、「未訪問の部屋にだけ掘るため輪ができない」理由をフェーズ2で学べるようにする。最終確認日: 2026-11-09。

## 問題（ユーザー指摘 2026-11-09）

- 棒倒し法には輪の実演（説明専用ステップ `loop-what-if`）があるが、穴掘り法には輪に関する説明がなかった。
- 穴掘り法の完成ステップは「輪がなく」と述べるだけで、なぜ輪ができないのか（掘り進める先が未訪問の部屋だけであること）は言語化されていなかった。

## 実装

- フェーズ2は 21 → 23 ステップ（コード対応21＋説明専用2）。自動再生は 3500ms/ステップで約74秒→約81秒。
- 説明専用ステップを完成の後に2つ追加した（`explanationOnly`、ガイドライン §2-6。棒倒し法 PR #324 で導入した共有の仕組みをそのまま使用）。
  - `no-loops`: 完成盤面そのもの（旗・経路なし）で、「掘り進める先はまだ掘っていない部屋だけなので、通路に輪はできず、どの部屋へも道は1本だけです。」と理由を述べる。「道は1本だけ」は全域木カード（EPIC／フェーズ7）の「経路がちょうど1つだけある」へつながる表現だが、カード本文の複写は避け、フェーズ2時点の語彙で述べた。
  - `loop-what-if`: 仮定盤面の実演。完成グリッドから決定的に作り、間の壁を1つだけ余分に掘る。もとの一本道（両側の部屋の間の最短路7マス）と新しい道で輪が閉じることを、経路の線（元の道＋掘った間の壁）で示す。掘った2マスは通常の掘削ステップと同じ highlight、掘り先の部屋が処理中。バリデータの扱い: この盤面は既存の穴掘り法検証（処理中は通路マス、highlight は壁でないマス、target は null、path は通路のみ・隣接・再訪なし）をそのまま通るため、検証器の拡張はしていない。具体的なマスは検証スクリプトで固定している。
- フェーズ4のチェックポイント契約を、棒倒し法と同じく「フェーズ2の全ステップ」から「コード対応ステップ（`codeMappedSteps`、説明専用を除く21）を順序どおり」に改訂した。説明専用ステップがチェックポイントに現れないことを検証で明示する。フェーズ4のフレーム数（669）と内容は不変。

## 検証

- `verify:maze-digging-code-mapping`: チェックポイントがコード対応21ステップと一致し、説明専用ステップを含まないことを確認。CPython トレース突き合わせは従来どおり全フレーム通過。
