# 主流レイアウト移行の記録（Issue #298）

- 目的: Issue #298「グラフサイズの変化」への対応として行った、学習画面のレイアウト移行（全5弾）の全体像と、置き換えた旧契約を記録する。
- 最終確認日: 2026-11-09
- 正本: Issue #298 と 2026-11-09 のユーザー承認（設計と矛盾レジスタ C1〜C10）。新しい方針の正本は [concept/learning-player-ui.md](concept/learning-player-ui.md) §5。

## 背景

- 設問画面では図が「残り高さ」を受けて拡縮していたため、テキスト量（通知・誤答後の注記・選択肢の折り返し）で図の大きさが変わっていた。
- 結果画面は画面ごとに自前のスクロール領域を持ち、単元コンテナのラッパーと合わせて二重スクロールになっていた。
- 大原則として「図の大きさは設問とビューポートだけで決める」を置き、一般的な Web 画面の形（上部固定＋中央スクロール＋下部固定）へ移行した。あわせて旧方針「操作はスクロールなしで1画面」を「進行ボタンは固定ゾーンで常時表示し、本文は中央領域でスクロールしてよい」へ置き換えた（C1）。

## 置き換えた旧契約

- #337 の安全な中央寄せ（marginTop auto）: 質問画面では廃止。結果画面の中央寄せはスクロール列の中で再現する形に置換（C3・C7）。
- #339 の図の上限方式（flex ＋ maxHeight で圧力時に縮小）: 固定高へ置換（C2）。
- #320 の Parsons 窓（残り高さ＋下限276px）と「画面スクロールなしで収まる」受け入れ文言: 固定高368px＋下限276px へ置換（C4）。#337 の他の要素（濃色カーソル、共有エディタテーマ、盤面の下限）は維持。
- #321 のフェーズ5レイアウト（コード窓＝残り高さ、問題文は上部固定）: コード窓は固定高320px、問題文は中央領域へ（C5）。結果画面へ直行する遷移と、保存成功後にフィードバックをマウントする契約は不変。
- #323 でラッパーが担った役割のうち、結果系画面の単一スクローラとしての役割は維持し、質問画面では中央領域がスクロールを担う形に分担を明確化（C6）。背景色（#303）の役割は不変。

## 単品プレビューの同型性

- 単品ページ（`/learning-preview/[contentId]`）は各プレビュー部品をそのまま描画するため、第2〜4弾の変更で自動的に同じ骨格になる。ステージ寸法（84dvh・下限）は従来どおり。
- 単品表示時の「直前の回答」通知は各プレビューの中央領域の先頭に置く（単元内では単元コンテナの固定ゾーン）。骨格そのものは同一である。

## 残る確認事項

- 実機（実効約1093×614）での受け入れ確認はユーザー側で行う: 通知表示＋誤答後に図の大きさが変わらないこと、進行ボタンが常時押せること、結果画面のスクロールバーが1本だけであること、Parsons 窓 368px とコード窓 320px の体感。
- DFS のプレビューは単元接続（Issue #129）の時点でこの骨格へ合わせる（learning-player-ui.md §5.2 に明記）。
- 教材指針（Drive 側）への §2-5・§2-6・§7-4 の反映待ちとは別件として、本移行は教材指針の改訂を要しない（C9）。
