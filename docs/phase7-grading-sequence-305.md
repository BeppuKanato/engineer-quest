# フェーズ7の採点シーケンス表示（Issue #305、案A'）

目的: フェーズ7「自分で実装」のテスト結果の見せ方を、ユーザーレビュー #305 と 2026-11-08 の擦り合わせで決まった案A'（採点シーケンス型）に変える。あわせて「配列で動きを見る」等のトレース取得が一時的な CDN 読み込み失敗で使えなくなる脆さを緩和する。
最終確認日: 2026-11-08

## 問題（変更前）

- テストは元々1件ずつ逐次実行され、結果も1件ずつ流れ込んでいたが、結果は右パネルの「テスト」タブの中だけにあり、コンソールタブを開いていると採点の進行に気づけなかった。
- 1件ごとの通過に音の手応えがなかった。
- 全通過した瞬間のレンダリングで画面全体が完了ビューに置き換わり、さらに進捗保存が終わると単元最終結果へ自動遷移した。このため「5/5 本通過」の一覧は実質見えず、完了ビュー自体も保存 API の応答時間しか表示されなかった。

## 変更内容（案A'）

対象はフェーズ7プレビューを持つ5単元すべて（BFS／バブルソート／棒倒し法／穴掘り法／二分探索）。各単元の `implementation/*ImplementationPreview.tsx` は命名差を除き同一構造のため、同じ変更を一貫適用した。各単元の単元コンテナ（`unit/*UnitPreview.tsx`）も同様。

1. テスト実行時は結果パネルを前面化する。タブ切替（`setPanel("tests")`）は従来から実装済みだったため維持し、小さい画面でサイドパネルが画面外にある場合にテスト実行中もパネルへスクロールするよう既存のコンソール用処理を拡張した。
2. テストが新たに通過するたび、既存の効果音 `answerCorrect`（確認問題の正解音と同じもの）を鳴らす。新規アセットは追加していない。通過数の増加を `useEffect` で検知する。
3. 全通過してもワークスペースを完了ビューに置き換えず、最終結果へも自動遷移しない。
   - 紙吹雪と歓声は `ResultConfetti`（フェーズ結果と同じ phase プリセット）を全通過時に発火する。1件ごとの紙吹雪はしない（賞賛の勾配：小さい達成は小さく、フィナーレだけ大きく）。
   - 達成バナーはエディタのコード領域右上へのオーバーレイ表示（`data-completion-banner`）とし、レイアウトには一切影響させない。全通過の前後でエディタ寸法は同一であること（ユーザーの明示懸念への対応）。
   - バナーには単元名入りの達成見出し、締め文、テスト実行回数と、「単元の結果を見る」ボタンを置く。ボタンは単元コンテナから渡す `onShowFinalResult` を呼び、従来の自動遷移と同じ `setScreen({ kind: "final" })` を学習者の操作で実行する。
   - 単元コンテナの `handleComplete` は、フェーズ7（transition "final"）で自動遷移しなくなった。進捗保存、要約・完了状態の記録、最終結果画面の表示内容は従来どおりで、ボタンで遷移したときに完了が反映される。フェーズ3・5・6の結果画面がボタンで進む既存パターンに揃えた形。
   - 単品プレビュー（単元コンテナなし）ではボタンは出ず、バナーのみ表示する。
4. 各単元の `implementation.content.ts` の `result` に `finalButton: "単元の結果を見る"` を追加した。
5. 検証スクリプトの追随: 各単元の `verify:* -implementation` が固定していた旧完了ビューの契約（`DrawnCheck size={76}` の完了ビュー先頭表示）を、案A'の契約（バナーのオーバーレイ表示、`DrawnCheck size={44}`、ボタン遷移、通過ごとの確認音）に書き換えた。

## トレース取得の読み込みリトライ

- トレース取得（`*/trace/acquireTrace.ts`）は単元共通で、採点用入力を持ち込まないため毎回 Worker を作り直し、Pyodide を CDN から冷再読込する。この読み込みが一時的に失敗すると「実行環境を読み込めませんでした」になっていた（#305 のスクリーンショット左下の文言が実体）。
- 対策として共有層 `front/src/lib/pyodideRunner.ts` の `preparePyodide` に一度だけ再試行を入れた。失敗した Worker は失敗した `readyPromise` を保持し続けるため、再試行前に `disposePyodideRunner()` で作り直す。タイムアウトは読み込み失敗ではないので再試行しない。Worker のライフサイクル自体（トレースごとの作り直し＝判定入力の分離）は変更していない。
- この変更はフェーズ7プレビューのマウント時準備や作る画面など `preparePyodide` の全利用箇所に効く。

## 見送った指摘（判断理由）

- 図の高さの不統一（テストタブ 210px／コンソールタブ 260px）: バブルソート固有ではなく、5単元すべてで「テスト図 210／試し実行の戻り値図 260」という同じ配分になっており、単なる定数ミスではなく共通の規約と読めるため、本 PR では変更せず留保として残す。統一したい場合は全単元の規約変更として別途判断する。
