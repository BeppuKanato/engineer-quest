## 判定

「助かった」は、本人が著者の投稿に付いた他者のSAVED_MEだけを数える。別の人の投稿、自分自身の反応、LIKE、HELPFULは対象外とする。「もらう」という条件を自己反応で満たさないようにした。

復習は本人のDailyReviewの回答済み行だけを読む。日本時間の日付が保存されたreviewDateのうち、直近の復習実施日を起点に、正解が続く日をさかのぼる。不正解・日付の欠落で途切れる。出題済みでも未回答の行は実施日に含めない。起点は今日ではなく直近の実施日なので、実施から時間が経っただけではその記録を失効させない。月・年・うるう日をまたぐ連続にも対応する。

エピックは本人のUserKnowledgeCardとKnowledgeCard.rarity=EPICの対応を数える。他者の所持やレア以下のカードでは成立しない。

自己ベストは、本人の提出履歴をクエストIDごとにまとめ、提出日時順に過去最高点を更新した回数を計算する。初回は基準点とし、同点・低下・別クエストの初回は更新にしない。直前の点数ではなく過去最高と比較する。過去に更新した事実は、その後低い点数を提出しても失わない。同一時刻の提出群は前後を推定せず、その群の最高点を使う。初回群の中だけで点数が上がっていても解除せず、厳密にそれより前の提出との比較で判断する。

条件用の追加参照は、その条件タイプが実績定義にある場合だけ行う。判定処理がDailyReview・学習進捗・学習イベント・評価証拠へ書き込むことはない。

## 非表示と解除のタイミング

現行の一覧APIには未解除シークレットを「???」として返す経路があったため、Issueの受け入れ条件を優先し、実績一覧とコレクションから未解除の行そのものを除外した。件数にも含めない。通常50件だけの状態では50件、4件をすべて解除すると54件が見える。

ホームの今日の狙いは#483の未解除・非シークレット条件を維持し、API側の非表示でも除外される。復習が2/3日のシークレット進捗を持つ状態でも表示されないことを検証した。シークレットを目標に設定する既存の禁止も維持する。解除後は通常の実績と同じように題名・説明・条件を表示し、既存の共通解除表示へ渡す。

評価の呼び出し箇所は追加していない。条件を満たした後、フェーズ完了・単元完了・作る提出など既存の評価が次に走ったときに解除される。掲示板の反応や復習回答の直後に、新しい評価や演出を追加するものではない。解除済みの記録は、反応の取り消しや後の復習不正解で取り消さない。

コレクションの最近の獲得では、従来の英語レアリティを共通の日本語ラベルへ置き換えた。共通解除表示・解除音の実装は変更していない。

## DB適用と未実施

今回、local・dev・productionのいずれにもDB操作はしていない。対象環境を明示・確認したうえで次の順に手動適用する。

1. backで `npx prisma migrate deploy` を実行し、`20261120010000_add_secret_achievement_conditions` を適用する。
2. 更新schemaで生成したPrisma Clientと新しい評価器を含むコードをデプロイする。
3. backで `npm run seed:preserve` を実行する。通常seedの削除同期は使わない。

新しい条件を含むseedは、更新コードを配置してから適用する。保持seedは既存の学習・所持・解除履歴を残すが、カードや教材など他の全マスタも更新するため、適用コミットを確認する。マージ・Cloud RunのCDだけではmigration・seedは適用されない。

実DBでのmigration・seed・解除確認、Firebase認証とCloud Runを通すE2E、実際の解除音の再生確認は未実施。
