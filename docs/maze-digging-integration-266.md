# 穴掘り法 アプリ統合（コース・カード・実績のシードと単元登録）（Issue #266）

目的: 穴掘り法単元（フェーズ1〜7は #257〜#263、視覚デバッグは #264、単元接続は #265）をアプリ全体へ統合し、コース一覧・ホーム・コレクション・実績で BFS と同等に扱えるようにする。マスタデータの正本は基準データ（`docs/concept/maze-digging-unit-baseline.md`）§5。最終確認日: 2026-11-07。

## 実装内容

- コースシード（`back/prisma/seedData/courseSeed.ts`）: `course-algorithm-maze-digging-v1`「穴掘り法」を追加。難易度 EASY、当初から解放・公開、version 1、カテゴリは GAME + ALGORITHM（基準 §5 の暫定判断どおり）。説明文は BFS・棒倒し法の書式（学ぶ内容＋前提知識）に合わせた。
- 知識カード（`back/prisma/seedData/knowledgeCardSeed.ts`）: 基準 §5 の3枚を追加。
  - バックトラッキング（RARE、フェーズ2 `maze-digging-execution` で配布）
  - スタック（COMMON、フェーズ5 `maze-digging-code-check` で配布）
  - 全域木（EPIC、フェーズ7 `maze-digging-implementation` で配布）
  - 配布スケジュールは BFS と同じテーブル表（15テーブル、平均約6割出現）を単元ごとに生成する形（`buildCardPhaseSchedule`）へ一般化した。BFS 分のスケジュール ID・内容は変更していない（後述の検証でダンプのバイト一致を確認）。
- 実績（`back/prisma/seedData/achievementSeed.ts`）: BFS と同じ構成の6件を追加。単元クリア（`ach-unit-maze-digging-complete`）、フェーズ7クリア、確認問題の初回全問正解、応用問題の初回満点、ノーヒントクリア、カードコンプリート（`ach-maze-digging-card-complete`）。
- 検証の汎用化（`back/src/scripts/verifyCollectionMasterData.ts`）: 「BFS の3枚だけが現行プール」「コース数7」などの BFS 前提を、カードを持つ単元ごとの検証へ一般化した（コース数8、カードは単元ごとにスロットと対応、スケジュール表は単元ごとに15テーブル、フェーズキーは実績のコース範囲で照合）。
- サムネイル（`front/src/app/courses/component/courseThumbnail.tsx`）: `course-algorithm-maze-digging-v1` の代表図（`MazeDiggingFigure`）を追加。教材と同じ主教材 9×9 の完成迷路（壁50マス・通路31マス、基準データの検証済み盤面）を縮小描画し、フェーズ1で示すスタート (1,1) → ゴール (7,7) の一本道（17マス）を重ねた。これにより単元一覧・ホームのカードと単元概要画面の背景図に、BFS と同経路で図が出る。
- 学習画面側の登録（unitRegistry）は #265 で完了済みであり、本 PR での追加作業はない。

## 判断と留保

- カードの sortOrder は 10〜12 とした。この系統では BFS の 1〜3 のみが存在するが、回収 PR #253（棒倒し法 4〜6）・#254 系統（バブルソート 7〜9）とも衝突しない値を選んだ。
- 実績の sortOrder は BFS の値 +3（113 / 323 / 333 / 343 / 353 / 413）とした。#253 の棒倒し法分は +1、#254 系統のバブルソート分は +2 であり、3単元分が合流しても一意になる。
- サムネイルの図の部品名は `MazeDiggingFigure` とした（#253 の棒倒し法分は `MazeFigure` で、合流時の識別子衝突を避けた）。
- 実績のうち全体カウント系（`ach-unit-count` の [1, 3, 7] 等）は既存実績の条件であり、本 PR では変更していない。なお `ach-knowledge` の最終段階はカード総数から自動で決まるため、この系統では6枚に追随する。
- カードの label・本文（description / connection / useCase）と実績の説明文は、基準 §5 の「内容」欄を正本とし、BFS カードの文体に合わせて書き起こした。文言の最終確認はレビューに委ねる。
- シードファイル（knowledgeCardSeed.ts / achievementSeed.ts / verifyCollectionMasterData.ts）は回収 PR #253・#254 でも変更されている。合流時の統合はメイン側で行う前提で、本ブランチ側の整合のみを担保した。一般化のパターン（`buildCardPhaseSchedule` と単元ごと検証）は #253 と同型にしてある。
- サムネイルの迷路図はこの環境でブラウザ実機の目視確認をしていない（壁配置と経路は基準データの検証済み盤面から算出し、壁50マス・通路31マス・経路17マスが検証済みの数値と一致することを確認済み）。デプロイ後の実機確認をお願いしたい。

## DB 適用の要否

- **マージ後に開発 DB へのシード再実行が必要**。CD はコードのみをデプロイし、シードは自動適用されない。本 PR のコードだけでは、コース一覧に穴掘り法は現れず、カード・実績も付与されない。シードは既存マスタの upsert と新規分の追加であり、BFS 分の既存データは変更しない（`verify:seed-preservation` の保持ポリシーの対象範囲内）。

## 検証

- `verify:collections`（コレクションマスタ検証）: 本 VM では Prisma Client が生成できない（エンジン取得不可）ため、schema.prisma から列挙値を読み込むスタブで同じ検証スクリプトを実行し、PASS を確認した（8コース、36実績、6カード、スケジュール54行）。あわせて一般化の前後で BFS 分のスケジュール（27行）のダンプがバイト一致であることを確認した。正式な実行は CI（`verify:static`）が正本。
- `verify:seed-preservation`: PASS（スタブ併用）。
- `verify:feedback-v1`: PASS（スタブ併用）。
- `verify:create-quests`: ベースブランチ（`feat/maze-digging-unit-265`）でも同一の失敗（参照解の実行環境起因）であり、本変更の影響ではないことを確認した。
- back typecheck: エラー署名の集合がベースブランチと一致（差分は同一の既存 TS2307 の相対パス表記のみ。新規エラーなし。既存分は Prisma Client 未生成に起因し、変更ファイルにはエラーなし）。
- front: 全 verify（49件）通過、lint エラー0件（警告3件はいずれも既存の単元プレビュー内の exhaustive-deps で、本変更ファイルにはなし）、typecheck / build 通過。

## 確認方法

1. 開発 DB へシードを再実行する（ユーザーの手元作業）。
2. 単元一覧とホームを開き、「穴掘り法」のカードに迷路のサムネイルが表示されることを確認する。
3. 穴掘り法の単元概要画面を開き、背景図に迷路が出ること、実績プレビューに穴掘り法の実績が並ぶことを確認する。
4. 穴掘り法の単元を通し、フェーズ2・5・7の完了でカード（バックトラッキング／スタック／全域木のいずれか、テーブルにより変動）が付与され、コレクション画面に未所持分がシルエット＋「？？？」で並ぶことを確認する。
5. 単元完了時に「穴掘り法を修得した」などの実績が解放されることを確認する。
