## 実装

### 生成と入力

- `feedbackV1.engine.ts`: 同じモデルを異なる役割で順番に2回呼び出す。①は現在の状態・理解・改善点・不確実な点・根拠IDと事実を出力。②は分析・根拠を引き継いで目標・一歩・推薦を出力する。
- ①にはHEXAD・ゲーム状態・掲示板・推薦候補を渡さない。コース内の全Activity回答、全演習試行、または当該「作る」課題の全試行を取得する。累計学習時間・滞在時間を能力推定入力にしない。
- ②には①の生の全回答ログを再送しない。全公開コースの既存ロードマップ、公開「作る」課題の概要・進捗、獲得カードの説明・関連・用途、公開または獲得済み実績の条件・進捗、XP・レベル、全公開投稿・全返信、実験割当以降の推薦・反応履歴を渡す。
- 掲示板や回答・試行履歴に件数制限・独自の要約を加えていない。投稿者・返信者は本人か否かだけを渡し、ユーザー名やメールアドレスは取得しない。
- STANDARDの②に保存済みHEXADを渡さない。PERSONALIZEDの②だけに質問紙版、4〜28の得点範囲と6得点を追加する。過去推薦ログのHEXAD適応記録は共通履歴から除く。
- PERSONALIZEDは6得点の正確な複写、解釈、選択への反映、目標・一歩・理由の表現調整、学習上の根拠、反映の限界を記録。行動ID・対象ID・全6得点の一致を検証する。適応の客観的正しさを保証するものではない。

### 推薦と表示

- 共通の22行動を定義し、実行可能な対象がない種類を事前に除く。各種類の全対象IDを残し、特定の教材を先に1件へ絞らない。
- Missionの解放・公開状態は既存ロードマップ判定を再利用。カードは公開・獲得済み、目標実績は非秘密・未獲得・現目標以外、返信先は他者の公開投稿に限定。
- 生成後に許可行動と対象IDを検証し、さらに最新状態でも再検証する。URLはシステムが構築し、モデルに生成させない。
- 通常Missionの報酬結果ページに自動表示を追加。コース末尾演習は既存の3区分表示を自動表示に変更。「作る」も既存表示へ接続し、再訪時に保存結果を取得する。
- カード推薦では該当カードの詳細を開く。実績推薦では該当シリーズを選択。投稿返信にはフォームの実アンカーを追加した。
- 既存の採点、教材、学習進行、報酬、実験割当レコードは変更しない。developに含まれる実機レビュー対応済みの二分探索・DFS・KMP等の教材修正は維持した。

### 保存と観測

- Prismaの`FeedbackV1`、`FeedbackV1Call`、`FeedbackV1Interaction`と追加用マイグレーションを管理。
- イベントキーは`mission:<MissionRewardRun.id>`、`create:<CreateQuestSubmission.id>`。DBの一意制約で重複生成を防ぐ。同一イベントは保存結果を再利用し、旧テーブルに生成済みの結果があればそれも再利用する。
- 段階ごとの実入力、実出力、モデル応答ID・使用モデル、設定、プロンプト版、トークン情報、処理時間、エラー、検証結果を保存する。再表示用応答から内部分析やHEXAD情報は返さない。
- 仮名IDとして内部User IDを使用し、User削除時は追加ログも連鎖削除する。
- 提示、viewportへの出現、クリック、行動先選択、表示成功・失敗、前面滞在時間、生成結果の再利用を区別する。viewport観測は読了確認ではない。
- 到達ログは遷移先のデータ・画面状態を正常表示した後に送る。カード一覧の表示だけでは特定カードへの到達にしない。ログには共有コードや本文等の任意クエリを複写しない。
- `summarizeReaction`は最初の選択と対応する到達だけを照合する。後から一致する行動を探さず、表示失敗・ログ欠測・順序が曖昧な場合はPENDINGとする。再提示回数とは別に推薦ID単位で提示有無を判断する。

## 実装時に選択した扱い

- 推薦は1件。モデルの既存既定値`gpt-5.4-mini`／`OPENAI_MODEL`、reasoning effort `medium`を継承。両段階・両条件で同じ設定を用いる。実稼働モデルを確認したという意味ではない。
- 無効出力・呼び出し失敗はFAILEDとして保存し、偽の推薦や自動代替教材を出さない。自動再生成しない。通常Missionには失敗表示と学習継続の導線を残す。
- 10分を超えてGENERATINGの結果は、次の読出し時に中断・タイムアウトとしてFAILEDへ変更する。リロードを再生成契機にしない。
- 候補0件時は推薦ID・対象IDをnullとするスキーマだが、現状はXP確認等が利用可能なため通常は候補が存在する。
- 事前テストは既存生成入力に存在しなかったため追加しなかった。要件文書の「最終除外判断は未確定」を確定に変更していない。

## 未検証・残る課題

1. **フィードバックの実DB保存・並行実行・操作試験が必要。** Neon devへのmigrationと保持seedは後述のとおり実施済み。生成パイプラインの実DB保存・競合・操作試験は未実施であり、メモリアダプタ試験をその代わりに扱わない。
2. **実モデル・実ブラウザによる3場面×2条件の通し確認は未実施。** 実入力トークン数・費用・待ち時間・推薦偏り・文章の妥当性は測定していない。fixtureの出力品質を実モデルの品質とみなさない。
3. **RQ1計測の網羅性は実機で要確認。** Linkと明示した遷移ボタン、および主要遷移先の成功／失敗表示に計測を加えた。独自の非Link操作、経由画面、同一画面の状態変更、複数タブ、通信中断・離脱時のログ欠測の網羅性は未保証。計測できないケースは非着手へ強制分類しない。セッションをまたぐ観測終了規則も確定していない。
4. 既存DBにない通常Activityのヒント閲覧履歴、すべてのカード閲覧履歴、掲示板の「作る」課題への構造化外部キーは復元できない。存在する記録を渡し、非観測を明示する。新しい推薦到達として観測されたカード閲覧は入力に反映する。
5. 旧フィードバックの対象ID・提示・閲覧・到達ログには欠損がある。生成履歴は含めるが、保存されていない反応を創作しない。旧生成結果をv1で再生成して比較可能なログへ見せかけない。
6. 同一時刻に競合する行動はPENDING。サーバで受信できていない行動がある場合の正しい順序は保証できない。実験集計では欠測確認が必要。
7. 入力全件方針のため、量が大きければモデルの入力上限・遅延に達し得る。独断で間引く処理は入れていない。実データ測定後の方針決定が必要。
8. 事前テストの最終入力方針、上記の失敗時方針・表示文量・モデル版の本実験固定は別途確定が必要。

実験開始可能・本番検証完了とは扱わず、上記の実DB・実機・実モデル確認を残す。
