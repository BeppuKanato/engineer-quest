# 二分探索 フェーズ1（導入）（Issue #286）

目的: 二分探索単元のフェーズ1（導入）を、基準データ §3 フェーズ1の場面案（数当てゲームと「半分に絞る」発想、6場面、用語はまだ出さない）に沿って実装する。設計は基準データ（docs/concept/binary-search-unit-baseline.md §0・§3、正本）に従う。最終確認日: 2026-11-07。

## 実装

- `front/src/features/learning/binary-search/binarySearch.ts`: 単元の実行データを組み立てる正本。参照コード（契約 binary-search-v1）と同じ手順で比較ごとの範囲（lo / hi / mid / 値 / 結果）を記録する `binarySearchProbes`、戻り値を返す `runBinarySearch`、数当てゲームの件数列 `binarySearchHalvingCounts`（100→50→25→13→7→4→2→1）。場面のデータは手書きのベタ書きにせず、この実行記録と検証済み定数から取る。入力は変更しない。
- `motivation/motivation.types.ts`: フェーズ1の Canvas 型。場面ごとの図を3種の判別共用体で表す。
  - `array`: 主教材の並んだ数字。描画は共通配列基盤に委譲する。単元の前提として「小さい順に並んでいる」ことを検証し、強調は「探す値」のマスだけに限定する。
  - `guess`: 1〜100 の数当てゲームの候補の帯。聞いた数と、答えの後に残った範囲を持つ。残った範囲は聞いた数を含まず片側だけに寄ることを検証する。
  - `halving`: 候補の数が半分（切り上げ）ずつ減る件数列。最後が 1 になることを検証する。
  - 出口（`{ label, nextPhase }`）は BFS・バブルソート フェーズ1と同じ形で、数当ての途中の場面には置けないよう検証する。
- `motivation/motivation.content.ts`: 6場面（すべて完全スナップショット、キャプションは1文）:
  1. `find-twenty-five` 主教材 [3, 7, 12, 19, 25, 31, 42] と探す値 25 の提示。「小さい順に並んだ7つの数字から25を探すとき、端から順に見ると最大で7回も見ることになります。」
  2. `guessing-game` 数当てゲームへの切り替え（候補の帯 1〜100、まだ聞いていない）。「たとえば、1から100のうちの1つの数を、『大きい』『小さい』のヒントだけで当てるゲームがあります。」
  3. `ask-middle` 真ん中の 50 を聞き、「もっと大きい」の答えで小さい方の半分が候補から消えた状態（残り 51〜100）。「真ん中の数を聞くと、答えに合わせて候補の半分が一度に消えます。」
  4. `seven-guesses` 件数列 [100, 50, 25, 13, 7, 4, 2, 1] の棒の列。「半分ずつに絞っていくと、100個の候補でも7回で必ず当たります。」
  5. `unit-overview` 主教材の配列に戻り、単元の見通しを提示。「この単元では、並んだ数字から目的の数を素早く見つける方法を、動きの確認からコード、そして自分で実装するところまで順に学びます。」
  6. `main-example-preview` 主教材の予告（探す値 25 を強調）＋ exit（`{ label: "動きの説明へ進む", nextPhase: 2 }`）。「最初の例では、この7つの数字から25を探す動きを見ていきます。」
- `motivation/BinarySearchMotivationCanvas.tsx`: 配列の場面は `player/ArrayDrawing` へ委譲（比べるペア・確定範囲は使わず、探す値だけを強調リングで示す）。数当ての帯は候補セル100個を1行に並べ、聞いた数を処理中（青）、捨てた側を完了グレー、残った候補を未処理（白）で表す。件数列は件数に比例する棒と件数ラベルで表す。色はすべて playerTokens から取り、HEX は直書きしない。出口ボタンは他単元フェーズ1と同じ重ね方。
- `motivation/BinarySearchMotivationPreview.tsx`: 共通 LearningPlayer への入口。単元フロー（接続Issue）向けに任意の接続ポート（embedded / onLearningEvent / active / onComplete）を持ち、未指定なら単品ページとして動く。
- 単体プレビュー: `front/src/app/learning-preview/binary-search-unit/page.tsx`（新規）。フェーズ2以降のプレビューはこのページへ追加していく前提で、現在はフェーズ1のみを表示する。出口ボタンは単品では未接続（無効表示）。
- 用語「二分探索」「インデックス」はフェーズ1では出さない（基準データ §3 の用語計画。名称付けは後続フェーズ）。用語表は日常語（真ん中／候補／半分）と後続フェーズの専門語（中央／探索範囲／半分）の対応だけを持つ。

## 検証

- `npm run verify:binary-search-motivation`: 契約 binary-search-v1 を検証スクリプト内で独立に再実装し、主教材の比較列（19→左を捨てる、31→右を捨てる、25→一致、戻り値 4）、転移用（戻り値 5）、不在ケース（20→-1、比較列が主教材と同じ道）がモジュールの実行記録と一致することを確認。数当て件数列（100 から 7 回で 1）も照合する。場面の状態、キャプションの1文性と禁止用語（「二分探索」「インデックス」「フェーズ」「対数」「バイナリサーチ」）の不在、出口が最終場面だけにあること、単元側検証の負系（並んでいない配列、範囲外の探す値、聞いた数を含む残り範囲、半分になっていない件数列など）、実描画（配列の棒7本と強調、数当てのセル100個・聞いた数・捨てた49個、件数列の棒8本、出口ボタン）、単体プレビューページの存在も確認する。
- 既存の `verify:learning-player`、front の `typecheck`（tsc --noEmit）、新規ファイルの `lint`、`build` も通過。
- DB・シードの変更はない。

## 留保（判断が必要な点）

- 数当てゲームの図（候補の帯・件数列）は共通の配列基盤ではなく、導入専用の図として単元側キャンバスで描いた。基準データ §0・§4 の配列上の状態語彙（探索範囲・中央・範囲外）はフェーズ2の盤面型で扱う前提とし、フェーズ1の配列場面だけを ArrayDrawing の流用に絞った。フェーズ2で盤面型を確定する際に、フェーズ1の帯の表現（捨てた側＝完了グレー等）と揃えるかは要確認。
- 教材指針 §フェーズ1の汎用型（候補比較コマA/B・実用例コマC）とは場面構成が異なる。基準データ §3 フェーズ1の場面案（数当てゲームで半分に絞る発想を体験する構成）が単元の正本として優先すると判断した。
- 単体プレビューは、他単元の `-unit`（[contentId] 動的ルートへの登録）とは異なり、専用ページ `learning-preview/binary-search-unit/page.tsx` として作った（Issue #286 の指定どおり）。登録方法を [contentId] 方式に寄せるかは要確認。
- 共通の ArrayDrawing は棒の下に位置番号（0〜6）を常時表示する（共有基盤の仕様で、バブルソート導入も同条件）。用語としての「インデックス」は文面に出していないが、数字ラベル自体はフェーズ1から見える。
- 場面3の数当ては「もっと大きい」側の答え（小さい方の半分が消える）だけを見せる圧縮をした。逆向きの切り捨ては主教材のフェーズ2で両方向を見せる前提である。
- 場面5（単元の見通し）と場面6（主教材の予告）はどちらも主教材の配列図で、場面6だけ探す値 25 の強調と出口を出して区別した。
