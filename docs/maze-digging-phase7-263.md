# 穴掘り法 フェーズ7（自分で実装）（Issue #263）

目的: 穴掘り法単元のフェーズ7を、基準データ §3 の自由記述課題 `dig_maze(size, choices)`（表示用2件＋判定用3件、全通過が完了条件のハードゲート）として実装する。設計は基準データ（docs/concept/maze-digging-unit-baseline.md §2・§3、正本は基準データ取り込み PR #267 で別途進行中のため、本実装はその承認済み原本に従う）と教材指針フェーズ7節に従う。最終確認日: 2026-11-07。本 PR は feat/maze-digging-phase6-262（PR #273）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/maze-digging/implementation/` を新設（構成は棒倒し法フェーズ7と同型）。
  - 課題: テンプレート（関数定義＋方向リスト＋コメント＋ `pass`）へ自由記述する。契約は maze-digging-v1（フェーズ4の参照コードと一致）。
  - テスト: 表示用 D1（主教材 9×9）・D2（転移 7×7）と判定用 J1（9×9）・J2（7×7）・J3（11×11）。期待グリッドは盤面データの正本 `mazeDiggingMaze` の組み立てから導き、フェーズ1〜6の盤面とずらさない。判定用の入出力・標準出力・生の例外は画面状態へ渡さない。
  - 段階式ヒント4段（教材指針 7-2、順に解放し利用回数を記録）: L1 使う部品（変数の役割説明＋トークンのタップ挿入）／L2 処理の流れ（初期化の後に、`while stack` の繰り返し3ステップを破線枠＋チップ「スタックが空になるまでくり返し」で囲んで示す）／L3 条件とループの骨格（参照コードの意味ID `while-stack`／`if-diggable`／`if-candidates`／`else-branch` の4行を原文のまま）／L4 並び替え前のコード（フェーズ6の Parsons 盤面を練習モードで再利用、採点なし）。差分ヒントは持たない。実行結果にはエラー種別（文法／実行時／結果の不一致／タイムアウト）を常に言葉で併記する。
  - 試しに実行: D1 だけを Worker を作り直して実行し、print の出力と戻り値の迷路を盤面で示す（期待と違うマスは枠＋件数）。通過数・実行回数・完了判定は変えない。
  - エディタは #149 の形式（ライトテーマ＋フォーカス色2px枠＋「Pythonコード」見出し）。全通過時は紙吹雪と大きな描画チェックで完了表示し、単元フロー接続用の embedded / onComplete（要約: テスト実行回数とヒント利用回数）／initialCode / onCodeChange のポートを持つ。
- 単品プレビュー: `/learning-preview/maze-digging-implementation`。

## 留保（判断が必要な点）

- J3（11×11）の判定は、基準データ §6-7 の推奨デフォルトどおり固定 choices の完全一致とした。期待グリッドは参照コードの出力そのものだが、完全迷路の性質を満たすことは検証スクリプトで事前確認している（棒倒し法 J3 と同じ扱い）。
- ヒント3の骨格行は、基準データ §3 の指定（`while stack` の形・候補の条件・候補あり／なしの分岐）に沿って `while-stack`／`if-diggable`／`if-candidates`／`else-branch` の4行とした。候補を集める `for` 行は骨格に含めていない（条件文側に寄せた）。
- ヒント2の流れは基準データ §3 の4ステップをそのまま文面にし、初期化（ステップ1）の後ろの3ステップを繰り返しの枠で囲んだ。棒倒し法フェーズ7のヒント2（ループ内1ステップのみ）より枠内が多いが、穴掘り法では集める→掘る→戻るの3動作すべてが `while` の内側にあるためである。
- 視覚デバッグ（学習者のコードの掘削過程のステップ表示）は基準データ §3 でフェーズ7に含まれるが、本 Issue では接続せず Issue #264 の対象とした（棒倒し法でもフェーズ7実装と視覚デバッグは別 Issue に分けた）。
- 基準データ正本（docs/concept/maze-digging-unit-baseline.md）は PR #267 のブランチにあり、本 PR のツリーにはまだ無い。マージ順によっては README からのリンクが一時的に解決しない（フェーズ1〜6と同じ留保）。
