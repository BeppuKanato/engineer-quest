# 二分探索レビュー修正（Issue #330・#331）

- 目的: ユーザーの実機レビュー（Issue #330 フェーズ2、Issue #331 フェーズ6）で明確だった項目を修正し、判断が要る提案と切り分けて記録する。
- 最終確認日: 2026-11-09

## Issue #331（フェーズ6：応用問題）

### (a) 表示の被り

- 症状: 選択肢の設問で、設問文が「直前の回答」通知に重なり、選択肢の下部も見切れる（Issue のスクリーンショット1枚目）。
- 根本原因: 全5単元の応用問題プレビューが同型で、画面は高さ100%＋`justifyContent: center` の縦フレックス、図の領域は `height: min(54dvh, 600px)`（下限320px）の固定サイズだった。図の高さがビューポート基準で決まるため、通知（約110〜150px）＋設問文＋操作説明＋選択肢（2段）＋進行ボタンの合計がフェーズ領域を超えると、中央寄せのフレックスが上下対称にはみ出し、上は通知へ、下は画面外へ溢れる。はみ出し量は実測の画面（約1917×905）でも約100px規模になる。
- 修正: 図の領域を `flex: "1 1 auto", minHeight: 0, maxHeight: "min(54dvh, 600px)"` へ変更した。余裕があるときの図の大きさは従来と同一（上限が同じ）で、収まらないときだけ図が縮む。あわせて、応用問題で使うキャンバス側の下限320pxが縮小を妨げないよう下限を外した（二分探索の応用問題専用キャンバス、バブルソート・棒倒し法・穴掘り法の確認問題キャンバス＝応用問題と共用、BFS は `ConsolidationGraph` へ `minHeight={0}` を渡す）。確認問題キャンバスの下限を外す変更はフェーズ3の画面にも効くが、320px以上の余裕がある場合は描画が変わらない。
- 適用範囲: BFS・バブルソート・棒倒し法・穴掘り法・二分探索の全5単元（同型のため一括で修正）。各単元の consolidation 検証のプレビュー契約アサーションも新しい形へ更新した。

### (b) lo / hi の定義がない

- 他単元のフェーズ6に変数の凡例（定義行）の既存パターンは無かった。そのため、二分探索の応用問題コンテンツに任意項目 `definitions` を足し、記号が初出になる Parsons の設問に `lo = 探索範囲の左端の位置、hi = 探索範囲の右端の位置、mid = 真ん中の位置` を置いた。表示は操作指示の直下・盤面の直上で、操作要素として1行に収まる。
- 対象は Parsons の設問のみ。他の設問（タップ・文章選択）は本文が「左端／右端／真ん中」と言葉で書かれており、記号は現れないため追加していない。

## Issue #330（フェーズ2：動きの説明）

### (a) ステップ5「ここ」の範囲の強調

- 対象はステップ5 `range-after-drop-left`（「残った範囲はここだけです。」）と、同じ確定盤面のステップ8 `range-single`（「残った範囲は 1 個だけです。」）。
- 盤面のハイライト（強調リング）は、バリデータが「発見セル」と「導入時の探す値」だけに限定しており、範囲の強調には使えない（既存の設計判断を維持）。そこで単元側のセル状態に `remaining` を追加し、描画側で queued（候補のベージュ）へ写すようにした。捨てた部分のグレーとの対比で、残った範囲が図でも判別できる。
- `remaining` の規律はバリデータで固定した: 中央が無い確定盤面でのみ使え、範囲の中はすべて `remaining`、実際に捨てた部分が存在しなければならない（全体や比較途中の盤面には使えない）。
- 波及先は盤面を共有する各所で同じ見た目になる: フェーズ3の Q1 の場面（`range-after-drop-left` をそのまま使う。回答対象の範囲がベージュになるが、正解のマスそのものは示さない）、フェーズ4の該当チェックポイント、フェーズ7トレース再生（変換器の確定盤面も同じ導出に合わせ、正準コードの再生がフェーズ2の11ステップと盤面・キャプションまで一致する検証を維持）。

### (b) ソートが前提であることの説明

- 単元が最初に整列へ依存する導入ステップのキャプションを、「数字が小さい順に並んでいることが前提の探し方で、25 を探します。」へ変更した（1ステップ1文の規律は維持）。フェーズ7トレース再生の先頭キャプション（`trace.content` の `initial`）も同じ文へ揃えた。
- Issue 本文の「最初はランダムな順番になっていていいんじゃない？」は、フェーズ2の構成そのものを変える提案であり、ユーザーの判断待ちのため本 PR では扱っていない（除外を PR 本文にも明記）。
