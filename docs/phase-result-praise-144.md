# 理解度確認リザルトの称賛強化（Issue #144）

- 目的: フェーズ3・5の区切りで、確認問題を解き切った達成を短い演出と事実に即した称賛で伝える。
- 適用範囲: `UnitResultScreen`（両フェーズで共有）。状態: 実装記録。
- 最終確認日: 2026-11-06
- 正本: [Issue #144](https://github.com/BeppuKanato/engineer-quest/issues/144)、[アプリUI/UX方針 §4・5](concept/app-ui-ux-guideline.md)、[教材指針](concept/learning-materials-guideline.md)、[プレイヤーUI定義](concept/learning-player-ui.md)。[カード提示 #147](card-presentation-147.md)より一段控えめにする。
- 起点: 最新develop `fe511de5d834dff5db7fb3f5316613667647ae27` から `feat/phase-result-praise-144` を作成。実装コミット: `6aebae4373cb3fe2f95d8bbddef725fd6fa8c7be`。

## 実装

- `UnitResultCelebration`に、18片の紙吹雪・到達アイコン・見出しの初回出現を閉じ込めた。既存のframer-motionとMUIだけを使用し、依存追加はない。
- 紙吹雪は中央の最大360×180pxに限定し、約1.31秒で透明になる。一度きりで、装飾全体を`aria-hidden`・`pointer-events: none`にする。アイコンと見出しは600ms（見出しの遅延80ms）で完成する。
- 待ち時間・入力ブロック・効果音を追加しない。カードの前振り／開示／賞賛の段階、回転・光条・グローは持ち込まない。単元完了でより大きな演出を出せる余地を残す。
- アニメーションはマウント時の`initial`→`animate`だけ。タイマー、完了コールバック、報酬やダイアログの状態、変化するkeyに接続しない。上に重なるカード提示の閉鎖を再発火の契機にしない。
- `prefers-reduced-motion`では紙吹雪を描画せず、アイコン・見出しは完成状態を即表示する。ハイドレーション前もCSSメディアクエリで紙吹雪を隠し、移動・透過を止める。
- 純粋関数`phaseResultPraise(summary)`は、既存summaryを読み取るだけで、初回全問正解／再挑戦後の到達／成績なしの3通りを返す。欠けた数値・不正な数値は標準文へ戻す。学習全体を理解した等の未検証の評価を加えない。
- 称賛文は20〜28pxの太字で常設し、演出終了後も残す。既存の到達数・初回正解数・次フェーズ予告も維持する。短い画面ではスクロールでき、文章の改行はバランスを取る。

| summary | 称賛文 |
| --- | --- |
| 初回正解数＝総問題数（正の整数） | やった！ 全問、初回で正解しました！ |
| 初回正解数が総問題数未満 | 最後まで取り組んで、全問正解にたどり着きました！ |
| summaryなし／成績の数値なし | やった！ 確認問題を最後まで解き切りました！ |

## 境界と指針の確認

このリザルトは再挑戦して全問正解した時点にしか出ない。完了時の正解数と初回正解数を混同せず、文の出し分けは初回正解数だけで行う。summaryの計算、assessment、判定、保存、ログ、遷移、報酬キューは変更していない。

マスコット、フェーズ6の診断、単元完了リザルト（#150）、カード提示（#147）は対象外。音・音源・サウンド設定・DB・seedの変更はなく、DB適用は不要。

着手時点でPR #157は未マージだった。既存の遷移ボタンとそのスタイル・文言・ハンドラはそのまま保持した。指示にある`app/presentation.ts`は現行ツリーにはなく、提示の実体である`rewards/presentation.ts`と`LearningRewardBoundary`の短い肯定的な文調を参照した。現在のUI/UX方針はフェーズ完了リザルトの賞賛を許可しており、本件の実装結果に影響する指針の矛盾は見つからなかった。

## 検証

- frontの`npm run lint`、`npm run typecheck`、`npm run build`を実行して通過。既存のESLintモジュール形式・複数lockfileの警告あり。
- frontの`verify:*`全16件を実行。10件は通常実行で通過。`bfs-code-mapping`、`bfs-code-check`、`bfs-consolidation`、`bfs-implementation`、`bfs-trace`、`bfs-free-execution`は既存スクリプトのWindowsパスキー混在による参照同一性、python3エイリアス／文字コードの環境差で失敗したため、リポジトリ外のアダプターで再検証して通過した。補正はパスキーの`path.resolve`、インストール済みPythonの指定、`PYTHONUTF8=1`のみ。検証のassertion・教材コードは変更していない。
- 新規verifyスクリプトは作らず、既存の`verify:bfs-unit`を拡張。純粋関数の3分岐と欠損／不正値、入力の不変性、両フェーズのSSR文言、装飾範囲・片数・終了・非ループ、再描画で不変の初期状態とkey、reduced-motionで紙吹雪なし・完成状態、マスコットなし、最終リザルトに適用しない契約を固定した。
- 本番ビルドのChromeでフェーズ3の初回2/2正解、フェーズ5の再挑戦後の初回1/2正解を確認。称賛の分岐・既存の成績・次フェーズ予告・演出後も残る文・紙吹雪の最終透明状態を確認した。
- 390×844pxで称賛・成績・予告が折り返され、次へボタンが画面内に表示されること、ページ全体の横はみ出しがないことを確認。検証後に表示幅を元へ戻した。ブラウザーのエラーログなし。
- ビルド初回は環境のネットワーク／生成先権限制約とディスク空き容量不足で停止。今回の失敗ビルド生成物と前回#146の再生成可能なビルドキャッシュだけを削除し、再実行した。

未実施: 認証付きアプリで実カードのダイアログを閉じる通し確認、OS側のreduced-motion設定での実表示、実験条件・保存・学習ログを含むE2E。カード協調は既存の配線を保持し、静的契約で確認。見た目の強さは実機レビューの対象。

## 確認方法

`front`で`npm run dev`を実行する。認証・バックエンド・DBが不要な対象URLは http://localhost:3000/learning-preview/bfs-unit 。確認サーバーがある場合は同じパスを開く。単品の`bfs-check`／`bfs-code-check`の完了表示は別コンポーネントで、本件の対象は単元内のリザルト。

1. フェーズ1のシークにフォーカスしEnd→「フェーズ2へ進む」。フェーズ2もEnd→「理解度を確認する」。
2. **初回全問正解**: C→「どれも入らない」。フェーズ3リザルトで短い紙吹雪・チェックアイコン・見出しの出現と「全問、初回で正解しました！」、初回2/2を確認する。演出が終わっても文は残り、次へは最初から押せる。
3. 「次のフェーズへ進む」→フェーズ4のシークでEnd→「コードの確認問題へ進む」。append→not inでも、フェーズ5で同じ初回全問正解の称賛になる。
4. **再挑戦あり**: ページをリロードして1からやり直す。フェーズ3でD（不正解）→C→「どれも入らない」。初回1/2のまま「最後まで取り組んで、全問正解にたどり着きました！」になることを確認する。フェーズ5ならpopleft（不正解）→append→not inで同じ分岐を確認できる。
5. 小画面で改行と次ボタン、動きを減らす設定で紙吹雪なし・静止した完成状態を確認する。

アプリ内の対象URLは http://localhost:3000/courses/roadmap/course-algorithm-breadth-first-search-v1/learn （ログインと対象フェーズへの進捗が必要）。カードを獲得するフェーズではダイアログを開閉し、背面リザルトが再アニメーションしないことも確認する。
