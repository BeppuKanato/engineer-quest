# 穴掘り法 フェーズ4（動きとコードの対応）（Issue #260）

目的: 穴掘り法単元のフェーズ4を、フェーズ2と同じトレースを参照コード（契約 maze-digging-v1）の行ハイライトと同期して自動再生する「照合」フェーズとして実装する。設計は基準データ（docs/concept/maze-digging-unit-baseline.md §2・§3、正本は基準データ取り込み PR #267 で別途進行中のため、本実装はその承認済み原本に従う）に従う。最終確認日: 2026-11-07。本 PR は feat/maze-digging-phase3-259（PR #270）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/maze-digging/code-mapping/` に code / types / content / presentation / Canvas / Preview / README.md を新設（構成は棒倒し法フェーズ4と同型）。
  - `mazeDiggingCode.ts`: 参照コードの契約。基準データ §2 の `dig_maze` を意味ID付きで固定する（22行、フェーズ5・7も同じ契約を使う）。
  - `codeMapping.content.ts`: フレーム列（全669フレーム）。盤面は複製せず、フェーズ2の21ステップのスナップショットへ直接参照する。フレームの並びと変数は参照コードの制御フローをシミュレーションして構成し、実行行1つにフレーム1つを対応させる（候補の収集は4方向の反復と繰り返しの終了確認まで、戻りは `stack.pop()` の1マスずつまで、実際の行順どおり）。
  - チェックポイント（フェーズ2ステップへの対応づけ）: 掘削は盤面とスタックの両方がフェーズ2の状態にそろう `stack.append((nx, ny))` 行、バックトラックは戻り切った最後の `stack.pop()` 行（基準 §3 の要点「候補が空のときの stack.pop() がフェーズ2のバックトラックステップに対応する」）、完成は `while stack:` の終了判定、初期盤面は `grid` の初期化行、スタート掘削は `grid[1][1] = 0` 行。
  - `else:` は CPython が行イベントを発しないため、候補が空と判定した直後に説明フレームを1つ挟む（全16回、変数は if の直後と同じ。棒倒し法フェーズ4と同じ扱い）。
  - 表示変数は参照コードのローカル変数の射影（size / step / x / y / dx / dy / nx / ny / candidates / stack）。grid は盤面が、directions は定数のため表示しない。コードエリア下部に表示し、直前フレームから変わった値をフォーカス青で反転させる（プレイヤーUI定義・教材指針フェーズ4節の型どおり）。

## 留保（判断が必要な点）

- フレーム総数は669と、棒倒し法フェーズ4（137）の約5倍になった。理由は構造的で、掘削・戻りのたびに「4方向の候補収集（反復行・計算行・条件行・終了確認）」が実行行として積み上がるためである（1回の走査で最大14フレーム、走査は全31回）。教材指針フェーズ4の同期実行ルール①（非描画行も必ず1ステップとして通過させる）と他単元の検証方式（実行行と1対1）を優先して圧縮はしていないが、自動再生の総時間（intervalMs 3500 で約39分）は実機レビューで確認したい論点である。圧縮する場合は「方向走査の途中経過を代表フレームへまとめる」等の設計判断が別途必要になる。
- フェーズ2はバックトラックを1ステップに圧縮して見せたが、フェーズ4では実際の実行どおり1マスずつ（pop ごとに候補収集を含む）たどる。対応づけは「戻り切った pop」で行うため、フェーズ2のバックトラックステップの盤面が現れるのは戻り切った時点になる。これは照合フェーズの目的（コードの実行順序どおりに見る）に沿う意図的な違いであり、基準 §3 フェーズ4の記述とも矛盾しないと判断した。
- 掘削チェックポイントを `dig_room` 行（部屋を掘る行）ではなく `stack.append` 行に置いた。フェーズ2の掘削ステップは盤面（間の壁＋部屋）に加えてスタック経路の表示を含むため、経路までそろうのは push の後であり、棒倒し法で「その行の実行でフェーズ2ステップが完成する行」を対応づけた考え方に合わせた。
- 基準データ正本（docs/concept/maze-digging-unit-baseline.md）は PR #267 のブランチにあり、本 PR のツリーにはまだ無い。マージ順によっては README からのリンクが一時的に解決しない（フェーズ1〜3と同じ留保）。
