# Issue #130 DFS 単元のアプリ組み込み

- 目的は、コースから DFS 単元を開き、途中から再開し、学習中のカードと実績を受け取れるようにすること。
- 対象は既存 DFS コース、学習進捗・イベント、知識カードと実績のマスターデータ。
- 最終確認日 2026-11-10
- 正本は [Issue #130](https://github.com/BeppuKanato/engineer-quest/issues/130)、[DFS 基準データ §0.1・§8](concept/dfs-unit-baseline.md)、[実装ルール](development-rules.md)。

## コースと進捗

既存の `course-algorithm-depth-first-search-v1` に DFS の7段階を登録した。コース一覧、単元画面と学習画面から開始・再開できる。既存の学習 API で段階の完了とサマリを保存し、最初の未完了段階から再開する。解答、再試行、復習、診断のイベントは既存の学習ログへ渡す。全段階の完了後は単元画面から「単元の結果を見る」で再度開ける。

## 知識カードと実績

知識カードは「動きの説明」のトポロジカルソート（RARE）、「コードの確認問題」のリストで作るスタック（COMMON）、「自分で実装」のバックトラッキング（EPIC）。既存単元と同じ15テーブルを使い、同じフェーズを完了し直した場合は付与済みのカードを再付与しない。

実績は単元完了、実装クリア、2つの確認問題での初回全問正解、応用問題の初回満点、ノーヒントクリア、DFS カード3枚の収集。単元別のカード収集実績は、そのコースのカードだけで判定する。既存の全体収集実績の達成ラインは15枚とした。

## DB 適用と確認

対象の開発 DB に既存の学習基盤のマイグレーションを適用した環境で、`back` の `npm run seed:preserve` を実行すると、コース説明、カード、配布表、実績が反映される。今回の変更は既存のスキーマを使う。実 DB への適用と通し確認は別途行う。

1. コース一覧から「深さ優先探索（DFS）」を開く。[単元画面](http://localhost:3000/courses/roadmap/course-algorithm-depth-first-search-v1)
2. 学習を開始し、途中でコース一覧へ戻る。再度開いたとき、最初の未完了段階が選べることを確認する。
3. 応用問題を初回満点にして結果を開く。自分で実装をヒントなしで全テスト通過し、単元の結果を開く。新着実績と、配布表に従ったカード提示を確認する。

`back` の `verify:dfs-learning` はメモリ上の Prisma アダプターで実サービスを呼び、保存・再開用データ、ログ、報酬の重複防止、15テーブル、実績の条件を照合する。フロントの自動検証では、DFS コースの解決、保存先 URL、再開位置、完了保存前に先へ進まないことを確認する。
