# 主流レイアウト移行（結果画面の単一スクロール化）

- 目的: Issue #298 の移行シリーズ第1弾として、フェーズ結果・ブリッジ・単元最終結果のスクロールを単元コンテナのラッパー1か所に一元化する。
- 最終確認日: 2026-11-09
- 正本: Issue #298 と 2026-11-09 のユーザー承認（主流レイアウト移行の設計）。方針の正本化は本シリーズ最終 PR で `docs/concept/learning-player-ui.md` に行う。

## 背景

- 学習画面のレイアウトを主流の学習アプリの形（上部固定＋中央スクロール＋下部固定）へ寄せる移行の第1弾。
- 従来はフェーズ結果画面（`UnitResultScreen`）とブリッジ画面（`PhaseBridgeScreen`）がそれぞれ自前の `overflowY: "auto"` を持ち、単元コンテナのラッパーのスクロールと二重になっていた（#298 項目3「リザルトのスクロールが独自」の実体）。
- 単元最終結果は既に自前スクロールを持たずラッパーに任せていた（#150）。

## 変更内容

- 全5単元の `UnitResultScreens.tsx`: フェーズ結果画面の自前 `overflowY: "auto"` を撤去。短い内容の中央寄せは、内側カラム（`minHeight: "100%"`）の中で `flex: 1` と `justifyContent: "safe center"` により従来どおり再現される。
- 共有 `PhaseBridgeScreen`（`bfs/unit/`、全単元が使用）: 自前 `overflowY: "auto"` を撤去。
- 全5単元の単元コンテナ（`*UnitPreview.tsx`）: 内側カラムの高さを「フェーズ画面のときだけ `100%`、結果・ブリッジ・最終結果では `auto`（内容の高さで伸びる）」に変更。あわせてラッパーの役割コメントを更新（#303 の背景色・はみ出し防止の役割は維持し、結果系画面の唯一のスクロール領域であることを明記）。

## 検証

- `verify:<unit>-unit`（5単元）: フェーズ結果・ブリッジが専用スクロールを持たないこと、内側カラムが結果系で伸びることを新契約として追加し、全て通過。
- `verify:learning-screens`、`verify:learning-rewards` 通過。
- 実績バンド（#345）とフィードバックの配置は結果画面内の従来位置のまま（in-flow）で変更なし。
