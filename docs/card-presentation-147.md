# 知識カード提示の作り直し（Issue #147）

- 目的: カード獲得の提示を「自動再生で終わる演出」から「学習者が発見を認識し、自分の操作で開く提示」に変える。あわせて、テーマ4（Issue #151）で先送りした P2（保存と演出の分離）を実施する。
- 適用範囲: 学習フローの報酬境界（`front/src/features/learning/rewards/` と `LearningScreen` の配線）。
- 最終確認日: 2026-11-06
- 正本へのリンク: 段階演出の水準はアプリ UI/UX 方針 論点4（前振り → 出現 → 賞賛、レア度で強弱、フェーズの切れ目で提示）。本書は Issue #147 の実装記録。

## 問題だった点（実機レビュー #147）
- 提示がタイマーで自動進行し、学習者は何が起きたか認識できないまま終わっていた。
- ランダム要素を「発見した」ことへの褒めがなかった。
- 提示の完了がフェーズ完了保存の Promise に含まれ、遷移全体を待たせていた（#151 の P2 として分離を先送りしていた）。

## 実装内容
### クリック開示型の提示（LearningRewardBoundary）
- 発見ステージ（anticipation）は自動で進まない。未開示のカード（？？？）に、見つけたこと自体への称賛文（「やった！ 学びの途中で、知識カードを見つけました！」）と「カードを開く」ボタンを出し、カード本体のクリックでも開示できる。未開示カードにはタップを誘う緩やかな鼓動を付け、`prefers-reduced-motion` で止める。
- 開示（appearance）: クリックで既存の出現モーション（拡縮・回転・光条・グロー、レア度連動）を再生し、効果音 `cardFlip` を鳴らす。開示操作は学習ログに `card_presentation_reveal` として記録する。
- 賞賛（praise）: 開示の余韻（durations[1]）の後に自動で進み、効果音 `cardAcquired` を鳴らす。ここから先は「学習を続ける」を押すまで閉じない。実績のみの提示も同様に、押すまで閉じない。
- スキップ（タイトルのボタン、背景クリック、Esc）は従来どおり可能で、ユーザの操作で進む形は維持される。

### 保存との分離（P2）
- `useRewardBoundary` を Promise 待ちからキュー方式に変更した。`present` は提示を積むだけで戻り、`finish` が次の提示へ進める。
- `LearningScreen.completePhase` は保存成功後に提示を積むだけで、その完了を待たない。フェーズ遷移は保存が済めば即座に進み、提示は遷移先の画面の切れ目に重なって表示される。
- 保存自体を提示の前提にする構造（保存失敗時は提示しない）は維持している。

## 検証
- `verify:learning-rewards` を新しい契約に合わせて更新（境界キューの非ブロッキング性、未マウント時の無効化、クリック開示の文言と記録、遷移を待たせない配線）。他の front verify 全件、lint、typecheck、build も通過。
- DB・seed の変更なし。提示の見た目と音の実機確認はユーザ環境で行う。
