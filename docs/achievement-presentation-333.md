# 実績提示の再設計（Issue #333）

- 目的: 実績の提示を「解除された瞬間」に移し、実績が学習の節目として印象に残るようにする。
- 適用範囲: 新フローの全接続単元（BFS、バブルソート、棒倒し法、穴掘り法、二分探索）のフェーズ結果画面と単元最終リザルト。DFS は単元コンテナ未接続のため対象外（部品は単元非依存）。
- 最終確認日: 2026-11-09
- 承認経緯: 提案モック（実績・達成モーメントの演出）をユーザーが承認（2026-11-09「提案の方法で一回実装してみて欲しい」）。

## 変更前の実態

- 実績の評価はサーバ側でフェーズ保存時と単元完了時に行われ、新規解除分は保存レスポンスで返る。
- しかし提示は、単元途中の解除分が「学びの発見」ダイアログ（知識カード演出）の賞賛段に静的な一覧行として付け合わせで出るだけだった（出現は 0.2 秒のフェード、実績専用の音なし）。フェーズ 7 の解除分はダイアログから除外され、最終リザルトのタイトルだけのコンパクト要約に埋もれていた。

## 設計と実装

1. **フェーズ結果画面の実績バンド**（新規 `front/src/features/learning/rewards/AchievementPresentation.tsx` の `AchievementBand`）
   - そのフェーズの保存で解除された実績を、結果画面のスコア文の下に提示する。見出しは「実績を獲得しました」。
   - 各実績はレアリティ色のトロフィーバッジ＋放射・グローのポップインで出現する（知識カード出現と同じ語彙、`presentationFor` の rays / glow を流用）。複数件は 0.15 秒ずつずらして出す。
   - 結果画面既存の紙吹雪・歓声はそのまま。新規の効果音は追加しない（歓声と二重に鳴らさない判断）。
2. **切れ目ダイアログは知識カード専用に**
   - `LearningRewardBoundary` から実績行を撤去し、`RewardBoundary` のペイロードから実績を外した。カードがない切れ目は開かず、キューだけ進める。
   - カードの発見→開示→賞賛のフローと効果音は不変。
3. **最終リザルトの「新しい実績」ゾーン**（同ファイルの `NewAchievementZone`）
   - フェーズ 7 と単元完了で解除された分を、締め文の直後に 1 件ずつ（0.35 秒間隔）ポップインで出す。
   - 従来のコンパクト要約（`FinalLearningRewards`）は「記録」としてゾーンの下に残す。
4. **配線**
   - 解除の振り分けは `LearningScreen` に集約した。フェーズ保存レスポンスの解除分を `phaseResultAchievements` で結果画面用と最終用に分け、フェーズキー別 state（結果画面用）と新着 state（最終用）に保持する。単元完了レスポンスの解除分は新着へ合流させる（いずれも ID で重複排除）。
   - 単元側は render prop（`renderPhaseAchievements` / `renderNewAchievements`）で受け、5 単元とも `UnitResultScreen` の `achievements` 受け口と `UnitFinalResult` の `newAchievements` 受け口に差し込む。単体プレビュー（未接続）では何も出ない。
5. **モーションと音の扱い**
   - `prefers-reduced-motion` では出現アニメーションと放射を止め、静止表示にする（`ResultConfetti` と同じ方針）。結果画面の歓声が既に鳴るため、実績専用の音は追加しない。
6. **学習ログ**
   - 実績 1 件ごとに既存の `achievement_present_view` を placement 付きで記録する（結果画面: `phase-result`、最終の新着: `unit-result-new`）。要約側の `unit-result` と区別でき、提示回数の分析に使える。スキーマ変更はなし。
