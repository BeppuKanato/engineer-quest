# Parsons のキープ印を回答時点の判定に固定（Issue #354）

目的: 応用問題の Parsons 問題で、誤答後に付く「動かさなくてよい行」の印（淡い緑＋丸付きチェック）が、ドラッグで並べ替えるたびにライブ再計算され、再回答しなくても正しい位置が分かってしまう問題を直す。印は提出した回答への判定であり、ライブの正誤オラクルではない、というのがユーザーの指摘（2026-11-09）。
最終確認日: 2026-11-09

## 問題（#341 の従来仕様）

- 共有盤面 `ParsonsBoard` は、現在のドラッグ中の並び `ordered` から `parsonsKeepLineIds` を毎レンダー再計算していた。
- そのため、誤答後に行を正しい場所へドラッグするだけでその行にチェックが付き、「緑になる位置を探す遊び」になっていた。再回答ボタンを押す前に正誤が分かる状態だった。

## 変更内容

- `ParsonsOrderFeedback` に `submittedLineIds`（直近に提出した並び）を追加した。
- 5単元の応用問題プレビューは、最新試行（`record.attempts.at(-1)`）の回答が並び替え回答のときに、その `lineIds` を `submittedLineIds` として渡す。未回答時は `undefined`。
- 盤面は印を `submittedLineIds` からだけ計算する。提出した並びが正解なら印は出さない。未提出なら印は出さない。ドラッグで並び替えても印・凡例は変わらず、次の回答を提出した時点でだけ判定し直す。
- 印は行 ID に対して付くため、提出後に行を動かしても、印はその行に付いたまま移動する（提出時の配置への判定であることが見た目にも残る）。
- フェーズ7ヒント L4 の盤面（`orderFeedback` 未指定）は従来表示のまま、変更なし。

## 置き換えた旧契約

- #341 で導入した「並び替えるたびに再計算し、正解の並びに到達した時点で印と凡例が消える」というライブ更新ルールを廃止した。
- UI 定義 `docs/concept/learning-player-ui.md` §5.2 の Parsons の印の文に、回答時点でのみ判定する旨を追記した。

## 検証

- `verify:parsons-order-feedback`: 提出した並びが盤面の現在の並びと異なっても印は提出時の判定に従うこと、提出が正解なら印が出ないこと、未提出では出ないことを追加で検証。全60本の verify と型チェック、build が通過。
- 実機での確認事項: 誤答 → 印が付く → ドラッグで並び替えても印が変わらない → 再回答すると新しい並びで判定し直される、の流れ。
