# 二分探索 フェーズ1 数当てゲームの答え明示（Issue #329）

目的: 二分探索フェーズ1の数当てゲーム場面について、ユーザーレビュー（Issue #329）の「50の場合の『大きい』『小さい』の情報が入ってないから50にピントこない」を受け、真ん中を聞く場面を「聞く場面」と「答えの場面」の2段構成にし、答えを図と文の両方で明示する。設計判断はユーザーが 2026-11-09 に確定した（答えを明示する2段構成。消えた側を青く塗る案は、青がプレイヤー全体で「処理中」の固定色でありフェーズ2では捨てた範囲をグレーで描く慣行と衝突するため不採用）。最終確認日: 2026-11-09。

## 背景

- 従来の場面3 `ask-middle` は、聞いた数 50 と残り範囲 [51, 100] を最初から同時に表示していた。つまり「答えが『50より大きい』だった」という結果だけが黙って表示され、答えそのもの（隠れた数との大小関係）は図にもキャプションにも現れなかった。キャプション「真ん中の数を聞くと、答えに合わせて候補の半分が一度に消えます。」は一般論のみで、学習者の注意が 50 に向く手掛かりがなかった。
- 答えの具体的な数は明かさない。数当てゲームは一般のゲームとして提示されており、必要なのは関係（50より大きい／小さい）だけである。

## 実装

- `motivation/motivation.content.ts`: 場面3を2場面に分割し、フェーズ1は全7場面になった。
  - `ask-middle`（聞く場面）: 帯は 50 を処理中（青）で強調するだけで、まだ何も消えていない（`asked: 50, remaining: null`）。キャプション「まず、答えが真ん中の数である50かどうかを聞いてみます。」
  - `ask-middle-result`（答えの場面、新規）: 答えを受けて左半分（1〜49）が完了グレーで消え、残りは 51〜100（`asked: 50, remaining: [51, 100]`）。キャプション「答えは『50より大きい』だったので、50より小さい候補は一度に消えます。」
  - 用語表（真ん中／候補／半分）の `firstStepId` は `ask-middle` のまま（真ん中を聞く行為は聞く場面で導入される）。
  - 場面2（ゲームの導入）と場面4（7回で当たる）は文言変更なし。場面2が『大きい』『小さい』のヒントを先に導入しており、場面4は答えの場面からの一般化としてそのままつながる。
- `motivation/BinarySearchMotivationCanvas.tsx`: 数当ての帯（`GuessStrip`）に答えの吹き出しを追加した。
  - 吹き出しの文は場面状態から導出する。残った範囲が聞いた数より大きい側なら「{聞いた数}より大きい」、小さい側なら「{聞いた数}より小さい」。型と検証（`motivation.types.ts`）は変更していない（残った範囲は聞いた数を含まず片側だけに寄ることが既存の検証で保証されている）。
  - 吹き出しは聞いた数の真上に置く丸角の枠＋小さな尾で、帯と聞いた数のラベルには重ならない。色は `playerTokens` のみ（面は surface、枠と文字は text）。消えた側の色は従来どおり完了グレーで、青は処理中（聞いた数）だけに使う。
  - 帯の形状（位置・セル幅・高さ）は聞く場面と答えの場面で同一であり、場面間で図のサイズは変わらない。

## 基準データとの差異

- 基準データ（docs/concept/binary-search-unit-baseline.md §3 フェーズ1）は場面案を「6場面程度」とし、項目3を「真ん中を聞くと、答え次第で半分が候補から消える」の1場面としていた。本変更でこの項目が2場面になり、全7場面になる。基準データ自体は書き換えず、本報告に差異を記録する（PR #324 の棒倒し法フェーズ2再構成と同じ扱い）。

## 他の変更との重なり

- Issue #329 のもう一つの変更（場面1 `find-twenty-five` の未ソート化）が別 PR で進行中の場合、本 PR は数当てゲームの場面（3の分割）と帯の描画・検証だけを変更し、場面1のキャプションと配列には触れていない。`motivation.content.ts` のステップ配列で隣接するため、取り込み順によっては同ファイルの軽微な競合があり得る。
