## 留保（判断が必要な点）

- 入力が変更されていないことは、既存の教材テスト基盤では検出できない。基準データ §3 は「入力が変更されていないことも判定に含める」と定めるが、`runCourseMissionTests` の Worker ハーネスは引数を JSON から都度生成して関数へ渡し、戻り値との完全一致（Python の `==`）だけを判定するため、関数が引数のリストを書き換えても結果に現れない。検証では、入力を直接並び替える変異（`result = values` と別名で書き換える実装）が全5テストの一致判定を通過し、かつ引数を実際に書き換えることを CPython で示した。入力の事後比較は create クエスト基盤の INPUT_UNCHANGED が持つ仕組みだが、教材テスト側には差し込み口がない。基盤側に用意された時点で、判定へ組み込むのが本来の形である。
- 内側ループの範囲が狭まらない変異（`range(n - 1)`）も、結果ベースのテストでは落とせない。この形でも並び替えの結果は正しく、増えるのは比較の回数だけである（フェーズ6 Q2 の「比べる回数はループの範囲だけで決まる」という学びと整合する）。範囲の誤りのうち結果が変わるもの（広すぎる `range(n - i)` は範囲外アクセスでエラー、狭すぎる `range(n - 2 - i)` は並び残し）は落ちることを検証で確認した。比較回数まで見て範囲の縮小を判定するには、create クエスト基盤の比較回数トラッキング相当の仕組みが教材テスト側に必要になる。
- Preview は `LearningInstrumentation` の `active` を受け取るが消費していない（BFS フェーズ7では視覚デバッグのダイアログが使う）。バブルソートの視覚デバッグは Issue #234 で追加し、その際に接続する。
- 基準データの正本（docs/concept/bubble-sort-unit-baseline.md）は PR #237 が未マージで本スタックに無いため、承認済み原本の §2・§3 に従った（フェーズ1〜6の実施記録と同じ留保）。
