# Issues #139・#140・#150 残りの個別修正（パンくず／フロー矢印／リザルトのスクロールと終了導線）— 実施記録

実機レビュー（#137〜#150）のうち、判断を要しない個別修正（分類 C）をまとめて対応した。各 Issue には他の論点（レイアウト設計、用語、賞賛演出など）が残るため、本対応では Issue は閉じない。

## 1. パンくず未使用（#139, #140）

- 単元画面は、戻り導線が素のボタン（「コース一覧へ」）だった。
- 対応: アプリ全体で使われている共通部品 `AppBreadcrumbs` に寄せた（単元画面 `UnitOverview`: コース ＞ 単元名）。パンくずは内容コンテナ（1200px）の外に独立した行として置き、左端と上余白を主要画面（コース・実績・履歴・知識カード・プロフィールの 1440px コンテナ＋ py {3,4}）に揃えた。内容側のレイアウト幅は従来どおり。
- 学習画面（教材内）にはパンくずを置かない。当初は学習画面にも入れたが、レビューで次の判断があり取りやめた: 学習画面は 100dvh の固定フレームで教材領域の占有率が定義されており、パンくずの帯がそれを食うこと、現在地は単元名＋フェーズチップが既に示していること、アプリ側とプレイヤー側の背景系が同居して帯が浮くこと。学習画面の戻り導線は従来の「単元画面へ戻る」リンクのまま。
- アプリ全体のパンくず配置統一（コレクション・掲示板詳細・作る画面など、主要画面と置き場所がずれている画面の是正）は、本対応とは分けて別 Issue で扱う。

## 2. フロー表示を矢印でつなぐ（#140）

- 学習画面上部のフェーズチップは並んでいるだけで、流れとして読めなかった。
- 対応: `BfsUnitPreview` のナビゲーションで、チップとチップの間（単元リザルトチップの前を含む）に `aria-hidden` の矢印アイコンを挟んだ。チップ自体の遷移・状態表現・文言は変更していない（文言は用語提案の判断待ち）。

## 3. 単元リザルトのスクロール（#150）

- 原因: 最終リザルト（`UnitFinalResult`）が専用の `overflowY: "auto"` を持ち、コンテンツ列（84vw）の右端にスクロールバーが出て、画面端から浮いて見えた。
- 対応: 最終リザルト表示時のみ、スクロールを外側の全幅コンテナ側に移した。リザルト自身は内側スクロールを持たない。フェーズ画面のレイアウト（固定表示）には影響しない。

## 4. 単元リザルトの終了導線（#150）

- 終了ボタンは「単元の先頭に戻る」（フェーズ1へ移動）だった。
- 対応: 「コース一覧に戻る」（`/courses` へのリンク）に変更した。復習は従来どおり、各フェーズの「復習する」と上部ナビから可能。

## 検証

- `verify:bfs-unit` に契約を追加した: ナビの矢印、単元画面の `AppBreadcrumbs` 使用と学習画面にパンくずが無いこと、最終リザルトが内側スクロールを持たないこと、終了導線が `/courses` であることとその文言。
- front の lint / typecheck / build と verify 全16件が成功。判定・保存・賞賛提示のロジックは変更していない。DB・シードの変更なし。
- GPT の PR #158（#144、同じ `UnitResultScreens.tsx` のフェーズ3・5リザルト側）とは変更箇所が別の関数で重ならない。

## 確認方法（マージ後・ローカル実行時）

1. 単元画面: 上部にパンくず（ホーム ＞ コース ＞ 幅優先探索（BFS））が出て、「コース」からコース一覧へ戻れること。パンくずの左端と高さがコース一覧など他の画面と揃っていること。
2. 学習画面: パンくずは無く、従来どおり「単元画面へ戻る」リンクだけがあること。上部のフェーズチップの間に矢印が表示され、流れとして読めること。
3. 単元リザルト: 内容が長いときにスクロールバーが画面の右端に出ること（コンテンツ列の内側に出ない）。最下部のボタンが「コース一覧に戻る」で、押すとコース一覧へ遷移すること。
