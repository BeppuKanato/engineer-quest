# 穴掘り法 フェーズ3（動きの確認問題）（Issue #259）

目的: 穴掘り法単元のフェーズ3を、フェーズ2の場面 `dig-3` を参照する連結2問として実装する。設計は基準データ（docs/concept/maze-digging-unit-baseline.md §3、正本は基準データ取り込み PR #267 で別途進行中のため、本実装はその承認済み原本に従う）に従い、§6 の要判断ポイントは推奨デフォルトで進行する決定済み。最終確認日: 2026-11-07。本 PR は feat/maze-digging-phase2-258（PR #269）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/maze-digging/check/` に content / types / Canvas / Preview / README.md を新設（構成は棒倒し法フェーズ3と同型）。
  - `check.content.ts`: 場面はフェーズ2の `dig-3`（主教材 9×9 で3回目まで掘った状態、壁74・現在マス (5, 3)）をステップIDで参照し、壁は複製しない。正解は `mazeDiggingMaze.ts` の組み立て済みトレースの4回目の掘削から導き、基準データ §3 の確定事項（(5,3) から右へ、部屋 (7,3)・間の壁 (6,3)）と一致することをモジュール読み込み時に検証する。
  - Q1 `next-room`「(5, 3) から右へ掘ります。掘られる部屋はどれですか」: 回答対象はアルゴリズムが実際に集める候補そのもの（現在マスから2マス先が盤内で、まだ壁のままの部屋を提示順に並べた3マス (5, 1)・(7, 3)・(5, 5)）。掘削済みの左 (3, 3) は候補に入らない。
  - Q2 `between-wall`「そのとき通路になる、間の壁マスはどれですか」: 回答対象は候補方向それぞれの間の壁マス3つ（(5, 2)・(6, 3)・(5, 4)）。Q1 の正解を `requires` に持つ（データ検証のみ。進行は位置ベースの統一仕様）。
  - 場面は2問とも場面ステップの canvas そのもの（`getMazeDiggingCheckScene`）。場面の検証は単元側の `validateMazeDiggingCanvas` で行う。
  - `MazeDiggingCheckCanvas.tsx`: 描画は共通グリッド基盤へ委譲し、回答ボタンはマスの中心に重ねる HTML ボタン（タップ領域は最低44px、共通の `answerCueSx`）。
  - `MazeDiggingCheckPreview.tsx`: アセスメント画面。単元フロー（接続 Issue）向けに embedded / onComplete（初回正解数の要約通知）を持ち、未指定なら単品ページとして動く。
- 進行は共通エンジンの統一仕様（PR #170）のまま: 回答では進まず「次の問題へ／結果を見る」で送る、正解で入力をロック、完了は最後まで進み全問に1回以上回答したこと（ソフトゲート）、結果は初回回答のみから導く。誤答後は復習モーダル（フェーズ2の `dig-3` → `dig-4` を参照のまま再生）を任意に開ける。
- 単品プレビュー: `/learning-preview/maze-digging-check`。

## 留保（判断が必要な点）

- 方向の提示方法は棒倒し法フェーズ3と異なる。棒倒し法は方向を独立フィールド＋画面の表示行で示したが、穴掘り法は基準データ §6-6 の推奨デフォルトどおり Q1 の問題文の中で提示し、独立フィールドは持たない（次の行き先が乱数で決まるため、方向なしでは正解が一意に定まらない前提は同じ）。
- 場面の差し替えをしない点も棒倒し法と異なる。棒倒し法フェーズ3では Q2 で処理中の柱を Q1 の正解へ移す場面を作ったが、穴掘り法は2問とも同じ掘削の「対象」と「直後の変化」を問うため現在マス (5, 3) が両問で変わらず、場面ステップの canvas をそのまま使う。
- Q1 の回答対象を候補の部屋3マスに限った。棒倒し法フェーズ3 Q1 は柱全9マスだったが、穴掘り法の「次に掘る部屋」は現在マスの候補集合の中でしか起こらないため、候補そのものを回答対象とする方が「候補から1つ選ぶ」というアルゴリズムの読みと一致する。Q2 の対象範囲の絞り方は棒倒し法 Q2（変化が起きる範囲だけ）と同型。
- 基準データ正本（docs/concept/maze-digging-unit-baseline.md）は PR #267 のブランチにあり、本 PR のツリーにはまだ無い。マージ順によっては README からのリンクが一時的に解決しない（フェーズ1・2と同じ留保）。
