## 実装内容

`front/src/features/learning/dfs/check/`にcontent/Canvas/Previewを置き、単品URL`/learning-preview/dfs-check`を追加した。表示名は基準書§0.1の共通名「動きの確認問題」。利用者向けに「フェーズ」は出さない。

問1は`skip-b-from-d`（ステップ11、スタックC,E,F）でFを選ぶ。問2は`dead-end-f`（13、スタックC,E）でEを選ぶ。正解文・論点タグは基準書§4に従う。両問に次の取り出し対象があるのでallowNoneはfalse。問1で誤答して先へ進んでも、問2は定義済みのFについて出題する。

図は`getLearningStep`で元のDFS実行ステップを参照し、グラフ・座標・状態・キャプションを複製しない。`DfsExecutionCanvas`へBFSと同じ任意の回答overlayを受け取る口を足した。未指定の通常再生・復習の表示は維持する。回答中は既存ノードとスタックの強調枠を抑え、全候補に同じ回答リングを付ける。現在の処理状態を表す塗りや辺は残す。

BFSの回答用リング・アイコン・HTML操作面を`assessment/NodeAnswerOverlay.tsx`へ切り出し、BFSとDFSが対等に使う。既存BFSの位置・色・操作・「どれも入らない」は維持する。図は共通GraphDrawing/graphGeometry/playerTokens、操作面は44px以上、案内の明滅は2回のみでreduced-motionでは停止する。

判定・記録・完了条件は共通`assessment.ts`をそのまま使う。正解後はUIとコールバック内の両方で回答を固定し、連打でも試行を増やさない。誤答は再回答でき、明示的な「次の問題へ」「結果を見る」で進む。初回正誤は再回答で上書きしない。完了では初回正解数を事実として1文で示し、もう一度解くと新しいセッションになる。

正誤は既存の`useAssessmentFeedback`/`AnswerFeedbackNotice`へ配線する。1500msの○/×と設定に従う既存効果音、演出後も読める太字の補足を再利用し、独自の正誤表示・音源は作らない。復習は共通LearningReviewDialog/LearningPlayerが元ステップを表示し、閉じても回答履歴は変わらない。

## 基準書・既存実装との相違

- DFS基準書§4には「両問正解で完了」「問1で正解したFについて出題」が残る。教材指針の2026-11-06改訂と現在のassessment/BFSはソフトゲートへ統一済み。AGENTSの優先順位に従い、新しい教材指針と現行共通基盤を採用する。基準書の古い完了案を新しいハードゲートとして復活させない。
- 問1の指定復習はpop-f（12）。動きを見られるよう直前のskip-b-from-d（11）を開始点に加え、11→12の元ステップを再生する（BFSの先例と同じ）。問2は指定どおり13→14。
- 基準書の完了キャプション案は「動きを追えた」と次のコード接続を予告する。誤答のままでも完了できるため、単品では初回正解数だけを表示する。次段階への予告は教材指針#141のブリッジの責務であり、今回の接続対象外。専用リザルトや単元フローは実装しない。
- BFSの機能READMEには旧ハードゲートの履歴が残るため、判断はREADMEより新しい教材指針と現在の実装・verifyを正とした。

## 確認方法

起動済みの作業環境: `http://localhost:3123/learning-preview/dfs-check`。通常のfront開発サーバー: `http://localhost:3000/learning-preview/dfs-check`。認証・DBは不要。

1. 問1でAなどを選び、復習ボタンからFの取り出しを確認する。閉じてFを選び直し、「次の問題へ」を押す。
2. 問2でFなどを選び、復習でFに追加がない→残っていたEを取り出す動きを見る。閉じてEを選び直し、「結果を見る」を押す。初回を両問間違えた結果は0/2。
3. 「もう一度解く」でF→次の問題へ→E→結果を見ると2/2。両問ともAを選んでそのまま次へ進んでも0/2で完了する。
4. 正解後は丸を押しても回答を変更できない。補足文は○/×が消えた後も読める。復習の閲覧は自動では始まらず、任意に開ける。

アプリ組み込み・進捗・学習ログ保存・他段階との接続は対象外。DB・seedの変更および適用は不要。
