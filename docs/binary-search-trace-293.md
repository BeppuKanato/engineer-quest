# 二分探索 視覚デバッグ（トレース）（Issue #293）

目的: 二分探索単元の視覚デバッグを、基準データ §3 フェーズ7（ボタン文言「範囲が狭まる様子を見る」、D1 の実行を配列図で再生し lo / hi / mid のマーカーと範囲外の切り捨てを見せる）と §4（共有ハーネスへの lo / hi / mid / target の int パススルー加算、単元側で array と lo・hi・mid から盤面スナップショットを作る変換）として実装する。構成はバブルソートの視覚デバッグ（#234）の型に従う。最終確認日: 2026-11-07。

## 実装

- 共有基盤（加算のみ）:
  - `front/public/python-trace-harness.mjs`: `_eq_locals` のスカラーパススルーに `lo` / `hi` / `mid` / `target`（int）を追加した。対象名の変数が無い単元では何も記録されず、既存単元のトレース結果は変わらない。
  - `front/src/lib/pythonTrace.types.ts`: `PythonTraceLocals` に同4キーを追加した。
- `front/src/features/learning/binary-search/trace/`（モジュール README に詳細）:
  - `acquireTrace.ts`: 表示用 D1（主教材 [3, 7, 12, 19, 25, 31, 42] で 25）だけを、Worker を作り直して送る。判定用 J1〜J3 の引数・期待値は送らない。イベント上限は既定 500。
  - `convertTrace.ts`: ハーネスのイベント列（array と lo / hi / mid）から、フェーズ2と同じ盤面型 `BinarySearchExecutionCanvasState` のスナップショット列を組み立てる。行イベントは実行直前に発火するため、比較は「範囲の更新・発見・return」が現れるイベントで確定させる（比較を保留し、範囲が保留中の中央の片側を超えた時点で「捨てた側の盤面」と「確定した範囲の盤面」をこの順で確定する。範囲が中央を含んだまま狭まる場合は保留を確定させずに解消し、次の比較として扱う）。正しい二分探索を再実行して差し替える処理はない。
  - `BinarySearchTraceDialog.tsx`: 既存 LearningPlayer とフェーズ2の `BinarySearchExecutionCanvas` を組み合わせるモーダル。下に観測行と values・lo・hi・mid・target を表示する。
  - `trace.content.ts` / `trace.types.ts`: 文言と型。
- `BinarySearchImplementationPreview.tsx`（フェーズ7画面）へ接続した: 編集画面と全テスト通過後のリザルトの両方に「範囲が狭まる様子を見る」ボタンを置き、取得中は編集・採点実行・試し実行・ヒント・重複実行を無効にする。学習イベント（implementation_run kind=trace / trace_result）はバブルソートと同じ契約で送る。

  - 正解コードの再生が、フェーズ2の正準11コマと盤面・強調・キャプションまで完全一致すること。スナップショットがコピーであること（過去イベントの書き換えが後続へ波及しない）。

## 留保（判断が必要な点）

- **発見の判定は戻り値ではなく最後の比較から行う**: 共有ハーネスは整数の戻り値を返さない（戻り値の記録は dict・グリッド・数値リストのみ）ため、「関数が正常に返った時点で、保留中の比較の中央が探す値と一致している」ことを発見の判定に使っている。中央が探す値と一致しているのに -1 を返す誤実装では、発見として表示される。行情報と盤面からは判別できないため割り切った近似であり、正確にやるにはハーネスの戻り値記録に整数を加える拡張が要る（本 PR の範囲外として見送った）。
- **最終状態表示へ落ちる実装の範囲**: lo / hi / mid という変数名を使わない実装（left / right / center 等の別名、線形探索、内側関数を使う再帰）は、バブルソートの規約どおり推測せず最終状態表示へ落とす。フェーズ7のヒントとテンプレートは lo / hi / mid へ強く誘導しているため、通常の学習経路では再生できる想定。
- **不正な範囲更新への近似**: 範囲が中央を含んだまま狭まる更新（例: `lo = mid`）はフェーズ2の意味論に無い形のため、捨てる盤面を作らず保留を解消して次の比較として扱う近似にした（誤コードでも「見つからなかった」という嘘の結末にならないことを優先した）。
