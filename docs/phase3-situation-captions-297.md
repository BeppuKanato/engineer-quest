# フェーズ3 状況キャプション追加（Issue #297）

目的: フェーズ3（動きの確認問題）の問題画面に、場面の状況を1文で示すキャプションを追加し、処理中色（青）の時間的な意味を文章で固定する。対象はバブルソートと棒倒し法。最終確認日: 2026-11-08。

## 問題（レビュー #297 の指摘）

場面はフェーズ2のステップ盤面をそのまま再利用するが、フェーズ2で意味を確定させていたステップキャプションが問題画面には出ない。

- バブルソート Q1: 場面 `compare-1-1` の青ペア (4, 5) は「比べ終えたペア」だが、青の語彙は「処理中＝今まさに比べているペア」で、学習者は推論が必要だった。Q2 では場面の青ペアが「これから比べるペア (5, 1)」に付け替わり、同じ色の時制が設問間で反転していた。
- Q1 では「次のペア」自体が答えのため、次のペアを視覚的に強調する直し方は成立しない。直せるのは直前のペアの意味の明示だけであり、ユーザーの決定により案1（状況キャプション、文言のみ）を採用した。案2（直前ペアの内側枠への格下げ）は「ぱっと見混乱する」として不採用。

## 実装内容

設問型に `situation: string` を追加し、プレビューの問題文の下（操作指示の上）に太字15pxで表示する。文言はハードコードせず、検証済みトレースから導出する。内容モジュールの読み込み時照合にキャプション文そのものを含め、トレースとずれたら落とす。

### バブルソート（`bubble-sort/check/`）

- Q1: 場面ステップの比較（ペア・交換有無）から完了形を導出 → 「4 と 5 を比べて、そのままにしました。」（交換ありなら「入れ替えました」）
- Q2: 前提として確定した次の比較から未来形を導出 → 「次に、5 と 1 を比べます。」Q2 が問うのは比べた後の大きい値の行き先であり、比べるペア自体は Q1 の前提として確定済みのため、答えは漏らさない。

### 棒倒し法（`wall-extension/check/`）

同型の反転があったため同じ仕組みを適用した。場面 `extend-2-4` の青い柱は伸ばし終えた柱 (2,4)、Q2 の場面では処理予定の柱 (4,4) へ移る。

- Q1: 場面の processing から直前の伸長を引いて完了形を導出 → 「真ん中の段の左の柱から、下へ壁を伸ばしました。」
- Q2: 前提の次の伸長から未来形を導出 → 「次は、真ん中の段の真ん中の柱から壁を伸ばします。」柱の位置表現はフェーズ2キャプションの言い方（段＋左右）に合わせ、座標から機械的に導く。方向は既存の「方向の指示」表示が担うため、キャプションでは柱の特定に留める。

## 他単元への適用判定

- 二分探索: 変更なし。Q1 の場面（`range-after-drop-left`）には処理中要素がなく（mid は null）、問題文自体が「左側を捨てました」と完了した操作を含む。Q2 の center は「今見ている真ん中」で、問題文も「比べた後」と時点を明示し、捨てた範囲はグレー（discarded）で過去と区別できる。青の時制の曖昧さは存在しない。
- 穴掘り法: 変更なし。場面 `dig-3` の青マス (5, 3) は掘り手の現在位置そのもの（現在形）で、Q1・Q2 で場面と意味が変わらない。問題文にも「(5, 3) から右へ掘ります」と現在位置と方向が明示されている。
- BFS: 変更なし（既知の通り、調べ終えたノードは completed グレー、キューは queued ベージュと、状態語彙そのものから時系列が読める）。

## 検証

- `verify:binary-search-check` / `verify:maze-digging-check` / `verify:bfs-check` / `verify:bubble-sort-unit` / `verify:wall-extension-unit`: 通過（変更なし単元の回帰なし）。
- front typecheck / lint（変更範囲） / build: 通過。
- DB・seed の変更なし。実機の目視確認は未実施（マージ後に単品プレビュー `bubble-sort-check` / `wall-extension-check` で確認可能）。
