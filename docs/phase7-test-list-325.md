# フェーズ7テストタブの一覧主構造化（Issue #325）

目的: フェーズ7「自分で実装」のテストタブの結果表示を、ユーザーレビュー #325 の期待（「✓ or × [テストケース名]」の一覧）どおり、一覧を主構造とする形に組み替える。
最終確認日: 2026-11-09

## 問題（変更前）

- テスト結果は1行ずつ（描画チェック＋太字の名前＋✓ 通過などの状態文）並んでいたが、表示テスト（D1/D2）の行の直下に入力テキスト・期待図（210px）・実際図が割り込んでいたため、タブの上部を図が占め、一覧として読めなかった。
- 通過した行は描画チェック（DrawnCheck）と「✓ 通過」のテキストで二重に印が付いていた。

## 変更内容

対象はフェーズ7プレビューを持つ5単元すべて（BFS／バブルソート／棒倒し法／穴掘り法／二分探索）。提示だけの変更で、結果データ・判定・#319 の採点シーケンスの仕組み（1件ずつの出現アニメーションと音、全通過時のみ紙吹雪と歓声、自動遷移なし、達成バナーのオーバーレイ）には触っていない。

1. **共通化**: 5単元の `ImplementationResults` は構造がほぼ同一で、単元ごとに違うのは表示テストの図の描き方だけだったため、一覧表示を担う共通コンポーネント `front/src/features/learning/implementation/ImplementationTestResults.tsx` を新設し、各単元の `ImplementationResults` は「行データ＋単元固有の図」を渡す薄いアダプタに置き換えた。
2. **一覧主構造**: テストタブの主構造は全テストの一覧（1テスト1行）。行は「✓/×/○ の印 + テスト名 + 状態（通過／未通過／未実行）」で、結果が届くたびに印が短いアニメーションで現れる従来の動きは共通コンポーネントに移して維持した。
3. **図の分離**: 表示テストの入力・期待・実際の図は行の下ではなく、一覧全体の下の「図のまとまり」へ移した。各表示テストはテスト名の見出し＋開閉ボタンで区切り、通過したテストの図は既定で閉じる（未通過・未実行は開いた状態が既定）。開閉は学習者が切り替えられる。コンソールタブの戻り値図（260px）は別タブの話なので変更していない。図の高さ（表示テスト210px）も従来どおり。
4. **二重印の解消**: 行の印はテキスト（✓/×/○）に一本化し、DrawnCheck は行から外した。理由は、ユーザーの期待形式が「✓ or × [テストケース名]」というテキスト印そのものであることと、小さい行内でも読み取りやすいこと。描画チェックは完了バナー・完了画面での使用を継続する。

## 検証

- 5単元の `verify:*-implementation` を新しい契約へ更新して全て通過させた。旧契約の主張（行ごとの描画チェック本数など）は、テキスト印の本数・共通コンポーネント経由の描画・通過図の既定閉じを主張する形に置き換えた。判定テストの入力・期待・実際が漏れないこと（秘匿の検証）は従来どおり維持している。
- フロントの型チェック（`tsc --noEmit`）と build を通過させた。
- 実機での目視確認は未実施。確認方法は PR 本文に記載する。
