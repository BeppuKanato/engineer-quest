# 棒倒し法 フェーズ7（自分で実装）（Issue #212）

目的: 棒倒し法単元のフェーズ7を、参照コード（契約 wall-extension-v1）と同じ `generate_maze(size, choices)` の自由記述課題として実装し、表示用2件＋判定用3件の全通過を完了条件とするハードゲート、試行中の4段ヒント、D1専用の試しに実行までを単品で操作できるようにする。設計は基準データ（docs/concept/wall-extension-unit-baseline.md §2・§3、正本は未マージのため承認済み原本に従う）と教材指針フェーズ7、BFS フェーズ7の実装の型に従う。最終確認日: 2026-11-06。本 PR は feat/wall-extension-phase6-211（PR #222）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/wall-extension/implementation/` に content / ロジック / Preview / 結果表示 / ヒント / 試しに実行 / README.md を新設（構成は BFS フェーズ7に合わせた）。単品プレビュー `/learning-preview/wall-extension-implementation` に登録。
  - 課題: `generate_maze(size, choices)` の実装。テンプレートは関数定義と方向の対応表（辞書）を与え、残りは自由記述。戻り値は 0（通路）/1（壁）の2次元リストで、フェーズ4の参照コードと契約を一致させた。
  - テスト（すべて実行検証済み）: 表示用 D1（9×9、choices [3,1,2,0,2,0,2,2,0]、主教材）／D2（7×7、choices [1,2,2,0]）、判定用 J1（9×9、choices [0,3,1,2,0,1,1,0,2]）／J2（7×7、choices [0,1,1,2]）／J3（11×11、choices 16件）。期待グリッドは盤面データの正本 `wallExtensionMaze` の組み立て（外周＋柱＋伸長）から導き、フェーズ1〜6の盤面とずらさない。D1 の期待グリッドがフェーズ2の完成盤面と一致することも検証で照合する。
  - 結果表示: 表示用は入力（盤面の大きさと方向の番号）・期待する迷路・実際の迷路を示す。実際の迷路は期待と違うマスをフォーカス青の枠で示し、件数を併記する（色だけに頼らない）。判定用は種別・合否だけを示し、値・標準出力・生の例外は画面状態へ渡さない（BFS フェーズ7と同じ秘匿契約）。
  - 試しに実行: D1 だけを Worker を作り直して実行し、戻り値の迷路をグリッド描画で示す（期待と違うマスの枠表示つき）。通過数・実行回数・完了判定は変えない。
  - ヒント（試行中の4段ラダー）: L1 使う部品（grid / pillars の説明と挿入トークン）、L2 処理の流れ（①外周を壁にする ②2マスおきに柱を立てる ③柱ごとに選んで隣を壁にする、の番号付き表示で、③を「柱の数だけくり返し」の破線枠で囲む）、L3 条件とループの骨格（参照コードの意味ID `for-pillar-row`／`for-pillar-column`／`if-first-row` の3行を原文のまま）、L4 並び替え前のコード（フェーズ6の Parsons 盤面を共通 `ParsonsBoard` で練習モード表示、採点しない）。
  - エディタは BFS フェーズ7と同じ画面契約（ライトテーマ、フォーカス色2px枠＋「Pythonコード」見出し）。全通過時は紙吹雪と大きな描画チェックで完了を示す。視覚デバッグ（学習者の生成過程のステップ表示）は Issue #213 の対象として含めていない。

## 留保（判断が必要な点）

- J3 は性質検証ではなく固定 choices の完全一致とした。基準データ §3 は J3 を「性質検証」と定めるが、既存の教材テスト基盤（`runCourseMissionTests` と Worker）は期待値との完全一致（Python の `==`）だけで判定し、カスタム検証関数の差し込み口を持たない。性質検証のために判定基盤へ新しい仕組みを足すのは本 Issue の範囲を超えるため、固定 choices の完全一致で判定し、期待グリッドが完全迷路の性質を満たすことは検証スクリプト側で示した。判定基盤にカスタム検証の差し込み口ができた時点で、J3 を性質検証へ差し替えるのが本来の形である。
- テンプレートには方向の対応表（辞書）そのものを含めた。基準データの「方向の対応表の置き場だけ与え」を、対応表を置いた状態で渡す解釈とした（BFS フェーズ7のテンプレートが import 文を与えるのと同じ考え方）。対応表の中身はフェーズ4・5で学習・確認済みであり、フェーズ7の負荷は組み立ての論理に寄せた。空欄にして思い出させる形にする場合はテンプレートの変更だけで済む。
- Preview は `LearningInstrumentation` の `active` を受け取るが消費していない（BFS フェーズ7では視覚デバッグのダイアログが使う）。棒倒し法の視覚デバッグは Issue #213 で追加し、その際に接続する。
- 基準データの正本（docs/concept/wall-extension-unit-baseline.md）は PR #216 が未マージで本スタックに無いため、承認済み原本の §2・§3 に従った（フェーズ3〜6の実施記録と同じ留保）。
