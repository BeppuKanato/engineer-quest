# 大目標の設定UIとホーム表示

- 目的: 大目標の設定画面（単元開始時）と、ホーム画面での目標表示を実装する（Issue #367、親 #364、依存 G2 #366 の提案 API）。
- 最終確認日: 2026-11-10
- 正本: 実装仕様「2026-11-10_大目標モデル実装仕様」4章・7章、モック「モック 大目標の設定と表示」（叩き台。実画面の構成に合わせて実装）

## 実装内容

### API クライアント（`front/src/api/bigGoal.api.ts`）

- G2 の `/api/big-goals` に対する型つきクライアント。レスポンス形は back の `bigGoalProposal.service.ts` の返却形を正とする。進捗（progress／evaluation）はサーバ側のコード計算の結果であり、フロントでは再計算しない。

### 単元開始時の目標設定（`front/src/features/learning/app/bigGoal/BigGoalGate.tsx`）

- `LearningScreen` の単元コンテナを `BigGoalGate` で包み、学習画面を開いた時点で提案 API（タイミングA：`POST /big-goals/proposals`、機会ごとの eventKey で冪等）を呼ぶ。
  - 候補なし（FAILED／NO_CANDIDATES＝カバー済みの単元・完了済みの単元）と、過去に合意済み（selectedCandidateKey あり）の場合は、設定を挟まずそのまま学習へ進む。
  - 生成中（GENERATING）は状態表示を出し、1.5秒間隔でポーリングする（フィードバック v1 の表示と同じ間隔）。
  - 生成済みで未合意の場合は設定画面を学習の前に挟む。
- 設定画面: 本命（おすすめ）を先頭に強調表示し、表示は本命＋他の候補2件まで。全候補に適合度と根拠を表示する。候補カードの選択で選び直しができ、「この目標ではじめる」で合意（confirm API）して初めて確定する。黙って有効化はしない。
- 確定時の 409（状態が変わって候補が合わなくなった場合）は、理由を示したうえで「学習をはじめる」導線を出す。生成に失敗した提案（NO_CANDIDATES 以外の FAILED）も、理由と進む導線を示す。
- 提案の取得自体が失敗した場合は、そのまま学習へ進める（fail-open）。大目標まわりの障害や、migration 未適用の環境で学習自体を止めないための判断であり、目標設定が学習の前提条件にならないようにした。

### ホーム表示（`front/src/features/learning/app/bigGoal/BigGoalBanner.tsx`）

- ホーム画面の上部に、アクティブな大目標を1件だけバナー表示する：表示文、進み具合（API の割合をそのまま％表示＋バー）、進捗の事実の一文。
  - 一文は評価の内訳（detail）から作る（到達型＝「7つのステージのうち3つが完了しています」、応用型＝完了件数、実績型＝獲得の有無）。数値は API の値をそのまま使い、フロントで数え直さない。内訳から文を作れない場合は無理に表示しない。
  - 目標の表示に所要日数・期限などの時間指定は付けない。
- 終了した目標（達成／未達成で終了／見直し済み）は「これまでの目標」として履歴表示する。状態の文言は「達成」「終了」「見直し済み」とし、非難の表現や赤・× は使わない。
- 取得に失敗した場合はバナーを出さず、ホーム自体は壊さない。

## モックから変えた点と理由

- モックの目標設定画面は達成時（タイミングB）の提示だったが、G3 の実装対象は単元開始時（タイミングA）のため、見出しと導入文を開始時の文脈に合わせた。達成時の提示（達成の事実＋次の目標の提案）はフィードバック専用画面（F1、#369）の範囲で扱う。
- モックのホームバナーは小さなパス図で進捗を表していたが、本実装ではバー＋割合＋事実の一文で表した（進捗の数値を API の計算結果のまま出すことを優先。図による近づきの表現は専用画面側の検討に委ねる）。
