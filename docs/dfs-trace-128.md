# Issue #128 DFS の視覚的デバッグ実装記録

- 目的は、学習者のコードでスタックと訪問順がどう変わり、どこで止まったかを基本グラフの上で見返せるようにすること。
- 対象は DFS「自分で実装」の表示用テスト D1 と、トレース取得・変換・再生。
- 最終確認日 2026-11-10
- 正本は [Issue #128](https://github.com/BeppuKanato/engineer-quest/issues/128)、[DFS 基準データ §2・§9-7](concept/dfs-unit-baseline.md)、[教材指針 §7-3](concept/learning-materials-guideline.md)。

## 実装

「グラフで動きを見る」は、新しい Worker に基本グラフと出発点 A だけを渡し、既存の実行時間上限と500イベントの上限を使う。DFS モードはスタック、発見済み集合、訪問順と処理対象を採取する。名前が異なる場合は、ループ内で `pop` を呼ぶリスト、直接返すリスト、一意な集合といった手掛かりで識別する。候補が曖昧なときは最終結果と停止位置を示す。

再生には「動きの説明」と同じ図とプレイヤーを使う。訪問順の記録を取り出しと一コマにまとめ、発見済みの記録は対応する追加と同時に見せる。正解コードでは17場面の状態と強調が一致する。取り出し順などを変えたコードは、観測した順序をそのまま使う。途中でエラーが出た場合は観測できた状態と停止行、図にできない値や上限に達した場合は表示できたところまでを示す。戻り値は最後のコマで確認できる。

## 確認方法

front の開発サーバーで [DFS 自分で実装](http://localhost:3000/learning-preview/dfs-implementation) を開く。

1. 基準データ §7.1 のコードで「グラフで動きを見る」を押し、訪問順 A → B → D → F → E → C と、スタック・発見済み集合の変化を確認する。
2. `stack.pop()` を `stack.pop(0)` に変更して再実行し、実際の取り出し順が図に反映されることを確認する。
3. `stack.append(neighbor)` を `raise RuntimeError()` に置き換え、停止前のコマとエラーの行を確認する。

`npm run verify:dfs-trace` は、共通ハーネスを CPython で実行して正解コードの17場面、取り出し順の変更、変数名の変更、曖昧な候補・エラー・上限での表示、D1 のみの取得を検証する。DB の適用は不要。
