# バブルソート フェーズ3（動きの確認問題）（Issue #229）

目的: バブルソート単元のフェーズ3を、フェーズ2の場面を参照する連結2問のアセスメントとして実装する。設計は基準データ（docs/concept/bubble-sort-unit-baseline.md §3、正本の取り込みは Issue #226 のため、本実装は承認済み原本に従う）に従う。最終確認日: 2026-11-06。本 PR は feat/bubble-sort-phase2-228（PR #239）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/bubble-sort/check/` に content / types / Canvas / Preview / README.md を新設（構成は棒倒し法フェーズ3と BFS フェーズ3に合わせた）。
  - `check.types.ts`: 共通エンジンの node-tap 形式の設問型・コンテンツ型と、単元接続用の要約型。棒倒し法フェーズ3の「方向の指示」に相当する追加フィールドは、バブルソートでは設問文が対象の値（5）を直接指すため設けていない。
  - `check.content.ts`: 設問・正解・依存条件・復習ID・タグ・完了文。場面はフェーズ2の `compare-1-1`（1周目の2回目の比較まで終えた状態、配列 [2, 4, 5, 1, 3]）をステップIDで参照し、配列を複製しない。正解は `../bubbleSort.ts` の実行記録の次の比較（1周目 j=2、ペア (5, 1)、交換あり）から導き、基準データ§3の確定事項（位置2 → 位置3）との一致をモジュール読み込み時に検証する。
  - `BubbleSortCheckCanvas.tsx`: 描画は共通配列基盤（`ArrayDrawing`）へ委譲し、回答ボタンは棒の列に重ねる HTML ボタン。共通の `answerCueSx`（破線リング＋タップアイコン）を使い、`aria-label` は「左から○番目のマス（値 ○）を選ぶ」。画面上で44px未満になる場合は中心から広げる。
  - `BubbleSortCheckPreview.tsx`: BFS・棒倒し法フェーズ3と同じ画面構成（キャプション、回答フィードバック、復習モーダル、embedded / onComplete による要約通知）。
- 設問（連結2問、教材指針の「処理対象の特定→直後の変化」）:
  - Q1 `next-pair`「次に比べるペアの左側のマスはどれか」: 回答対象は未確定範囲のマス（この場面では全5マス）、正解は位置2（値5）。場面はフェーズ2のステップ canvas そのもの（参照同一）。
  - Q2 `larger-destination`「比べた後、大きい方の 5 はどのマスへ行くか」: 回答対象は比べるペアの2マス（位置2・3）、正解は位置3。`requires` で Q1 の正解と連結する（データ検証として保持し、進行は位置ベースの現行仕様に従う）。
- 回答形式は共通エンジン（`assessment.ts`）の `node-tap-check` をそのまま使い、ノードIDの代わりに配列の位置（インデックス）の文字列を渡す。新規の判定・進行は作っていない。
- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」で進む。正解していなくても進める（ソフトゲート）。完了は「最後まで進み、全問に1回以上回答」で、要約は初回回答のみから導く。正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 復習は両問ともフェーズ2の元ステップ `compare-1-1` → `compare-1-2` を参照のまま再生し、回答記録を変えない。
- 単品プレビュー: `/learning-preview/bubble-sort-check`（フェーズ1・2と同じ登録方法）。

## 検証

- `npm run verify:bubble-sort-check`（新規）: 正解が実行記録の次の比較（1周目 j=2、ペア (5, 1)、交換あり、比較後の配列で 5 が位置3）と一致すること、Q1の場面がフェーズ2の該当ステップと参照同一で Q2の場面も同じ配列（comparing が [2, 3] へ移る）であること、回答対象の範囲（Q1=未確定範囲の全5マス、Q2=ペアの2マス）、共通エンジン経由の完了条件（回答では進まない／未正解でも完了できる／初回結果の保持／古い設問への回答の混入防止）、実描画の棒の本数と回答ボタンの数・ラベル・ロック、プレビューの実コールバック（復習の開閉、Q2場面のペア表示、完了キャプション）を確認。
- 回帰: `verify:bubble-sort-execution` / `verify:bubble-sort-motivation` / `verify:wall-extension-check` / `verify:bfs-check` 通過。front の `lint`（警告1件は既存 BfsUnitPreview の無関係なもの）/ `typecheck` / `build` 通過。
- DB・シードの変更はない。

## 留保（判断が必要な点）

- Q2の場面の作り方: フェーズ2に「比べる直前」のステップは無いため、Q2の場面は `compare-1-1` の配列（値は同一）を保ったまま、これから比べるペアを前提設問の正解の位置から [2, 3] と示し、直前の比較を表す highlight を外して導出している（`getBubbleSortCheckScene`）。ステップ canvas の参照同一で済むのは Q1 のみ。「場面の配列が該当ステップと一致する」という要件は、値の配列については両問とも満たす。
- Q1の場面では、直前に比べたペア (4, 5) が青いまま残る（フェーズ2のスナップショットの意味どおり）。「次に比べるペア」を問う場面として、直前に比べた位置を示す手がかりとして残した。
- Q1の回答対象は未確定範囲の全マス（この場面では位置0〜4）とした。右端の位置4はペアの左側にはなり得ないが、未確定範囲のマスをそのまま候補にする棒倒し法フェーズ3（Q1は柱全マス）の考え方にそろえた。Q2は逆に、大きい値の行き先がペアの2マスに限られるため候補を2マスに絞った。
- 設問文は基準データの表記どおり句点・疑問符なし（「次に比べるペアの左側のマスはどれか」）とした。BFS / DFS の設問文は「？」で終わるため、表記をそろえる場合は別途判断がいる（棒倒し法フェーズ3と同じ留保）。
- 基準データ正本（docs/concept/bubble-sort-unit-baseline.md）は Issue #226 で取り込み予定のため本 PR には含まれない。本実装は承認済み原本 §3 に従った（フェーズ1・2と同じ留保）。
