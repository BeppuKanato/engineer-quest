# Issue #148 フェーズ6のボタンの近さと優先順位 — 実施記録

実機レビュー（#148）の2点への対応。対象はフェーズ6（応用・総括）の画面。

## 1. 選択肢が図から離れすぎている

- 原因: 図（`ConsolidationGraph`）の領域が残りの高さいっぱいに伸びる（flex: 1）ため、指示文と選択肢が画面の下端まで押し下げられていた。図の描画自体はアスペクト比で収まるので、伸びた分は空白になっていた。
- 対応: プレビュー側で図の高さに上限（`min(54dvh, 600px)`、最小320px）を設け、指示文と選択肢が図の直下に並ぶようにした。指示文は太字にし、選択肢ボタンも太字にして視認性を上げた（形・大きさは従来どおり高さ48pxのピル型）。
- ノードを選ぶ問題でも、指示文が図の近くに来ることで「何ができるか」が伝わりやすくなる。

## 2. 並び替えで主なボタンが分からない

- 対応: 「この順序で回答する」を outlined から contained の主ボタン（高さ48px・太字・focus 青）に変更し、「提示順に戻す」は従のテキストボタンのままにした。
- 回答後の「次の問題へ／診断結果を見る」も同じ主ボタン形式にした。復習ボタンは従のまま。
- フェーズ7のヒントで使う並び替え盤面（回答ボタンなしの練習モード）には影響しない。

## 検証

- `verify:bfs-consolidation` に、図の高さ上限と、主な操作2つが contained の主ボタンであることを固定した。
- front の lint / typecheck / build と verify 全16件が成功。判定・フィードバック（#146）のロジックは変更していない。DB・シードの変更なし。

## 確認方法（マージ後・ローカル実行時）

1. フェーズ6の選択問題: 指示文と選択肢が図の直下に表示され、画面下端まで離れていないこと。
2. フェーズ6の並び替え問題: 「この順序で回答する」が青い主ボタンとして目立ち、「提示順に戻す」より優先して見えること。回答後は「次の問題へ／診断結果を見る」が主ボタンになっていること。
