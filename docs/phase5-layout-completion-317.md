# フェーズ5レイアウト組み替えと完了ビューのバイパス（Issue #317、#315）

目的: 棒倒し法フェーズ5レビュー（#317）の3点——(1)コードがフェーズチップ列に被る、(2)選択肢を常時見える状態にしコードだけをスクロールさせたい、(3)「もう一度解く」の画面が一瞬しか出ない（フェーズ3の #315 と同一）——を、全5単元共通の構造として直す。最終確認日: 2026-11-08。

## Part 1: フェーズ5（コードの確認問題）のレイアウト

### 原因

- 各単元の code-check プレビューは `justifyContent: "center"` の縦フレックスで、縦の上限もスクロールもなかった。コード実体は行ピッチ約29〜32pxで、棒倒し法の正本21行だけで約620〜680px。問題文・指示・選択肢との合計が表示領域（ノートPC実効約1093×614では約493px）を超えると、中央寄せのため上下対称にはみ出し、上はチップ列に被り、下は選択肢が画面外に出た。
- 選択肢は元々最初から描画されていた。見えなかったのは画面外に押し出されていたためである。
- この構造は5単元（BFS／バブルソート／棒倒し法／穴掘り法／二分探索）で同一であり、棒倒しが最悪ケースというだけだった。

### 実装（5単元の code-check プレビューに同一の組み替え）

- セクションを高さ固定（埋め込み時100%／単品時84dvh）の縦フレックスにし、中央寄せをやめた。問題文は上部に固定（flexShrink: 0）。
- コード領域は `flex: 1; minHeight: 0; overflow: auto`（縦横両方）の窓にした。内側は margin: auto の安全な中央寄せで、コードが窓より小さいときは中央に、大きいときは先頭からスクロールできる。
- 指示文・選択肢・案内文・ボタン行は下部の固定ゾーン（flexShrink: 0）にまとめ、常に画面内に出る。
- 空欄の自動スクロールは、既存の横方向センタリングに縦方向の対応版を追加した。問題が替わるたび（およびリサイズ時）に、空欄行が視界の外にあれば縦スクロールで中央へ寄せる。
- 背の高い画面では、セクション高さ自体がビューポート比（84dvh／コンテナ100%）で制限され、コードは窓の中で上下中央に置かれるため、間延びせずに収まる。別途の最大高さは設けていない。
- 完了時（チップで戻ったとき）は完了キャプション＋「もう一度解く」が従来どおり出る（ボタンは下部ゾーンに残る）。

## Part 2: 完了ビューのバイパス（案1、フェーズ3・5）

### 仕組みと問題

- フェーズ3・5のプレビューは、最後の問題を終えた瞬間に内部の完了ビュー（完了キャプション＋「もう一度解く」）へ切り替わり、同時に単元コンテナへ完了を通知する。コンテナは従来、進捗保存APIの完了を待ってから結果画面へ遷移していたため、完了ビューの表示時間＝保存の往復時間（体感1〜2秒）となり、読むことも使うこともできなかった（#315 の「進捗保存中に出てる画面内容が変化した」の正体）。

### 実装（5単元の単元コンテナに同一の変更）

- `transitionOut === "result"` のフェーズ（3・5）では、完了通知を受けた時点で結果画面へ即時に遷移し、保存は並行して行うようにした。他の遷移（bridge／result-in-phase／final）は従来どおり保存完了後に遷移する。
- 保存中は従来の「進捗を保存しています…」ピルが結果画面上にも出る。保存に失敗した場合は、コンテナ直下の警告（Alert）が画面種別に依らず表示され、コンテンツは inert のまま再試行できる。再試行時は遷移と `phase_complete` の記録を繰り返さない（failed の対象フェーズと一致するかで判定）。
- 完了キャプションは結果画面へ移していない。結果画面は「事実のみ、次の目標はブリッジが担う」が既存の文言原則であり、完了キャプション（次フェーズへの動機づけ文）はその原則と合わないためである。前進フローでは落とし、チップでフェーズに戻ったときの完了ビューと単品プレビューでは従来どおり表示される。
- 「もう一度解く」は、結果画面からチップでフェーズへ戻れば従来どおり使える（プレビューはマウントされたまま完了状態を保持する）。完了ビュー自体のボタンは残している。

### フィードバック（#202）との相互作用

- 結果画面が保存完了前に表示されるようになったため、結果画面のフィードバックは保存が確定してからマウントするよう絞った（`!saving && !failed`）。未保存のまま先行リクエストすると、バックエンドは未完了として404を返し、FeedbackV1 はその画面では二度と表示されなくなるためである。先行生成（onCheckPhaseCompleted）は従来どおり保存成功後に発火する。

## 検証

- front typecheck: エラーなし。
- front の全 verify スクリプト: 全件通過（check／code-check を含む）。
- 変更範囲の lint: エラーなし（コンテナの `goToPhase` 依存警告は既存のもの）。
- front `npm run build`: 通過。
- DB／seed の変更なし。実機の目視確認は未実施（確認方法を参照）。

## 確認方法

1. ノートPC相当の表示（実効約1093×614）で棒倒し法フェーズ5を開き、問題文・コード窓（空欄が見える位置に自動スクロール）・指示・選択肢・「次の問題へ」が画面内に収まり、チップ列への被りがないこと。問題を切り替えると空欄行が視界に入ること。
2. 背の高い画面でフェーズ5を開き、コードが窓の中央に置かれて間延びしないこと。
3. フェーズ3または5を最後まで解き、完了ビューで止まらずに結果画面へすぐ移ること。結果画面にスコアと（対象者では）フィードバックが出ること。
4. 結果画面からチップでフェーズ3・5へ戻ると、完了ビューと「もう一度解く」が使えること。
5. フェーズ6の結果表示とフェーズ7の完了フローが従来どおりであること。
