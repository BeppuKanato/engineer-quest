## 実装

編集画面と全通過リザルトの「配列で動きを見る」でD1をトレースしてプレイヤーを開く。取得中はコード編集・採点・試し実行・ヒント・重複実行を無効にし、状態を表示する。トレースの利用で採点実行回数・ヒント回数は変更しない。

共通pyodideRunner／Workerのtrace経路は BFS 専用（queue・distances・node の記録）だったため、ハーネス（`public/python-trace-harness.mjs`）と型（`lib/pythonTrace.types.ts`）に、数値リストの記録（優先名 `result`、なければ型・内容で一意に検出）と整数の添字 i・j・n の記録、数値リストの戻り値の記録を追加した。BFS の検出・変換は変更しておらず、`verify:bfs-trace` が従来どおり通る。取得は毎回新しいWorkerで行い、表示用D1の関数名と引数だけを送る。判定用ケースを含むWorkerや、tests・期待値・他ケースの入力は持ち込まない。

変換は別モジュールとし、正しいバブルソートを再実行して置き換えず、実際の作業リスト・i・j からフェーズ2と同じ ArrayBarsCanvasState を生成する。行イベントは「その行が実行される直前」に発火し、比較の結果（交換後の並び）は次のイベントで初めて見えるため、比較を開始時点の並びとともに保留し、次の比較・周の切り替わり・return のイベントで、比較後の並びと比較したペアを1コマとして確定する遡及方式を採った。正解コードの再生はフェーズ2の正準16コマ（初期・比較10・各周の確定4・完成）と、並び・比べたペア・確定範囲・交換の強調がすべて一致する。

## 対応付け・判断点

- 終端コマの並びは作業リストのスナップショットではなく、実際に返されたリストを正とする（`sorted(values)` を返すなど、作業リストと戻り値が食い違う実装でも最後のコマが結果と一致する）。
- 例外や打ち切りで抜けたフレームにも CPython は return イベントを送るため、成功（status が returned）の場合だけ return イベントを終端として扱う。これを誤ると、エラー時に存在しない「周の確定」コマが混入する（検証で発見し修正済み）。
- 外側ループの行イベントでは j が前の周の値のまま残るため、そのイベントからは比較を始めず、周の終わりの確定コマを挟む。変数表示の i・j はPythonに残っている実値であり、図の比較ペアは確定した比較を示す。
- 作業リストの候補が複数あり `result` という名前もない場合は、推測せず最終状態表示へ落とす。入力 `values` をコピーした別名リストで作業する実装はこの対象になる（想定解法に沿った `result = list(values)` 形式が段階適用の範囲）。
- `values` を直接並び替えるインプレース実装は、候補が1つだけのため型・内容の検出で再生できる（フェーズ7のテスト判定がインプレースを不合格にしないことと整合）。
- i・j を使わない実装（while など）では並びの変化だけを追い、比べたペアは示さない。負数を含む並びなど棒で描けない状態は飛ばし、末尾が描けない場合は変換できた範囲を「途中まで表示」と明示する。再帰など作業リストのスナップショットが取れない構造、変換できた状態がない場合、候補が曖昧な場合は最終状態モードへ落とす。
- エラー時はそこまでの状態を保ち、最後を停止行・種別のフレームにする。変換不能でも停止行と種別は表示する。最終状態モードは1フレームで再生操作を無効にする。
- 1イベントのコピーはコレクション64件・文字列100文字まで、記録は既定500件（APIの上限2000件）。時間上限は既存の15秒。ネイティブ処理などで時間切れになるとWorkerが破棄され記録は取り出せないため、再生せずタイムアウトを表示し、新しいWorkerで再試行できる。

参照コード（bubbleSortCode）・フェーズ7のテスト・4段階ヒント・試しに実行・フェーズ2のステップデータは変更していない。フェーズ7の検証 `verify:bubble-sort-implementation` にあった「視覚デバッグは #234 の対象」というスコープpinは、接続済みを確認するpinへ更新した。DB適用なし。単元フローへの組み込み・接続は対象外（Issue #235）。

## 確認方法

`front/`で依存をそろえて `npm run dev`。起動したマシンのブラウザで http://localhost:3000/learning-preview/bubble-sort-implementation を開く。ログイン・バックエンド・DB不要。

1. MonacoとPyodideの読込完了を待つ。正解に沿った bubble_sort を書き、「配列で動きを見る」を押す。
2. モーダルで再生・一時停止・前後・シーク、矢印／Home／Endを操作する。フェーズ2と同じ順で比較・交換が進み、各周の終わりに右端の値が確定表示（グレー）になる。最後は [1, 2, 3, 4, 5] と空の比較表示になる。
3. 比較条件を `result[j] < result[j + 1]` へ変えて確認する。降順に並び替わる過程がそのまま再生され、最後は [5, 4, 3, 2, 1] になる（正しい並びへ差し替えられない）。
4. 交換行を `raise ZeroDivisionError("任意の本文")` へ置き換えて確認する。そこまでの状態と停止行・ZeroDivisionErrorを表示し、本文・トレースバックは出ない。
5. `while True:` で止まらないコードを実行し、途中までの表示と打ち切りを確認する。`time.sleep(20)` 等のネイティブ処理では15秒後に記録なしのタイムアウトとなる。
6. 閉じてもコード・採点・ヒント利用状態は変わらない。再試行や「テストを実行する」で通常の5テスト実行が可能で、全通過後は「配列で動きを見る」から同じコードを確認できる。テスト実行回数には再生を含めない。
