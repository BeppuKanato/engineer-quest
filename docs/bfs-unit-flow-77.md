# Issue #77 BFS単元フローの実装・検証記録

- 目的: 単品ページで確認済みの BFS フェーズ1〜7を、1つの単元として通して学習できるよう接続する。
- 適用範囲: 単元プレビュー内のフェーズ遷移、リザルト画面、単元内ナビゲーション。状態: 記録。最終確認日: 2026-11-05。
- 起点: `develop` `555969d`（PR #100マージ済み）。
- 正本: [Issue #77](https://github.com/BeppuKanato/engineer-quest/issues/77)、[教材指針の遷移モデル](concept/learning-materials-guideline.md)、[学習フロー要約](concept/learning-materials-v2.md)。詳細は[単元フロー README](../front/src/features/learning/bfs/unit/README.md)。

## 実装

単元プレビュー `/learning-preview/bfs-unit` を追加した。上部の単元ナビゲーション（フェーズ1〜7のチップと、単元完了後の「単元リザルト」チップ）の下に、幅84vwのフレームで現在のフェーズまたはリザルト画面を表示する。進捗は画面内の状態だけに持ち、保存しない。

遷移は `unit.content.ts` の `transitionOut` で駆動し、指針の3類型に対応する。

- フェーズ1→2（意思確認の区切り）: フェーズ1の最終場面に描かれているボタンそのものを、単元内でのみ有効化して進む（単品ページでは従来どおり無効表示）。
- フェーズ2→3、フェーズ4→5（シームレス）: 共通プレイヤーに最終ステップ限定の `endAction` を追加し、操作バーのボタンで次フェーズへ直結する。リザルト画面は挟まない。
- フェーズ3・5の後（リザルト）: 単元側のリザルト画面を出す。到達状況は事実のみ（全問正解と初回正解数）で、次フェーズの予告と導線を持つ。
- フェーズ6の後: 診断画面がリザルトを兼ねるため画面は切り替えず、診断内に「フェーズ7：自力実装へ進む」を追加した。
- フェーズ7の全テスト通過後: 最終リザルトを出す。称号と締めの文はフェーズ7の完了表示と文言を揃え、フェーズごとの到達状況（フェーズ3・5・6は初回正解数、フェーズ7はテスト実行回数とヒント使用）と復習導線を持つ。

各単品プレビューには任意 props（`embedded`、`onComplete`、フェーズ6は `onNext` / `nextLabel`、プレイヤー系は `nextLabel`）を追加した。未指定なら単品ページの見た目と挙動は変わらない。`embedded` ではビューポート基準の高さを親基準に切り替える。

一度開いたフェーズはマウントしたまま隠すため、戻っても再生位置・回答・フェーズ7で書いたコードが残る。前進は各フェーズの完了によってのみ解放され、ナビゲーションでは到達済みフェーズまで自由に戻れる。フェーズ3・5は完了後に「もう一度解く」でセッションを作り直せる（再完了も単元へ通知する）。

## 判断点

- フェーズ3・5のリザルトは、単品側の完了表示がキャプション差し替えのみで画面としてのリザルトを持たないため、単元側で新設した。フェーズ6は診断画面がリザルトの実質を備えているため新設せず、導線だけを足した。
- フェーズ7の完了画面は単元内でもそのまま残し、最終リザルトは単元のまとめとして別に置いた。最終リザルトから「復習する」でフェーズ7へ戻ると、完了画面（「動きを確認する」を含む）が再び見られる。
- プレイヤー UI 定義への適合（Issue #83）は本 PR の範囲外とし、従来のプレイヤーのまま接続した。アプリ本体への組み込み（入口導線、進捗保存、ログ保存）は #78 の範囲。
