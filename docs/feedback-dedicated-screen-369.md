# フィードバック専用画面

- 目的: フィードバック v1 の表示を、結果画面の付属ボックスから独立した専用画面へ移す（Issue #369、親 #364、Issue #299 の実装）。
- 最終確認日: 2026-11-10
- 正本: 方針資料「2026-11-10_大目標・フィードバック方針」（Drive）の専用画面と称賛に関する決定、Issue #369／#299、モック「モック フィードバック専用画面」（叩き台。実画面の構成に合わせて実装した）

## 導線と画面

- 確認フェーズ（3・5・6）の結果画面で「次へ進む」を押すと、ブリッジの前にフィードバック専用画面が入る。任意リンクではなく結果画面の前進そのものが導線であり、フィードバックが適用されない学習者（後述）では従来どおりブリッジへ直接進む。フェーズ6（応用問題）は結果がフェーズ内に出る形式（result-in-phase）のため、その結果からの前進（ビューの onNext）を同じ専用画面への導線にしている。なお従来のボックス表示では、フェーズ6のフィードバックは先行生成だけが行われ、表示面が無かった（結果画面にのみ差し込まれていたため）。本変更で初めて表示されるようになる。
- 単元のフィードバックは、最終結果の主ボタン「フィードバックへ進む」から専用画面へ進む（コース一覧への導線は副次に下げる）。専用画面からは「結果に戻る」で最終結果へ戻れる。
- 専用画面（`front/src/features/learning/app/feedback/FeedbackScreen.tsx`）の構成は、見出し、現在位置の図、大目標の進捗（ある場合）、4項目（現在の状態／次の目標／次の一歩／この一歩の理由）、推薦する行動の主ボタン、「そのまま次へ」（フェーズ画面）または「結果に戻る」（単元画面）の副次的な出口。
  - 推薦する行動が主ボタンで、推薦先へのアプリ内遷移の横取り（`?phase=` の解釈）は従来のボックス表示と同じ規則。出口は生成中・生成失敗時を含め常時置き、読み飛ばしは学習者の自由のまま（着手は uptake として計測される任意の選択であり続ける）。
  - 生成待ちは従来どおり先行生成（フェーズ完了保存時・最終結果表示時）＋1.5秒間隔のポーリングで受ける。結果画面を読んでいる時間がバッファになる。
  - 画面の表示は学習ログに `feedback_view`（フェーズ画面、phaseKey 付き）と `unit_feedback_view`（単元画面）として記録する。推薦の提示・閲覧・到達の計測（FeedbackObservation）は従来の仕組みをそのまま使う。
- 称賛演出は専用画面では繰り返さない（直前の結果画面で済んでいるため）。達成感は、到達の事実（位置の図）と大目標の進捗の表示で引き継ぐ。大目標の達成そのものの称賛は #370 が担う。

## 現在位置の図

- `front/src/features/learning/app/feedback/FeedbackPositionFigure.tsx`。単元のパス表現（サインカーブ、スタート／ゴールの旗）のミニ版を再利用し、固定された構造目標（単元の全7ステージの完了）に対する現在位置だけを示す。LLM が生成する「次の目標」に対しては測らない。
- 状態の色は教材・単元概要と揃える：完了は到達の青（#2563eb）、現在地は同じ青に輪を重ねて「現在地」と示す、未到達はベージュ。完了グレー・赤・× の非難表現は使わない。
- 図の状態（完了集合と現在位置）は学習状態を持つ単元コンテナが組み立て、`nav.figure` として画面へ渡す。フェーズ画面では完了した確認フェーズが現在地、単元画面では全ステージ完了として示す。

## 大目標の進捗表示

- 有効な大目標がある場合、専用画面に表示文と進捗を併記する。割合（％とバー）と事実の一文（`bigGoalProgressFact`、ホーム表示と共有）は API のコード計算の結果をそのまま使い、フロントでは再計算しない。割合が定義できない型ではバーを出さない。
- 現在の大目標は `GET /big-goals/current` で取得し、フェーズ保存・単元完了のたびに取り直す（`LearningScreen` の `refreshCurrentGoal`）。

## 達成した大目標の提示（タイミングB）

- 保存レスポンスの最小拡張（back）: フェーズ完了・単元完了の保存で大目標が達成へ遷移した場合、レスポンスに `achievedBigGoals`（id／type／displayText）を追加する。既存項目の形は変えていない。
  - `back/src/service/bigGoal.service.ts`: `evaluateBigGoalsForUser` の遷移に type と displayText を含める（取得列に displayText を追加）。
  - `back/src/service/learning.service.ts`: これまで破棄していた遷移の戻り値を受け取り、達成へ遷移したものだけを `achievedBigGoals` として返す。保存経路に新しい Prisma 呼び出しは増やしていない（評価は従来どおり保存時に実行済み）ため、CI の verify 用スタブへの追加は不要。
- フロントは保存レスポンスの `achievedBigGoals` をフェーズキー別／単元完了分に保持し、対応するフィードバック専用画面の後段に `BigGoalNextProposal` を出す：達成の事実（旗のバッジ＋「大目標を達成しました」＋達成した目標の表示文）に続き、提案 API（タイミングB：ON_ACHIEVEMENT）で得た次の目標の候補を提示する。
  - 候補提示の本体 `BigGoalSetting` を単元開始時のゲート（#367）から共有コンポーネントとして切り出し、見出し・導入文・確定ボタンの文言を文脈に合わせて差し替えられるようにした。ゲート側の表示と挙動は従来どおり。
  - 候補が無い場合・生成が失敗した場合は達成の提示だけに留め、学習の流れは止めない。確定済みの提案が再表示された場合は、選ばれている次の目標を事実として示す。
  - 単元完了と重なる達成では、最終結果の後（単元のフィードバック画面）でこの提示を行う。結果画面への統合（称賛）は #370 の範囲。
  - 到達型の大目標は、全フェーズの進捗が揃う最終フェーズの保存で達成へ遷移するのが主経路であるため、最終フェーズの保存レスポンスに含まれる達成は、単元完了保存の分と合わせて単元側の提示（単元のフィードバック画面）にも振り向けている（重複は目標IDで除く）。

## 適用されない学習者の扱い

- 実験割り当てがない学習者にはフィードバックが生成されない（409）。この学習者を結果画面の前進で画面に留めないため、先行生成のリクエスト結果から適用可否を判定する（`LearningScreen` の `feedbackAvailability`）。
  - 先行生成が成功すれば available、409／404 なら unavailable とし、unavailable の間は結果画面の前進が従来のブリッジへ向かい、最終結果にも入口ボタンを出さない。
  - 判定が間に合わず専用画面へ入った場合でも、画面側の取得が 404／409 を確定させたら本来の導線へ自動で進める。保存直後の競合で完了イベントがまだ見えない 404 は、少し待って依頼し直してから判定する（#321 の教訓。取得フック `useFeedbackV1` に集約し、従来のボックス表示 `FeedbackV1` も同じフックを使う）。

## Issue #299 の指摘への切り分け

1. フィードバックが気づかれにくい（結果画面の下部に埋もれる）→ 専用画面化で解消。
2. AI の文章が内部用語（「フェーズ」や単元キー等）を含む → 生成文そのものの問題であり、生成側（#332 系）の範囲。専用画面自体は内部用語を持ち込んでいない（見出しは「○○のフィードバック」、段階名は教材の正式名称）。
3. 進むボタンが2つある（結果画面の「次へ進む」とボックス内の「次のフェーズへ進む」）→ 解消。結果画面には自身の「次へ進む」だけが残り、専用画面の主ボタンは推薦行動1つに絞った。
4. 推薦ボタンの色がアプリの主要導線と合わない → 主ボタンを学習プレイヤーの主要導線と同じ体裁（playerTokens.focus の contained）に統一した。

## モックから変えた点

- モックの画面構成（段階チップ付きヘッダー配下に図・4項目・主ボタン・副導線）は実画面の単元コンテナのヘッダーと段階チップをそのまま使う形に寄せ、専用画面側に独自のヘッダーは作らなかった。
- モックの「図なし」切り替えは入れていない。位置の図は方針で入れることが決まっており、出し分けの分岐を持たない方が計測条件も揃うため。
- 大目標の進捗は、モック相当の位置づけ（図の下）に、API の割合と事実の一文を併記する形で実装した。
