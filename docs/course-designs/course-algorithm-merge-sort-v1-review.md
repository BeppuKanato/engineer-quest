# マージソートコース実装・受講レビュー

レビュー日: 2026-09-29。対象コースID: `course-algorithm-merge-sort-v1`。

## 結論

プログラミング経験が少なく、アルゴリズムを難しいと感じる学習者を想定し、「何を解決するか」→「半分に分ける」→「小さくなるまで同じ処理を繰り返す」→「2列を比べて結合する」→「処理全体を並べる」→「コードを組み立てる」→「自力実装」の順で受講した。全7 Mission、全32 Activityを画面で完了し、誤答、再挑戦、分割と結合のステップ操作、ヒント、コード保存と復元、7件の実行テスト、提出、コース完了まで確認した。

分割と結合を同時に説明せず、先に「半分へ分け続ける理由」と停止条件を理解してから、2列の先頭だけを比較する結合へ進む構成にした。再帰コードに入る前に処理の順番を図と並べ替え問題で確認するため、初学者が前提のない概念を一度に要求される箇所は見つからなかった。

## 自分で受講して見つけた問題と修正

| 見つけた問題 | 初心者への影響 | 修正 |
| --- | --- | --- |
| 結合図で片方の列を使い切った後も「未使用の先頭は末尾: 1」と表示されていた | 使い切った列にまだ比較対象があるように見え、残りをそのまま追加する理由が分かりにくい | ポインターを消し、「未使用の値なし」と明示する表示に変更した |
| 並べ替え問題の正解順を`correctOrder`で記述しており、正しい順番でも完了できなかった | 内容を正しく理解しても次へ進めず、学習者が自分の理解を疑う | データを`answerOrder`へ統一し、全ステップIDを重複なく含むことをフロントとバックの両方で検証するようにした |
| 全体手順の選択肢に停止条件が書かれていなかった | 「長さ1になったら止める」が補足事項に見え、無限に分割する手順として覚える可能性がある | 正解の手順内へ「長さ1以下ならそのまま返す」を明記した |
| 導入で「一定の速さ」と表現していた | 入力サイズに対して常に同じ時間で終わると誤解される | 「分割と結合を使って効率よく並べ替える」へ変更し、計算量の未学習段階でも誤解しない表現にした |

## 誤答と再挑戦の確認

- 7個の値を分ける位置で誤った区切りを選び、左右の個数差を1以下にする説明から正答へ戻れた。
- 長さ1で止める理由を誤り、値が1個なら既に並んでいるため分割が不要だと確認した。
- 結合時の比較で大きい値を先に選び、小さい値を先に結果へ移す説明から修正できた。
- 片方の列を使い切った後も比較を続ける選択肢を選び、残りの列は既に昇順なのでそのまま追加できることを確認した。
- Course Missionで比較を`left[i] >= right[j]`へ反転したところ1/7だけ通過した。残る6ケースでは期待結果と降順になった実行結果が並び、比較の向きを直すべきだと画面だけで判断できた。
