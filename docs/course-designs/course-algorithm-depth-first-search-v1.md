# 深さ優先探索（DFS）コース設計票

作成・調査日: 2026-09-25。コースID: `course-algorithm-depth-first-search-v1`。

## 選定理由

既存の幅優先探索（BFS）で、グラフ、隣接リスト、開始地点、発見済み、到達できる範囲を学べる。次は同じ入力を使い、調べる順番だけを「近い順」から「一つの道を進めるところまで進み、行き止まりで戻る」へ変える。共通点と差分を具体的に比べられるため、DFSはBFSの次に最も自然である。DFSで戻る動きと再帰呼び出しを理解すると、今後の連結成分、サイクル検出、トポロジカル順序へ接続できる。重み付き最短路を扱うダイクストラ法はその後に置く。

## 想定する学習者

大学生、Python経験半年〜2年を中心とするが、対象アルゴリズムは未経験として扱う。変数、リスト、辞書、集合の存在、if、for、関数、returnを一度学んだ経験を想定する。BFSコースの修了を推奨するが、グラフと隣接リストは本コース内でも画面に再掲し、記憶を要求しない。再帰、呼び出しの積み重なり、行きがけ順、戻りがけ順、DFS木、計算量証明は未経験とする。

専門用語や英語変数名を自力で推測できること、前Activityの具体的な図や値を記憶していること、分からない内容を外部検索し続けることは前提にしない。各画面で、現在地、進んできた道、発見済み、次に見る隣、戻り先を確認できるようにする。

## 前提知識

リスト、辞書、if、for、簡単な関数とreturnを一度学んだ経験。`graph.get(node, [])`と発見済み判定は短く復習する。集合の`add`、関数が自分自身を呼ぶ再帰、内側の関数、呼び出しが終わると一つ前へ戻る動きはコース内で具体例から導入する。

## 与える体験と学習価値

迷路を一方向へ探索する動き、つながった範囲の列挙、探索アルゴリズムの違い、再帰コードの読み方を学びたい学習者を想定する。完成コードを暗記させず、図上の「進む」と「戻る」、呼び出しの積み重なり、Pythonの`visit(neighbor)`を一手ずつ対応づける。最終的に、開始地点から到達できる場所をDFSで訪れた順に返す`dfs_order`を自力実装する。

## 解決する問題と扱う範囲

場所名をキー、直接つながる場所名のリストを値とする辞書と開始地点を受け取り、各場所の隣接リストを左から見て、到達できる場所を深さ優先で初めて訪れた順に返す。無向グラフを中心に扱い、開始地点から届かない場所は含めない。

最短距離、重み付き辺、経路復元、グラフ全体の全連結成分、サイクルの有無そのものを返す処理、行きがけ・戻りがけ時刻、トポロジカルソート、強連結成分、計算量証明、反復版DFSは扱わない。

## 開始時点と完了時点

開始時点では、BFSまたはグラフの基本を見た経験があっても、1本の道を奥へ進んだ後にどこへ戻るか、再帰呼び出しがどの順で終わるかを追えない。完了時には、現在の呼び出し、戻り先、未発見の隣、発見済みを区別し、次に進む場所または戻る場所を予測できる。循環・分岐・合流を含むグラフで、決められた隣接リスト順のDFS訪問順を実装できる。

## 頭の中に作らせたい処理イメージ

現在地で隣を左から一つずつ見る。未発見の隣があれば、現在地を戻り先として残したままその隣へ進む。進んだ場所をすぐ発見済みにする。未発見の隣がなくなったら、その呼び出しを終えて一つ前の場所へ戻り、残りの隣を続ける。これを開始地点から届く範囲で繰り返す。

## 用語の導入順

一つの道を奥へ進む→行き止まりで戻る→深さ優先探索→DFS。戻り先を残す→関数の呼び出しが積み重なる→再帰。今の場所を調べる`visit(node)`→未発見の隣へ`visit(neighbor)`。初めて着いたときに記録→`visited.add(node)`と`order.append(node)`。正式語の「バックトラック」は「一つ前へ戻る」を図で理解した後に補助語として紹介する。

- Mission 1ではBFSとの違いを「近い順」と「一つの道を奥へ」の一項目だけで比べ、再帰コードは出さない。
- Mission 2では隣接リストの左から最初の未発見の隣を選ぶ規則だけを扱い、戻る処理はまだ求めない。
- Mission 3冒頭で行き止まりを提示し、「現在地だけでは戻り先が分からない」という問いから呼び出しの積み重なりを導入する。
- 再帰という名前を出す前に、AでBを調べている途中にBでDを調べ、Dが終わればBの続きへ戻る具体例を示す。

- Mission 5では`order.append(node)`を初到着時に実行する行きがけ順だけを扱う。戻りがけ順は誤答理由の比較に留める。
- 各採点Activityは、回答前に正しい次の頂点や完成順を強調しない。

## 想定する誤解とフィードバック

- BFSと同じく隣を全部先に見る: 最初の未発見の隣へ進み、その場所の探索を終えてから残りへ戻る図を示す。
- 図で近い位置を次に選ぶ: 隣接リストの左から見るという決定規則を画面内に再掲する。
- 行き止まりで探索終了: 呼び出しの積み重なりから一つ前へ戻り、残りの隣を続ける。
- 戻るときに同じ場所を結果へ再追加する: `order`へ追加するのは初めて到着した直後だけと示す。
- 発見済みの記録を再帰後に行う: A→B→Aの二頂点循環で、次へ進む前に記録する必要を示す。
- `visited`だけで順序も返せると思う: 集合は重複防止、リストは順序保存と役割を分ける。
- DFSで最短距離が求まると思う: 訪問順は隣接リスト順で変わり、最短距離を保証しないとMission 1と最終仕様に明記する。

## 正解コード

```python
def dfs_order(graph, start):
    visited = set()
    order = []

    def visit(node):
        visited.add(node)
        order.append(node)
        for neighbor in graph.get(node, []):
            if neighbor not in visited:
                visit(neighbor)

    visit(start)
    return order
```

## Course Missionとテスト方針

関数名は`dfs_order`、引数は`graph`と`start`、戻り値は隣接リストを左から調べる再帰DFSで初めて訪れた場所のリスト。開始地点を先頭に含め、届かない場所は含めない。一本道、分岐と深掘り、循環、合流、非連結、孤立、長い文字列ラベルの7ケースを使う。

訪問済み判定を外す、記録を戻りがけに移す、最初の隣だけで終了する、開始呼び出しを忘れる、発見済み記録を再帰後へ移す誤実装を検出する。禁止コードは`networkx`と完成済みの探索関数とする。

## 成功条件

- グラフと隣接リストから次に確認する隣を判断できる。

- 到着直後に発見済みへ記録する理由を循環例から説明できる。
- 集合は重複防止、リストは訪問順保存と区別できる。
