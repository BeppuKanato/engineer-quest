# 深さ優先探索（DFS）コース実装・受講レビュー

レビュー日: 2026-09-25。対象コースID: `course-algorithm-depth-first-search-v1`。

## 結論

プログラミング経験が少なく、アルゴリズムを難しいと感じる学習者を想定し、目的→一つの道を奥へ進む→行き止まりで戻る→再帰→発見済み→訪問順→コード統合→自力実装の順で受講した。全7 Mission、全28 Activityを画面で完了し、誤答、再挑戦、ステップ操作、ヒント、コード保存と復元、7件の実行テスト、提出、コース完了まで確認した。

BFSで学んだグラフ表現を再掲しつつ、DFS固有の難所を「右端が現在地の呼び出しの積み重なり」で見えるようにした。戻る動きを理解してから再帰コードへ進み、循環を止めてから訪問順を記録するため、前提のない概念を同時に要求する箇所は見つからなかった。

## 自分で受講して見つけた問題と修正

| 見つけた問題 | 初心者への影響 | 修正 |
| --- | --- | --- |
| 目的説明の完成図で、全頂点が確認済みなのにCだけが「現在地」の青で表示されていた | 探索完了後にも現在地が残ると誤解し、青と緑のどちらを読むべきか迷う | `currentNode`を外し、全頂点を確認済みの緑で統一した。凡例も「確認済み」だけになった |
| 再帰をコードだけで説明すると、呼び出しが終わった後の戻り先を追いにくい | `visit(neighbor)`を単なる繰り返しと捉え、一つ前のforへ戻る仕組みが分からない | グラフと同じ画面に呼び出しを左から積み、右端の現在の呼び出しを強調できる表示を追加した |
| 既存の待ち行列表示は左端を強調するため、DFSの現在地表示には意味が合わない | A→B→D→FでFではなくAを現在地と誤読する | 表示設定に末尾強調を追加し、DFSでは右端、BFSでは従来どおり左端を強調するようにした |
| 容器表示の文言がBFSの「待ち行列」「取り出す側」に固定されていた | 再帰の呼び出しをキュー操作として誤って理解する | 「呼び出しの積み重なり」「開始地点側」「現在の呼び出し」をActivityごとに指定できるようにした |

## 誤答と再挑戦の確認

- 次に調べる場所で「BとCを同時に調べる」を選び、一つの道を先に進める説明から正答へ戻れた。
- 行き止まり後の戻り先でBを選び、呼び出しの右端Fを外すとDへ戻ることを確認した。
- 発見済みにするタイミングを「すべての隣を調べた後」と答え、A→B→Aへ戻る前に記録する必要を確認した。
- コード穴埋めで、隣を記録する、条件を逆にする、同じnodeを呼ぶ誤りを同時に入れ、「記録するのはnode、条件はnot in、呼び出すのはneighbor」と修正箇所を確認した。
- Course Missionで条件を`if neighbor in visited:`へ反転したところ、孤立ケースだけ1/7通過した。残る6ケースは期待順と実行結果`["A"]`を並べて表示し、未発見の隣へ進めていないと判断できた。

## 画面と操作の確認

- コースロードマップで全7 Mission、全28 Activity、Graph/Search分類を確認した。
- グラフは現在地、発見済み、確認済みを文章と色で区別し、各画面で実際に使う状態だけを凡例に表示した。
- 呼び出しの積み重なりは開始地点側と現在の呼び出しを明記し、A→B→D→Fと進む操作、F→D→Bと戻る操作を一手ずつ確認できた。
- 集合`visited`とリスト`order`は比較表で役割を分け、同じ到着時点で更新することを図からコードへ接続できた。
- コード穴埋めは各空欄に日本語の役割があり、不要候補を含む状態でも選択理由を判断できた。
- Course Missionの画面だけで、入力形式、隣を見る順、戻り値、開始地点を含めること、到達不能頂点を含めないこと、最短距離ではないこと、関数名と引数名、全7テストを確認できた。
- ヒント1を開いてコードを保存し、再読み込み後も修正済みコード、保存時刻、開いたヒントが復元された。
- 正解コードは実ブラウザのPython実行環境で7/7を通過し、提出後の正解説明、Course Mission完了、コース完了画面を確認した。
