# 幅優先探索（BFS）コース実装・受講レビュー

レビュー日: 2026-09-25。対象コースID: `course-algorithm-breadth-first-search-v1`。

## 結論

プログラミング経験が少なく、アルゴリズムを難しいと感じる学習者を想定し、目的→図とつながり一覧→距離の層→待ち行列→重複防止→コード統合→自力実装の順で受講した。30 Activityをすべて画面で完了し、誤答、再挑戦、ヒント、コード保存と復元、7件の実行テスト、提出、コース完了まで確認した。

既存の配列・文字列コースから新しい「つながり」の題材へ移るため、最初から専門語やコードを並べず、丸と線、直接つながる場所、近い順という日常語から導入した。Missionごとに新しく増える状態を一つに絞ったため、学習順に前提の飛躍は見つからなかった。

## 自分で受講して見つけた問題と修正

| 見つけた問題 | 初心者への影響 | 修正 |
| --- | --- | --- |
| 目的説明の最初の図に、まだ説明していないつながり一覧と待ち状態の色が出ていた | 何を見ればよいか分からず、色の意味を推測させる | 最初は完成した距離の全体像だけに絞り、つながり一覧と待ち行列を隠した。全頂点は処理済みとして表示した |
| 距離の層を学ぶ途中で待ち行列が表示されていた | 次Missionの概念が先に現れ、層とキューを同時に理解する必要がある | Mission 3では待ち行列を隠し、「同じ距離を全部先に見る」ことだけに集中させた |
| 距離の規則で`distances[...]`というコード語が先に出ていた | 規則ではなく構文の解読が必要になる | 「現在の距離に1を足す」という日本語の規則へ変更した |
| 循環の導入図に6頂点すべてが残っていた | A→B→Aに注目したい場面で無関係な線が視線を奪う | AとBだけの小さな循環図へ変更した |
| 重複防止の説明で`distances`の意味を画面内で再確認できなかった | 前画面を覚えていないと問題文を読めない | 「発見した場所と最少の辺数を記録する辞書」と同じ画面に明記した |
| グラフ凡例に、その画面では使わない状態も常に表示された | 色の種類が増え、現在必要な情報が埋もれる | 実際に登場する状態だけを凡例へ表示するようにした |

## 誤答と再挑戦の確認

- 直接の隣を問う問題で、間接的な場所を含む選択肢を選び、線を直接たどる説明から正答へ戻れた。
- 次に調べる場所で奥へ進む選択肢を選び、距離1の場所を両方先に扱う説明を確認した。
- `pop`と`appendleft`を使う誤答では、左から取り出し右へ追加するFIFOの役割が示された。
- 発見済みにするタイミングを「取り出した後」と答え、待ち行列へ追加する前に記録する理由を確認した。
- 未発見判定、距離の`+1`、右端追加の3箇所を同時に誤り、各修正理由を一つのフィードバックで確認した。
- Course Missionで`popleft()`を`pop()`へ変えたところ6/7となり、「複数経路：短い方を保つ」だけが未通過になった。期待距離2に対して実行距離3が表示され、取り出し順が最短距離に影響することを確認できた。

## 画面と操作の確認

- コースロードマップで全7 Mission、全30 Activity、Graph/Search分類、進捗を確認した。

- コード穴埋めは各空欄に日本語の役割があり、不要候補を含む状態でも選択理由を判断できた。
- Course Missionの画面だけで、入力形式、戻り値、開始地点の距離、到達不能頂点、重複防止、関数名と引数名、全7テストを確認できた。

- 正解コードは実ブラウザのPython実行環境で7/7を通過し、提出後に成功メッセージとコース完了画面を確認した。
