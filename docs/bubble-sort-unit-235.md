# バブルソート フェーズ接続・単元コンテナ接続（Issue #235）

目的: 単品ページで確認済みのバブルソートフェーズ1〜7を、1つの単元として通して学べるよう接続し、アプリの学習画面（進捗保存・学習ログ・フィードバック #202）へ登録する。遷移・結果画面・フィードバックの仕組みは BFS 単元（Issue #77 / #202）の接続モデルを正本とし、画面出し分けの形は棒倒し法（Issue #214）の一般化に揃える。最終確認日: 2026-11-07。

## 実装内容

- 単元コンテナを新設（`front/src/features/learning/bubble-sort/unit/`）：
  - `unit.content.ts`: 単元定義。タイトル「バブルソート」、導入文、フェーズ並び（ID は単品プレビューの contentId と一致）、遷移類型（BFS と同じ bridge / result / result-in-phase / final の統一モデル）、ブリッジ文、フェーズ3・5のリザルト見出し、カードのレアリティ（基準データ §5：フェーズ2=RARE、フェーズ5=COMMON、フェーズ7=EPIC）。
  - `BubbleSortUnitPreview.tsx`: 単元の状態機械と単元ナビゲーション。状態機械・遷移・保存失敗時の再試行・滞在記録は `BfsUnitPreview` と同一の実装で、フェーズの実体と単元定義だけが異なる。一度開いたフェーズはマウントしたまま隠し、戻っても再生位置・回答・コードが残る。
  - `UnitResultScreens.tsx`: フェーズ3・5のリザルト画面と単元最終結果。お祝い（`UnitResultCelebration`）は BFS 側の共通部品をそのまま使い、到達図はバブルソート側の `BubbleSortResultFigure`（並び替えが完成した主教材の配列。正本の手順 `runBubbleSort` から導出した並びを全マス確定で描く）に差し替えた。
  - ブリッジ画面は `bfs/unit/PhaseBridgeScreen` をそのまま使う。単元固有の文言は props のフェーズ定義から読む部品であり、唯一の BFS 依存は総フェーズ数（両単元とも7で一致）の参照だけである。
- フェーズ1・2・4の単品プレビューに接続ポートを追加：BFS・棒倒し法の各フェーズと同じ任意 props（embedded / onLearningEvent / active / onComplete、2・4 は nextLabel）。フェーズ1は最終場面の出口ボタンを onComplete へ、フェーズ2・4は共通プレイヤーの endAction を onComplete へ接続する。未指定なら単品ページとして従来どおり動く。フェーズ3・5・6・7のポートは各フェーズの実装時に用意済みだったものをそのまま使う。
- アプリ登録：`app/unitRegistry.ts` に courseId `course-algorithm-bubble-sort-v2`（既存シード）を kind `"bubble-sort"` で登録。`app/LearningScreen.tsx` は kind でコンテナを出し分け、進捗保存（PhaseLearningProgress / UnitLearningProgress）・コード下書き・学習ログ・フィードバック接続の props は単元共通の形で組み立てて両コンテナへ渡す（コンテナ側の受け口の形は単元間で同一）。出し分けの形は棒倒し法（#214）の変更と同形に揃えてあり、上位で両 PR が合流したときに衝突が最小になる。
- フィードバック接続（#202）：BFS と同じ配線。確認フェーズ（3・5・6）の完了保存後に先行生成を依頼し、フェーズ3・5のリザルト画面と単元最終結果に差し込み口を持つ。バック側は単元非依存の実装済みで変更はない。実験割当のない利用者・未完了イベントでは部品側の契約（404 / 409）により何も表示されない。
- 単品プレビューに `bubble-sort-unit` を追加し、ログイン・DB なしで通し再生を確認できるようにした。

## 判断と留保

- 本 PR の土台は PR #248 のブランチ（`feat/bubble-sort-trace-234`）であり、PR の base も同ブランチにしている。上位の PR 群（#245 回収 → #248）が develop へ合流した後に、本 PR の base を develop へ付け替える想定である。
- LearningScreen / unitRegistry への変更は、棒倒し法（#214、PR #249）の同ファイルへの変更と同形の形（共通 props の組み立て＋kind 出し分け）で入れてある。ただし本系統のツリーには #214 の棒倒し法登録がまだ無いため、本 PR 単体では出し分けは BFS とバブルソートの2単元になる。両 PR の合流時は、レジストリのエントリ追加と出し分け条件の追加として解消できる見込み。
- リザルト画面（UnitResultScreens）は BFS 版が BFS の到達図とフェーズ7文言に結び付いているため、無理に一般化せずバブルソート側に同形の複製を置いた。差分は到達図・フェーズ7文言・単元定義の参照だけに閉じている。単元がさらに増える場合は、この複製を共通化する再設計が要る。
- ブリッジ画面の再利用は構造的なもの（フェーズ定義の形が同一）であり、総フェーズ数の参照が BFS 側定義に残る。両単元とも7フェーズの間は問題ないが、フェーズ数が異なる単元を接続するときはブリッジ画面の共通化が必要になる。
- 到達図の配列はブラウザ実機での目視確認をこの環境では行っていない（verify の静的描画で棒5本・全マス確定・値 [1, 2, 3, 4, 5] の出力を確認済み）。デプロイ後の実機確認をお願いしたい。
- 知識カード・実績のシードは Issue #236 の範囲で、本 PR には含まない。コースシード（`course-algorithm-bubble-sort-v2`）は既存のため、本 PR の登録で単元一覧・学習画面にバブルソートの新フローが現れる。

## 確認方法

1. `front/` で `npm run dev` を起動し、`http://localhost:3000/learning-preview/bubble-sort-unit` を開く（ログイン・DB不要）。
2. フェーズ1の最終場面のボタンからフェーズ2へ進み、以降も各フェーズの完了でブリッジ画面（次のステージ名と目標）を挟んで進むことを確認する。フェーズ3・5の後はリザルト画面（スコアのドットと完成した並びの図）が出ること、フェーズ6は内の結果から進むこと、フェーズ7の全テスト通過で最終リザルト（到達状況の一覧と要約タイル）が出ることを確認する。
3. 上部のナビゲーションで到達済みのフェーズへ自由に戻れること、戻っても回答や再生位置が残っていることを確認する。
4. アプリ側は、実験割当のあるアカウントでコース `course-algorithm-bubble-sort-v2` の学習画面を開き、進捗が保存されることと、フェーズ3・5の結果画面・単元最終結果にフィードバックが出ること（割当のないアカウントでは出ないこと）を確認する。
