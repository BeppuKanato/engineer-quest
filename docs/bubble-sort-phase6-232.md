# バブルソート フェーズ6（応用問題）（Issue #232）

目的: バブルソート単元のフェーズ6を、転移タップ1問・選択2問・Parsons 1問の診断型アセスメントとして実装する。設計は基準データ（docs/concept/bubble-sort-unit-baseline.md §3、正本の取り込みは Issue #226 のため、本実装は承認済み原本に従う）に従う。最終確認日: 2026-11-06。本 PR は feat/bubble-sort-phase5-231（PR #242）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/bubble-sort/consolidation/` に content / types / Preview / README.md を新設（構成は棒倒し法フェーズ6に合わせた）。
  - `consolidation.types.ts`: 共通エンジンの diagnostic-check 形式に場面の配列と正誤の解説文を足した設問型・コンテンツ型と、単元接続用の要約型。
  - `consolidation.content.ts`: 設問・場面・選択肢・正解・タグ・操作指示・正誤文・復習先・完了文と、読み込み時の検証（`validateBubbleSortConsolidation`）。
  - `BubbleSortConsolidationPreview.tsx`: 診断型のアセスメント画面。棒倒し法フェーズ6と同じ画面構成（結果は初回正解スコア＋論点ごとの結果、復習はフェーズ4の元フレームをモーダルで参照再生）。embedded / onComplete（要約通知）/ onNext（診断画面から次へ進む導線）を持つ。
  - 単品プレビュー `/learning-preview/bubble-sort-consolidation` を登録した。
- 設問（基準データ §3 フェーズ6の確定事項）:

| 設問 | 形式 | 場面 | 正解 |
| --- | --- | --- | --- |
| `next-swap-pair` | 配列タップ | 転移用 [3, 1, 4, 2] の1周目を終えた状態 [1, 3, 2, 4]（右端の4は確定） | 位置1（ペア (3, 2)） |
| `sorted-array-behavior` | 選択 | 並び済み [1, 2, 3, 4] の開始状態 | 交換は一度も起きないが、比べることは範囲が尽きるまで行われる |
| `why-right-end-fixed` | 選択 | フェーズ2の `pass-end-1` | 比べるたびに大きい方が右へ移るので、1周すると一番大きい値が右端に届くため |
| `whole-code-order` | Parsons | 参照コード8行すべて | 元の行順（順序自由な行なし） |

- Q1の場面・正解は、転移用の実行記録（`bubbleSortComparisons`）から導く。1周目を終えた配列と右端の確定（`fixedFrom`）を場面とし、正解は2周目で最初に入れ替えが起きる比較の左位置。回答対象はフェーズ3の問1と同じ考え方で、未確定範囲のマス（位置0〜2）に限る。
- Q3の場面はフェーズ2の `pass-end-1` の盤面を参照のまま使う。復習先はすべてフェーズ4のフレームで、新しい配列の答え合わせは作らない。
- 進行・診断は共通エンジンの現行統一仕様（回答では進まずボタンで進行／正解後ロック／初回のみ集計／ソフトゲート）に従い、新規の判定は作らない。

## 留保（判断が必要な点）

- Parsons に順序自由な行を設けなかった。棒倒し法フェーズ6では外周の書き込み4行が互いに独立なため順序自由としたが、バブルソートの8行はコピーが範囲計算より前、条件が交換より前など、すべて順序が意味を持つ。検証では隣接するどの2行の入れ替えも不正解になることを固定した。
- Q2の場面は基準データに盤面の指定がないため、対象配列 [1, 2, 3, 4] の開始状態（比べているペアなし・確定範囲なし）を組み立てた。Q1・Q3の場面は実行記録とフェーズ2の盤面から導いている。
- 基準データ正本（docs/concept/bubble-sort-unit-baseline.md）は Issue #226 で取り込み予定のため本スタックに無い。本実装は承認済み原本 §3 に従った（フェーズ1〜5と同じ留保）。
