# 棒倒し法 フェーズ3（動きの確認問題）（Issue #208）

目的: 棒倒し法単元のフェーズ3を、フェーズ2の盤面を参照する連結2問のアセスメントとして実装する。設計は基準データ（docs/concept/wall-extension-unit-baseline.md §3、正本は未マージのため承認済み原本に従う）に従う。最終確認日: 2026-11-06。本 PR は feat/wall-extension-phase2-207（PR #218）の上に積むスタック PR である。

## 実装内容

- `front/src/features/learning/wall-extension/check/` に content / types / Canvas / Preview / README.md を新設（構成は BFS フェーズ3に合わせた）。
  - `check.types.ts`: 共通エンジンの `NodeTapQuestion` に方向の指示（`direction`）だけを足した設問型・コンテンツ型と、単元接続用の要約型。
  - `check.content.ts`: 設問・正解・依存条件・復習ID・タグ・完了文。場面はフェーズ2の `extend-2-4`（4本目まで伸ばした状態）をステップIDで参照し、壁を複製しない。正解は `wallExtensionMaze.ts` の組み立て済みトレースの5本目から導き、基準データ§3の確定事項（柱 (4,4)・右・(5,4)）との一致をモジュール読み込み時に検証する。
  - `WallExtensionCheckCanvas.tsx`: 描画は共通グリッド基盤（`MazeGridDrawing`）へ委譲し、回答ボタンはマスの中心に重ねる HTML ボタン。共通の `answerCueSx`（破線リング＋タップアイコン）を使い、`aria-label` は「○列目、○行目のマスを選ぶ」。画面上で44px未満になる場合は BFS フェーズ3と同じ考え方で中心から広げる。
  - `WallExtensionCheckPreview.tsx`: BFS フェーズ3と同じ画面構成（キャプション、回答フィードバック、復習モーダル、embedded / onComplete による要約通知）。方向の指示がある設問では「方向の指示：右」の行を盤面の上に示す。
- 設問（連結2問、教材指針の「処理対象の特定→直後の変化」）:
  - Q1 `next-pillar`「次に処理する柱はどれですか」: 回答対象は柱9マス、正解は (4,4)。場面はフェーズ2のステップ canvas そのもの（参照同一）。
  - Q2 `wall-target`「壁になるマスはどれですか」: 方向の指示「右」を示し、回答対象は柱 (4,4) に隣接する未壁マス3つ、正解は (5,4)。`requires` で Q1 の正解と連結する（データ検証として保持し、進行は位置ベースの現行仕様に従う）。
- 回答形式は共通エンジン（`assessment.ts`）の `node-tap-check` をそのまま使い、ノードIDの代わりにセルキー（`"x,y"`）を渡すグリッド版とした。新規の判定・進行は作っていない。
- 進行は全形式統一の現行仕様（PR #170）: 回答では進まず、「次の問題へ／結果を見る」で進む。正解していなくても進める（ソフトゲート）。完了は「最後まで進み、全問に1回以上回答」で、要約は初回回答のみから導く。正解した設問は入力をロックする（ボタン無効化＋送信側でも正解済み設問への追加試行を弾く）。
- 復習は両問ともフェーズ2の元ステップ `extend-2-4` → `extend-4-4` を参照のまま再生し、回答記録を変えない。
- 単品プレビュー: `/learning-preview/wall-extension-check`（フェーズ1・2と同じ登録方法）。

## 検証

- `npm run verify:wall-extension-check`（新規）: 正解セルが組み立て済みトレースの5本目（柱 (4,4)・右・(5,4)）と一致すること、Q1の場面がフェーズ2の該当ステップと参照同一で Q2の場面も同じ盤面（壁集合が同一）であること、回答対象の範囲（Q1=柱9マス、Q2=隣接する未壁マス3つで既に壁の (4,3) を含まない）、共通エンジン経由の完了条件（回答では進まない／未正解でも完了できる／初回結果の保持／古い設問への回答の混入防止）、実描画の壁数と回答ボタンの数・ラベル・ロック、プレビューの実コールバック（復習の開閉、方向の指示の表示、完了キャプション）を確認。
- 回帰: `verify:wall-extension-execution` / `verify:wall-extension-motivation` / `verify:bfs-check` 通過。front の `lint`（警告1件は既存 BfsUnitPreview の無関係なもの）/ `typecheck` / `build` 通過。
- DB・シードの変更はない。

## 留保（判断が必要な点）

- Q2の場面の作り方: フェーズ2に「伸ばす直前」のステップは無いため、Q2の場面は `extend-2-4` の盤面（壁は同一）を保ったまま、処理中の柱を前提設問の正解 (4,4) へ移し、伸ばした直後を表す highlight を外して導出している（`getWallExtensionCheckScene`）。ステップ canvas の参照同一で済むのは Q1 のみ。「盤面が該当ステップと一致する」という要件は、壁の集合については両問とも満たす。
- Q1の場面では、直前に処理した柱 (2,4) が青いまま残る（フェーズ2のスナップショットの意味どおり）。「次に処理する柱」を問う場面として、処理順の直前の位置を示す手がかりとして残した。
- Q2の回答対象を隣接する未壁マスに限定した。壁は柱の隣にしか伸びないため変化の範囲はこの3マスに限られるが、全マスを対象にする案もあり得る。教材指針の「直後の変化の特定」に絞る判断として PR に明記する。
- 設問文は基準データの表記どおり句点・疑問符なし（「次に処理する柱はどれですか」）とした。BFS / DFS の設問文は「？」で終わるため、表記をそろえる場合は別途判断がいる。
