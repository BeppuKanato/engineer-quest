# 発展ミッションの実装（Issue #507）

目的: Issue #507 として、第2層（活用）の発展ミッションを実装する。適用範囲はフロントエンドの画面と、ミッションのデータ・スコア記録。最終確認日: 2026-11-25。
正本・前提: [redesign-overview-2026-11.md](redesign-overview-2026-11.md) §2.1・§2.4、[redesign-ui-policy-2026-11.md](redesign-ui-policy-2026-11.md)。画面の詳細設計は未確定であり、本書は要件仕様である。見え方は提示ポリシーに従い、実装 PR のスクリーンショットで確認する。

## 要件

### 置き換えの範囲

- 独立セクションとしての「作る」は廃止する。旧作るクエスト（テーマ付き実装課題＋得点）5件が発展ミッションになる。作業画面は挑戦画面になる。
- 作品は /my-works に残す。共有と掲示板投稿はミッション側から行う。
- 知識カードの行き先データ（カード→クエスト対応）は、発展ミッションへの対応に付け替える（カード側の表示と参照 UI は Issue #510）。

### 一覧（/missions）

- 単元リザルトやコース一覧からの入口を受ける、発展ミッションの主たる目録とする。
- 各ミッションは、課題（何を解決するか）を先に示す。使うアルゴリズムは事前に決めず、表示でも固定しない。
- 学習者が立てた目標（ティア）と自己ベストがあれば、カード上に示す。

### 挑戦画面

- 課題の提示（仕様・成功条件）→ 実装 → スコアの確定、という流れにする。実装の土台はフェーズ7の画面（Issue #501 の形）を引き継ぐ。
- 難易の差は勝敗ではなくスコア／クリアランクで付ける：正しい単純な解法でもクリアでき、より良いアルゴリズムは高スコアになる。
- スコアは「そのアルゴリズムで改善される測定可能な利益」で定義し、決定的な回数（比較回数、移動回数など）で数える。実時間（壁時計）は使わない。
- 自己ベストを記録し、更新が再挑戦の動機になるよう、結果に自己ベストとの差を示す。
- 目標スコアはティアから選ぶ（自由入力にしない）。システムが既定のティアを提案する。目標はゲートにしない（目標未達でもクリアはクリア）。

### 未決事項（本 Issue で決めない）

- 発展ミッション完了時にフィードバックを出すかどうかは未決（実験計画と論文第3章に触る）。既定は出さない形とし、出す場合は別 Issue で足す。
- ボス課題（特に複雑・複数解法のミッション）の扱いは未定。本 Issue では通常の発展ミッションだけを対象にする。

## 確認方法

1. 旧「作る」の導線が残っていないこと、一覧→挑戦→結果→作品（/my-works）→共有・掲示板投稿が一通り通ることを確認する。
2. 単純な解法でクリアでき、より良い解法でスコアが上がることを、同じミッションで確認する。
3. ティア目標の設定と自己ベスト更新の表示を確認する。
4. スクリーンショットは約1093×614と約2560×1440の2サイズを PR に付ける。seed の適用手順は PR に明記する。
