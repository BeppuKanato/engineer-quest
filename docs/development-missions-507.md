# 発展ミッションの実装（Issue #507）

目的: Issue #507 として、第2層（活用）の発展ミッションを実装する。適用範囲はフロントエンドの画面と、ミッションのデータ・スコア記録。最終確認日: 2026-11-25。
正本・前提: [redesign-overview-2026-11.md](redesign-overview-2026-11.md) §2.1・§2.4、[redesign-ui-policy-2026-11.md](redesign-ui-policy-2026-11.md)。画面の詳細設計は未確定であり、本書は要件仕様である。見え方は提示ポリシーに従い、実装 PR のスクリーンショットで確認する。

## 要件

### 置き換えの範囲

- 独立セクションとしての「作る」は廃止する。旧作るクエスト（テーマ付き実装課題＋得点）5件が発展ミッションになる。作業画面は挑戦画面になる。
- 作品は /my-works に残す。共有と掲示板投稿はミッション側から行う。
- 知識カードの行き先データ（カード→クエスト対応）は、発展ミッションへの対応に付け替える（カード側の表示と参照 UI は Issue #510）。

### 一覧（/missions）

- 単元リザルトやコース一覧からの入口を受ける、発展ミッションの主たる目録とする。
- 各ミッションは、課題（何を解決するか）を先に示す。課題の提示（題・説明・成功条件）では、解法（使うアルゴリズム）を指定しない。どのアルゴリズムを選ぶか自体が第2層の学びであるためで、クリア後のフィードバックや知識カードの参照でアルゴリズム名に触れることは妨げない。
- 自己ベストがあれば、カード上にランクの色のメダルと並べて示す。
- 解放条件として、対応する単元の完了を指定できる（2026-11-25 Kanato 容認）。どの単元がどのミッションに対応するかは、接続方法と合わせて後で決める。

### 挑戦画面

- 課題の提示（仕様・成功条件）→ 実装 → スコアの確定、という流れにする。土台はフェーズ7の自由実装の枠（Issue #501 のプログラム形式：問題タブ／テスト／コンソール／ヒント／橋渡し）をそのまま流用し、そこへスコアの表示と、関連する知識カードを簡単に見られる参照要素（Issue #510）を足す。
- 問題タブには「入力の見方」の図解を置く：例の入力をそのまま図にし（グリッドの色分け、版の箱の並びなど）、記号の意味を凡例で示す。文章を読まなくても、S が入口・# が壁といった記号の意味と、入力の形（1行目が何か）が分かるようにする。出力の例も、行ごとに意味を注記して示す（生のテキストだけを置かない）。
- ヒントで解法を名指ししない。旧作るクエストにあった「役立つアルゴリズム」ヒント（アルゴリズム名＋単元リンク）は廃止する（2026-11-25 Kanato 決定）。
- 難易の差は勝敗ではなくスコア／クリアランクで付ける：正しい単純な解法でもクリアでき、より良いアルゴリズムは高スコアになる。
- 自己ベストを記録し、更新が再挑戦の動機になるよう、結果に自己ベストとの差を示す。
- 目標は「次のランクまであと何点」で表す（下記の通りティアは置かない）。目標はゲートにしない（ランクが低くてもクリアはクリア）。

### スコアとランク

- スコアは「そのアルゴリズムで改善される測定可能な利益」で定義し、決定的な回数（比較回数、調べた部屋数など）で数える。実時間（壁時計）は使わない。数える量は、答えと一緒に出力する操作回数とし、答えの正しさはテストで別途検証する（回数だけ少なく申告してもクリアにならない）。
- 各ミッションは「数える量」について2つの基準値を持つ：理論上の最小値と、単純な解法（端から調べる等）の想定値。得点は1000点満点で、最小値で1000点、単純解法の想定値で300点になるよう直線で換算する（クリアすれば最低300点）。基準値の具体値はミッションごとに決める。
- ランクは得点で切る：S = 950点以上、A = 800点以上、B = 550点以上、C = クリア（300〜549点）。閾値は全ミッション共通とする。ただし閾値の数字は暫定であり、実際に挑戦データが揃ってから調整する（2026-11-25 Kanato 指摘）。
- ティア（ブロンズ／シルバー／ゴールド）は置かない（2026-11-25 Kanato 決定：ランクと意味が二重になるため）。目標は「次のランクまであと何点」で表す。
- 表示（Kanato 要望 2026-11-25：スコア条件・得点・ランクの対応が分かりやすく見えること）：
  - 点数の横に、そのランクの色のメダルを置く（S = 金、A = 銀、B = 銅、C = 灰）。
  - 挑戦画面にスコアパネルを常時置く。スコア条件（何を数えるか、小さいほど高得点であること）、ランクのメダルと点数の対応、自己ベスト（次のランクまでの点数つき）を並べる。
  - 結果では、今回の得点とランク（メダルつき）、自己ベストとの差、次のランクまでの点数を示す。

### フィードバック（2026-11-25 決定）

- 発展ミッション完了時にもフィードバックを出す。称賛は単元完了と同レベルにする（Kanato 決定）。実験計画と論文第3章への反映は論文側の作業として別途行う。

### 未決事項（本 Issue で決めない）

- ボス課題の概念は 2026-11-25 に畳んだ（役割は単元ミッションと発展ミッションが引き継いだ）。本 Issue は発展ミッションだけを対象にする。
- 発展ミッションへの接続方法（導線）は、発展ミッションができてから決める（2026-11-25 Kanato 決定）。

### 候補（BFS・DFS・二分探索まわり、2026-11-25 下書き）

解放条件の「対応する単元」は、その単元で学ぶアルゴリズムが自然に活きる課題に付ける（解法の指定ではない）。

| 題 | 課題 | 解放条件 | 数える量 |
| --- | --- | --- | --- |
| ダンジョンの最短脱出 | 部屋と通路のダンジョンで入口から出口までの経路を返す | BFS | 経路の部屋数と調べた部屋数 |
| 紹介の輪をたどる | 人のつながりで、AからBまで何人経由かと経路を返す | BFS | 調べた人数 |
| 水の広がり予報 | 水源のあるマップで、各マスに水が届く時刻を全部返す | BFS | 計算で訪れたマス数 |
| 島の数を数える | 海と陸のマップで、陸地の塊の数を返す | DFS | 訪れたマスの総数 |
| スキルツリーの前提を全部出す | 目標スキルを覚えるのに必要な前提を全部返す | DFS | 調べたスキル数 |
| 迷路の宝を全部集める | 迷路の宝を全部集めて出口に行く経路を返す | DFS | 歩いたマス数 |
| ショップの商品検索 | 番号順の商品リストから目当ての位置を返す（無ければ -1） | 二分探索 | 比較回数 |
| バグが入った版を特定する | 途中から全部壊れている履歴で、最初に壊れた版を返す | 二分探索 | 確認した版の数 |
| 条件を満たす最初の位置 | 並んだ数列で「X以上になる最初の位置」を返す | 二分探索 | 比較回数 |

最初に型を作る推しは各単元1件：ダンジョンの最短脱出（旧クエストの要件が残っている）、島の数を数える、バグが入った版を特定する。

## 確認方法

1. 旧「作る」の導線が残っていないこと、一覧→挑戦→結果→作品（/my-works）→共有・掲示板投稿が一通り通ることを確認する。
2. 単純な解法でクリアでき、より良い解法でスコアが上がることを、同じミッションで確認する。
3. ランク表示（点数の横のメダル）と自己ベスト更新、次のランクまでの点数の表示を確認する。
4. スクリーンショットは約1093×614と約2560×1440の2サイズを PR に付ける。seed の適用手順は PR に明記する。
