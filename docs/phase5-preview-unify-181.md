# フェーズ5単品画面のフェーズ3単品への統一（Issue #181）

目的: フェーズ5（コードの確認問題）の単品画面にだけ違う操作の仕組みが残っている状態を、フェーズ3（動きの確認問題）単品に揃える。最終確認日: 2026-11-06。

## 調査結果

- 回答→進行のコアフロー（回答しても進まず「次の問題へ／結果を見る」で進む、正解で固定、初回回答で結果判定）は PR #170 で両者とも共通基盤に統一済みだった。
- 残っていた画面側の差分は次の2点。
  1. **再回答の合図**: フェーズ3は、間違えた問題に再回答するとき見出しが「もう一度、〜」になる。フェーズ5にはその合図がなく、同じ値を算出する `retry` 変数が使われないまま残っていた（lint の未使用変数警告の正体）。
  2. **「もう一度解く」の出方**: フェーズ3は回答後ボタンと同じ行に出る。フェーズ5は完了時に別の行として独立して出て、ボタン行自体も回答の有無で出たり消えたりしていた。

## 実装

- フェーズ5の見出しに、フェーズ3と同一の「もう一度、」前置きを付けた（`retry` を実際に使用）。
- フェーズ5のボタン行を常時確保（最小高さ44）し、「もう一度解く」をその行の中へ移した。案内文（再回答か次へ進める旨）は従来どおり不正解時に出す。
- 復習ボタンの文言（「💡 この処理の動きをもう一度見る」）はフェーズ6と共通の系統であり、リトライのボタンではないため変更していない。

## 検証

- `verify:bfs-code-check` に、見出しの再回答合図と「もう一度解く」が1回だけ・共有のボタン行に出ることを固定した。lint の未使用変数警告も解消した。
- 全 verify・front の lint・typecheck・build が通過する。

## 確認方法

スクリーンショットは環境の都合で未取得のため、見え方はデプロイ後の実機確認に委ねる。

1. フェーズ5単品で間違えて再回答するとき、見出しが「もう一度、〜」になること。
2. 完了時の「もう一度解く」が、他のボタンと同じ行に出ること。
