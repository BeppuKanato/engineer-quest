# 貪欲法（硬貨問題）フェーズ3（動きの確認問題）（Issue #383）

目的: 貪欲法（硬貨問題）単元のフェーズ3（動きの確認問題）を、基準データ §3 フェーズ3の連結2問サイクルに沿って実装する。設計は基準データ（docs/concept/greedy-coins-unit-baseline.md §1・§3、正本）に従う。最終確認日: 2026-11-11。前提: 硬貨図基盤とフェーズ1は #381、フェーズ2は #382（本 PR の base ブランチ）。

## 実装

- `front/src/features/learning/greedy-coins/check/check.content.ts`: 連結2問。場面はフェーズ2のステップ `select-3` をIDで参照し、盤面を複製しない（500・100・100 の3枚を使い終わり、残額86、トレイ [500, 100, 100]）。
  - Q1 `next-coin`: 次に選ぶ硬貨を額面列からタップする。正解は実行記録（`greedyCoins.ts` の selections）の4枚目の選択から導く 50。
  - Q2 `why-not-100`: 概念確認（concept-check）の文章4択「なぜ100円ではなく50円を選ぶのか」。正解は「100円は残額の86円より大きくて使えないから」。誤答は「50円の方が小さい硬貨だから」「100円はもう2枚使ったから」「小さい硬貨から順に使う決まりだから」。
  - 誤答時のフィードバックは、どちらの設問でも「残額以下で一番大きい硬貨を選ぶ」という決め方に言及する（基準データ §3）。Q2 の誤答文では、同じ額面は何枚でも使えることも併せて述べる。
  - 完了ステップは `select-4`（50が選ばれたところ）。
- `check.types.ts`: 共通エンジンの concept-check 形式に正誤の解説文を足した設問型・コンテンツ型と、単元接続用の要約型。
- `GreedyCoinsCheckCanvas.tsx`: 盤面描画はフェーズ2の `GreedyCoinsExecutionCanvas`（硬貨図）へ委譲し、額面チップに回答ボタンを重ねる。タップ領域は額面チップの強調リングの円で、画面上で44px未満になる場合は中心から広げる。
- `GreedyCoinsCheckPreview.tsx`: アセスメント画面。二分探索フェーズ3と同型の3段組（#298）。embedded / onComplete（要約通知）を持ち、未指定なら単品ページとして動く。
- ゲートモデルは共通基盤どおり: 回答では進まず「次の問題へ／結果を見る」で進む（ソフトゲート）、結果は初回回答で判定、正解した問題は入力をロックする。復習はフェーズ2の元ステップ（`select-3` → `select-4`）を参照のまま再生する。
- 単品プレビュー: 共有の `front/src/app/learning-preview/[contentId]/page.tsx` に `greedy-coins-check` として登録した。

## 留保（判断した点）

- **Q1 の回答対象は全6額面とした**: 基準データは「額面列のタップ」とだけ定める。同じ額面は何枚でも使えるため、100（もう2枚使った）も500（通過した）も候補から外さず、「残額より大きい硬貨は使えない」ことを含めて判断させる形にした。候補を未通過の額面だけに絞ると、最初の未通過額面がそのまま答えになってしまう。
- **Q2 の選択肢の文言**: 基準データは正解文（「100 は残額 86 より大きくて使えないから」）と誤答の方向（額面の大きさ・使用回数に引っ張られるもの）だけを定めるため、文言は他単元の選択肢の体裁に合わせて整えた。4択目は「小さい硬貨から順に使う決まりだから」（進め方の誤解）を置いた。
