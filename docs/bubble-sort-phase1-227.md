# バブルソート 配列描画基盤とフェーズ1（導入）（Issue #227）

目的: 選択ソート・二分探索と共用できる配列（棒）の描画基盤を新設し、バブルソート単元のフェーズ1（導入）を実装する。設計は基準データ（docs/concept/bubble-sort-unit-baseline.md §3・§4、正本の取り込みは Issue #226 のため、本実装は承認済み原本に従う）に従う。最終確認日: 2026-11-06。

## 配列描画基盤（player 配下、GraphDrawing / MazeGridDrawing の隣）

- `player/arrayBars.types.ts`: CanvasSnapshot の具体型 `ArrayBarsCanvasState`。`data = { kind: "array-bars" }`、`state = { values（数値配列）, comparing（[左index, 右index] or null）, fixedFrom（この index 以上は確定済み） }`、`highlights` はセル index の指定（空配列で「なし」を表現できる）。
- `validateArrayBarsCanvas`: 値が有限な非負数であること、fixedFrom の範囲、comparing が隣接ペアで値の範囲内かつ未確定範囲に収まること、highlight の範囲外・重複を検証する。不正な配列はロード時に例外になる。棒の高さで表す前提のため、負の値は教材データの誤りとして弾く。
- `player/arrayBarsGeometry.ts`: viewBox 600×450 に、値に比例する高さの棒を横並びにする配置。基準線は y=368 で全場面共通、最大値の棒の高さは 288。値ラベルは棒の真上、位置（インデックス）は基準線の下に小さく置く。
- `player/ArrayDrawing.tsx`: SVG 描画。比べているペアは処理中（フォーカス青）、確定済みの右端は完了グレー、それ以外は未処理（白地＋グレーの輪郭）、highlight はフォーカス青の内側の枠。色はすべて playerTokens から取り、緑は使わない。

## フェーズ1（導入）

- `front/src/features/learning/bubble-sort/bubbleSort.ts`: 配列データの組み立て。参照コード（契約 bubble-sort-v1）と同じ手順をたどり、比較ごとの配列を記録する。場面の配列は手書きのベタ書きにせず、この実行記録から取る。入力は変更しない（契約どおり新しいリストを作る）。
- 7場面（すべて完全スナップショット、キャプションは1文）:
  1. バラバラの主教材 [4, 2, 5, 1, 3]。「ゲームのスコアを、小さい順に並べ替えたい場面があります。」
  2. 並び終えた状態 [1, 2, 3, 4, 5] を見せてゴールを共有する。「目指すのは、このように小さい順にきれいに並んだ状態です。」
  3. バラバラに戻り、方法を提示する（comparing=[0,1]）。「並べ替え方は、隣同士を比べて、左が大きければ入れ替えるだけです。」
  4. 最初の交換の後 [2, 4, 5, 1, 3]（交換した2マスを highlight）。「4 と 2 を比べると、左の 4 が大きいので入れ替わりました。」
  5. (5, 1) の交換の後 [2, 4, 1, 5, 3]（交換した2マスを highlight）。「5 と 1 を比べて入れ替わると、大きな 5 が右へ動きました。」
  6. 1周の終わり [2, 4, 1, 3, 5] で 5 が右端に確定（fixedFrom=4）。「1周すると、一番大きい 5 が右端に決まります。」
  7. 完成形 [1, 2, 3, 4, 5]（fixedFrom=0）＋ exit（`{ label: "動きの説明へ進む", nextPhase: 2 }`、BFS・棒倒し法フェーズ1と同じ仕組み）。「残りの範囲も同じことをくり返すと、全体が小さい順に並びます。」
- 用語「バブルソート」はフェーズ1では出さない（基準データ §3 の用語計画。名称付けは後続フェーズ）。
- 単品プレビュー: `/learning-preview/bubble-sort-motivation`（棒倒し法フェーズ1と同じ登録方法）。出口ボタンは単品では未接続（無効表示）。

## 検証

- `npm run verify:bubble-sort-motivation`: 契約 bubble-sort-v1 を検証スクリプト内で独立に再実装し、主教材の全比較（10回・交換6回）と場面の値の遷移（最初の交換、(5, 1) の交換、1周の終わり）が一致することを確認。基盤検証の負系（隣接しないペア、確定範囲内の比較、highlight の重複など）、実描画の棒の本数・ペアの色づけ・確定マス・出口ボタンも確認する。
- 既存の `verify:wall-extension-motivation`、front の `lint`（警告1件は既存の BfsUnitPreview のもので本変更と無関係）/ `typecheck` / `build` も通過。
- DB・シードの変更はない。

## 留保（判断が必要な点）

- 場面5・6は1周目の途中経過を圧縮している。場面4の後、(4, 5) の「交換しない比較」と (5, 3) の交換は場面として見せず、場面5は (5, 1) の交換後、場面6は1周の終わりの状態を置いた。フェーズ1は方法の体験が目的で、全ステップは フェーズ2（動きの説明）で扱う前提である。
- 場面2（ゴールの共有）は確定済みの意味を持たせないため fixedFrom = 要素数（すべて未確定の色）で描く。完成形の場面7は全て確定済み（fixedFrom = 0）であり、同じ並びでも色の意味が場面の役割で異なる。
- 基準データ正本（docs/concept/bubble-sort-unit-baseline.md）は Issue #226 で取り込み予定のため本 PR には含まれない。本実装は承認済み原本 §3・§4 に従った（棒倒し法フェーズ3〜7と同じ留保）。
