# 穴掘り法の座標表示を (y, x) の順に統一（Issue #326）

目的: 穴掘り法単元の学習者向け座標表記を、コードの `grid[y][x]` の添字順に合わせて (y, x) の順に統一し、フェーズ4で「部屋 (3, 1) と言いながら盤面は grid[1][3]」という読みのねじれをなくす。最終確認日: 2026-11-09。

## 問題（レビュー #326 の指摘）

- 穴掘り法は場所によって (x, y) と (y, x) が混在していた。フェーズ4のステップ29では、キャプションの部屋 (3, 1) に対して実際の盤面は `grid[1][3]` で、コード的には正しいが学習者には追いにくい。
- ユーザーの方針: 全部 (y, x) の順番に統一する。

## 変更（表示のみ。コードのロジック・契約・セルキーは変更なし）

座標を文字列化する箇所は単元内に6つあり、すべて反転した。各ヘルパーに「grid[y][x] の添字順に合わせる」旨のコメントを残した。

| ファイル | 対象 | 変更前 → 変更後（例） |
| --- | --- | --- |
| `maze-digging/execution/execution.content.ts` | `coordinate()`（フェーズ2全キャプション） | `(3, 1) から下へ掘ります。` → `(1, 3) から下へ掘ります。`／戻り先 `(7, 3) まで戻ります` → `(3, 7) まで戻ります` |
| `maze-digging/check/check.content.ts` | `coordinate()`（フェーズ3の問題文） | `(5, 3) から右へ掘ります` → `(3, 5) から右へ掘ります` |
| `maze-digging/consolidation/consolidation.content.ts` | `coordinate()`（フェーズ6の問題文・正解フィードバック） | `(3, 5) から左へ掘ります` → `(5, 3) から左へ掘ります` |
| `maze-digging/code-mapping/codeMapping.content.ts` | `coord()`（フェーズ4のキャプション全般） | `(3, 1) を現在マスとします` → `(1, 3) を現在マスとします`。進む量も同じ順: 右 `(1, 0)` → `(0, 1)` |
| `maze-digging/code-mapping/codeMapping.presentation.ts` | `rooms()`（candidates / stack の変数表示） | `[(5, 1), (3, 3)]` → `[(1, 5), (3, 3)]`（保持している値の順はコードどおり (x, y) のまま、表示だけ反転） |
| `maze-digging/trace/convertTrace.ts` | `coordinate()`（フェーズ7トレース再生のキャプション） | フェーズ2と同じ反転 |

- 合わせて、フェーズ3・フェーズ6の README とフェーズ3の場面コメントの座標表記も同じ順に直した。
- 検証スクリプト4本（execution / check / consolidation / code-mapping）のキャプション・表示アサーションを (y, x) 順に更新し、code-mapping には「キャプションと変数表示が (y, x) 順であること」の固定アサーションを追加した。

## 変更しなかったもの（PR 本文にも明記）

- 参照コード（契約 `maze-digging-v1`、本文凍結）の組表記は (x, y) のまま: `x, y = stack[-1]`、`candidates.append((nx, ny))`、`stack = [(1, 1)]`、`directions = [(0, -1), (1, 0), (0, 1), (-1, 0)]`（dx, dy の組）。フェーズ7テンプレートの directions 行も同じ。変数名 x / y / dx / dy / nx / ny もコードの意味そのものなので変更しない。統一したのはコードの周りの表示（キャプション・変数の組表示）である。
- セルキー（`"x,y"` 文字列）は内部識別子のため変更しない。
- 棒倒し法単元は変更しない（本 Issue の対象外）。
- Issue #326 のもう1件「シークバーのチャプター目印」は、ユーザーが「なくても問題はない」とした任意項目のため本 PR では実装しない。

## 検証

- 穴掘り法の verify 9本と front の全 verify、lint / typecheck / build の結果は PR 本文に記録する。
- DB・seed の変更なし。マージのみで反映される。
