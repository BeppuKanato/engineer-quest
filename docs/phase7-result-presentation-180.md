# フェーズ7のテスト結果の出し方の作り直し（Issue #180）

目的: テスト結果が単調で通過の積み上がりが見えない問題と、全通過時の完了表示が素のテキストだけだった問題を直す。最終確認日: 2026-11-06。

## 前提

- テストは1件ずつ実行され、結果は順に届く（`runImplementationTests` の進捗コールバック）。この「届く順」を演出に使う。
- 状態バッジの出現アニメーション自体は既に develop に入っている（PR #188 の取り込み時に同等実装が入ったもの）。本 Issue はその上に積む。

## 実装

- **テスト行**: 通過したテストの見出し横に、リザルト画面と共通の `DrawnCheck`（円とチェックが描き込まれる図形、22px）を出す。結果が届いた行から順に描かれるため、通過の積み上がりが目で追える。未通過・未実施の行には付けない（責める見た目にしない原則どおり）。
- **全通過時の完了表示**: 先頭に大きな `DrawnCheck`（76px）を置き、フェーズ用の紙吹雪（`ResultConfetti` の phase プリセット）を出す。単元フロー埋め込み時も同じ画面のため同じく出るが、単元最終リザルトの final プリセットより一段弱い、賞賛の勾配どおりの強さにしてある。
- 歓声の音声は Issue #179（音源ファイルの受け渡し待ち）で別途入れる。

## 検証

- `verify:bfs-implementation` に、全通過の描画でテスト件数分（5件）の描き込みチェックが出ること・未実施/未通過では出ないことを、実際にコンポーネントを描画して固定した。ソース側のピン（DrawnCheck の通過条件、完了表示の紙吹雪と大きなチェック）も追加した。
- 全 verify・front の lint・typecheck・build が通過する。

## 確認方法

スクリーンショットは環境の都合で未取得のため、見え方はデプロイ後の実機確認に委ねる。

1. フェーズ7でテストを実行し、通過した行から順にチェックが描き込まれることを確認する。
2. 全テスト通過時に、完了表示で大きなチェックと紙吹雪が出ることを確認する。
