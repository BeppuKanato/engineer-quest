# 単元ミッションストーリーの統一（#544）

正本: redesign-ui-policy-2026-11.md §7、story-phase-bridge-511.md。バブルソートを維持し、残り8単元を6コマで提示。図は独立したSVG部品で、正解コードや具体的な探索手順は教えない。初コマは一覧・単元帯と同じ場面。

## bfs

1. 倉庫では、配送ロボットが荷物を積んで、いくつもの通路を通って届け先へ向かいます。
   - 図：倉庫の配送
2. 道を選び間違えると、同じ長さの通路を何本も余分に通ることになり、配達が遅れてしまいます。
   - 図：余分な通路
3. 通路の長さがすべて同じなら、通る道の本数が最も少ない行き方を見つけられるとよさそうです。
   - 図：道の本数が少ない行き方
4. 人間なら、小さな倉庫の地図を見渡して、いくつかの行き方を比べることができます。
   - 図：地図で行き方を比較
5. でもロボットには、まだ調べていない場所をどう選び、どの行き方が最短か判断するのか、正確な手順が必要です。
   - 図：どの場所を調べる？
6. この単元で、その方法を学び、自分のコードで出発点から各届け先までの最短距離を求めましょう。
   - 図：各届け先までの最短距離

## dfs

1. 迷路のあちこちに宝が隠されていて、ロボットはどこにあるか分からないまま探し始めます。
   - 図：宝の隠れた迷路
2. 行き当たりばったりに進むと、同じ場所を何度も通り、まだ調べていない場所が残ってしまいます。
   - 図：同じ道を何度も通る
3. たどり着ける場所を一つも見落とさずに調べられれば、隠された宝も見逃さずに済みます。
   - 図：見落としのない探索
4. 人間なら、小さな迷路で通った場所を地図に書き込み、まだ調べていない道を確認できます。
   - 図：調べた場所を記録
5. でもロボットには、調べた場所の記録や分かれ道での判断を、迷わず繰り返すための正確な手順が必要です。
   - 図：次にどこを調べる？
6. この単元で、その方法を学び、自分のコードでたどり着ける場所を漏れなく調べ、訪問順を記録しましょう。
   - 図：探索漏れのない記録

## binary-search

1. 倉庫には商品が番号の小さい順に並んでいて、ロボットは注文された番号の商品を探します。
   - 図：番号順の商品棚
2. 商品が何百個もあると、端から一つずつ番号を確かめるだけでも時間がかかります。
   - 図：端から探す負担
3. 番号が順番に並んでいることを利用して、調べる商品を少なくできれば、注文に素早く応えられます。
   - 図：確認回数を減らしたい
4. 人間なら、番号の並んだ棚を見渡して、探す番号がありそうな場所に当たりをつけられます。
   - 図：番号から当たりをつける
5. でもロボットには、番号を比べた結果から次にどこを確認し、ない場合はいつ探すのをやめるかという手順が必要です。
   - 図：次に調べる場所は？
6. この単元で、その方法を学び、自分のコードで並んだ番号から目的の商品がある位置を見つけましょう。
   - 図：商品の位置を特定

## maze-digging

1. ゲームの世界では、岩で埋まった場所から、プレイヤーが探検できる迷路を作りたいと考えています。
   - 図：岩から迷路を作る
2. 毎回同じ迷路では道を覚えてしまい、毎回手作業で作るにも時間がかかります。
   - 図：同じ迷路ばかり
3. 岩を掘って、すべての部屋が通路でつながる迷路を自動で作れれば、違う迷路を楽しめます。
   - 図：部屋がつながった迷路
4. 人間なら、小さな盤面で掘った通路を見ながら、部屋が孤立しないように次の場所を考えられます。
   - 図：通路を考える設計者
5. でもコンピュータには、どの岩を掘ってよいか、これ以上掘れないときにどうするかという明確な判断手順が必要です。
   - 図：次に掘る場所は？
6. この単元で、その方法を学び、自分のコードで部屋がつながった迷路を作りましょう。
   - 図：新しい迷路の完成

## wall-extension

1. ゲームの新しいステージを作るため、広場に立った柱を使って、壁のある迷路を作りたいと考えています。
   - 図：柱の並ぶ広場
2. 壁を毎回手で配置するのは大変で、置き方によっては通れない区画ができてしまいます。
   - 図：壁が通路をふさぐ
3. 柱から壁を伸ばして、通路を残しながら違う形の迷路を自動で作れればよさそうです。
   - 図：通路を残す壁配置
4. 人間なら、小さな広場の配置図を見て、壁が通路をふさいでしまわないか考えながら置けます。
   - 図：配置図で考える
5. でもコンピュータには、各柱からどの方向に壁を置いてよいかという、矛盾しない明確な規則が必要です。
   - 図：壁を伸ばす方向は？
6. この単元で、その方法を学び、自分のコードで柱から壁を伸ばして迷路を作りましょう。
   - 図：迷路の壁の完成

## greedy-coins

1. お店のレジでは、500円から1円までの日本の6種類の硬貨を使ってお釣りを渡します。
   - 図：レジのお釣り
2. 小さな硬貨ばかり使うと、同じ金額でもたくさんの硬貨を数え、受け取る人も大変です。
   - 図：小銭が多すぎる
3. 金額は変えずに渡す硬貨の枚数を減らせれば、お釣りの受け渡しがしやすくなります。
   - 図：同じ金額で少ない枚数
4. 人間なら、例えば500円を1円玉500枚で渡すより、500円玉1枚で渡す方がよいと気づけます。
   - 図：500円の渡し方を比べる
5. でもレジには、残りの金額に対してどの硬貨を使うか、いつ支払いを終えるかという明確な手順が必要です。
   - 図：どの硬貨を選ぶ？
6. この単元で、その方法を学び、日本の硬貨を使って枚数の少ないお釣りを求めるコードを書きましょう。
   - 図：金額に合うお釣り

## dijkstra

1. 配送ロボットが荷物を届ける倉庫には、滑らかな床や坂道があり、通路ごとに必要なエネルギーが違います。
   - 図：電池で走る配送ロボット
2. 見た目には短い行き方でも、消費の大きな通路を通ると、遠回りより電池を多く使うことがあります。
   - 図：坂道で電池を消費
3. 道の本数ではなく、出発から届け先までの消費エネルギーの合計が最も小さい行き方を見つけられればよさそうです。
   - 図：消費エネルギーの合計
4. 人間なら、小さな地図に書かれた消費量を足して、いくつかの行き方を比べることができます。
   - 図：経路ごとの消費を比較
5. でもロボットには、たくさんある行き方の中からどこを調べ、何を記録すれば最小の消費量を判断できるのか、正確な手順が必要です。
   - 図：何を調べて記録する？
6. この単元で、その方法を学び、自分のコードで消費エネルギーが最小の経路とそのコストを求めましょう。
   - 図：最小消費の配送経路

## astar

1. 救助ドローンに、広い地図の向こうにある救助地点まで物資を届ける任務が入りました。
   - 図：救助物資を届けるドローン
2. 道ごとの移動時間を調べて最短経路を探せますが、地図が広いと救助地点から離れた場所まで調べる時間がかかります。
   - 図：広い地図を調べる時間
3. 移動時間が最小の経路を見つけることは諦めずに、調べる地点を減らせれば、出発までの時間も短くできます。
   - 図：最短経路と探索の負担
4. 人間なら地図を見て、救助地点の方向やおおよその距離を手がかりに、まず調べたい場所を考えられます。
   - 図：救助地点への見積もり
5. でもドローンには、ゴールまでの見積もりをどう使い、最短の可能性がある経路を見落とさずに判断するかという正確な手順が必要です。
   - 図：見積もりをどう使う？
6. この単元で、その方法を学び、自分のコードでゴールまでの見積もりを活用した最短経路探索に挑戦しましょう。
   - 図：救助地点への最短経路

## レビュー上の注意

- BFSは等コストの道を対象にし、実装課題の各地点までの距離を求める契約に合わせる。
- DFSは出口到達でなく、教材の探索漏れ防止と訪問順の記録に合わせる。
- 二分探索は整列済みの番号列を前提とする。
- 貪欲法は日本の硬貨を対象とし、任意の額面で最適とは主張しない。
- ダイクストラは非負の移動コストの合計を対象とする。
- A*は最短性と探索負担を区別し、必ず探索数が減る／必ず計算時間が短縮されるとは主張しない。
- ストーリーの変更は提示層のみ。教材の正解・ログ・フィードバック・DBには変更なし。
- 既存のフェーズ1冒頭・教材ハッシュは変更しない。ストーリー→フェーズ1の画面での接続、ブラウザの2サイズ撮影、ユーザー文面レビュー、CIは別途確認する。
