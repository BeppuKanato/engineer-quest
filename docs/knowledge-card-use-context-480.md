# 知識カードの作業状況と関連クエスト（Issue #480）

- 目的: 知識カードを、アプリ内の学習・実装へ再訪するきっかけにする。
- 適用範囲: 全21枚のカードseedと使える場所の対応データ。表示の実装はD3-bの対象。
- 最終確認日: 2026-11-19
- 正本: [Issue #480](https://github.com/BeppuKanato/engineer-quest/issues/480)、[開発ガイド](../AGENTS.md)
- 対象実装コミット: `49677220`（本報告の追加前）
- 状態: 実装・静的検証済み。migration・seedはDB未適用。

## 変更内容

全21枚の `useCase` を、特定のクエスト名・画面名を含まない「その知識が効く作業の状況」へ変更した。たとえば「安定なソート」は「同じ値どうしの順番を保ったまま、データを並び替えたい場面で使える。」とした。現時点で対応する作るクエストがないカードも、単元の再学習やコードの試行で使う状況を記述している。

KnowledgeCard に `relatedCreateQuestIds String[] @default([])` を追加した。使える場所は文章とは分離した安定IDの配列で保持し、複数の対応を許容する。13枚に対応を設定し、対応がない8枚は明示的な空配列とした。文章を変えずに配列だけを付け替えられ、既存のカードupsertで配列を丸ごと更新するため、対応を外した場合も `seed:preserve` で反映できる。

カードの枚数・ID・単元・図鑑番号・取得フェーズ（2・5・7）・レアリティ・並び順・公開状態・配布表は変更していない。既存の所持レコードを作り直す処理はなく、同じカードIDの中身を更新する。

## 重複の解消とIssue本文との差異

本文には「深さ優先探索と棒倒し法」とあるが、実データの重複は「深さ優先探索と穴掘り法」である。棒倒し法の3枚は重複していないため、useCaseと対応データ以外は変更しなかった。

| 知識 | 残したカードと理由 | 差し替えたカード（ID維持） |
| --- | --- | --- |
| スタック | 深さ優先探索の「リストで作るスタック」。フェーズ5で扱うappend・popによる実装と近い | `knowledge-card-maze-digging-stack` →「再帰呼び出し」。リストで管理した進む・戻る動きから、関数に同じ処理を任せる別の実装へつなげる |
| バックトラッキング | 穴掘り法の「バックトラッキング」。現在の経路を保ち、行き止まりから候補のある部屋まで戻る教材の動きと近い | `knowledge-card-dfs-backtracking` →「枝刈り」。深さ優先探索を基に、最良の結果を改善できない枝を打ち切る工夫へつなげる |

差し替えは label・title・description・connection・useCase・searchKeywords に限り、既存の所持キーを保持した。全21枚のタイトルは異なる。新しい2枚は教材の問題や正誤判定を追加・変更せず、関連知識として扱う。

## 使える場所の対応

| カード | 対応する既存クエスト |
| --- | --- |
| 重みなし最短経路・双方向探索・バックトラッキング・枝刈り | ダンジョンの最短脱出ルートを作ろう |
| collections.deque・リストで作るスタック | ダンジョンの最短脱出ルートを作ろう／ゲームのスキルツリーを調べよう |
| 安定なソート・値の交換 | RPGの行動順を作ろう |
| 計算量 | RPGの行動順を作ろう／ショップの商品検索を作ろう |
| 再帰呼び出し | ゲームのスキルツリーを調べよう |
| 探索範囲を半分にする・中央の値と比べる・対数時間 | ショップの商品検索を作ろう |
| 手続き型生成・乱数とシード・完全迷路・全域木・トポロジカルソート・貪欲な選択・残額を減らしていく・最適とは限らない | 対応なし |

迷路の生成と既存の経路検索は別の作業なので、生成のカードを経路検索へ一律に結び付けていない。トポロジカルソートも、到達可能な派生先を列挙する既存クエストとは目的が異なるため対応なしとした。

### D3-b向けの参照契約

カードの `relatedCreateQuestIds` を読み、CreateQuestのIDに対して検索する。タイトル・公開状態は検索時のクエストデータから取得し、画面へクエスト名を決め打ちしない。空配列は「対応なし」。削除済み・非公開のIDはリンクとして表示しない。配列には外部キー制約を設けておらず、seed上の存在・重複は `verify:knowledge-card-content` で検証する。クエストの削除・ID変更時は同時に対応配列を更新する。

このPRは新規API・フロントのレスポンス型・表示を追加しない。D3-bで必要なAPIに対応データと公開中のクエスト情報を接続する。

## 適用手順と影響

対象DB（local / dev / production）を明示・確認したうえで、次の順番で手動適用する。

1. `back` で `npx prisma migrate deploy` を実行し、`20261119110000_add_knowledge_card_use_context` を適用する。
2. 新しいschemaで生成したPrisma Clientを含むコードをデプロイする。
3. `back` で `npm run seed:preserve` を実行する。通常seedによる削除同期は使わない。

列追加の既定値は空配列なので、既存カードを削除せず追加できる。更新したクライアントは列を参照するため、コードを動かす前にmigrationを適用する。seedは既存と同じ全マスタの保持更新であり、本PRのカードだけでなく、その時点の他のマスタもupsertする。適用前に採用するコミットを確認する。

マージやCloud RunのCDだけではカードの中身は更新されない。今回local・dev・productionのいずれのDBにもmigration・seedを適用していない。
