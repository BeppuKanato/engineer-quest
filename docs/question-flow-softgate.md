# 確認問題のソフトゲート統一とフェーズ6の正解後固定

目的: 実機レビュー（2026-11-06）の指摘として、(1) 確認問題の中でフェーズ6だけ「次の問題へ」を押さないと進めない形が不統一であること、(2) フェーズ3・5でも「次の問題へ」で問題を変えられるようにすること、(3) フェーズ6で正解した後に再回答（連打・選び直し）ができることを直す。最終確認日: 2026-11-06。

## 実装内容

- 共通 assessment の進行を全形式で位置ベースに統一した（`assessment.ts`）。確認問題（フェーズ3・5）でも、誤答した問題に「再回答するか、正解していなくても次へ進めます。結果には初回の回答を使います。」の案内と「次の問題へ／結果を見る」ボタンを出し、正解しなくても進めるようにした（フェーズ6と同じソフトゲート）。正解した場合は従来どおり自動で次の問題へ進む。
- 完了条件を全形式で「最後まで進み、全問に1回以上回答していること（正解は問わない）」に統一した。結果（スコア・ドット・単元最終リザルトの合算）はこれまでどおり初回回答から導くため、全問未正解でも完了でき、その場合は初回正解 0 として記録される。
- フェーズ3の連動2問は、問1に正解していなくても問2へ進める（問2は問1の要素についてそのまま出題する）。内容データの `requires` は教材データの整合性検証として残し、進行の前提条件からは外した。
- フェーズ6は、正解した問題の入力を固定した：選択肢ボタンは無効化、グラフはタップ不可、Parsons は並び替え・提示順に戻す・回答のすべてを無効化する。正解時は「再回答するか…」の案内を出さず、「次の問題へ／結果を見る」だけを出す。不正解の問題は従来どおり再回答できる。
- 教材指針 `docs/concept/learning-materials-guideline.md` の完了定義を改訂した：フェーズ3・5のハードゲート（全問正解まで進めない）を廃止してソフトゲートへ統一し、フェーズ6の完了定義に「正解した問題は選び直せない」を明記した。Drive 側の指針文書への反映は別途行う。

## 検証

- `verify:bfs-check` / `verify:bfs-code-check`（拡張）: 未回答では進めないこと、誤答→「次へ」で依存する次問へ到達できること、全問未正解でも完了し初回記録が保持されること、画面側に進む導線があることを固定した。
- `verify:bfs-consolidation`（拡張）: 正解後の固定（選択肢・グラフ・Parsons の無効化）を固定した。初回診断・0/5 完了などの既存契約は不変。
- 上記を含む全 verify、front の lint・typecheck・build が通過する。

## 確認方法

対象 URL は http://localhost:3000/courses/roadmap/course-algorithm-breadth-first-search-v1/learn （ログインと進捗が必要）。スクリーンショットは環境の都合で未取得のため、見え方はデプロイ後の実機確認に委ねる。

1. 動きの確認問題（フェーズ3）でわざと誤答し、「次の問題へ」が出ること、押すと正解しなくても問2へ進むこと、最後は「結果を見る」でリザルトへ進み初回正解が 0 になることを確認する。
2. コードの確認問題（フェーズ5）でも同じく、誤答→「次の問題へ」で進めることを確認する。
3. 応用問題（フェーズ6）で正解し、その問題の選択肢・グラフ・Parsons がもう操作できないこと、「次の問題へ」だけが出ることを確認する。不正解の場合は再回答と「次へ」の両方ができることも確認する。

## 追記（2026-11-06、進行の仕組みの統一）

- 初版ではフェーズ3・5は正解時に自動で次の問題へ進んでいたが、「問題を進める仕組みは揃える」との指摘を受け、正解時も「次の問題へ／結果を見る」を押して進む形に統一した（全フェーズ共通）。assessment の回答処理は位置を進めず、進行は `advanceAssessment` に一本化した。
- あわせてフェーズ3・5でも、正解した問題の入力（フェーズ3はグラフと「どれも入らない」、フェーズ5は選択肢）を固定し、選び直しができないようにした（フェーズ6と同じ）。
