# フィードバック入力の教材根拠と利用目的

- 目的：実回答を選択肢・図・コードの意味に結び付け、アナリストが支援を判断し、チューターが具体的に説明できるようにする。
- 適用範囲：新フロー7単元・150確認設問、P3/P5/P6終了・P7単元完了の入力。2026-11-18確認。
- 基準：`develop` `44fb3415`から実装。正本は[LLMフィードバック設計整理](https://docs.google.com/document/d/1nMvW51AOsE5aWeOMAGkV7sxb-3HeEx4_PiNSsedjlDw)の4.1・5.2・付録A。最新の研究方針は[研究の現在地](https://docs.google.com/document/d/15Z80TzY61Bm3GsE9pIK5XRc2Z286WeI9l9eNpYIkk7Y)を参照する。

## 入力と用途

| 情報 | 保存・投入する内容 | LLMでの用途 |
| --- | --- | --- |
| 実回答 | 設問・セッション・試行順・回答・正誤・根拠ID・記録時刻 | 誤答と修正の過程を検討する。正誤だけから習得を断定しない |
| 教材 | 設問、全選択肢、正答、タップ対象ID、前提、図の状態、コード全文、空欄位置、並べ替え行、復習ステップの説明 | IDが何を指すか解釈し、教材に即した考え方を説明する |
| 教材解説 | 元教材の正答・誤答時の説明。未定義はnull。元の正答・図・コード・復習キャプションを根拠として保持 | 解説を創作した保存データにせず、説明の根拠を残す |
| 教材版 | 教材一式のSHA-256を、完了証拠v3のmaterialVersionとして回答と同時に保存 | 回答当時の選択肢・場面を解決する。記録形式のversionとは別 |
| フェーズ | 7フェーズの役割・学習目標・画面のブリッジ文・扱う設問 | 現在位置と次の段階のつながりを判断する |
| 同単元履歴 | その時点までの回答・実装・ヒント。フェーズ指定時は後続フェーズを除外 | 今回までの取り組みを振り返る |
| 他単元履歴 | 本人の、意味上対応する概念の過去の試行・教材。取得時点より後のイベントを除外 | 同じ規則に関する別課題の回答を参考にする。探索順序・難易度・習得は同一視しない |
| 推薦先 | 対象名・教材の役割と扱う内容・URL・利用条件。課題は説明と要件、実績は説明と条件 | 実行可能で支援目的に合う候補を選ぶ |
| 公開投稿 | 単元完了時だけ、同単元の公開投稿とコメントを保存 | 参考リソース。本人の理解の証拠にはしない |
| 大目標 | 既存の目標・達成条件・計算済み進捗を維持 | 目標と現在の取り組みを結び付ける |

`learning.materialContext`に学習構造、各設問の`materials`に教材、`relatedConceptHistory`に他単元の回答、`referencePosts`に参考投稿を保存する。教材と履歴はHEXADなしのアナリストへ渡す。チューターにも固定済み入力から同じ設問教材・根拠・参考情報を渡す。新たな教材取得を生成途中で行わない。

推薦反応履歴は両段階へ渡さない。研究条件のMULTI削除やペルソナ変更は本変更に混ぜず、既存保存結果の読込互換性を維持する。

## 教材の正本と更新

`front/scripts/syncFeedbackMaterials.cjs`が、実行可能なフロント教材を既存ローダーで読み、画面と同じ問題・場面を解決する。別の手書き正答集は作らない。復習は場面の全フレームを再送せず、既存ステップID・キャプション・コード注目箇所を保存する。設問そのものの図とコードは保持する。

教材を変更したらfrontで実行し、教材と生成物を同じPRに含める。

```sh
npm run sync:feedback-materials
npm run verify:feedback-materials
```

- `back/src/learning/feedback/materials.json`：教材版ごとの保存データ。公開済みの過去版を削除・編集しない。
- `front/src/features/learning/assessment/materialVersions.ts`：ブラウザーが送る小さな版一覧。大きな教材保存データをブラウザーへ追加配信しない。
- 2026-11-20（#489）: BFS・DFS・棒倒し法・穴掘り法の導入文章は、`motivationSteps`（ID・キャプション）として版の計算・保存に収録する。導入文の変更だけでも新しい教材版になる。対象は今回文章を変更した4単元からとし、他3単元の版は変更しない。この情報は版管理用で、採点問題やフィードバック生成の入力項目を増やすものではない。
- CIで現在の画面教材と保存データを照合する。バックエンドではv3の回答ID・回答形式・正誤を同じ教材版に照合する。
- 教材の再生成は新しい情報を作らない。フェーズの目的文は本実装の運用定義であり、支援の有効性を実証したものではない。

## 他単元の概念対応

`feedbackMaterials.ts`で明示した2組のみ照合する。BFS/DFSの「発見済みの場所を重ねて追加しない規則」と「出発点から到達できない場所」。対応する教材・設問をPRで確認するための規則であり、学習者の習得が同一だという意味ではない。

その他は共通IDなし。例えばバブルソートと二分探索の`sorted`、各単元の`flow`を、名前が似ているだけで結合しない。新しい対応は対象設問・意味と前提の等価性をレビューして追加する。

関連回答なし、参考投稿なし、フェーズ中なので対象外、古い入力では未取得、教材版不明を区別して保存する。履歴が存在しない学習者に架空の履歴や投稿を作らない。

## 過去の入力JSON

過去の`FeedbackV1.input`と回答証拠v1/v2は読めるが、当時の教材版がなければ自動で「確認済み」にしない。旧版の実回答・コード・未取得の他単元履歴を推測して補わない。

backの変換CLIはDB・LLMを呼ばず、SQLエクスポートの`cases_json`も展開できる。出力は新規ファイル限定。

```sh
npm run feedback:prepare-inputs -- --input=export.json --out=prepared.json
```

教材版がある回答は解決する。ない回答は`unversioned-answer`として残す。操作者が「当時の教材として現在の教材を仮定する」と明示するときに限り、次を使用できる。

```sh
npm run feedback:prepare-inputs -- --input=export.json --out=prepared-assumed.json --assume-current-materials
```

設問文・回答ID・正誤を照合し、異なる場合は停止する。一致しても当時の図・教材版を証明できないので、`explicit-legacy-assumption`と注意書きを残す。元ファイル・元DBレコードは上書きしない。チューターの入力もこの区別を維持する。

新しい教材版付き入力を確実に得るには、フロント・バック両方の適用後に取得する。既に保存した旧入力へ、未記録の実装コードや他単元履歴を後から復元したように追加しない。

## 検証・適用

- フロント：lint、型チェック、build、教材版と全150問の回答保存、概念対応・表示・候補、7単元の実装検証。
- バック：lint、型チェック/build、verify:static。教材版・正誤矛盾・未知IDの拒否、両段階への受け渡し、他単元の所有者と時点、投稿の範囲、旧入力の明示的な補完を検証。
- DB migration・seed変更なし。新しい情報は既存のJSON欄へ保存する。
- 実DB・実API・実画面での保存と生成は未実施。ローカルの入力・テスト成功と、デプロイ済み・教育的に有効を混同しない。
- 入力内容と生成指示が変わるため、エンジン版を`feedback-four-arm-two-stage-grounded-input-2026-11-18-v1`へ変更する。以前の保存済み計画を同じ版として再利用しない。
- このPRは最新developに対する入力基盤の変更。専用作業フォルダーのv5ペルソナは別の未コミット作業であり、このPRには含めない。今回の24件を作る前に、採用するペルソナと入力基盤を揃えて版を記録する。
