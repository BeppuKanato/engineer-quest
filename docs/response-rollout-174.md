# 他画面・掲示板遷移・ヘッダーのレスポンス改善（Issue #174）

目的: PR #152 でホーム／コースに導入した読み込みの仕組み（セッション共有＋クライアントキャッシュ）を、ヘッダーから飛べる他の画面すべてに横展開する。最終確認日: 2026-11-06。

## 棚卸し結果

- 対象の10画面（コレクション、履歴、知識カード、実績、プロフィール、掲示板の一覧・新規・詳細、作るの一覧・詳細・挑戦中一覧）はすべて、画面ごとに `onAuthStateChanged` を購読し直し、`getIdToken()` を取り直してから取得を始める旧方式のままだった。開くたびに認証コールバック→トークン取得→API の順待ちになり、その間は画面が空になる。
- ヘッダー自体はセッション共有済みで固有の待ちはない。ヘッダーの反応の悪さは、遷移先の画面が空になる時間の体感として現れていたため、画面側の解消がそのまま効く。
- 掲示板の新規投稿は、一覧と同じ2件の取得（投稿一覧・コース一覧）を自前でやり直していたのが待ちの主因。

## 実装内容

- 対象画面の認証を `useUserSession` に寄せ、初期表示を `peekClientQueryData` でキャッシュから種まきし、取得を `fetchClientQuery`（鮮度5分・タグ付き）に統一した。前のデータがある間は読み込み表示で画面を消さない。
- 画面ごとのキャッシュ:
  - コレクションと知識カードは同じ取得（コレクション）なのでキャッシュを共有する。プロフィールもコレクション分は同じキャッシュを使う。
  - 掲示板の一覧と新規投稿は、投稿一覧（キー `quest-board`）とコース一覧（キー `quest-board-courses`）を共有する。一覧を開いた後なら新規投稿フォームは即座に準備できる。
  - 投稿詳細は投稿ごとにキャッシュし、反応・編集・コメントなどの変更はキャッシュにも書き戻す（再訪時に自分の変更が消えない）。
  - 実績の目標設定・プロフィール表示の変更、プロフィールのマスコット変更は、成功後にキャッシュ側も同期する。
  - 作る課題詳細は課題ごとにキャッシュする。作る実装画面は、挑戦状態の正しさを優先して内容はキャッシュせずセッション化のみとし、保存・提出の成功後に作る系のキャッシュ（タグ `works`）を無効化する。

## 検証

- `verify:response-feedback` を拡張し、対象13画面について「セッションを使うこと・自前の認証購読を持たないこと・キャッシュで初期表示を種まきすること」を固定した。作る実装画面についてはセッション化と保存・提出後の無効化を、新規投稿については一覧とのキャッシュ共有を固定した。
- 全 verify・front の lint・typecheck・build が通過する。

## 確認方法

スクリーンショットは環境の都合で未取得のため、見え方はデプロイ後の実機確認に委ねる。

1. 実績・履歴・知識カード・プロフィール・コレクション・作るを一巡し、一度開いた画面に戻ったときに内容が即座に表示されることを確認する。
2. 掲示板の一覧を開いた直後に「新規投稿」へ進み、フォームの準備（カテゴリ・関連コース）が即座に終わることを確認する。
3. 投稿詳細でコメントや反応をしたあと、一覧に戻って同じ投稿を開き直し、変更が残っていることを確認する。
4. 作る課題で保存・提出をしたあと、課題詳細や「挑戦中・提出済み」に戻り、状態が古くないことを確認する。
