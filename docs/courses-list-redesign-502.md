# コース一覧の確定形への刷新（Issue #502）

目的: Issue #502 として、コース一覧を設計確定形に刷新する。適用範囲はフロントエンドの提示層。最終確認日: 2026-11-23。
正本・前提: [redesign-ui-policy-2026-11.md](redesign-ui-policy-2026-11.md) §6。完成形の画像は `ui-targets/courses.png`。

## 実装内容（仕様）

- 画面の目的は「次に学ぶものを選ぶ画面」。構成は：標題＋集計帯（「全7単元中 N単元完了」＋緑 #16a34a のバー）→ 絞り込み2行 → 3列グリッド → 「その他のコース」→ 発展ミッション帯。
- 絞り込みは2行ともラベルつきチップ行にする：学習状況（すべて／学習中／未着手／完了、件数つき）、カテゴリ（すべて＋各課題軸）。選択中は主色で塗る。
- グループ行は作らない。全7単元を1つのグリッドに流し、同じ課題軸の単元が隣り合うようにする（行をまたいで組が割れない）。並びは状態順（学習中→未着手→完了）を既定とし、同状態内はフロー順（BFS、DFS、バブルソート、穴掘り法、棒倒し法、二分探索、貪欲法）を保つ。状態による並び替えを既定にはしない（再開はホームの役割）。
- カードの構成：場面サムネイル（高さ196px 級）＋軸チップ行（右端に目標フラグ）＋単元名 18/900＋ミッションの題 16/700＋説明＋「どんな問題を解く？」ボタン＋状態ボタン。
- 軸チップ：軸アイコン＋軸名、18px/700、白地、本文色の2px枠。軸ごとの色分けはしない（軸の数が未定で色が枯渇・衝突するため、過去に試して撤回済み）。
- サムネイルは単元ミッションの「場面」を描く：描くのは「何かをしたくて困っている状態（AS-IS）」であり、解法は描かない。条件は3つ：①課題が一目で分かる、②答えは描かない、③見た人が「自分ならどうする？」と考え始める。同じ課題の組（BFS/DFS、穴掘り法/棒倒し法）は、手法の空間的な性格で描き分ける（例：BFS＝広く浅い倉庫に短い試行の跡、DFS＝暗い区画に1本深く曲がる通路）。単元画面のミッションバンドと同一の図を使う。
- 説明文の形：題＝課題、説明＝「〜することで、…の仕組みを学びます」。
- 状態表示：未着手＝印なし、主ボタン（青）▶「学習を始める」。学習中＝サムネイル下端の緑の進捗バー（「段階 n/6」のピルつき）＋カードの主色2px枠＋青く塗った ▶「学習中」バッジ＋ボタン上に「次は『段階名』」＋青 ▶「続きから学ぶ」。完了＝バッジなし、緑の輪郭ボタン ↻「復習する」。状態の違いはボタンの色ではなく印と進捗の形で表す。灰色は「操作できない状態」だけに使う。
- 目標フラグはチップ行の右端に置く（サムネイル上には置かない）。単元ミッションを自分の目標として採用するトグルであり、目標はゲートにしない。

## 確認方法

1. 学習中／未着手／完了の3状態が表示範囲の先頭に揃って見えるダミー状態で、印・バー・ボタンの違いを確認する。
2. 学習状況とカテゴリの絞り込みが効くこと、軸の組が隣り合いを保つことを確認する。
3. スクリーンショットは約1093×614と約2560×1440の2サイズを PR に付ける。
