# プレイヤー操作系の中央寄せ・拡大と出現ボタンのフェードイン（Issue #140）

目的: Issue #140 の残件として、(1) プレイヤーの再生ボタン・バーが目立たない問題（位置は横方向の真ん中、図の下、サイズ拡大）、(2) 次へ進むボタンが突然現れる問題（最低限フェードイン）、に対応する。適用範囲は共通プレイヤー（`LearningPlayer`）とフェーズ1の出口ボタン、およびプレイヤーUI定義。最終確認日: 2026-11-06。
Issue #140 の他の指摘（フロー矢印とユーザ向け用語、パンくず、次ボタンの分かりやすさ、押下時の無反応）は #160 / #162 / #157 / #151 / #168 で対応済みであり、本 PR の対象は上記2件。中央寄せはプレイヤーUI定義（左寄せ）との競合だったため、ユーザの決定（2026-11-06）により定義ごと改訂した。

## 実装内容

- 操作グループを図の下・横方向中央に配置した（`LearningPlayer` の操作行を中央寄せ）。要素の並び（再生・前へ・次へ・スライダー・n/N）とグループを広げない原則は従来どおり。
- サイズ拡大：再生ボタン 48px → 56px（アイコン 32 → 40）、前へ／次へ 40px → 48px（アイコン 30）。スライダーは幅 320px 以下の統一（#145・#156 の決定）を保ち、つまみ 18 → 22px、レール／トラックを太くして視認性を上げた。n/N は 15px に。
- 最終ステップで出る次へボタン（endAction）は、操作行の右端に絶対配置し、出現しても中央グループの位置が動かないようにした。出現時はフェードイン（opacity + scale、0.3 秒）。フェーズ1の出口ボタンも同じくフェードイン（opacity + 上に 8px、0.35 秒）にした。どちらも動きを減らす設定ではアニメーションなしで即表示する。
- プレイヤーUI定義 `docs/concept/learning-player-ui.md` §3 を改訂した：基準形を「図の下・横方向中央の操作グループ」とし、再生 56px・前後 48px の目安、次へボタンの右端配置とフェードインを明記。改訂理由（実機レビューで操作系が見落とされた）は定義内に注記した。

## 検証

- `verify:learning-player`（拡張）: 中央寄せ、再生 56px・前後 48px、次へボタンの右端配置と motion による出現を固定した。スライダー統一（320px）の契約は不変。
- `verify:bfs-motivation`（拡張）: フェーズ1の出口ボタンが motion でフェードインすることを固定した。
- 上記を含む全 verify、front の lint・typecheck・build が通過する。

## 確認方法

対象 URL は http://localhost:3000/courses/roadmap/course-algorithm-breadth-first-search-v1/learn （ログインと進捗が必要）。スクリーンショットは環境の都合で未取得のため、見え方はデプロイ後の実機確認に委ねる。

1. 導入（フェーズ1）を開く。再生ボタンなどの操作系が図の下の中央に大きく並んでいることを確認する。最後の場面で、右下の次へボタンがフェードインで現れることを確認する。
2. 動きの説明（フェーズ2）でも操作系が中央にあり、最終ステップで右端に次へボタンがフェードインし、その際に中央の操作系が左右へ動かないことを確認する。
3. スライダーのドラッグ・矢印キー・Home / End の操作が従来どおり効くことを確認する。
4. 動きを減らす設定で、ボタンの出現アニメーションがなく即表示になることを確認する。

## 追記（2026-11-06、ユーザの実機確認による位置の修正）

- 最終ステップの次へボタンをバーの右端に置いたところ、「ボタンの位置だけ遠すぎる」との指摘を受けた。次へボタンはシークバーの近く（操作グループの右隣、n/N の直後）に置く形に改め、プレイヤーUI定義 §3 もその形に合わせた。出現時のフェードインは維持する。
- あわせて、シークバーを持たない画面の次へボタンは中央に寄せる原則を定義に明記し、フェーズ1の出口ボタン（図の右下にあった）を図の下部中央へ移した。ブリッジ画面・リザルト画面・フェーズ6のボタンはもともと中央の流れの中にあるため変更なし。
